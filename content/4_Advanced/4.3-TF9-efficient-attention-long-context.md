## Overview

Long-context methods change one of several resources: which token pairs interact, how attention is computed, what state is cached, or whether recurrence replaces an explicit attention matrix. Grouping all of them under “efficient attention” hides these different trade-offs.

We will derive linearized, low-rank and hashing approaches from the computation they avoid. Then we will evaluate what approximation or architectural constraint each introduces alongside measured runtime and memory.

## FlashAttention

### Where the time goes

| level | size | bandwidth |
| --- | --- | --- |
| registers | ~256 KB per SM | ~20 TB/s |
| SRAM (shared memory) | ~192 KB per SM | ~19 TB/s |
| HBM (device memory) | 40–80 GB | ~2 TB/s |

Across the device, SRAM totals roughly 20 MB, so it is ten times faster and a few thousand times smaller than HBM. An algorithm that keeps its working set in SRAM wins, and one that streams through HBM does not, regardless of its FLOP count.

### Exactness, and why it matters

**FlashAttention-2** rearranges the loops so the outer iteration is over query blocks and the rescaling happens once per block rather than per inner step, roughly doubling throughput by reducing non-matmul work. **FlashAttention-3** adds asynchrony and fp8 support for newer hardware.

That makes it categorically different from the methods in [Linear Attention](/module/?id=efficient-linear-attention) and [Sparse attention, sinks and eviction](/module/?id=sparse-attention-sinks-and-eviction), all of which compute a *different* function that approximates attention. Those require an accuracy argument. This one requires only a correctness proof. When comparing long-context methods, the first question to ask is which category a method is in: several papers claiming to "beat quadratic attention" are compared against an unfused baseline that FlashAttention alone would have beaten without approximating anything.

**A systems parallel: PagedAttention.** The same thinking applied to the KV cache rather than the score matrix: allocate in pages, eliminate fragmentation, share prefixes ([Sharing keys and values](/module/?id=efficient-sharing-keys-and-values)). Neither changes the mathematics. Both change the throughput by more than any architectural change of the period.

### From Scratch

```python
import numpy as np


def online_softmax_update(m, l, O, s_block, V_block):
    """The FlashAttention core. Shift-invariance of softmax makes the rescaling
    EXACT: e^{z-m} = e^{m'-m} e^{z-m'}, so nothing is approximated."""
    m_new = max(m, float(s_block.max()))
    exp_old = np.exp(m - m_new)                       # rescale what we had
    exp_new = np.exp(s_block - m_new)                 # normalize the new block
    l_new = exp_old * l + float(exp_new.sum())
    O_new = exp_old * O + exp_new @ V_block
    return m_new, l_new, O_new


def flash_attention(Q, K, V, block=64, mask_fn=None):
    """Never materializes the n x n matrix. Memory O(n), output identical to
    the standard implementation up to floating-point associativity."""
    n, d = Q.shape
    m_keys = K.shape[0]
    O = np.zeros((n, V.shape[1]))
    for i0 in range(0, n, block):                     # query tile
        i1 = min(i0 + block, n)
        Qi = Q[i0:i1]
        m = np.full(i1 - i0, -np.inf)
        l = np.zeros(i1 - i0)
        Oi = np.zeros((i1 - i0, V.shape[1]))
        for j0 in range(0, m_keys, block):            # key/value tile
            j1 = min(j0 + block, m_keys)
            S = Qi @ K[j0:j1].T / np.sqrt(d)
            if mask_fn is not None:
                S = np.where(mask_fn(np.arange(i0, i1)[:, None],
                                     np.arange(j0, j1)[None, :]), S, -1e9)
            m_blk = S.max(1)
            m_new = np.maximum(m, m_blk)
            exp_old = np.exp(m - m_new)
            P = np.exp(S - m_new[:, None])
            l = exp_old * l + P.sum(1)
            Oi = exp_old[:, None] * Oi + P @ V[j0:j1]
            m = m_new
        O[i0:i1] = Oi / l[:, None]
    return O


def arithmetic_intensity(flops, bytes_moved):
    """Compare against the hardware ratio (~150 FLOP/byte for A100 fp16).
    Below it, the kernel is memory-bound and FLOP counts are irrelevant."""
    return flops / max(bytes_moved, 1)


def standard_attention_traffic(n, d, dtype_bytes=2):
    """Write S, read S, write P, read P -- four passes over an n x n matrix."""
    return {"qkv": 3 * n * d * dtype_bytes,
            "score_matrix": 4 * n * n * dtype_bytes,
            "total": (3 * n * d + 4 * n * n) * dtype_bytes}


def flash_traffic(n, d, dtype_bytes=2):
    """Q, K, V read once; O written once. No n^2 term at all."""
    return {"total": (4 * n * d) * dtype_bytes}


def backward_savings(n, h, L, dtype_bytes=2):
    """Compare storage beyond O, which both paths keep. Standard stores the
    n x n matrix per head per layer. Flash stores two scalars per row."""
    standard = n * n * h * L * dtype_bytes
    flash = 2 * n * h * L * 4
    return {"standard_bytes": standard, "flash_bytes": flash,
            "ratio": standard / max(flash, 1)}
```

Running `flash_attention` against a naive implementation and checking `np.allclose(..., atol=1e-6)` is the exercise that makes the exactness claim concrete: the outputs agree to floating-point noise, which no approximate method can say.

```python
import torch.nn.functional as F

out = F.scaled_dot_product_attention(q, k, v, is_causal=True)

# Conditions that silently fall back to the slow path:
#   - need_weights=True (you asked for the matrix, so it must be materialized)
#   - an arbitrary additive attn_mask (rather than is_causal)
#   - fp32 inputs on some versions
#   - head dimension above the kernel's supported maximum

# Measure the difference.
import time
for backend in (SDPBackend.MATH, SDPBackend.FLASH_ATTENTION):
    with sdpa_kernel(backend):
```

The `need_weights=True` trap is worth repeating: asking for the attention matrix forces it to be materialized, which is exactly the thing FlashAttention exists to avoid. A model that is mysteriously slow and memory-hungry has often had that flag left on from a debugging session.

### Worked Example

**Part A: the traffic, counted.** $n = 8192$, $d = 128$, fp16, one head.

**Standard implementation.** The score matrix is $8192^2 = 6.7\times10^7$ elements, 134 MB in fp16. It is written after $QK^\top$, read for the softmax, written after the softmax, and read for $AV$: four passes, so **537 MB** of traffic. The $Q, K, V$ tensors are $3(8192)(128)(2) = 6.3$ MB, negligible by comparison.

**FlashAttention.** $Q, K, V$ read once and $O$ written once: $4(8192)(128)(2) = 8.4$ MB. **No $n^2$ term at all.**

Ratio: $537/8.4 = 64\times$, so FlashAttention moves about $1/64$ of the traffic. At 2 TB/s, that is 269 µs against 4 µs.

**Part B: why the speedup is 2–4× rather than 64×.** The matrix multiplies still have to happen. $QK^\top$ and $AV$ together cost $4n^2d = 4(8192^2)(128) = 3.4\times10^{10}$ FLOPs, which at 300 TFLOP/s is 114 µs, and that is irreducible.

So standard attention takes roughly $269 + 114 = 383$ µs (traffic and compute partly overlap, but traffic dominates), and FlashAttention takes roughly $114$ µs, bounded by the arithmetic it cannot avoid. The observed 2–4× is exactly what this accounting predicts: the memory cost went to zero, and what remains is the compute that was always necessary.

**Part C: the backward pass.** Standard attention stores the $n\times n$ matrix for the backward pass: at $n=8192$, $h=32$, $L=32$ in fp16 that is

$$
8192^2(32)(32)(2) = 137\text{ GB}.
$$

FlashAttention stores the same $O$ as the standard implementation and, in place of the score matrix, $m$ and $\ell$, two scalars per row per head per layer:

$$
2(8192)(32)(32)(4) = 67\text{ MB}.
$$

A factor of about 2000 in the storage that differs between the two passes. Both also keep $O$, which is $8192(128)(32)(32)(2) = 2.1$ GB either way. The recomputation in the backward pass costs one extra $QK^\top$, which is $1.7\times10^{10}$ FLOPs per head-layer. That cost is real, and cheaper than the 137 GB of traffic it replaces by a wide margin.

**Part D: exact versus approximate, in a comparison table.** A paper claims a new linear-attention method is "3× faster than attention at 8k context". The question to ask is what it was compared against:

| baseline | time at $n=8192$ | exact? |
| --- | --- | --- |
| naive PyTorch attention | 383 µs | yes |
| FlashAttention | 114 µs | yes |
| the proposed linear method | 128 µs | **no** |

Against the naive baseline the method is 3× faster. Against FlashAttention it is slightly *slower*, and it approximates. That comparison pattern was common enough in the 2020–2022 literature to be worth checking for by default: a method that is not exact must be compared against the best exact implementation, not against the textbook one.

## Linear Attention

For a head-size-2 worked example of the reassociation, the recurrent form and the elu feature map, see [Linear Attention](/module/?id=efficient-linear-attention). This section covers why the softmax kernel has no finite feature map, random-feature approximations, and the rank bound that makes sharp attention impossible.

### Why exact linearization is impossible

**Theorem.** The exponential kernel $k(q,k) = \exp(q^\top k)$ has **no** finite-dimensional feature map.

*Proof.* Expand the exponential:

$$
\exp(q^\top k) = \sum_{m=0}^{\infty}\frac{(q^\top k)^m}{m!} .
$$

Each term $(q^\top k)^m$ is a polynomial kernel of degree $m$, whose feature map consists of all degree-$m$ monomials, of which there are $\binom{d+m-1}{m}$. The sum runs over **all** $m$, so the feature map is the concatenation of infinitely many finite blocks and is genuinely infinite-dimensional.

Suppose for contradiction that $\exp(q^\top k) = \phi(q)^\top\phi(k)$ with $\phi:\mathbb{R}^d\to\mathbb{R}^D$ finite. Then for any $n$ points, the Gram matrix $K_{ij} = \exp(q_i^\top q_j)$ would have rank at most $D$. But the exponential kernel is strictly positive definite: for distinct points its Gram matrix has **full rank** $n$, for every $n$. Taking $n > D$ gives a contradiction. $\blacksquare$

This is the same fact as the RBF kernel's infinite-dimensional feature map ([SVMs and Kernels](/module/?id=kernel-methods-svms), "The kernel trick"), and it means every linear-attention method is **necessarily an approximation**, not a reformulation.

### Performer and random features

Approximate the exponential kernel with random features rather than replacing it with a different one.

**Positive random features (FAVOR+).** Define

$$
\phi(x) = \frac{e^{-\lVert x\rVert^2/2}}{\sqrt{m}}\Big[e^{\omega_1^\top x},\ \dots,\ e^{\omega_m^\top x}\Big], \qquad \omega_i\sim\mathcal{N}(0,I_d).
$$

**Unbiasedness.** Using the Gaussian moment-generating function $\mathbb{E}_\omega[e^{\omega^\top z}] = e^{\lVert z\rVert^2/2}$ for $\omega\sim\mathcal{N}(0,I)$:

$$
\mathbb{E}_\omega\big[\phi(q)^\top\phi(k)\big]
= e^{-\frac{\lVert q\rVert^2+\lVert k\rVert^2}{2}}\,\mathbb{E}_\omega\big[e^{\omega^\top(q+k)}\big]
= e^{-\frac{\lVert q\rVert^2+\lVert k\rVert^2}{2}}e^{\frac{\lVert q+k\rVert^2}{2}} = e^{q^\top k} ,
$$

since $\lVert q+k\rVert^2 = \lVert q\rVert^2+2q^\top k+\lVert k\rVert^2$. **Exactly the softmax kernel, in expectation.** $\blacksquare$

**Why positive features and not trigonometric ones.** The classical random-Fourier-feature approach uses $[\cos(\omega^\top x),\sin(\omega^\top x)]$, which is unbiased for the RBF kernel. Multiplying each feature map by $e^{+\lVert x\rVert^2/2}$ makes it unbiased for the softmax kernel. But those features take **negative** values, so the estimated attention weights can be negative and the denominator $\phi(q)^\top\sum\phi(k)$ can be near zero or negative, which produces enormous variance and numerical blow-up exactly where the true attention is small. Positive features avoid negative estimates, although their relative variance still depends on $q$ and $k$. The worked example below shows a case where that variance is zero.

**Error.** The estimator has variance $O(1/m)$, so accuracy improves as $1/\sqrt m$. Getting a good approximation needs $m$ comparable to $d$, at which point the cost advantage is modest at moderate $n$.

### What you give up

The mechanism is a rank bound. With a $d'$-dimensional feature map, the implicit attention matrix $\phi(Q)\phi(K)^\top$ has rank at most $d'$. A one-hot attention pattern, where every query attends to a different single key, is a permutation matrix of rank $n$. So for $n > d'$ the pattern is not representable, and the model must blur.

**Where it is fine.** Tasks where the useful information is an aggregate rather than a specific token: summarization at a coarse level, many vision tasks, and any setting where the sequence is long precisely because it is redundant.

### Modern linear attention

The idea did not die. It was rebuilt with the recurrent view taken seriously.

- **RetNet** adds an exponential decay to the state update, $S_i = \gamma S_{i-1} + \phi(k_i)v_i^\top$, giving three equivalent forms (recurrent, parallel, chunked) and a controllable memory horizon.
- **GLA and gated variants** make the decay input-dependent, which is the selectivity that [State-space models](/module/?id=state-space-models) shows to be essential.
- **DeltaNet** replaces the additive state update with a delta rule that can *overwrite* rather than only accumulate, which fixes a specific capacity failure of the additive form.

All of them are, structurally, linear attention with a better-designed state update. The convergence between this line and state-space models is close enough that recent work treats them as one family.

### From Scratch

```python
import numpy as np


def elu_feature_map(x):
    """phi(x) = elu(x) + 1: simple, and POSITIVE -- needed so the denominator
    cannot vanish or change sign."""
    return np.where(x > 0, x + 1.0, np.exp(x))


def linear_attention(Q, K, V, phi=elu_feature_map):
    """Reassociate: phi(Q) (phi(K)^T V) instead of (phi(Q) phi(K)^T) V.
    O(n d' d_v) instead of O(n^2 d), and the n x n matrix never exists."""
    Qp, Kp = phi(Q), phi(K)
    KV = Kp.T @ V                                    # (d', d_v) -- computed ONCE
    Z = Kp.sum(0)                                    # (d',)
    num = Qp @ KV
    den = (Qp @ Z)[:, None] + 1e-6
    return num / den


def causal_linear_attention(Q, K, V, phi=elu_feature_map):
    """A RECURRENCE with a fixed-size state. Generation is O(1) per token with
    NO KV cache -- the transformative property for serving."""
    n, d = Q.shape
    Qp, Kp = phi(Q), phi(K)
    S = np.zeros((Kp.shape[1], V.shape[1]))          # the entire memory
    z = np.zeros(Kp.shape[1])
    out = np.zeros((n, V.shape[1]))
    for i in range(n):
        S += np.outer(Kp[i], V[i])
        z += Kp[i]
        out[i] = (Qp[i] @ S) / (Qp[i] @ z + 1e-6)
    return out


def state_size(d_feature, d_value, dtype_bytes=2):
    """Fixed, regardless of sequence length. Compare a KV cache growing as
    2 L n h d_k."""
    return d_feature * d_value * dtype_bytes


def performer_features(x, omega, eps=1e-6):
    """FAVOR+: positive random features, unbiased for exp(q.k) by the Gaussian
    MGF. Positivity is the point -- trigonometric features are also unbiased
    and blow up when the denominator approaches zero."""
    m = omega.shape[0]
    proj = x @ omega.T                               # (n, m)
    norm = (x ** 2).sum(-1, keepdims=True) / 2
    return np.exp(proj - norm - np.log(m) / 2)


def performer_unbiasedness_check(q, k, m=10000, seed=0):
    """E[phi(q).phi(k)] = exp(q.k), exactly. Verify numerically."""
    rng = np.random.default_rng(seed)
    omega = rng.standard_normal((m, len(q)))
    est = float(performer_features(q[None], omega) @ performer_features(k[None], omega).T)
    return {"estimate": est, "exact": float(np.exp(q @ k))}


def attention_rank_bound(d_feature, n):
    """phi(Q) phi(K)^T has rank <= d'. A one-hot pattern is a rank-n
    permutation matrix, so sharp attention is INEXPRESSIBLE for n > d'."""
    return {"max_rank": d_feature, "needed_for_one_hot": n,
            "sharp_attention_possible": d_feature >= n}


def sharpness(weights):
    """Max attention weight per query. Softmax reaches ~1; a rank-limited
    factorization cannot."""
    return float(np.asarray(weights).max(-1).mean())


def retnet_step(S, k_phi, v, gamma=0.96):
    """RetNet: an exponential decay on the state, giving a controllable memory
    horizon 1/(1-gamma) instead of unbounded accumulation."""
    return gamma * S + np.outer(k_phi, v)


def crossover_length(d, d_feature):
    """Linear attention wins once n exceeds roughly d' -- below that the
    constant factors favor exact attention, especially with FlashAttention."""
    return d_feature
```

```python
import torch
import torch.nn.functional as F

# The exact baseline any linear method must beat -- not the naive one.
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)   # FlashAttention

# Linear attention, in three lines.
def linear_attn(q, k, v, eps=1e-6):
    q, k = F.elu(q) + 1, F.elu(k) + 1
    kv = torch.einsum("bshd,bshm->bhdm", k, v)      # (B, H, D, M) -- fixed size
    z = 1 / (torch.einsum("bshd,bhd->bsh", q, k.sum(1)) + eps)
    return torch.einsum("bshd,bhdm,bsh->bshm", q, kv, z)

# Libraries worth knowing: fla (flash-linear-attention) implements RetNet, GLA,
# DeltaNet with fused chunked kernels; performer-pytorch for FAVOR+.

#   - needle-in-a-haystack at several depths (tests sharp retrieval)
#   - an induction-head probe (a repeated random sequence)
# Perplexity alone will NOT reveal the failure.
```

Benchmark against FlashAttention, not against a naive implementation, and report the crossover length. A method that is faster at $n = 64{,}000$ and slower at $n = 4{,}000$ is useful only for a narrow set of applications, and papers that omit the crossover are usually omitting it for a reason.

### Worked Example

**Part A: the generation saving.** A 32-layer model with 32 heads, $d_k = 128$, generating at 100,000 tokens of context, fp16.

**Transformer KV cache:** $2Lnhd_k \times 2 = 2(32)(10^5)(32)(128)(2) = 5.24\times10^{10}$ bytes $= 52$ GB, per sequence. The final factor of 2 is the number of bytes per fp16 value.


**Linear attention state:** $Lhd'd_v \times 2 = 32(32)(64)(64)(2) = 8{,}388{,}608$ bytes $= 8.4$ MB, per sequence, **independent of $n$**. One $d'\times d_v$ state per head per layer, matching the transformer figure's 32 heads.

A factor of about 6,250. At batch 64 the transformer needs 3.3 TB of cache and the linear model needs 0.54 GB. That is the property the whole line of work exists for, and it is why the idea keeps being revisited despite the quality gap.

**Part B: why sharp attention is impossible.** Take $n = 1024$ queries, each of which should attend to exactly one distinct key: the pattern an induction head needs.

The true attention matrix is a $1024\times1024$ permutation matrix, of **rank 1024**. Linear attention's implicit matrix is $\phi(Q)\phi(K)^\top$ with $\phi(Q)\in\mathbb{R}^{1024\times64}$, so its rank is at most **64**.

By Eckart–Young ([Advanced Linear Algebra](/module/?id=linear-algebra-ii-eigenvalues-eigenvectors-spectral-theory)), the best rank-64 approximation to a $1024\times1024$ permutation matrix has Frobenius error

$$
\sqrt{\sum_{i>64}\sigma_i^2} = \sqrt{1024-64} = 31.0
$$

against $\lVert A\rVert_F = 32$, so **its relative Frobenius error is 97%**. The model does not approximate the pattern badly. It cannot express it at all.

**Part C: Performer's variance, and why positivity matters.** Take $\lVert q-k\rVert^2 = 10$, so the RBF kernel value being estimated is $e^{-5} = 0.0067$, a position the query should essentially ignore.

**Trigonometric features** estimate this as an average of $\cos(\omega^\top(q-k))$ terms, each in $[-1,1]$, whose mean is $0.0067$. With $m = 64$ features the standard error is at most $1/\sqrt{64} = 0.125$, an upper bound **nineteen times the quantity being estimated**, and estimates can be negative.

A negative estimate is not merely inaccurate: it enters a denominator that is supposed to be a sum of positives, and a few such terms can drive it toward zero, producing an output of arbitrary magnitude.

**Positive features** can estimate the same RBF kernel by using $\phi_{\mathrm{RBF}}(x) = e^{-\lVert x\rVert^2/2}\phi(x)$ with the positive softmax features above. The estimate cannot be negative. For example, when $q=-k$ and $\lVert q\rVert^2=2.5$, every term before averaging equals $e^{-5}$, so this estimator has zero variance.

**Part D: the empirical picture.** Perplexity on a language-modeling benchmark and accuracy on an induction probe, at matched parameters:

| model | perplexity | induction accuracy | 8k-token generation memory |
| --- | --- | --- | --- |
| transformer | 18.2 | 96% | 4.2 GB |
| linear (elu) | 21.7 | 12% | 8.4 MB |
| Performer ($m=256$) | 19.9 | 34% | 34 MB |
| RetNet | 18.9 | 71% | 8.4 MB |

Perplexity understates the gap badly: a 3-point difference looks tolerable, while the induction probe shows the linear model has essentially lost a capability the transformer has. That divergence between an averaged metric and a targeted one is the pattern throughout this literature, and it is why the probe belongs in every evaluation.

## Low-Rank and Hashing Attention

### Linformer

**The observation.** The attention matrix $A = \operatorname{softmax}(QK^\top/\sqrt d)$ is empirically **approximately low-rank**: its singular values decay quickly, so a few dozen components capture most of it.

**The method.** Project the keys and values along the *sequence* dimension before attending:

$$
\text{out} = \operatorname{softmax}\!\left(\frac{Q(EK)^\top}{\sqrt d}\right)(FV),
$$

with learned $E, F\in\mathbb{R}^{k\times n}$ and $k\ll n$. The attention matrix is now $n\times k$, so the cost is $O(nkd)$, linear in $n$ for fixed $k$ (typically 256).

**Two fatal restrictions:**

1. **Fixed sequence length.** $E$ and $F$ have $n$ columns, so the model works only at the length it was trained at. Every other method here handles variable lengths.
2. **No causal masking.** Projecting mixes *all* positions into each of the $k$ summary slots, including future ones. There is no way to mask afterwards, because the future has already been blended in. **Linformer cannot be used for autoregressive generation**, which rules out language modeling entirely.

It works for encoder-only classification at a fixed length, which is a narrow niche.

### Nyström

**Nyströmformer** approximates the softmax matrix by the Nyström method: choose $m$ **landmark** positions (by segment-means of $Q$ and $K$), and reconstruct

$$
A \approx \tilde A = A_{Qk}\,A_{kk}^{+}\,A_{kQ},
$$

where $A_{Qk}$ is attention from all queries to the landmark keys, $A_{kk}$ is landmark-to-landmark, and $A_{kQ}$ is landmarks to all keys. Each factor applies its own row-wise softmax over its columns, so these are separately normalized attention matrices, not blocks extracted from the full $A$. Cost $O(nmd)$ for the products involving the sequence, and unlike Linformer it handles variable lengths and can be made causal with care.

The pseudo-inverse $A_{kk}^{+}$ is cheap to compute for small $m$, since it is only $m\times m$.

**What landmarks buy over a learned projection.** The landmarks are computed *from the input* at each forward pass, so nothing is tied to a fixed $n$, and the approximation adapts to the actual content rather than to a projection learned once during training. That is also the classical Nyström method's advantage in kernel approximation, and it is the same mathematics.

### Hashing and other families

**Reformer** uses locality-sensitive hashing to bucket similar queries and keys and attends within buckets plus an adjacent one at chunk boundaries. $O(n\log n)$. The intuition is that softmax is dominated by the largest scores, so finding approximate nearest neighbours in key space suffices.

The specific LSH is random projection onto a sphere: hash $x$ to $\arg\max([xR; -xR])$ for a random $R$, which assigns nearby vectors the same bucket with high probability. Queries and keys share the projection so that a query lands in the bucket of the keys it would score highly against.

Fiddly in practice: several hash rounds are needed to reduce the chance of missing a relevant key, buckets must be balanced to batch efficiently, and chunk boundaries need care. Reformer also ties $Q = K$, which changes the model.

**Other families, briefly:**

- **Longformer / BigBird** are sparse patterns rather than approximations of the full matrix, covered in [Sparse attention, sinks and eviction](/module/?id=sparse-attention-sinks-and-eviction).
- **Synthesizer** dispenses with content-based attention entirely, learning the attention weights as parameters. Surprisingly competitive on some tasks, which says something uncomfortable about how much of attention is content-dependent.
- **Clustered attention** groups queries by similarity and computes one attention row per cluster, a query-side analog of Reformer's bucketing.

### The Long Range Arena

The **Long Range Arena** (Tay et al., 2020) benchmarked efficient transformers on six long-sequence tasks. The findings:

1. Quality loss is **real and larger than the individual papers reported**: each paper compared against a baseline favorable to it.
2. **No method dominates.** Different methods win different tasks, with no consistent ordering.
3. Vanilla attention is competitive or better on several tasks despite the cost.
4. Reported speedups often did not materialize on real hardware.

Point 4 deserves emphasis: an asymptotic improvement with a bad constant, an irregular memory access pattern, or a step that does not map onto a matrix multiplication can be slower in wall-clock terms than the quadratic method it replaces, at every length anyone actually uses.

### And then the baseline moved

The efficient-attention literature was competing against a *naive* $O(n^2)$ implementation that materializes the score matrix. **FlashAttention** is 2–4× faster and uses $O(n)$ memory, **exactly** ([FlashAttention](/module/?id=efficient-flashattention)).

So a method that was 2× faster than the naive baseline is now *slower* than the exact one, and it approximates. The memory argument, the original motivation for most of these methods, also evaporated, since FlashAttention's memory is already linear.

**What survived the reassessment:**

- **Exact and better-implemented** methods (FlashAttention, PagedAttention): universally adopted.
- **Architectural changes** rather than attention approximations: state-space models ([State-space models](/module/?id=state-space-models)) and modern linear attention, which change what the model *is* rather than approximating what it was.
- **Sparse patterns with a structural justification**: sliding windows in Mistral, which are cheap, causal, and easy to reason about.

**What did not:** Linformer, Reformer, Synthesizer, and most of the 2020–2021 approximation literature are essentially unused today.

### How to read a claim in this area

Five questions, in order:

1. **Exact or approximate?** If approximate, every speed claim needs a paired quality claim on a task that stresses what is being approximated.
2. **What baseline?** Against naive attention is not informative post-2022.
3. **At what length?** Report the crossover. A win only at $n = 64{,}000$ is a win for a small set of applications.
4. **Causal?** Many methods work only for encoders, which excludes language modeling.
5. **Which evaluation?** Perplexity is forgiving. Needle-in-a-haystack and induction probes are not, and the gap between them is where these methods fail.

### From Scratch

```python
import numpy as np


def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)


def attention_spectrum(Q, K, d):
    """The empirical claim behind every method here: the singular values of the
    attention matrix decay fast. Check it on YOUR data before relying on it."""
    A = softmax(Q @ K.T / np.sqrt(d))
    s = np.linalg.svd(A, compute_uv=False)
    return {"singular_values": s,
            "energy_in_top_64": float((s[:64] ** 2).sum() / (s ** 2).sum())}


def linformer_attention(Q, K, V, E, F, d):
    """Project along the SEQUENCE dimension. Fast, fixed-length, and NOT
    causal -- each summary slot already contains the future."""
    K_proj = E @ K                                   # (k, d)
    V_proj = F @ V                                   # (k, d_v)
    A = softmax(Q @ K_proj.T / np.sqrt(d))           # (n, k)
    return A @ V_proj


def linformer_causality_violation(E, position, future_position):
    """E[:, future] != 0 means the summary slot contains the future. There is
    no post-hoc mask that can undo the mixing."""
    return float(np.abs(E[:, future_position]).max())


def nystrom_attention(Q, K, V, m, d):
    """Landmarks are computed FROM THE INPUT, so nothing is tied to a fixed n
    and the approximation adapts to the content."""
    n = Q.shape[0]
    seg = max(n // m, 1)
    Q_land = np.stack([Q[i * seg:(i + 1) * seg].mean(0) for i in range(m)])
    K_land = np.stack([K[i * seg:(i + 1) * seg].mean(0) for i in range(m)])

    F_ = softmax(Q @ K_land.T / np.sqrt(d))          # (n, m)
    A_ = softmax(Q_land @ K_land.T / np.sqrt(d))     # (m, m)
    B_ = softmax(Q_land @ K.T / np.sqrt(d))          # (m, n)
    return F_ @ np.linalg.pinv(A_) @ (B_ @ V)


def lsh_hash(x, R):
    """Random projection LSH: nearby vectors share a bucket with high
    probability. Queries and keys use the SAME projection, so a query lands
    where its high-scoring keys are."""
    proj = np.concatenate([x @ R, -(x @ R)], axis=-1)
    return proj.argmax(-1)


def lsh_attention(Q, K, V, n_buckets, d, n_rounds=4, rng=None):
    """O(n log n) in principle. Several rounds are needed because one hash
    frequently misses a relevant key -- which is where the constant goes."""
    rng = rng or np.random.default_rng(0)
    out = np.zeros((Q.shape[0], V.shape[1]))
    for _ in range(n_rounds):
        R = rng.standard_normal((d, n_buckets // 2))
        bq, bk = lsh_hash(Q, R), lsh_hash(K, R)
        for b in np.unique(bq):
            qi, ki = np.where(bq == b)[0], np.where(bk == b)[0]
            if len(qi) == 0 or len(ki) == 0:
                continue
            A = softmax(Q[qi] @ K[ki].T / np.sqrt(d))
            out[qi] += A @ V[ki]
    return out / n_rounds


def approximation_error(A_true, A_approx):
    """Relative Frobenius error. Report this per HEAD -- the diffuse heads
    approximate well and the retrieval heads do not, and the average hides it."""
    return float(np.linalg.norm(A_true - A_approx) / np.linalg.norm(A_true))


def eckart_young_floor(A, rank):
    """The best ANY rank-k method can do. If this is already large, no clever
    low-rank scheme will help."""
    s = np.linalg.svd(A, compute_uv=False)
    return float(np.sqrt((s[rank:] ** 2).sum()) / np.sqrt((s ** 2).sum()))
```

Before adopting any approximate method, compute the Eckart–Young floor on your own attention matrices at the rank you intend to use. If the unavoidable error is already 30%, no implementation detail will rescue the approach, and the experiment costs one forward pass.

### Worked Example

**Part A: is the attention matrix actually low rank?** Consider illustrative attention spectra at $n = 2048$. The diffuse and positional rows below are assumed examples, not model measurements. The previous-token pattern attends to the preceding token, with the first row attending to itself. The induction pattern is an idealized permutation. Compare the fraction of Frobenius energy captured by the top 64 singular values:

| head type | energy in top 64 | rank needed for 95% |
| --- | --- | --- |
| diffuse (broad context) | 0.97 | 41 |
| positional (fixed offset) | 0.88 | 130 |
| previous-token | $65/2048 \approx 0.032$ | 1,945 |
| induction | $64/2048 = 0.03125$ | 1,946 |

The previous-token pattern has squared singular values $2$, then $2046$ ones, then $0$. The induction permutation has $2048$ ones. Thus the ranks needed for 95% energy are $\lceil 0.95(2048)-1\rceil = 1945$ and $\lceil 0.95(2048)\rceil = 1946$.

**The low-rank claim depends on the head.** The diffuse example is approximately low rank. The previous-token and induction patterns are near-permutation matrices of nearly full rank, modeling retrieval by heads involved in in-context learning ([Sparse attention, sinks and eviction](/module/?id=sparse-attention-sinks-and-eviction)).

A rank-64 approximation can therefore preserve diffuse attention while discarding most of a retrieval pattern.

**Part B: the Eckart–Young floor.** For the induction head above, the best possible rank-64 approximation has relative error

$$
\frac{\sqrt{\sum_{i>64}\sigma_i^2}}{\sqrt{\sum_i\sigma_i^2}} = \sqrt{1 - 64/2048} \approx 0.984 .
$$

**The minimum relative Frobenius error is about 98.4% at rank 64**, by the optimal approximation ([Advanced Linear Algebra](/module/?id=linear-algebra-ii-eigenvalues-eigenvectors-spectral-theory)). Linformer's learned projection, Nyström's landmarks, and every other rank-64 scheme are bounded by this: they cannot do better than the SVD, and they all do somewhat worse.

That single calculation, which costs one forward pass, would have predicted the failure of an entire literature on retrieval-heavy tasks.

**Part C: Linformer's causality violation, made concrete.** $n = 8$, $k = 2$, with a learned $E\in\mathbb{R}^{2\times8}$ whose first row is $(0.1, 0.1, 0.2, 0.1, 0.2, 0.1, 0.1, 0.1)$.

Summary slot 1 is $\sum_j E_{1j}k_j$, which includes $0.1k_8$, the key at position 8. A query at position 2 attending to slot 1 has therefore incorporated information from position 8, six steps in its future.

**Masking cannot fix this.** A causal mask zeroes attention *from* a query *to* a key, but here the future key has already been summed into the slot. The query attends to one number in which position 8's contribution is inseparable from position 1's. To make it causal you would need a different $E$ per query position, which is $n$ projections, restoring the quadratic cost the method existed to remove.

**Part D: Reformer's constant.** LSH attention is $O(n\log n)$ asymptotically. In practice:

| component | cost |
| --- | --- |
| hash rounds | 4–8× the work, to reduce the chance of missing a key |
| sorting into buckets | $O(n\log n)$ with poor memory locality |
| bucket balancing | irregular shapes, poor GPU utilization |
| chunk handling | attend to the adjacent bucket too, doubling the work |

The measured crossover against FlashAttention is beyond $n = 32{,}000$ on typical hardware, and the model must also tie $Q = K$, which changes what it can represent.

**The general shape:** an asymptotic win with a constant of 8 and an irregular access pattern loses to a quadratic method with a constant of 1 and perfect locality, until $n$ is very large indeed.

**Part E: the reassessment, tabulated.** Time per forward pass at $n = 4096$, $d = 64$, one head, on a modern accelerator:

| method | time | exact? | causal? |
| --- | --- | --- | --- |
| naive attention | 5.2 ms | yes | yes |
| **FlashAttention** | **1.4 ms** | **yes** | **yes** |
| Linformer ($k=256$) | 1.1 ms | no | **no** |
| Nyströmformer ($m=64$) | 1.9 ms | no | with care |
| Reformer (4 rounds) | 4.8 ms | no | yes |
| linear (elu) | 0.9 ms | no | yes |

Against the naive baseline, all four approximate methods are faster, though Reformer only by 8%. Against FlashAttention, only two are faster, both approximate, and one cannot do causal masking at all.

These are single-head wall-clock times, dominated by kernel-launch overhead rather than by arithmetic, so they are not comparable with the compute-bound microsecond figures in the FlashAttention section: they rank the methods, and do not price them.

**That table is the whole story of the field between 2020 and 2022**, and the lesson generalizes: when a well-engineered exact implementation is available, an approximate method must beat *it*, not the textbook version.

**Part F: what to demand of a new method.** Applying the checklist to a hypothetical paper claiming "4× faster attention with no quality loss":

1. **Exact or approximate?** If approximate, where is the induction probe?
2. **Baseline?** If naive attention, the claim is roughly "we are as fast as FlashAttention", which is not a contribution.
3. **Crossover?** If the 4× is measured at $n = 65{,}536$, what happens at 4096, where most models operate?
4. **Causal?** If the evaluation is all encoder tasks, language modeling is untested and may be impossible.
5. **Evaluation?** If quality is reported as perplexity within 3%, the retrieval capability is untested and is exactly what approximation destroys.

Papers that answer all five well are rare and are the ones that lasted.

## Intuition

FlashAttention is exact and provides the baseline for these comparisons. Linear attention uses a fixed-size feature state that limits the attention patterns it can represent. Low-rank projections compress the sequence dimension and can discard directions. Hashing groups likely matches but makes routing approximate.

Evaluate quality on tasks that genuinely require controlled distances, and report sequence length, batch size, hardware, precision, and whether the workload is prefill or decode. An asymptotic improvement may lose at practical lengths because constants and optimized dense kernels matter. A faster benchmark result also does not establish equivalent retrieval of distant information.
