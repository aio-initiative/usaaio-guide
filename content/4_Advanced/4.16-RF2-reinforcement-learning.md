## Overview

Supervised learning is handed the right answer for every example. Reinforcement learning never is. An **agent** acts in an **environment**, receives a scalar **reward**, and must work out which of its past choices deserve credit.

Three things make this harder than supervised learning, and every idea on this page answers one of them:

* **No labels, only evaluation.** The reward says *how good* the action was, not what the best action would have been.
* **Delayed credit.** A move can be decisive twenty steps before the payoff arrives. Assigning blame across that gap is the **credit assignment problem**.
* **The data depends on the policy.** The agent's own behavior determines what it sees next, so a bad policy never collects the experience that would reveal a better one. This forces the **exploration-exploitation** trade-off.

## The Markov decision process

An MDP is the tuple $(\mathcal{S}, \mathcal{A}, P, R, \gamma)$: states, actions, transition probabilities $p(s' \mid s, a)$, rewards, and a discount factor.

MDPs rest on one assumption, the **Markov property**: the next state depends only on the current state and action, not on how the agent got there:

$$
P(S_{t+1} \mid S_t, A_t, S_{t-1}, A_{t-1}, \dots) = P(S_{t+1} \mid S_t, A_t)
$$

Because of it, the agent can choose an action from the current state $s$ alone, without remembering a history that keeps growing. Sometimes the property fails. In poker you cannot see the other players' cards, and a robot's camera sees only part of the room. That setting is a *partially observable* MDP, and the usual fix is to add some recent history to the state, such as the last few observations, until the property roughly holds again.

### Return and discounting

The agent maximizes not immediate reward but the **discounted return**:

$$
G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots
= \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}
$$

with $\gamma \in [0, 1)$. Discounting does two jobs. First, it keeps the sum finite. If no reward is larger than $R_{\max}$ in size, the sum is bounded by a geometric series, $|G_t| \le R_{\max}/(1-\gamma)$, and the convergence proof below depends on that. Second, it makes the agent prefer rewards sooner rather than later. A reward $k$ steps away counts only $\gamma^k$ as much as one now, so the agent looks about $1/(1-\gamma)$ steps ahead, its **effective horizon**: ten steps at $\gamma = 0.9$, a hundred at $\gamma = 0.99$.

### Value functions

A **policy** $\pi(a \mid s)$ maps states to action probabilities. Its two value functions are just expected returns:

$$
V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s], \qquad
Q^\pi(s, a) = \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a]
$$

$V(s)$ says how good it is to be in state $s$. $Q(s, a)$ says how good it is to take action $a$ in state $s$ and follow the policy afterwards. The difference matters in practice. With $Q$, choosing the best action is easy: compare $Q(s, a)$ across the actions and take the largest. With only $V$, you would also need to know where each action leads, which means knowing $p(s' \mid s, a)$. **That is why methods with no model of the environment, called model-free methods, learn $Q$.**

## The Bellman equations

Returns obey a recursion, $G_t = R_{t+1} + \gamma G_{t+1}$, and pushing that through the expectation gives the **Bellman expectation equation**:

$$
V^\pi(s) = \sum_a \pi(a \mid s) \sum_{s'} p(s' \mid s, a)
\left[ r(s,a,s') + \gamma V^\pi(s') \right]
$$

In words: the value of a state is the average, over the actions the policy might take and the states each action might lead to, of the reward received plus the discounted value of the next state. For the *optimal* policy, replace the average over actions with a maximum, which gives the **Bellman optimality equation**:

$$
V^*(s) = \max_a \sum_{s'} p(s' \mid s, a)
\left[ r(s,a,s') + \gamma V^*(s') \right]
$$

The $\max$ makes this a nonlinear system of equations, so it cannot be solved like a linear one. It is solved by iteration instead.

### Why value iteration converges

Call the right-hand side $T$: it takes a table of values $V$, one number per state, and returns a new table $TV$. **Value iteration** starts from any table and applies $T$ over and over, $V_{k+1} = TV_k$. This works because $T$ is a **$\gamma$-contraction**: applied to any two tables, it shrinks the largest gap between them, over all states, to at most $\gamma$ times what it was. That largest gap is the *sup norm* of their difference, where $\|V\|_\infty = \max_s |V(s)|$. For any $V, V'$:

$$
\|TV - TV'\|_\infty \le \gamma \|V - V'\|_\infty
$$

The proof takes two steps. First, two maxima can differ by no more than the largest gap between the things being maximized, $|\max_a f(a) - \max_a g(a)| \le \max_a |f(a) - g(a)|$. Second, inside that gap the rewards cancel, leaving $\gamma$ times an average of $|V(s') - V'(s')|$ weighted by the transition probabilities. An average is never larger than its largest term, so the result is at most $\gamma\|V - V'\|_\infty$.

The Banach fixed-point theorem then guarantees three things. $T$ has exactly one *fixed point*, a table that $T$ leaves unchanged. That table is $V^*$. And applying $T$ repeatedly reaches it from *any* starting table, with the error shrinking by a factor of $\gamma$ each sweep:

$$
\|V_k - V^*\|_\infty \le \gamma^k \|V_0 - V^*\|_\infty
$$

In practice this means two things. The starting table changes only how long convergence takes, never where it ends up. And a larger $\gamma$ plans further ahead but converges more slowly. The code below shows the largest sweep-to-sweep change shrinking by exactly $\gamma$ each sweep.

## Learning without a model

Value iteration needs $p(s' \mid s, a)$, so it *plans* with a known model rather than learning from experience. A real agent rarely knows the transition probabilities, but it can still try actions and see what happens.

### Temporal-difference learning

Monte Carlo methods wait until an episode ends, then average the returns that actually happened. That average is unbiased but noisy, because one episode's return depends on many random events, and it cannot work at all for tasks that never end. **Temporal-difference** (TD) learning updates after every single step instead. For everything after that step, it plugs in its own current estimate of the next state's value:

$$
V(S_t) \leftarrow V(S_t) + \alpha \underbrace{\left[ R_{t+1}
+ \gamma V(S_{t+1}) - V(S_t) \right]}_{\text{TD error } \delta_t}
$$

The **TD error** $\delta_t$ measures surprise: the gap between what the agent expected and what one real step of experience suggests. Updating a guess with the help of another guess is called **bootstrapping**. It adds a little bias, since the estimate $V(S_{t+1})$ may be wrong, but it removes most of the noise, because only one random step is involved instead of a whole episode.

### Q-learning and SARSA

Applying the same idea to $Q$ gives the two standard algorithms. They differ in a single term:

$$
\textbf{Q-learning:}\quad Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha
\left[ R_{t+1} + \gamma \max_{a'} Q(S_{t+1}, a') - Q(S_t, A_t) \right]
$$

$$
\textbf{SARSA:}\quad Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha
\left[ R_{t+1} + \gamma\, Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t) \right]
$$

Q-learning's target uses the best next action, $\max_{a'} Q(S_{t+1}, a')$, whatever the agent actually does next. SARSA's target uses $A_{t+1}$, the action the agent really *takes* next. That one difference makes Q-learning **off-policy**, meaning it learns about a different policy from the one that generates its experience, and SARSA **on-policy**, meaning it learns about the policy it is following:

* **Q-learning** converges to $Q^*$ regardless of how the agent behaves, as long as every pair keeps getting visited. It learns the optimal policy while following an exploratory one.
* **SARSA** converges to the value of *the policy it is actually running*, exploration included. It therefore accounts for the cost of its own random moves.

Q-learning's max has a cost of its own. Taking the maximum of noisy estimates is biased upward: $\mathbb{E}[\max_a\hat Q]\ge\max_a\mathbb{E}[\hat Q]$ by Jensen's inequality, since $\max$ is convex. With $n$ independent unbiased estimates of equal true value and noise $\sigma$, the expected maximum is about $\sigma\sqrt{2\ln n}$ above the truth. The bias compounds: an inflated $Q(s',a')$ enters the target for $Q(s,a)$, which inflates it, which inflates its predecessors, and on a long chain the accumulated overestimation can be large enough to change the policy. **Double Q-learning** removes it by decoupling selection from evaluation: keep two estimates $Q_1, Q_2$, use one to pick the action and the other to value it, $Q_1(s,a)\leftarrow Q_1(s,a) + \alpha[r + \gamma Q_2(s', \arg\max_{a'}Q_1(s',a')) - Q_1(s,a)]$, alternating which one is updated. Because the noise in $Q_2$ has nothing to do with the choice $Q_1$ made, the target no longer overshoots: it can fall short of $\max_{a'} Q(s', a')$, but it does not systematically exceed it.

**A worked case.** A delivery robot can reach its charger along a corridor of 4 cells that runs beside an open stairwell, or along a hallway of 8 cells with nothing to fall into. Every move costs 1, and falling into the stairwell costs another 50 and ends the run. The robot explores with $\varepsilon = 0.1$ over 4 actions, so on each corridor cell the random action is the one into the stairwell with probability $0.1/4 = 0.025$. Counting only those moves, a run down the corridor falls with probability $1 - 0.975^4 \approx 0.096$, and its expected cost works out to about 8.7.

* Q-learning's target assumes greedy moves from the next state on, and a greedy robot never falls. It values the corridor at $-4$ and the hallway at $-8$, so it learns the corridor, and while it keeps exploring about 1 run in 10 ends in the stairwell.
* SARSA's target uses the move the robot really makes next, falls included. Its estimates approach $-8.7$ for the corridor and $-8$ for the hallway, so it learns the hallway.

Which choice is better depends on what happens after training. With exploration switched off the corridor costs 4, so Q-learning's route is the better one. With exploration left on, the hallway's 8 beats the corridor's 8.7, so SARSA's is.

### Exploration

Start every $Q$ at 0, and suppose the first action an agent tries in some state, left, earns 1. Left now has the highest estimate, so a purely greedy agent picks it in that state from then on. Right might be worth 5, but its estimate stays at 0 because right never gets tried. **$\varepsilon$-greedy** breaks the deadlock: with probability $\varepsilon$ it picks an action uniformly at random, and otherwise the one with the highest $Q$. Training usually begins with $\varepsilon$ near 1 and lowers it step by step to a small floor such as 0.05. The schedule is called **annealing**. Early estimates are poor, so most moves explore, and later moves mostly use what has been learned.

Q-learning's convergence guarantee depends on exploration. It holds only if every state-action pair keeps being tried, infinitely often in the limit. An agent that stops exploring can get stuck with a poor policy for good, because it never collects the experience that would show it something better. The floor in the schedule above is there for this reason: it keeps every action being tried now and then for as long as training runs.

## Scaling up

Everything above stores one number per state or per state-action pair. That is hopeless past toy problems: backgammon has around $10^{20}$ states, and a game played from raw pixels is effectively continuous.

The fix is to **approximate** $Q(s,a)$ with a neural network $Q_\theta(s,a)$, which is what **DQN** (deep Q-network) does. Two problems appear right away, and their fixes show up all over deep RL:

* **Correlated samples.** Consecutive transitions are very similar to each other, but SGD assumes its training examples are independent (i.i.d.). A **replay buffer** stores past transitions and samples minibatches at random, breaking the correlation.
* **A moving target.** The regression target $r + \gamma \max_{a'} Q_\theta(s', a')$ depends on the very weights being updated, so the network chases itself. A **target network**, a periodically-refreshed copy $\theta^-$, holds the target still between updates.

Replay and target networks reduce correlations and moving-target effects without providing a universal convergence guarantee. Function approximation + bootstrapping + off-policy training can **diverge**, and any two of the three are safe.

<ProblemCard id="rl-one-weight-chasing-its-target" />

The natural next step is [policy-gradient methods](4.17-RF3-policy-gradients.md), which learn the policy $\pi_\theta$ directly instead of deriving it from $Q$. They are also how RLHF fine-tunes language models.

## From scratch

Here are two agents on the same 4×4 grid. The agent starts in the top-left corner, every move costs $0.04$, reaching the bottom-right corner pays $1$, and walking into a wall leaves it where it was. Value iteration is given these rules. Q-learning is not, and has to learn them by moving around.

```python
import numpy as np

N, GOAL = 4, (3, 3)
STEP_COST, GAMMA = -0.04, 0.95
ACTIONS = {"^": (-1, 0), "v": (1, 0), "<": (0, -1), ">": (0, 1)}
STATES = [(r, c) for r in range(N) for c in range(N)]

def step(s, a):
    """Deterministic grid move; walking into a wall leaves you put."""
    if s == GOAL:
        return s, 0.0
    dr, dc = ACTIONS[a]
    r, c = s[0] + dr, s[1] + dc
    if not (0 <= r < N and 0 <= c < N):
        r, c = s
    return (r, c), (1.0 if (r, c) == GOAL else STEP_COST)

def backup(s, a, V):
    """One-step lookahead: reward plus discounted successor value."""
    s2, r = step(s, a)
    return r + GAMMA * V[s2]

def value_iteration(tol=1e-12):
    V = {s: 0.0 for s in STATES}
    deltas = []
    while True:
        newV = {s: (0.0 if s == GOAL else max(backup(s, a, V) for a in ACTIONS))
                for s in STATES}
        delta = max(abs(newV[s] - V[s]) for s in STATES)
        V, _ = newV, deltas.append(delta)
        if delta < tol:
            return V, deltas

V, deltas = value_iteration()
print(f"converged in {len(deltas)} sweeps")
print(f"  sweep 1: delta = {deltas[0]:.5f}   ratio = ---")
for i in range(1, len(deltas)):
    if deltas[i] == 0:
        break
    print(f"  sweep {i + 1}: delta = {deltas[i]:.5f}   ratio = {deltas[i] / deltas[i-1]:.3f}")
```

```output
converged in 7 sweeps
  sweep 1: delta = 1.00000   ratio = ---
  sweep 2: delta = 0.95000   ratio = 0.950
  sweep 3: delta = 0.90250   ratio = 0.950
  sweep 4: delta = 0.85737   ratio = 0.950
  sweep 5: delta = 0.81451   ratio = 0.950
  sweep 6: delta = 0.77378   ratio = 0.950
```

Each sweep fixes the values one more step away from the goal, and the largest change shrinks by a factor of exactly $0.95$, which is $\gamma$. So on this grid the bound from the proof is reached exactly. The far corner is six moves from the goal, so the values stop changing after six sweeps, and the seventh confirms it.

Now the same problem without the model. Q-learning calls `step` only to *take* actions. It never looks ahead at where each action would lead, and it never reads a transition probability.

```python
rng = np.random.default_rng(0)
Q = {(s, a): 0.0 for s in STATES for a in ACTIONS}
alpha, episodes = 0.1, 4000

for ep in range(episodes):
    s = (0, 0)
    eps = max(0.05, 1.0 - ep / (episodes * 0.5))      # anneal exploration
    for _ in range(100):
        if s == GOAL:
            break
        if rng.random() < eps:
            a = str(rng.choice(list(ACTIONS)))
        else:
            a = max(ACTIONS, key=lambda a: Q[(s, a)])
        s2, r = step(s, a)
        best_next = 0.0 if s2 == GOAL else max(Q[(s2, a2)] for a2 in ACTIONS)
        # off-policy: bootstraps off the max, not off the action taken next
        Q[(s, a)] += alpha * (r + GAMMA * best_next - Q[(s, a)])
        s = s2

pi_q = {s: max(ACTIONS, key=lambda a: Q[(s, a)]) for s in STATES if s != GOAL}
optimal = sum(
    abs(backup(s, pi_q[s], V) - max(backup(s, a, V) for a in ACTIONS)) < 1e-9
    for s in pi_q
)
print(f"optimal actions: {optimal}/{len(pi_q)}")
print("max |max_a Q(s,a) - V*(s)|:",
      f"{max(abs(max(Q[(s, a)] for a in ACTIONS) - V[s]) for s in pi_q):.4f}")
```

```output
optimal actions: 15/15
max |max_a Q(s,a) - V*(s)|: 0.0000
```

Q-learning recovered $V^*$ to four decimals from experience alone.

One trap when checking a result like this: if you printed the two policies as grids of arrows, they would disagree in places. That is not an error. Nine of the fifteen non-goal states have **more than one optimal action**, because on this grid going down then right costs exactly the same as going right then down. So the code checks whether each chosen action is optimal, not whether it matches the other policy's arrow. The same goes for evaluating RL agents in general: two policies can look different and be equally good, so compare their *values*, not their actions.
