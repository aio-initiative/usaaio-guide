# 4.14 · TF32 · 5. State-space models

> **Goal:** A state-space model gets parallel training and constant-memory generation, because linearity lets the recurrence be rewritten as a convolution.
> **Stage:** Advanced, Extension topics.

## The model

A linear state-space model is

$$
h'(t) = Ah(t) + Bx(t), \qquad y(t) = Ch(t) + Dx(t),
$$

discretized (by the zero-order hold or bilinear transform) to

$$
h_t = \bar Ah_{t-1} + \bar Bx_t, \qquad y_t = Ch_t .
$$

The discretization step $\Delta$ is a parameter: $\bar A = \exp(\Delta A)$ under the zero-order hold, so $\Delta$ controls how much the state changes per token, effectively the model's timescale.

## The dual view

Unrolling the recurrence from $h_{-1}=0$:

$$
y_t = \sum_{i=0}^{t}C\bar A^{i}\bar B\,x_{t-i} = (\bar K * x)_t, \qquad \bar K = \big(C\bar B,\ C\bar A\bar B,\ C\bar A^2\bar B,\ \dots\big).
$$

**It is a convolution with a structured kernel.** So the model has two equivalent forms:

- **Recurrent:** $O(1)$ per token, $O(1)$ memory, ideal for generation.
- **Convolutional:** compute $\bar K$ once, apply by FFT in $O(n\log n)$, fully parallel over the sequence, ideal for training.

**This resolves the RNN's fundamental problem.** An RNN is fast at inference and unparallelizable at training ([Recurrent Networks](3.5-NL2-sequence-models-transfer-learning.md)), and a transformer is parallel at training and expensive at inference. A state-space model gets both, because linearity lets the recurrence be rewritten as a convolution.

**Why linearity is essential.** A nonlinear recurrence $h_t = \sigma(Ah_{t-1}+Bx_t)$ cannot be unrolled into a fixed kernel, because $\sigma$ does not distribute over the sum: every term would depend on all the previous ones through the nonlinearity. Linearity is what buys the parallel form, and the model recovers expressiveness by stacking linear SSM layers with pointwise nonlinearities between them.

## HiPPO

A naive random $A$ forgets exponentially, exactly like a vanilla RNN: the kernel $C\bar A^i\bar B$ decays as $\rho(\bar A)^i$, and the effective memory is $1/\log(1/\rho)$ steps.

**HiPPO** derives a specific $A$ that makes $h_t$ the coefficients of an optimal polynomial approximation to the input history, so the state provably compresses the entire past rather than the recent window. Different measures give different variants: HiPPO-LegS weights all of history equally (giving genuinely unbounded memory), HiPPO-LagT applies exponential decay.

That, plus a diagonal-plus-low-rank structure making $\bar A^i$ computable efficiently, is what made **S4** work. Computing the kernel naively would cost $O(n d^2)$ per layer. The structured form reduces it to $O(n + d)$ operations via a generating-function trick, and later work (S4D, S5) showed a purely diagonal $A$ initialized from the HiPPO spectrum works nearly as well and is far simpler.

**The empirical result** that established the line: S4 solved the Long Range Arena's Path-X task (16,384-token sequences requiring long-range spatial reasoning), on which every transformer variant scored at chance.

## Mamba and selectivity

S4's $A, B, C$ are **fixed**, the same for every input, so the model cannot decide to remember one token and forget another. That is why S4 fails at *selective copying* and at induction, tasks attention handles trivially.

**Mamba makes $B$, $C$, and the discretization step $\Delta$ functions of the input:**

$$
B_t = \text{Linear}_B(x_t), \qquad C_t = \text{Linear}_C(x_t), \qquad \Delta_t = \text{softplus}\big(\text{Linear}_\Delta(x_t)\big).
$$

Now the model gates content-dependently, which is what attention does. Reading the parameters: $\Delta_t$ large means "this token matters, update the state substantially", and $\Delta_t$ small means "skip this one". It is a learned, per-token, per-channel forget gate, the LSTM's idea ([Recurrent Networks](3.5-NL2-sequence-models-transfer-learning.md)) in a form that still parallelizes.

**But input-dependent parameters destroy the convolutional view**: the kernel is no longer fixed, so there is no single $\bar K$ to FFT. Mamba's answer is a hardware-aware **parallel scan**: the recurrence $h_t = \bar A_th_{t-1}+\bar B_tx_t$ is an associative operation, so a prefix-scan computes all $h_t$ in $O(\log n)$ depth with $O(n)$ work. The implementation keeps the state in SRAM and never materializes it in HBM, the same memory-hierarchy insight as [FlashAttention](4.11-TF29-efficient-flashattention.md#lesson-flashattention).

## Results and hybrids

Mamba matches transformers of the same size on language modeling with **linear** scaling and 5× faster generation. It remains weaker on tasks needing precise long-range retrieval, which is why **hybrid** architectures, a few attention layers interleaved among many Mamba layers (Jamba, Zamba), currently perform best.

The hybrid ratio is informative: roughly one attention layer per seven SSM layers suffices to recover retrieval, which suggests the two mechanisms are complementary rather than competing. The SSM layers handle aggregation and local structure cheaply, and the few attention layers supply the sharp lookup that a fixed-size state cannot.

**The convergence with linear attention.** Mamba's recurrence and gated linear attention's state update are structurally the same object: a matrix-valued state, an input-dependent decay, and a rank-one update per token. Recent work treats them as one family under names like "linear attention with gating" or "state-space duality", and the practical distinctions are about which parameterization trains best rather than about the underlying mechanism.

## Where each wins

| | transformer | SSM (Mamba) |
| --- | --- | --- |
| training parallelism | full | full (scan) |
| generation cost per token | $O(n)$ | $O(1)$ |
| generation memory | $O(n)$ cache | $O(1)$ state |
| precise retrieval | strong | weak |
| very long context | expensive | cheap |
| ecosystem maturity | enormous | growing |

**Use an SSM** when the sequence is very long, generation memory is the constraint, or the task is aggregation rather than lookup: audio, genomics, time series, and long-document processing. **Use attention** when precise retrieval matters. **Use a hybrid** when you want both, which is currently the best-performing option at scale.

## From Scratch

```python
import numpy as np


def discretize_zoh(A, B, delta):
    """Zero-order hold: A_bar = exp(delta A). Delta controls the TIMESCALE --
    how much the state moves per token."""
    A_bar = np.exp(delta * A)                        # diagonal A
    B_bar = (A_bar - 1.0) / A * B
    return A_bar, B_bar


def ssm_recurrent(x, A_bar, B_bar, C):
    """O(1) per token, O(1) memory. The generation form."""
    n, = x.shape
    h = np.zeros_like(A_bar)
    y = np.zeros(n)
    for t in range(n):
        h = A_bar * h + B_bar * x[t]
        y[t] = float(np.real(C @ h))
    return y


def ssm_kernel(A_bar, B_bar, C, L):
    """K = (C B, C A B, C A^2 B, ...). Computed ONCE, then applied by FFT."""
    return np.array([np.real(C @ (A_bar ** i * B_bar)) for i in range(L)])


def ssm_convolutional(x, A_bar, B_bar, C):
    """The SAME model, computed in parallel by FFT: O(n log n), full GPU
    utilization. The two computations are equivalent."""
    L = len(x)
    K = ssm_kernel(A_bar, B_bar, C, L)
    K_f = np.fft.rfft(K, n=2 * L)
    x_f = np.fft.rfft(x, n=2 * L)
    return np.fft.irfft(K_f * x_f, n=2 * L)[:L]


def forms_agree(x, A_bar, B_bar, C, tol=1e-8):
    """Verify the duality numerically -- recurrent and convolutional must
    produce identical outputs."""
    a = ssm_recurrent(x, A_bar, B_bar, C)
    b = ssm_convolutional(x, A_bar, B_bar, C)
    return {"max_diff": float(np.abs(a - b).max()), "agree": np.allclose(a, b, atol=tol)}


def hippo_legs(N):
    """HiPPO-LegS: the state becomes the coefficients of an optimal polynomial
    fit to the ENTIRE history, rather than an exponentially-decaying summary."""
    A = np.zeros((N, N))
    for n in range(N):
        for k in range(N):
            if n > k:
                A[n, k] = -np.sqrt((2 * n + 1) * (2 * k + 1))
            elif n == k:
                A[n, k] = -(n + 1)
    return A


def random_A_forgets(rho, gap):
    """A random transition decays as rho^i -- exactly the RNN's problem, which
    is what HiPPO's specific A avoids."""
    return rho ** gap


def selective_params(x, W_B, W_C, W_delta):
    """Mamba: B, C, and delta become FUNCTIONS OF THE INPUT. Large delta means
    'this token matters'; small delta means 'skip it'. A forget gate that
    still parallelizes."""
    B = x @ W_B
    C = x @ W_C
    delta = np.log1p(np.exp(x @ W_delta))            # softplus, so positive
    return B, C, delta


def associative_scan(A_seq, B_seq):
    """(A_t, B_t) composes associatively: (A2 A1, A2 B1 + B2). A prefix scan
    therefore computes every h_t in O(log n) DEPTH with O(n) work -- which is
    what recovers parallelism after selectivity kills the convolution."""
    n = len(A_seq)
    h = np.zeros(n)
    acc = 0.0
    for t in range(n):                               # sequential reference version
        acc = A_seq[t] * acc + B_seq[t]
        h[t] = acc
    return h


def compose(pair1, pair2):
    """The associative operator the scan is built on."""
    a1, b1 = pair1
    a2, b2 = pair2
    return (a2 * a1, a2 * b1 + b2)


def generation_cost(n, d_state, d_model, n_layers, expand=2, dtype_bytes=2):
    """SSM: fixed state. Transformer: cache growing with n. The gap at long
    context is the reason to care. expand is the SSM's inner width, as in
    Mamba, where the state is d_state x (expand x d_model) per layer."""
    ssm = n_layers * expand * d_state * d_model * dtype_bytes
    transformer = 2 * n_layers * n * d_model * dtype_bytes
    return {"ssm_bytes": ssm, "transformer_bytes": transformer,
            "ratio": transformer / max(ssm, 1)}


def hybrid_schedule(n_layers, attn_every=8):
    """One attention layer per ~7 SSM layers recovers retrieval -- evidence
    that the two mechanisms are complementary."""
    return ["attention" if (i + 1) % attn_every == 0 else "ssm" for i in range(n_layers)]
```

## Worked Example

**Part A: the duality, verified.** A one-dimensional SSM with $A = -0.5$, $B = 1$, $C = 1$, $\Delta = 1$.

**Discretize** (zero-order hold): $\bar A = e^{-0.5} = 0.6065$, $\bar B = (\bar A - 1)/A = (0.6065-1)/(-0.5) = 0.7869$.

**The kernel:** $\bar K = (C\bar B,\ C\bar A\bar B,\ C\bar A^2\bar B,\dots) = (0.7869,\ 0.4773,\ 0.2895,\ 0.1756,\dots)$, a decaying exponential.

**Recurrent form** on input $x = (1, 0, 0, 0)$:

$$
h_0 = 0.7869, \quad h_1 = 0.6065(0.7869) = 0.4773, \quad h_2 = 0.2895, \quad h_3 = 0.1756 .
$$

**Convolutional form:** $y = \bar K * x = \bar K$ since $x$ is an impulse: $(0.7869, 0.4773, 0.2895, 0.1756)$ ✓.

Identical, as they must be. The recurrence computed it in four sequential steps, and the convolution computed it in one FFT that could have covered a million steps in parallel.

**Part B: the parallelism, quantified.** Training on a sequence of $n = 16{,}384$.

| form | depth | work | GPU utilization |
| --- | --- | --- | --- |
| RNN (nonlinear) | 16,384 sequential steps | $O(n d^2)$ | a few % |
| SSM convolution | 1 FFT | $O(nd\log n)$ | high |
| SSM scan (Mamba) | $\log_2 16384 = 14$ | $O(nd)$ | high |
| transformer | 1 matmul | $O(n^2d)$ | very high |

The RNN's 16,384-step critical path is what killed it, and every other row has depth under 15. That is the entire reason recurrence became viable again.

**Part C: why a random $A$ fails.** Take $\bar A$ with spectral radius $\rho = 0.9$. The kernel's $i$-th entry is proportional to $\rho^i$, so the contribution of a token 100 steps back is $0.9^{100} = 2.7\times10^{-5}$, the same exponential forgetting as a vanilla RNN ([Recurrent Networks](3.5-NL2-sequence-models-transfer-learning.md)).

**HiPPO-LegS** instead sets $A_{nk} = -\sqrt{(2n+1)(2k+1)}$ for $n>k$ and $-(n+1)$ on the diagonal, derived so that $h_t$ holds the Legendre coefficients of the best polynomial approximation to $x_{0:t}$ under a uniform measure over all of history.

The consequence: the state is a *compression* of the whole past rather than a decaying trace of the recent past, and the reconstruction error is that of a degree-$N$ polynomial fit rather than an exponential cutoff. On Path-X (16,384 tokens), that is the difference between chance performance and solving the task.

**Part D: what selectivity adds.** The **selective copying** task: a sequence containing a few tokens to remember interspersed with random filler, and the model must reproduce the memorable ones in order.

**S4** applies the same $\bar A$ to every token, so filler updates the state exactly as much as content does. With 50 filler tokens between two content tokens, the first is decayed by $\bar A^{50}$ regardless of its importance. S4 scores at chance.

**Mamba** computes $\Delta_t$ from the token: for filler it outputs a small $\Delta$, so $\bar A_t = e^{\Delta_t A}\approx1$ and the state passes through nearly unchanged. For content it outputs a large $\Delta$, updating substantially. It solves the task.

Reading the learned $\Delta$ directly is instructive: on text it is large on content words and rare tokens, small on punctuation and function words: a learned relevance gate, and the closest thing an SSM has to attention weights.

**Part E: the cost of selectivity, and the scan's recovery.** With input-dependent $\bar A_t$, the unrolled form is

$$
y_t = \sum_i C_t\Big(\prod_{j=t-i+1}^{t}\bar A_j\Big)\bar B_{t-i}x_{t-i},
$$

whose kernel differs at every position, so there is no single $\bar K$, and no FFT.

**The rescue:** the recurrence $h_t = \bar A_th_{t-1}+\bar B_tx_t$ is generated by the associative operator

$$
(\bar A_1,\bar B_1)\circ(\bar A_2,\bar B_2) = (\bar A_2\bar A_1,\ \bar A_2\bar B_1 + \bar B_2),
$$

and any associative operator admits a parallel prefix scan: $O(\log n)$ depth, $O(n)$ work. At $n = 16{,}384$ that is 14 sequential steps instead of 16,384.

**The implementation matters as much as the algorithm.** Materializing the $(B, L, D, N)$ state tensor in HBM would make the kernel memory-bound. Mamba's fused kernel keeps it in SRAM and recomputes it on the backward pass, precisely FlashAttention's trade, applied to a different operation.

**Part F: generation cost at long context.** A 32-layer model, $d_{\text{model}} = 2048$, $d_{\text{state}} = 16$, generating at $n = 100{,}000$ tokens, fp16.

**Transformer KV cache:** $2Lnd_{\text{model}}s = 2(32)(10^5)(2048)(2) = 2.6\times10^{10}$ bytes $= 26$ GB.

**Mamba state:** $L\cdot\text{expand}\cdot d_{\text{state}}d_{\text{model}}s = 32\cdot2\cdot16\cdot2048\cdot2 = 4.2$ MB, **independent of $n$**.

A factor of 6,250, and the per-token compute follows the same pattern: the transformer reads the whole cache each step, the SSM reads a fixed state. That is the property, and it is why long-context and streaming applications are where SSMs are adopted first.

**The counterweight:** on a needle-in-a-haystack test at the same 100,000 tokens, a pure Mamba model retrieves reliably only within a few thousand, while a transformer retrieves throughout. The fixed state is the saving and the limitation, and it is the same trade as linear attention's.
