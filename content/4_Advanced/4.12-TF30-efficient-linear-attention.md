## The problem

The KV cache (Step 2) and FlashAttention (Step 4) make attention cheaper without changing what it computes. Sharing keys and values (Step 3) and sliding windows (Step 4) save more by changing the result. With attention kept exact, two costs remain, and both grow with the length of the text:

- **Work per token.** Every new token is compared with every earlier one. At 1,000 tokens that is 1,000 comparisons for the next token. At 100,000 it is 100,000.
- **Memory.** The cache holds a key and a value for every earlier token, so it grows with every token generated.

A dashed flat line near the bottom marks the goal: the same work for every token.">
With softmax attention, each new token costs more than the one before.
</Figure>

The goal here is attention whose work per token stays the same however long the text is, and whose memory stays fixed during generation.

## Earlier approaches

### Recurrent networks

They have fixed memory and constant cost per token, but read one token at a time and forget over distance (Step 0 of Build a Transformer): by the blank in "The students who failed the exam ___", "students" may already be lost.

### Faster softmax attention

The KV cache and FlashAttention keep attention exact, and shared keys and values trade some of the result for a smaller cache. All three still do work that grows with the square of the length: FlashAttention still computes about 67 million scores per head for 8,192 tokens. A sliding window (Step 4) fixes the work per token by changing the result, since no token can look directly further back than the window.

## Linear attention

**A simpler similarity.** The obstacle is the softmax, which forces every score to be computed separately. **Linear attention** (Katharopoulos et al., 2020) replaces it. Each query and key is passed through a function $\phi$ that makes its numbers positive, and the similarity is their dot product. For example, 1.020 becomes 2.020 and −0.416 becomes 0.660. The weights are the similarities divided by their total:

$$
\text{output} = \frac{\sum_j \big(\phi(q) \cdot \phi(k_j)\big) \, v_j}{\sum_j \phi(q) \cdot \phi(k_j)}.
$$

**The running state.** The query appears in every term, so it can be taken out of both sums:

$$
\text{output} = \frac{\phi(q) \cdot \big(\sum_j \phi(k_j) \, v_j^\top\big)}{\phi(q) \cdot \big(\sum_j \phi(k_j)\big)}.
$$

The two sums in brackets do not depend on the query. They are a small running **state** that each token adds to, and every output is read from it. Memory stays fixed however long the text gets, like a recurrent network: in the running example the state is 6 numbers, after 3 tokens or after 3,000.

**Counting the work.** For a whole text of $n$ tokens and head size $d$, softmax attention computes the $n \times n$ table of scores, each a dot product of $d$ numbers, and then as many multiply-adds again for the weighted sums, about $2 \times n \times n \times d$. Linear attention adds $n$ products of $d \times d$ numbers into the state and reads $n$ outputs from it, about $2 \times n \times d \times d$. In matrix form it is the same product bracketed the other way: softmax attention has to compute the $n \times n$ table $QK^\top$ before multiplying by $V$, while linear attention computes $\phi(K)^\top V$, which is only $d \times d$, first. The second way is cheaper as soon as the text is longer than the head size. At 8,192 tokens and GPT-2's head size of 64 it takes 67 million multiply-adds against 8.6 billion, 8,192 ÷ 64 = 128 times fewer.

**The price.** Softmax weights can put almost everything on one token. Linear weights are usually much flatter than softmax weights, so recalling one specific earlier token works poorly. In a test where one key is hidden among 512 others and searched for exactly, softmax attention returns its value almost perfectly, while linear attention returns a blur of everything. That is why most models still use softmax attention with FlashAttention.

</Figure>

**Forgetting.** The state adds in every token with the same weight and never lets go of any. A **decay** $\gamma$ between 0 and 1 shrinks the state before each new token is added,

$$
\text{state} \leftarrow \gamma \times \text{state} + \phi(k)\, v^\top,
$$

and the total of the keys likewise, so a token $a$ steps back counts $\gamma^a$ times its similarity. With $\gamma = 0.5$, "the", two steps back from "sat", counts 0.25 times and "cat" 0.5 times. The weights of "sat" become 0.119, 0.379 and 0.502 instead of 0.275, 0.436 and 0.289, and its output moves to (0.894, 0.494). A decay favors recent tokens and loses older ones faster. RetNet gives each head a fixed decay. Mamba (Gu and Dao, 2023) and gated linear attention compute the decay from each token, so the model learns what to keep and what to forget, much like the forget gate of an [LSTM](3.5-NL2-sequence-models-transfer-learning.md).

### Feature map of the softmax

**Powers of a dot product.** The softmax weight $e^{q \cdot k}$ can also be written as a dot product, but of endless lists. Its series is

$$
e^{s} = 1 + s + \frac{s^2}{2} + \frac{s^3}{6} + \dots,
$$

and every power of a dot product is itself a dot product of longer lists: $(q \cdot k)^2 = (q \otimes q) \cdot (k \otimes k)$, where $q \otimes q$ lists every product of two numbers of $q$, $(q_1 q_1, q_1 q_2, q_2 q_1, q_2 q_2)$ for a query of 2 numbers. Collecting the terms gives $e^{q \cdot k} = \psi(q) \cdot \psi(k)$, with a feature map $\psi$ of its own:

$$
\psi(q) = \Big(1,\ q,\ \frac{q \otimes q}{\sqrt{2}},\ \frac{q \otimes q \otimes q}{\sqrt{6}},\ \dots\Big).
$$

Take "sat" and "cat" in head 1, with the query and the key each divided by $2^{1/4} = 1.189$, so that their dot product already includes the division by 1.414: $q = (0.858, 1.682)$, $k = (1.295, 0.849)$ and $q \cdot k = 2.539$, the score of "sat" on "cat". Then $(q \cdot k)^2 = 2.539^2 = 6.447$, and the dot product of the two lists of 4 products gives the same 6.447.

**Cutting the list.** Stopping after degree $N$ gives a finite feature map. Its dot product is the series up to $s^N / N!$, and for head size $d$ it has $1 + d + d^2 + \dots + d^N$ numbers. For the score of "sat" on "cat", against the exact $e^{2.539} = 12.667$:

| Cut after degree | Features at head size 2 | Similarity of "sat" and "cat" |
|---|---|---|
| 1 | 3 | 3.539 |
| 2 | 7 | 6.762 |
| 4 | 31 | 11.222 |
| 8 | 511 | 12.651 |

Every cut leaves out the terms after it, so this list gives the softmax exactly only at its full, endless length. At real head sizes even an early cut is long: with head size 64, the cut after degree 2 already has 1 + 64 + 4,096 = 4,161 features.

**Even degrees.** Linear attention divides by the total similarity, so every similarity must stay positive. A cut after an odd degree can go negative: after degree 1 the similarity is $1 + s$, which is −1 for a score of −2. A cut after an even degree cannot. After degree 2 it is $1 + s + s^2/2$, which is smallest at $s = -1$, where it is 0.5, and at $s = -2$ it is 1.

## Running example

### A simpler similarity

Take the row of "sat" in head 1 again. Passing the query and keys through the function that makes their numbers positive:

| | Before | After |
|---|---|---|
| Query of "sat" | (1.020, 2.000) | (2.020, 3.000) |
| Key of "the" | (1.000, 0.000) | (2.000, 1.000) |
| Key of "cat" | (1.540, 1.010) | (2.540, 2.010) |
| Key of "sat" | (−0.416, 1.020) | (0.660, 2.020) |

Positive numbers get 1 added, and −0.416 becomes $e^{-0.416} = 0.660$. The similarities and weights:

| Key of | Similarity with (2.020, 3.000) | Linear weight | Softmax weight, for comparison |
|---|---|---|---|
| the | 2.020 × 2.000 + 3.000 × 1.000 = 7.040 | 0.275 | 0.115 |
| cat | 2.020 × 2.540 + 3.000 × 2.010 = 11.161 | 0.436 | 0.709 |
| sat | 2.020 × 0.660 + 3.000 × 2.020 = 7.393 | 0.289 | 0.175 |

The linear weights are much more even: "cat" gets 44% instead of 71%, and the output is (0.905, 0.827) instead of (0.872, 1.135).

### The running state

The same output comes from the running state: four totals of key-number × value-number, plus the totals of the key numbers. Each token adds its own products to the totals (the entries are computed before the inputs are rounded, so the last digit can differ from the products of the rounded numbers above):

| After | Key 1 × value 1 | Key 1 × value 2 | Key 2 × value 1 | Key 2 × value 2 | Total of key 1 | Total of key 2 |
|---|---|---|---|---|---|---|
| the | 2.000 | 2.000 | 1.000 | 1.000 | 2.000 | 1.000 |
| cat | 4.138 | 5.913 | 2.691 | 4.096 | 4.540 | 3.010 |
| sat | 4.737 | 5.638 | 4.528 | 3.255 | 5.200 | 5.030 |

The output for "sat" combines its query with the last row:

- first number: (2.020 × 4.737 + 3.000 × 4.528) ÷ (2.020 × 5.200 + 3.000 × 5.030) = 23.153 ÷ 25.594 = 0.905,
- second number: (2.020 × 5.638 + 3.000 × 3.255) ÷ 25.594 = 21.154 ÷ 25.594 = 0.827.

That is the same (0.905, 0.827), from six stored numbers. With a thousand earlier tokens, the state would still be six numbers.

```python
import numpy as np

def positive(x):                       # 1 added above zero, e^x below zero
    return np.where(x > 0, x + 1.0, np.exp(np.minimum(x, 0)))

q = positive(np.array([1.020, 2.000]))
K = positive(np.array([[1.000, 0.000], [1.540, 1.010], [-0.416, 1.020]]))
V = np.array([[1.000, 1.000], [0.841, 1.540], [0.909, -0.416]])

state, key_total = np.zeros((2, 2)), np.zeros(2)
for k, v in zip(K, V):                 # one update per token, fixed size
    state += np.outer(k, v)
    key_total += k

print((q @ state / (q @ key_total)).round(3))   # about [0.904 0.826]; inputs are rounded
```

## Common questions

**Why can softmax attention not keep a running state?** Its weight needs $e^{q \cdot k}$. The feature map above writes it as a list computed from the query alone dotted with a list computed from the key alone, but that list gives the softmax exactly only at its full, endless length, and every cut of it is an approximation. A plain dot product $\phi(q) \cdot \phi(k)$ of short lists splits at once, which is what lets the keys be added up before any query arrives.

**Why are the linear weights so even?** The softmax turns a gap between scores into a ratio. "cat" beats "the" by 2.539 against 0.721, a gap of 1.818, which becomes $e^{1.818} = 6.2$ times the weight. The linear similarities are 11.161 against 7.040, only 1.6 times.

**Is the state really a fixed size?** Yes. It has one total for every pair of a key number and a value number, 2 × 2 = 4 here, plus one total for every key number, 2 here. That is 6 numbers per head however many tokens have been read.

**Is linear attention used in practice?** Rarely for language models, because of the loss of focus. Most models use softmax attention with a KV cache and FlashAttention.
