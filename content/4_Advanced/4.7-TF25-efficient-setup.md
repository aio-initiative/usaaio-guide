# 4.7 · TF25 · 0. Setup

> **Goal:** Repeated work, memory and long texts, and the roadmap.
> **Stage:** Advanced, Extension topics.

## The problem

A model is trained once but run every time someone uses it, token by token, often for many users at once and on long texts. Three costs dominate:

1. **Repeated work.** Generating text means running the model again after every new token, and a naive run redoes the work for every earlier token: a 1,000-token reply reruns the model 1,000 times over the whole text so far.
2. **Memory.** A GPU computes far faster than it reads its memory: an NVIDIA A100 80 GB does about 312 trillion FP16 operations a second and reads about 2 trillion bytes a second, so it can do about 156 operations in the time it reads one byte. Much of the time goes into moving numbers rather than computing with them.
3. **Long texts.** Attention compares every pair of tokens, so doubling the length quadruples the work: 4,000 tokens need 16 million scores per head (counting every pair, as full attention does), 8,000 need 64 million.

The third cost. Twice the length is four times the scores.

The size of the model adds to all three. A model with 70 billion weights needs about 140 GB just to store them, more than one 80 GB GPU holds, before any memory for the conversations it serves.

## History

| Year | Idea | What it fixes |
|---|---|---|
| From the start | The KV cache: keep the keys and values of earlier tokens during generation | Repeated work |
| 2019 | Multi-query attention: all heads share one set of keys and values (Shazeer) | The memory those keys and values take |
| 2020 | Linear attention: replace the softmax so the cost grows only with the length (Katharopoulos et al.) | Cost that grows with the square of the length |
| 2022 | FlashAttention: compute attention in small blocks that stay in fast memory (Dao et al.) | Time lost moving the table of scores in and out of memory |
| 2023 | Grouped-query attention: groups of heads share keys and values (Ainslie et al.), used by Llama 2 70B | A middle ground between full sharing and none |
| 2024 | Multi-head latent attention: store a compressed version of the keys and values (DeepSeek-V2) | The memory of keys and values, without removing heads |

These ideas became necessary as inputs grew longer. GPT-2 read at most 1,024 tokens. Many current models accept more than 100,000.

## The intuition

- **Do not redo work.** Adding a token never changes the keys and values of the tokens before it, so they can be computed once and kept (Steps 1 and 2). Appending "on" to "the cat sat" leaves the keys and values of the first three tokens exactly as they were.
- **Move fewer numbers.** Memory traffic sets the speed, so store less (Step 3) and keep the work in the GPU's small, fast memory (Step 4). Letting groups of 8 heads share their keys and values makes the cache 8 times smaller.
- **Change the calculation.** Linear attention drops the softmax so the cost grows only with the length, at a price in what it can do (Step 5): "sat" then gives "cat" 44% of its attention instead of 71%.
