## Overview

Show a model a photo of a dog with a ball and ask "what is the dog holding?" To answer, the model has to see the ball, understand the question and write a sentence. [CLIP](2.14-RP2-contrastive-learning.md) can tell whether a caption matches an image, but it cannot write anything. A language model can write, but it only reads tokens. How do you feed a picture to a language model?

A **vision-language model** reads an image and text and writes text. One design, used by LLaVA (Large Language and Vision Assistant, Liu et al. 2023), turns the image into a sequence of vectors that the language model reads as if they were words. The USAAIO syllabus stops at vision transformers. The IOAI syllabus goes further. It lists CLIP-style vision-text encoders, and encoder-decoder models for vision-language modeling, as practical topics. So this is camp preparation for IOAI.

## Example: count the tokens and the parameters

A model uses a CLIP image encoder. The encoder cuts a $224 \times 224$ image into patches of $14 \times 14$ pixels each and outputs a 1,024-number vector for each patch. A linear layer turns each of these into a 4,096-number vector that the language model can read, called a **visual token**. The user's question is 12 tokens long and the answer is 8 tokens.

1. How many visual tokens does one image produce?
2. How many parameters does the linear layer have?
3. How long is the sequence the language model reads, and how many of its positions are targets of the loss?

## Explanation

### An image as a sequence of patches

A language model does not work with token ids directly. It looks each id up in an embedding table and works with the vectors it gets back, one per token. If we turn an image into a sequence of vectors of the right size, we can skip the lookup and put them where word vectors would go.

A [vision transformer](3.3-CV6-vision-transformers-vit-attention.md#lesson-vision-transformer) already does the first half. It cuts the image into a grid of square patches and turns each patch into a vector. A $224 \times 224$ image cut into $14 \times 14$ patches gives a $16 \times 16$ grid:

$$
\frac{224}{14} \cdot \frac{224}{14} = 16 \cdot 16 = 256 \text{ patches.}
$$

After the encoder's layers, each of the 256 output vectors describes its patch in the context of the whole image. The encoder also outputs one extra class vector. LLaVA drops it and keeps the 256 patch vectors. For a question about a small detail inside one image, a single image vector may discard the needed detail.

Which encoder should we use? CLIP's image encoder was trained on about 400 million image-caption pairs to place each image near its caption. So its vectors already carry meanings like "dog" and "ball", and we do not have to teach a new encoder what objects look like. LLaVA keeps the encoder **frozen**: its weights are not changed during training.

### Bridging two different spaces

The encoder's vectors have 1,024 numbers, and the language model expects 4,096. Matching the size is not enough. The language model has never seen CLIP's vectors, so their numbers would mean nothing to it. We need a learned map from CLIP's vectors to vectors the language model can use.

The simplest map is one linear layer, called the **projector**. Write one patch vector as a row $\mathbf{z}$ of 1,024 numbers. The projector computes $\mathbf{z}W + \mathbf{b}$, where $W$ is a $1024 \times 4096$ weight matrix and $\mathbf{b}$ holds one bias for each of the 4,096 outputs. So it has

$$
1024 \cdot 4096 + 4096 = 4{,}198{,}400 \text{ parameters.}
$$

That is less than a tenth of a percent of a 7-billion-parameter language model ($4{,}198{,}400 / (7 \times 10^9) \approx 0.0006$). A later version, LLaVA-1.5, replaced the single linear layer with a two-layer MLP (linear, GELU, linear) and got better results.

### Reading the image like words

Now put the visual tokens in front of the text. The sequence is 256 visual tokens, then 12 question tokens, then 8 answer tokens: 276 in all. Real LLaVA prompts also contain a system message and role markers, which we leave out here.

The language model runs as usual, with its causal mask, so each position sees itself and everything before it. Every text token comes after all 256 visual tokens, so the answer can depend on what is in the picture.

<ProblemCard id="vlm-question-before-the-photo" />

Training uses the usual next-token loss, but only where the correct next token is part of the answer. Visual tokens are vectors, not entries in the vocabulary, so there is no correct token to compare against. We want the model to write answers, not to predict what users will ask, so the question gets no loss either. That leaves 8 targets in a sequence of 276. LLaVA also scores an end-of-answer marker so the model learns where to stop. We leave the marker out to keep the count simple.

### Training in two stages

LLaVA trains in two stages.

1. **Alignment.** Freeze the encoder and the language model, and train only the projector, on 595,000 image-caption pairs. Each pair becomes a short exchange: a request such as "describe the image briefly", with the caption as the answer. Only the projector's weights change (4.2 million in our focus model). Since the language model is frozen, this stage cannot change anything it already knows. The projector alone learns to produce vectors that the language model reads as a description of the image.

2. **Instruction tuning.** Keep the encoder frozen, and train the projector and the language model together on about 158,000 examples. These are conversations, detailed descriptions and step-by-step reasoning questions about images. This stage teaches the model to answer requests instead of only writing captions.

Both stages use the same answer-only loss.

### The other design: cross-attention

LLaVA puts the image into the sequence. **Flamingo** (Alayrac et al. 2022) keeps the sequence text-only. It adds new **cross-attention** layers between the language model's frozen layers. In a cross-attention layer, each text token attends to a set of image vectors. A [T5](2.12-TF4-transformer-architectures-t5-encoder-decoder.md) decoder attends to its encoder's outputs in the same way. To keep that set small, a network called the Perceiver Resampler first turns each image's features into 64 vectors.

Suppose our focus model used Flamingo's design instead. To compare the cost, count the query-key scores one attention head computes. With a causal mask over $T$ positions, position $t$ scores itself and the $t - 1$ positions before it. So one layer computes $1 + 2 + \dots + T = T(T+1)/2$ scores.

- **LLaVA design.** $T = 276$, so each self-attention layer computes $276 \cdot 277/2 = 38{,}226$ scores.
- **Flamingo design.** The language model's own layers see only the 20 text tokens, so they compute $20 \cdot 21/2 = 210$ scores. Each cross-attention layer adds $20 \cdot 64 = 1{,}280$ scores, one per pair of text token and image vector.

A bigger image adds visual tokens to LLaVA's sequence. In Flamingo it still becomes 64 vectors, so the cost of the cross-attention layers stays the same. The image encoder still does more work on a bigger image in both designs, and so does Flamingo's resampler.

<ProblemCard id="vlm-one-softmax-or-two" />

Each new Flamingo layer's output is multiplied by $\tanh \alpha$ before it is added to the layer's input. Here $\alpha$ is a number learned in training, and it starts at 0. Since $\tanh 0 = 0$, the new layers add nothing at first, and the model starts out as the original language model. The image's influence grows as $\alpha$ is trained.

### Solving the focus problem

1. $224/14 = 16$ patches per side, so the encoder gives $16 \cdot 16 = 256$ patch vectors. The projector turns each one into a visual token, so there are 256 visual tokens.
2. The projector has a $1024 \times 4096$ weight matrix and 4,096 biases: $1024 \cdot 4096 + 4096 = 4{,}198{,}400$ parameters.
3. The language model reads $256 + 12 + 8 = 276$ positions. Only the 8 answer tokens are targets of the loss.

In symbols, stack the 256 encoder outputs as the rows of a $256 \times 1024$ matrix $Z$. The visual tokens are the rows of $ZW + \mathbf{b}$, a $256 \times 4096$ matrix, with $\mathbf{b}$ added to every row. Let $A$ be the set of answer positions, and let $y_t$ be the correct token at position $t$. The training loss is

$$
\mathcal{L} = -\sum_{t \in A} \log P(y_t \mid \text{everything before } t),
$$

where $P$ is the probability the language model gives to $y_t$. Positions outside $A$ add nothing. Libraries usually average over the positions in $A$ instead of summing, which only rescales the loss.

## Implementation

The first block follows the shapes of the focus problem, not a real model. It cuts a random image into patches to show the $256 \times 588$ patch matrix. Then, instead of running CLIP, it draws a random $256 \times 1024$ matrix as a stand-in for the encoder's output. It projects that matrix and builds the sequence and the loss mask.

```python
import numpy as np

rng = np.random.default_rng(0)
size, patch, channels = 224, 14, 3
image = rng.random((size, size, channels))
grid = size // patch                                         # 16 patches per side
# split rows and columns into 16 blocks of 14, put the two block indices
# next to each other, then flatten each 14 x 14 x 3 block into one row
patches = image.reshape(grid, patch, grid, patch, channels).transpose(0, 2, 1, 3, 4).reshape(-1, patch * patch * channels)
print("patches:", patches.shape)

d_vision, d_llm = 1024, 4096                                 # CLIP ViT-L/14 width, LLaMA-7B width
vision_out = rng.standard_normal((len(patches), d_vision))   # stand-in for the encoder's output
W_proj = rng.standard_normal((d_vision, d_llm)) * 0.01
b_proj = np.zeros(d_llm)
visual_tokens = vision_out @ W_proj + b_proj
print("visual tokens:", visual_tokens.shape, " projector parameters:", W_proj.size + b_proj.size)

question = rng.standard_normal((12, d_llm))                  # embedded question tokens
answer = rng.standard_normal((8, d_llm))                     # embedded answer tokens
sequence = np.concatenate([visual_tokens, question, answer])
print("sequence fed to the language model:", sequence.shape)

loss_mask = np.r_[np.zeros(len(visual_tokens) + len(question)), np.ones(len(answer))]
print("positions with a loss:", int(loss_mask.sum()), "of", len(loss_mask))
```

```output
patches: (256, 588)
visual tokens: (256, 4096)  projector parameters: 4198400
sequence fed to the language model: (276, 4096)
positions with a loss: 8 of 276
```

Each raw patch has $14 \cdot 14 \cdot 3 = 588$ numbers. The encoder turns it into 1,024 numbers, and the projector into 4,096. The mask has 268 zeros (image and question) and 8 ones (answer), as in part 3.

In PyTorch, freezing a module means turning off its gradients with `requires_grad_(False)`. For the loss, positions with no target get the label -100, which `F.cross_entropy` skips by default (its default `ignore_index` is -100). The block below freezes a stand-in encoder, builds the labels for the focus problem and scores random logits.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
vision_encoder = nn.Linear(588, 1024)      # stand-in for CLIP: patch pixels to 1,024 numbers
projector = nn.Linear(1024, 4096)
vision_encoder.requires_grad_(False)       # frozen: no gradients, so no updates
parts = [vision_encoder, projector]
print("trainable:", sum(p.numel() for m in parts for p in m.parameters() if p.requires_grad))

n_image, n_question, n_answer, vocab_size = 256, 12, 8, 1000
answer_ids = torch.randint(vocab_size, (n_answer,))
labels = torch.full((n_image + n_question + n_answer,), -100)   # -100 means "no target here"
labels[n_image + n_question:] = answer_ids
logits = torch.randn(len(labels), vocab_size)  # stand-in: row t scores every candidate for label t
loss = F.cross_entropy(logits, labels)         # skips label -100 by default
by_hand = -F.log_softmax(logits[-n_answer:], dim=1)[torch.arange(n_answer), answer_ids].mean()
print("targets:", int((labels != -100).sum()), " loss:", round(loss.item(), 4), " by hand:", round(by_hand.item(), 4))
```

```output
trainable: 4198400
targets: 8  loss: 8.1231  by hand: 8.1231
```

Only the projector's 4,198,400 parameters count as trainable, as in stage 1. The loss from `F.cross_entropy` matches the average over the 8 answer rows alone, so the 268 rows labeled -100 had no effect. In a real model the logits come from the language model, and the scores for the label at position $t$ are computed at position $t - 1$.

<Warning>

An easy mistake is to budget the context window in text tokens only. One
$336 \times 336$ image costs 576 tokens, so four images use 2,304 tokens of a
4,096-token window before the question starts. Some models, such as
LLaVA-1.5-HD, also split a large image into several pieces and encode each
one, which multiplies the cost. When a model handles a long conversation with
images badly, count the tokens first.

</Warning>
