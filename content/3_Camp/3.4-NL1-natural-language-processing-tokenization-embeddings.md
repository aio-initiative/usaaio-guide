### WordPiece, Unigram, and byte-level BPE

BPE is one of three tokenizer families in common use. They differ in two choices: how the vocabulary is learned, and how a new word is split.

* **Byte-level BPE**, used by GPT-2 and most GPT-style models, runs the same merge loop over the 256 possible bytes of UTF-8 text instead of over characters. Every string is a sequence of bytes, so every string can be encoded and no unknown token is needed. The price is that text outside ASCII starts out longer: a Chinese character takes 3 bytes, so until merges cover it, it costs 3 tokens.
* **WordPiece**, used by BERT, also merges pairs, but it picks the pair with the highest score $\text{count}(ab) / \big(\text{count}(a)\,\text{count}(b)\big)$ rather than the highest count. (Google never released its training code, so this rule is a reconstruction from the published literature, not the official algorithm.) That favors pairs whose parts rarely appear apart. To split a new word it takes the longest vocabulary entry that matches at the start, then the longest that matches what is left, and so on, marking pieces after the first with `##`, so `playing` becomes `play` and `##ing`. A word with no match at some position becomes `[UNK]`.
* **Unigram**, the default in the SentencePiece library and the tokenizer of T5 and many multilingual models, works the other way round. It starts from a large set of candidate tokens and prunes it, keeping the tokens that matter most to the likelihood of the training text. Each token $t$ gets a probability $p(t)$, a segmentation's probability is the product of its tokens' probabilities, and a word is split the most probable way. Finding that split is a shortest-path problem over positions in the word, solved by **Viterbi** dynamic programming: the best split of the first $i$ characters is the best split of some shorter prefix plus one more token.

```python
import math

# A unigram tokenizer's vocabulary: every token has a probability, single characters included.
probs = {"token": 0.05, "tokeni": 0.002, "ization": 0.04, "zation": 0.003,
         "iz": 0.01, "ation": 0.03, "at": 0.02, "ion": 0.02}
probs.update({c: 0.005 for c in "tokenizat"})
logp = {t: math.log(p) for t, p in probs.items()}

def viterbi(word):
    """Most probable split. best[i] is the best log-probability of word[:i]."""
    best, back = [0.0] + [-math.inf] * len(word), [0] * (len(word) + 1)
    for end in range(1, len(word) + 1):
        for start in range(end):
            piece = word[start:end]
            if piece in logp and best[start] + logp[piece] > best[end]:
                best[end], back[end] = best[start] + logp[piece], start
    pieces, end = [], len(word)
    while end > 0:                                     # walk the back-pointers from the end
        pieces.append(word[back[end]:end])
        end = back[end]
    return pieces[::-1]

def longest_match(word):
    """WordPiece-style split: take the longest vocabulary entry at each position."""
    pieces, i = [], 0
    while i < len(word):
        j = max(j for j in range(i + 1, len(word) + 1) if word[i:j] in logp)
        pieces.append(word[i:j])
        i = j
    return pieces

for name, split in [("Viterbi", viterbi("tokenization")),
                    ("longest match", longest_match("tokenization"))]:
    print(f"{name:<14} {split}  log-probability {sum(logp[p] for p in split):.2f}")

# BPE merges the most frequent pair. WordPiece divides by how often the parts occur alone.
pair_counts = {("t", "h"): 30, ("q", "u"): 10}
symbol_counts = {"t": 200, "h": 60, "q": 10, "u": 50}
print()
for (a, b), n in pair_counts.items():
    print(f"pair {a}{b}: BPE count {n:>2}, "
          f"WordPiece score {n / (symbol_counts[a] * symbol_counts[b]):.4f}")

# Byte-level BPE starts from UTF-8 bytes, so any text encodes, at a price outside ASCII.
print()
for text in ["cat", "café", "日本"]:
    print(f"{text}: {len(text)} characters, {len(text.encode('utf-8'))} bytes")
```

```output
Viterbi        ['token', 'ization']  log-probability -6.21
longest match  ['tokeni', 'zation']  log-probability -12.02

pair th: BPE count 30, WordPiece score 0.0025
pair qu: BPE count 10, WordPiece score 0.0200

cat: 3 characters, 3 bytes
café: 4 characters, 5 bytes
日本: 2 characters, 6 bytes
```

Viterbi finds the split with the highest total log-probability, `token` and `ization`. Taking the longest piece first commits to `tokeni` and is left with the rare `zation`, a split about 330 times less probable. Longest match is still how WordPiece encodes, and it works there because WordPiece vocabularies are built with that encoder in mind. The scores show WordPiece's preference: `th` is three times as frequent as `qu`, but `q` almost never appears without `u`, so WordPiece merges `qu` first. The last lines are the price of byte-level BPE: two Chinese characters start as six tokens.

### Word2vec skip-gram: deriving the objective

Word2vec (Mikolov et al., 2013) learns a table of the same shape as the Transformer's $E$, one row of $d$ numbers per word, with no Transformer at all. It learns from one signal, which words appear near which. The table it produces is static: a word keeps the same row in every sentence, and no attention layers follow to adjust that row to the context. Here the table is written $W_{\text{in}}$.

The **skip-gram** model learns $W_{\text{in}}$ by training each word to predict the words around it. Each word has two vectors: a "center" vector $\mathbf{v}_w$, its row of $W_{\text{in}}$, and a "context" vector $\mathbf{u}_w$, its row of a second table $W_{\text{out}}$ that is usually discarded after training. The probability of context word $o$ given center word $c$ is a **softmax** over the vocabulary:

$$
P(o \mid c) = \frac{\exp(\mathbf{u}_o^\top \mathbf{v}_c)}
{\sum_{w=1}^{V} \exp(\mathbf{u}_w^\top \mathbf{v}_c)}.
$$

The dot product $\mathbf{u}_o^\top \mathbf{v}_c$ is a similarity score. Training minimizes the negative log-likelihood of every observed (center, context) pair

$$
\mathcal{L} = -\sum_{(c,\,o)\,\in\,\mathcal{D}} \log P(o \mid c)
= -\sum_{(c,\,o)} \Big[ \mathbf{u}_o^\top \mathbf{v}_c
- \log \sum_{w=1}^{V} \exp(\mathbf{u}_w^\top \mathbf{v}_c) \Big].
$$

This is a [cross-entropy / softmax loss](1.28-ML9-loss-functions.md) whose "classes" are the $V$ words of the vocabulary.

### CBOW, the same model run backwards

The word2vec paper introduced two architectures, and skip-gram is the second. **CBOW**, continuous bag of words, swaps which side does the predicting. Average the context embeddings into one vector and use it to predict the center word:

$$
\mathbf{h}_t = \frac{1}{2W}\!\!\sum_{-W \le j \le W,\; j \ne 0}\!\! \mathbf{v}_{w_{t+j}},
\qquad
P(w_t \mid \text{context}) = \frac{\exp(\mathbf{u}_{w_t}^\top \mathbf{h}_t)}
{\sum_{w} \exp(\mathbf{u}_w^\top \mathbf{h}_t)}.
$$

Same two embedding tables, same softmax, same negative sampling below. The only changes are the direction and the averaging. Counting what they do to the training signal gives the arithmetic behind the two claims usually made about CBOW, that it is faster and that it is worse on rare words:

```python
import numpy as np

rng = np.random.default_rng(0)
V, N, W = 5000, 200_000, 5

zipf = 1.0 / np.arange(1, V + 1); zipf /= zipf.sum()
counts = np.bincount(rng.choice(V, size=N, p=zipf), minlength=V)

print(f"corpus of {N:,} tokens, vocab {V:,}, window +/-{W}\n")
print(f"  skip-gram examples : {2*W*N:,}   (one per center/context pair)")
print(f"  CBOW examples      : {N:,}   (one per position, the context is averaged)")
print(f"  ratio              : {2*W}x\n")

# Gradient reaching one word's INPUT embedding, per occurrence of that word.
#   skip-gram: it is the center once, which spawns 2W pairs, each a full gradient.
#   CBOW:      it is a context word in 2W windows, but h = mean of 2W embeddings,
#              so each contribution is scaled by 1/(2W).
print("  full-strength gradient updates to a word's input embedding:\n")
print(f"  {'rank':>6} {'occurrences':>12} {'skip-gram':>11} {'CBOW':>7}")
for rank in (0, 9, 99, 999, 4999):
    c = counts[rank]
    print(f"  {rank+1:>6} {c:>12,} {2*W*c:>11,} {c:>7,}")
print(f"\n  Every row differs by the same factor of {2*W}, and for the rank-5000 word")
print(f"  that is {2*W*counts[4999]} updates against {counts[4999]}.")
```

```output
corpus of 200,000 tokens, vocab 5,000, window +/-5

  skip-gram examples : 2,000,000   (one per center/context pair)
  CBOW examples      : 200,000   (one per position, the context is averaged)
  ratio              : 10x

  full-strength gradient updates to a word's input embedding:

    rank  occurrences   skip-gram    CBOW
       1       22,219     222,190  22,219
      10        2,200      22,000   2,200
     100          221       2,210     221
    1000           29         290      29
    5000            6          60       6

  Every row differs by the same factor of 10, and for the rank-5000 word
  that is 60 updates against 6.
```

**CBOW is faster because it does a tenth of the work.** One training example per position against one per center-context pair, so at window $\pm 5$ this corpus yields $200{,}000$ examples rather than $2{,}000{,}000$.

**The rare-word claim is where the arithmetic stops.** Follow one occurrence of a word. In skip-gram it is the center once, that occurrence spawns $2W$ separate pairs, and each delivers a full gradient to its embedding. In CBOW it is a context word in $2W$ windows, but the softmax input is the *mean* of $2W$ embeddings, so $\partial\mathbf{h}/\partial\mathbf{v}_c = 1/2W$ and every contribution arrives at a tenth strength. On paper the rank-5000 word, seen six times, gets 60 full-strength updates from skip-gram and 6 from CBOW.

That was long offered as the reason skip-gram wins on rare words. The standard implementations did not apply the $1/2W$, though. İrsoy, Benton and Stratos (2021) found that the negative-sampling CBOW update in the official word2vec.c and in Gensim omits it (they discuss the same bug in fastText), and that CBOW trained with the correct gradient matches skip-gram on their benchmarks while training many times faster. A constant factor applied to only one of the two embedding tables is not something a single learning rate can absorb, since it changes the relative step sizes of the input and output vectors. What survives is the cost: skip-gram does $2W$ times the work.

The bug sat in widely used code for years, and a finite-difference check of the derived gradient would have caught it. The same check is worth running on any gradient you derive by hand.

### Why negative sampling

The problem is the denominator: it sums over **all $V$ words** for every training pair, and $V$ can be a million.

**Negative sampling** replaces the expensive softmax with a cheap binary question: "is this (center, context) pair real, or did I fake it?" For each true pair $(c, o)$, draw $k$ **negative** words $w_1, \dots, w_k$ from a noise distribution and train a logistic classifier to score the real pair high, the fakes low. The per-pair objective becomes

$$
\log \sigma(\mathbf{u}_o^\top \mathbf{v}_c)
+ \sum_{i=1}^{k} \mathbb{E}_{w_i \sim P_n} \big[ \log \sigma(-\mathbf{u}_{w_i}^\top \mathbf{v}_c) \big],
$$

where $\sigma(x) = 1/(1+e^{-x})$ is the logistic sigmoid. Each step now touches only $k+1$ words instead of $V$ (Mikolov et al. recommend $k$ in the range 5-20 for small datasets and 2-5 for large ones), so the cost no longer depends on vocabulary size at all. It optimizes a related objective rather than the exact softmax, but produces embeddings of comparable quality far faster.

### GloVe: embeddings from global counts

Word2vec learns from one window at a time. **GloVe** (Pennington, Socher and Manning, 2014) starts from the whole corpus at once: a co-occurrence table $X$, where $X_{ij}$ counts how often word $j$ appears within a window around word $i$, each occurrence weighted by one over its distance.

The observation behind it is that meaning shows up in *ratios* of co-occurrence probabilities. For a probe word $k$, the ratio $P(k \mid i) / P(k \mid j)$ is large when $k$ goes with $i$ but not $j$, small in the reverse case, and near 1 when $k$ relates to both or to neither. A model whose dot products track log probabilities turns those ratios into differences, so GloVe asks for

$$
\mathbf{w}_i^\top \mathbf{c}_j + b_i + b'_j \approx \log X_{ij}
$$

for every pair with $X_{ij} > 0$, with separate word and context vectors and a bias for each, fitted by weighted least squares:

$$
J = \sum_{i,j:\ X_{ij} > 0} f(X_{ij})\,\big(\mathbf{w}_i^\top \mathbf{c}_j + b_i + b'_j - \log X_{ij}\big)^2,
\qquad
f(x) = \min\!\Big(\big(x / x_{\max}\big)^{\alpha},\ 1\Big),
$$

with $\alpha = 3/4$ and $x_{\max} = 100$ in the paper. The weight does two jobs. Small counts have noisy logarithms, so they get small weights, and the most frequent pairs are capped at 1 so that pairs with words like "the" do not dominate the fit. The published vectors are $\mathbf{w}_i + \mathbf{c}_i$.

Strip out $f$ and the biases and GloVe becomes a familiar problem: find rank-$d$ matrices $W$ and $C$ with $WC^\top \approx \log X$ in squared error. The best answer is the truncated SVD of $\log X$, by the Eckart-Young theorem from [Eigenvalues and Spectral Theory](1.8-MA2-linear-algebra-ii-eigenvalues-eigenvectors-spectral-theory.md), and gradient descent on the factors finds it:

```python
rng = np.random.default_rng(0)

# A co-occurrence table with real structure: 40 words, 3 latent "topics", counts all >= 1.
V, d = 40, 3
topic = rng.normal(size=(V, d))
X = rng.poisson(np.exp(1.5 + 0.8 * topic @ topic.T / np.sqrt(d))) + 1
L = np.log(X)

# GloVe with the weights and biases stripped out: fit w_i . c_j to log X_ij by gradient descent.
W, C = 0.1 * rng.normal(size=(V, d)), 0.1 * rng.normal(size=(V, d))
for _ in range(20000):
    R = W @ C.T - L                      # residual on every pair
    W, C = W - 0.01 * R @ C, C - 0.01 * R.T @ W
sv = np.linalg.svd(L, compute_uv=False)
print(f"gradient descent, rank {d} fit to log X : squared error {np.sum((W @ C.T - L) ** 2):.4f}")
print(f"truncated SVD, the best rank-{d} fit   : squared error {np.sum(sv[d:] ** 2):.4f}")

def glove_weight(x, x_max=100.0, alpha=0.75):
    return np.minimum(x / x_max, 1.0) ** alpha
print("\nf(x) at counts 1, 10, 100, 1000:",
      "  ".join(f"{glove_weight(x):.3f}" for x in (1, 10, 100, 1000)))
```

```output
gradient descent, rank 3 fit to log X : squared error 295.6438
truncated SVD, the best rank-3 fit   : squared error 295.6438

f(x) at counts 1, 10, 100, 1000: 0.032  0.178  1.000  1.000
```

The two numbers agree to four decimals: without its weighting, GloVe *is* a truncated SVD of the log counts. That is why taking a GloVe matrix apart with SVD, as the contest problem below does, finds structure the training put there. The weights and biases turn it into a weighted low-rank problem with no closed form, which is why GloVe trains by gradient descent. A count of 1 carries about 3% of the weight of a count of 100.

<ProblemCard id="twe-what-the-biases-buy" />

Word2vec is closer than it looks. Levy and Goldberg (2014) showed that skip-gram with negative sampling implicitly factorizes a shifted pointwise mutual information matrix, $\log\frac{P(i, j)}{P(i)\,P(j)} - \log k$ for $k$ negatives. The unshifted matrix, averaged under $P(i, j)$, is the [mutual information](3.1-PS4-information-theory-core.md) between neighboring words. Both methods compress the same co-occurrence statistics into a low-rank product. They differ in which entries they weight and how.
