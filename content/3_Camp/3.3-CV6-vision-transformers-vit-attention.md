## Vision Transformer

### The problem

A convolution only looks at a small area. A 3 × 3 filter sees 9 pixels at a time, so one layer can relate two things only if they are right next to each other.

For example, to understand a photo of someone about to catch a ball, the model has to relate the hand and the ball, which may be far apart. In the grid below the two dark pixels are 9 rows and 9 columns apart, and no 3 × 3 filter covers both.

<Figure src="assets/module-media/vision-problem-vit.svg" alt="A 12 by 12 grid of pixels. One dark pixel is near the top-left corner and another near the bottom-right, joined by a dashed line. A 3 by 3 square outlined in the top-left corner contains only the first. Notes say: one 3 by 3 filter sees only this corner, and the two dark pixels are 9 rows and 9 columns apart, for example a hand and a ball.">
Two parts of an image that one small filter cannot see together.
</Figure>

Stacking layers widens the view, but slowly. One 3 × 3 layer sees 3 pixels across, two layers see 5, and three see 7, so covering both dark pixels takes 5 layers. Information from far away has to pass through every one of them.

Attention, from Build a Transformer, relates any two tokens in one layer. The question is what the tokens of an image should be.

### Earlier approaches

#### Deeper CNNs

Stacking more layers, as in [Deeper networks](2.25-CV12-vision-classify.md#lesson-deeper-networks), widens what each position sees, but information from far away still has to pass through many layers to arrive.

#### Attention on pixels

Treating every pixel as a token makes attention far too expensive. A 224 × 224 image has 50,176 pixels, so one attention layer would compute 50,176 × 50,176, about 2.5 billion, scores.

### Patches as tokens

**Patches.** The **Vision Transformer** (ViT) cuts the image into square patches, usually 16 × 16 pixels, and treats each patch as a token. An image of $n \times n$ pixels cut into patches of $p \times p$ gives $(n / p)^2$ tokens. A 224 × 224 image gives 14 × 14 = 196 patches, so attention needs 196 × 196 = 38,416 scores, not 2.5 billion.

<Figure src="assets/module-media/vision-patches.svg" alt="The 6 by 6 image divided into four 3 by 3 patches, with the top-left patch outlined most heavily. Arrows lead from the top-left patch to its attention weights on all four patches: 0.366 on itself, 0.134 on the top-right, 0.366 on the bottom-left and 0.134 on the bottom-right. The two patches that contain the line get the larger weights.">
The running example cut into four patches, and the attention weights of the top-left patch.
</Figure>

**From patch to token.** Each patch is flattened into a list of numbers, 16 × 16 × 3 = 768 for a color patch, and multiplied by a learned matrix to give its token vector. This is the embedding from [Embed](2.30-TF10-transformer-setup.md#lesson-embed) in Build a Transformer, with a multiplication in place of a table lookup.

**Patch embedding as a convolution.** Each column of the learned matrix holds 768 numbers, one for each value of a patch, so it can be folded back into a 16 × 16 × 3 filter. Multiplying every patch by that column is then a convolution with the filter moved 16 pixels at a time, so the windows never overlap. Libraries compute the patch embedding this way, as `nn.Conv2d(3, D, kernel_size=16, stride=16)` in PyTorch, where $D$ is the size of a token vector. In the running example, multiplying each flattened patch by the flattened vertical filter from [Convolution](2.23-CV10-vision-convolution.md#lesson-convolution) gives −3, 0, −3, 0, the numbers of that vertical map at rows 1 and 4 and columns 1 and 4, where a filter moved 3 pixels at a time lands.

<Figure src="assets/module-media/vision-patch-embedding.svg" alt="The 6 by 6 image cut into four 3 by 3 patches, times the vertical filter, whose rows are each -1, 2, -1. An arrow labeled each patch leads to a 2 by 2 grid with rows -3, 0, one number per patch. An equals sign leads to the 4 by 4 vertical map from Convolution with rows -3, 6, -3, 0, where only the four corner cells, -3, 0, -3 and 0, are outlined: the map at stride 3.">
Multiplying each patch by one flattened filter gives the same numbers as the filter moved 3 pixels at a time.
</Figure>

**Position.** Position embeddings are added, as in [Add position](2.30-TF10-transformer-setup.md#lesson-add-position) in Build a Transformer, because attention alone does not know where a patch came from. Without them, the image and the same patches shuffled would look identical.

**Classification.** An extra learned token, the **class token**, is added at the start, and after the Transformer layers its output vector is used to classify the image. Unlike a language model, there is no mask: every patch can look at every other patch.

**Mean pooling.** Many later models leave out the class token and classify the average of the output vectors of all the patches, called **mean pooling**. Averaged as they go in, the four patches of the running example give 0, 0, 0.5, 0, 0, 0.5, 0, 0, 0.5: the line keeps its place in the patch at half strength, because two of the four patches hold it.

**Registers.** Trained ViTs develop high-norm artifact tokens in uninformative background patches, which corrupt the attention weights. Adding a few extra learnable tokens that carry no output gives the model somewhere to put that state, and the artifacts disappear.

**Data.** ViT has no built-in idea that nearby pixels are related, so it must learn that from data. Measuring the **attention distance** confirms it. For one query patch, average the pixel distance to every patch it attends to, weighting each patch by the attention it receives, then average over images, per head and per layer (heads come from [Multi-head](2.37-TF17-transformer-weighted-sum.md#lesson-multi-head) in Build a Transformer). Some heads in the first layer already attend to most of the image, while others keep a small distance, and the distance grows with depth. Trained on ImageNet alone, it did worse than ResNets. Trained first on 300 million images, it did better. DeiT (2020) later trained it well on ImageNet alone with heavy data augmentation.

### Running example

#### Patches

Cut the 6 × 6 image into four 3 × 3 patches. The line runs through the left half, so the two left patches contain it:

| Patch | Flattened (9 numbers) |
|---|---|
| top-left | 0, 0, 1, 0, 0, 1, 0, 0, 1 |
| top-right | 0, 0, 0, 0, 0, 0, 0, 0, 0 |
| bottom-left | 0, 0, 1, 0, 0, 1, 0, 0, 1 |
| bottom-right | 0, 0, 0, 0, 0, 0, 0, 0, 0 |

#### Attention between patches

Using these vectors directly as queries and keys, the top-left patch scores each patch with a dot product divided by $\sqrt{9} = 3$, then a softmax:

| Patch | Score | Scaled | Attention weight |
|---|---|---|---|
| top-left | 3 | 1 | 0.366 |
| top-right | 0 | 0 | 0.134 |
| bottom-left | 3 | 1 | 0.366 |
| bottom-right | 0 | 0 | 0.134 |

The top-left patch attends most to itself and to the bottom-left patch, the other piece of the same line. In a real image, the two patches could be on opposite sides and it would work the same way. In a trained model, the attention weights show where it looks, but not by themselves what it computes.

```python
import numpy as np

image = np.zeros((6, 6)); image[:, 2] = 1.0
patches = np.array([image[i:i + 3, j:j + 3].ravel()
                    for (i, j) in [(0, 0), (0, 3), (3, 0), (3, 3)]])

scaled = patches @ patches[0] / np.sqrt(9)
print((np.exp(scaled) / np.exp(scaled).sum()).round(3))   # [0.366 0.134 0.366 0.134]

vertical = np.array([[-1, 2, -1]] * 3, dtype=float)
print(patches @ vertical.ravel())                         # [-3.  0. -3.  0.]
print(patches.mean(axis=0))                               # mean pooling
```

### Common questions

**Why 16 × 16 patches?** It is a trade. Smaller patches keep more detail but give more tokens, and attention grows with the square of their number. Patches of 8 × 8 would give 28 × 28 = 784 tokens, four times as many, and 614,656 scores, sixteen times as many. A CNN's cost is only quadratic in resolution.

$N$ is the number of tokens. Per-layer FLOPs are about $24ND^2 + 4N^2D$, and the crossover where the attention term overtakes the rest is $N = 6D$. For ViT-Base ($D=768$), that is $N = 4608$ patches, far above 196, so at standard resolution a ViT is dominated by the projections and the MLP, not by attention: at $N = 197$ the attention term is about 4% of the layer. The quadratic term only bites at high resolution.

**Can a trained ViT read larger images?** Yes, with one change. Fine-tuning at 384 × 384 instead of 224 × 224 keeps the 16 × 16 patches, so the grid grows from 14 × 14 to 24 × 24 and the sequence from 197 tokens, counting the class token, to 577. The patch embedding and the Transformer layers work on any number of tokens, but there is one learned position embedding for each cell of the old grid, plus one for the class token. The patch ones are laid out as a 14 × 14 grid and resized to 24 × 24 by interpolation, and attention then costs (577 ÷ 197)² = 8.6 times as much per layer. In the running example, a 12 × 12 image gives 16 patches where the model saw 4, and its 2 × 2 grid of position embeddings is resized to 4 × 4.

**Why is there no mask?** A language model must not see the tokens it is trained to predict. An image classifier predicts one label for the whole image, so every patch may look at every other.

**Why do the two empty patches still get weight?** Their scores are 0, and $e^0 = 1$ is not 0. The softmax gives every patch some weight: 0.134 for each empty patch against 0.366 for each patch with the line.

## Object detection

### The problem

A classifier gives one label for the whole image. Many tasks need more. A self-driving car has to know about every pedestrian, car and sign in view, and where each one is.

For example, for the street scene sketched below, a classifier could answer "street". A detector has to return 3 boxes, two labeled "car" and one labeled "person". Each **box** is four numbers: its left, top, right and bottom edges.

<Figure src="assets/module-media/vision-problem-detection.svg" alt="A rectangle standing for one image, with three boxes drawn inside it: two labeled car and one labeled person. Beside it: a classifier gives one label, street. A detector gives 3 boxes, each with a label and 4 numbers.">
One image, and what a classifier and a detector each have to return.
</Figure>

Three things make this harder than classification:

- **Where.** The output includes positions, not just a label.
- **How many.** One photo has 3 objects and the next has 12, so the output has no fixed size.
- **Judging.** A predicted box is rarely exactly right. There has to be a way to say when it is close enough, and to notice when two boxes are the same object found twice.

### Earlier approaches

#### Sliding windows

Run a classifier on every window of the image, at several sizes. A 32 × 32 window fits in (224 − 32 + 1)² = 37,249 positions in a 224 × 224 image, and the search repeats for every size, so this is slow, and most windows contain nothing.

#### R-CNN

R-CNN (2014) first picked about 2,000 candidate regions with a separate method, then ran a CNN on each one. It was far more accurate than before, but proposing the regions and computing features for all 2,000 of them took 13 seconds per image on a GPU.

### Detection methods

**One run.** **YOLO** (2015) runs the network once. It divides the image into a grid, 7 × 7 in the original, and each cell predicts a few boxes, how confident it is that each box holds an object, and the class. With 2 boxes per cell that is 7 × 7 × 2 = 98 boxes from one run, at 45 images per second.

**Intersection over union.** **IoU** measures how well two boxes match: the area where they overlap divided by the area they cover together,

$$
\text{IoU} = \frac{\text{area of overlap}}{\text{area of union}}, \qquad \text{union} = \text{area}_1 + \text{area}_2 - \text{overlap}.
$$

1 means identical and 0 means no overlap. For example, two boxes of area 4 that overlap in an area of 2 cover 4 + 4 − 2 = 6 together, so their IoU is 2 ÷ 6 = 0.333. A predicted box usually counts as correct when its IoU with the true box is above 0.5. IoU is scale-invariant: multiplying every coordinate by the same factor multiplies both areas by its square, so the ratio is unchanged and one threshold serves objects of every size.

**The overlap.** The overlap of two boxes is itself a box. Its left edge is the larger of the two left edges and its right edge the smaller of the two right edges, and the same for the top and the bottom. For box A of the running example, (2, 1, 3, 6), and the true box, (2, 0, 3, 6), that gives left 2, right 3, top 1 and bottom 6, an overlap of 1 × 5 = 5. For two boxes that do not touch, right minus left or bottom minus top comes out negative, so each is clamped at 0 and the overlap is 0.

<Figure src="assets/module-media/vision-iou.svg" alt="The 6 by 6 image with three boxes drawn around the bright column. The true box, a solid outline, covers column 3 from top to bottom and has area 6. Box A, dashed, covers the same column but misses the top row. Its IoU with the true box is 0.833. Box B, dotted, starts at the same left edge but is half a column too wide. Its IoU is 0.667.">
The true box and the two predicted boxes of the running example.
</Figure>

**Non-maximum suppression.** Several cells often find the same object. **Non-maximum suppression** keeps the most confident box and drops any other box whose IoU with it is above a threshold, often 0.5. Then it repeats with the most confident box that is left. It runs separately for each class.

#### Anchor boxes

**Anchors.** Predicting a box from nothing is hard, so many detectors since Faster R-CNN (2015) start from **anchor boxes**: fixed boxes of a few sizes and shapes centered on every cell of a grid. For each anchor the network predicts class scores and four numbers that adjust the anchor toward an object. YOLO took them up in its second version (2016). In the running example, split the image into a 3 × 3 grid of cells of 2 × 2 pixels. The line's center, (2.5, 3), falls in the cell from 2 to 4 across and down, and two anchors are centered on that cell: a tall one, (2, 0, 4, 6), and a square one, (2, 2, 4, 4).

**Labels.** In training, each anchor is labeled by its IoU with the true boxes. Faster R-CNN calls an anchor an object at 0.7 or more and background below 0.3, and gives every object its best anchor even below 0.7. The tall anchor and the true box overlap in 6 of the 12 pixels they cover, an IoU of 0.5, the best of the two, so the tall anchor is the line's anchor. The square one has an IoU of 2 ÷ 8 = 0.25 and is background.

<Figure src="assets/module-media/vision-anchors.svg" alt="The 6 by 6 image divided by heavier lines into a 3 by 3 grid of 2 by 2 cells. The true box, a solid outline, covers column 3 from top to bottom. A dashed tall anchor covers columns 3 and 4 from top to bottom, and a dotted square anchor covers columns 3 and 4 in rows 3 and 4. A dot marks their shared center, 3, 3, the center of the middle cell. Notes say: true box, center 2.5, 3, width 1, height 6. Tall anchor, IoU 0.5, the line's anchor. Square anchor, IoU 0.25, background. Offsets from the tall anchor: -0.25, 0, -0.693, 0.">
Two anchors in the cell that holds the line's center, and the offsets that move the tall one onto the true box.
</Figure>

**Offsets.** The four numbers are offsets from the anchor, with each box written by its center $(x, y)$, width $w$ and height $h$, and the anchor's by $(x_a, y_a, w_a, h_a)$:

$$
t_x = \frac{x - x_a}{w_a}, \qquad t_y = \frac{y - y_a}{h_a}, \qquad
t_w = \log \frac{w}{w_a}, \qquad t_h = \log \frac{h}{h_a}.
$$

The true box has center (2.5, 3), width 1 and height 6, and the tall anchor's center (3, 3), width 2 and height 6, so the targets are $t_x = -0.5 \div 2 = -0.25$, $t_y = 0$, $t_w = \log(1 \div 2) = -0.693$ and $t_h = \log 1 = 0$. Decoding reverses them: $x = 3 + (-0.25) \times 2 = 2.5$ and $w = 2 \times e^{-0.693} = 1$. Dividing by the anchor's size gives the same targets for an image and a copy 10 times larger, and the logarithm makes half as wide, −0.693, and twice as wide, +0.693, equally large. The offsets are trained with the smooth L1 loss, the Huber loss of [Loss functions](1.28-ML9-loss-functions.md). When an anchor is close to the target box, its offsets are small. A poorly matched anchor still needs a large correction, so the choice of anchors affects the regression task.

FCOS predicts a box from each location, CenterNet predicts object centers, and DETR uses learned queries. None of them uses anchors. DETR goes further and removes non-maximum suppression too, by using bipartite Hungarian matching so each object is matched to exactly one query.

#### Two stages

**Region proposals.** Faster R-CNN works in two stages. A small network slides over the CNN's feature map and scores 9 anchors at every position, 3 sizes times 3 shapes, as object or background. The best 300 boxes after non-maximum suppression go to a second head, which classifies each one and refines its box with the same offsets. It ran at about 5 images per second. One-stage detectors such as YOLO, SSD and RetinaNet skip the proposals and predict over the whole grid at once, which is faster: YOLO ran at 45 images per second.

**Reading a box's features.** The second stage needs features for each box, cut out of the feature map. The vertical pooled map from [ReLU and pooling](2.23-CV10-vision-convolution.md#lesson-relu-and-pooling) is 2 × 2 for a 6 × 6 image, so one unit on the map stands for 3 pixels, and box A runs from 2 ÷ 3 = 0.667 to 3 ÷ 3 = 1 across and from 0.333 to 2 down. **RoIPool** rounds the edges to whole cells: 0.667 and 1 both become 1, so it reads only the second column of the map, which holds 0, the empty side of the image. **RoIAlign** keeps the fractions and reads the map by bilinear interpolation. At the box's center, 0.833 across, a third of the way from the first column's center at 0.5 to the second's at 1.5, it reads 6 × (1 − 0.333) + 0 × 0.333 = 4. A shift like this hardly changes a class label but moves a mask, which is why Mask R-CNN ([Segmentation](2.7-CV3-semantic-segmentation-unet-masks.md#lesson-segmentation)) reads its features with RoIAlign.

Box A is a narrow solid rectangle from 0.667 to 1 across, near the right edge of the first column. A dashed rectangle covers the whole second column, labeled RoIPool rounds to the second column: reads 0. A dot inside box A marks its center, labeled RoIAlign at the center, 0.833: reads 4. #### Objects of every size

**Feature pyramid.** Deep maps know what is in the image but have lost detail, and small objects vanish from them. Shallow maps keep the detail but know less. A **feature pyramid network** (FPN, 2017) sends what the deep maps know back down. Starting from the deepest map, it enlarges the map by a factor of 2 and adds the shallower map of the same size, passed through a 1 × 1 convolution called the lateral connection. In the running example the pooled map, 6, 0 in each row, is enlarged to 6, 6, 0, 0, and adding the 4 × 4 map from before pooling, 0, 6, 0, 0, with a lateral weight of 1 gives 6, 12, 0, 0. The finer level now holds the line's exact column, 12, and the wider area the deeper level found, 6. Every level has the same number of channels, 256 in the paper, so one detection head with one set of weights runs on all of them.

<Figure src="assets/module-media/vision-pyramid.svg" alt="Four grids. The 2 by 2 pooled map, rows 6, 0, is enlarged 2 times to a 4 by 4 grid with rows 6, 6, 0, 0. A plus sign adds the 4 by 4 map from before pooling, rows 0, 6, 0, 0, through a 1 by 1 of weight 1. An equals sign gives the pyramid level, outlined most heavily, with rows 6, 12, 0, 0.">
One level of a feature pyramid in the running example.
</Figure>

**Focal loss.** Most boxes a one-stage detector scores hold nothing. Of YOLO's 98 boxes, an image with one object, such as the line, has 97 that should say background. Even when each already says so with probability 0.99, their cross-entropy terms add up to 97 × (−log 0.99) = 0.975, against −log 0.9 = 0.105 for box A. **Focal loss** (RetinaNet, 2017) multiplies each term by $(1 - p)^\gamma$, where $p$ is the probability given to the right answer, usually with $\gamma = 2$:

| | Cross-entropy | Focal loss, $\gamma = 2$ |
|---|---|---|
| 97 background boxes at 0.99 | 0.975 | 0.0000975 |
| Box A at 0.9 | 0.105 | 0.00105 |

The easy boxes now count for almost nothing, and box A outweighs all 97 of them by 10.8 times. Two-stage detectors avoid most of the problem, because their first stage passes on only a few hundred boxes.

#### Scoring

**Precision and recall.** A predicted box is a true positive when its IoU with a true box of its class is above the threshold, usually 0.5, and no more confident box has already matched that true box. Otherwise it is a false positive, and a true box left unmatched is a false negative. Precision is the share of predicted boxes that are right and recall the share of true boxes found. After non-maximum suppression the running example has one box, A, and it is right: precision 1 and recall 1. Without non-maximum suppression, B is a second answer for a line A already found, a false positive, and precision falls to 0.5.

**Average precision.** Lowering a confidence threshold step by step adds boxes in order of confidence and traces precision against recall. The area under that curve is a class's **average precision** (AP), and its mean over the classes, **mAP**, is the usual headline number. The COCO benchmark also averages over IoU thresholds from 0.5 to 0.95 in steps of 0.05. Box A, with an IoU of 0.833, is a true positive at 7 of those 10 thresholds, so on this image the class scores 0.7 rather than 1. In practice the curve is interpolated to be monotonically non-increasing: $p_{\text{interp}}(r) = \max_{\tilde r\ge r} p(\tilde r)$, which removes the sawtooth caused by each new true positive momentarily raising precision. Then AP is the sum of $(\Delta r)\cdot p_{\text{interp}}$ over the recall steps (the "all-points" convention, whereas older PASCAL VOC used an 11-point sample).

**Computing AP from a ranked list.** Six detections are scored against 4 ground-truth boxes, sorted by confidence:

| Rank | Score | TP? | cum TP | cum FP | Precision | Recall |
|---|---|---|---|---|---|---|
| 1 | 0.95 | ✓ | 1 | 0 | 1.0000 | 0.25 |
| 2 | 0.90 | ✓ | 2 | 0 | 1.0000 | 0.50 |
| 3 | 0.85 | ✗ | 2 | 1 | 0.6667 | 0.50 |
| 4 | 0.80 | ✓ | 3 | 1 | 0.7500 | 0.75 |
| 5 | 0.70 | ✗ | 3 | 2 | 0.6000 | 0.75 |
| 6 | 0.60 | ✗ | 3 | 3 | 0.5000 | 0.75 |

Only 3 of the 4 ground-truth boxes were found, so recall tops out at 0.75. Interpolate precision to be non-increasing, scanning right to left: at recall 0.75 the max precision at recall ≥ 0.75 is 0.75, at recall 0.50 the max at recall ≥ 0.50 is max(1.0, 0.6667, 0.75) = 1.0, and at 0.25 it is 1.0. Sum delta-r × p_interp at the recall steps:

AP = (0.25 − 0)(1.0) + (0.50 − 0.25)(1.0) + (0.75 − 0.50)(0.75) = 0.25 + 0.25 + 0.1875 = 0.6875.

The model would score 1.0 if it found all four with no false positives. It loses 0.25 for the missing object, whose recall level is never reached, and a further 0.0625 for the false positive at rank 3, which dragged precision down at the 0.75 recall level.

### Running example

#### Intersection over union

Boxes are written as (left, top, right, bottom), in pixels. The line fills column 3, so the true box is (2, 0, 3, 6), with area 1 × 6 = 6. The detector predicts two boxes:

| Box | Coordinates | Area | Confidence | Overlap with truth | IoU with truth |
|---|---|---|---|---|---|
| A | (2, 1, 3, 6) | 5 | 0.9 | 5 | 5 ÷ 6 = 0.833 |
| B | (2, 0, 3.5, 6) | 9 | 0.7 | 6 | 6 ÷ 9 = 0.667 |

Box A misses the top row. Box B is too wide. For A, the union is 5 + 6 − 5 = 6. For B, it is 9 + 6 − 6 = 9.

#### Non-maximum suppression

Both boxes found the same line. Non-maximum suppression keeps A, the more confident one, and checks B against it: they overlap in an area of 5 and cover 9 together, so their IoU is 0.556. That is above 0.5, so B is dropped. The final answer is box A, which counts as correct because its IoU with the truth is above 0.5.

```python
def iou(a, b):
    """Boxes as (left, top, right, bottom)."""
    w = max(0, min(a[2], b[2]) - max(a[0], b[0]))
    h = max(0, min(a[3], b[3]) - max(a[1], b[1]))
    area = lambda r: (r[2] - r[0]) * (r[3] - r[1])
    return w * h / (area(a) + area(b) - w * h)

truth, A, B = (2, 0, 3, 6), (2, 1, 3, 6), (2, 0, 3.5, 6)
print(round(iou(A, truth), 3), round(iou(B, truth), 3), round(iou(A, B), 3))
# 0.833 0.667 0.556
```

### Common questions

**Why not just measure the overlap?** A huge box that covers the whole image overlaps every object completely. Dividing by the union punishes that: box B covers all 6 units of the true box, but its extra area brings its IoU down to 0.667.

**Why is the threshold 0.5?** It is a convention. Stricter tests use 0.75, or average the result over thresholds from 0.5 to 0.95.

**Can non-maximum suppression remove a real object?** Yes. Two different objects that overlap heavily, such as two people standing one behind the other, can have an IoU above the threshold, and the less confident box is dropped. A higher threshold has the opposite risk: at 0.6, box B, whose IoU with A is 0.556, would stay as a second answer for the same line. **Soft-NMS** instead *decays* the score, $s_i \leftarrow s_i\,e^{-\text{IoU}^2/\sigma}$ with $\sigma$ setting how harshly overlap is punished (the paper uses $\sigma = 0.5$), so a heavily-overlapping box is demoted rather than removed and can still survive if its score was high enough.

**What is the IoU of two boxes that do not touch?** 0. Their overlap is 0, whatever their sizes. **Why not train the box to maximize IoU?** Its gradient is zero whenever the boxes do not overlap, so a prediction far from the target gets no signal at all. **GIoU** repairs this by subtracting a penalty based on the smallest enclosing box $C$: $\text{GIoU} = \text{IoU} - \frac{|C\setminus(A\cup B)|}{|C|} \in[-1,1]$, which is negative when the boxes are separated and tends to $-1$ as they move apart.
