## The problem

Part 2 gave a loss. Two things remain.

**Training.** The 13 weights have to be adjusted until the loss is close to 0. For the untrained network it is 23.5.

**Checking.** A loss of 0 does not prove the network is right, because the loss only looks at the 9 collocation points between 0 and 2. For example, the gray curve below is not the solution. But it starts at 1 and satisfies the equation exactly at all 9 points, so its loss is 0. Between the points it is off by as much as 0.21.

The loss also says nothing about $t = 3$ or $t = 4$, which it never looked at. So the result has to be compared with something trusted, at points that were not used in training.

## Earlier approaches

### Plain gradient descent

Taking fixed-size steps downhill works, but physics losses are often badly scaled, steep in some directions and nearly flat in others, so plain gradient descent can need a very large number of steps.

### Classical solvers

For a small, fully known problem like this one, a classical solver is faster and more accurate, and comes with error estimates. A PINN is not a replacement for it there.

## Training and checking

**Training.** PINNs are usually trained with Adam, then with **L-BFGS**, which uses the gradients from recent steps to estimate how the loss curves and takes better-scaled steps. Raissi et al. used L-BFGS. Here it takes the loss from 23.5 to 0.00000023 in 100 iterations.

**Fresh points.** A loss over the same 9 points can be fooled: the gray curve above has residual 0 at those points but swings between them. With Adam, a fresh set of collocation points can be drawn at every iteration, so there is no fixed set to fit between. L-BFGS keeps one set, because its steps use the gradients of earlier iterations, so here 9 points drawn at random from 0 to 2 test the result after training. The equation part at each set of 9 points:

| Function | Training points | Random points |
|---|---|---|
| Gray curve | 0 | 1.63 |
| Trained network | 0.00000023 | 0.00000024 |

The gray curve's equation part jumps from 0 to 1.63, while the trained network's barely moves.

**Checking.** Checking means comparing against something trusted: an exact solution when one exists, as here, or a classical solver. It should include points that were not used in training, especially points outside the training range, where nothing in the loss constrained the network. Here the network was trained on $t$ from 0 to 2, so it is also checked at $t = 3$ and $t = 4$.

**Inverse problems.** The main strength of PINNs is **inverse problems**. If a constant in the equation is unknown, it can be made a trainable weight and learned from a few measurements, with the equation filling in between them. For example, in $dy/dt = -k \, y$ the unknown $k$ becomes a 14th weight. A classical solver would need a separate run for every value of $k$ it tried.

## Running example

### Training

Training with L-BFGS from the untrained network of part 1:

| Iterations | Loss |
|---|---|
| 0 | 23.5 |
| 1 | 4.55 |
| 5 | 0.229 |
| 20 | 0.0227 |
| 50 | 0.0000121 |
| 100 (converged) | 0.00000023 |

### Checking

Checking against $e^{-t}$, inside the training range of 0 to 2 and outside it:

| t | 0 | 0.5 | 1 | 1.5 | 2 | 3 | 4 |
|---|---|---|---|---|---|---|---|
| Network | 1.0000 | 0.6063 | 0.3679 | 0.2230 | 0.1353 | 0.0511 | 0.0214 |
| Exact | 1.0000 | 0.6065 | 0.3679 | 0.2231 | 0.1353 | 0.0498 | 0.0183 |
| Error | 0.0000 | 0.0002 | 0.0000 | 0.0001 | 0.0001 | 0.0013 | 0.0031 |

Errors are worked out from the unrounded network output, so the two 0.1353 entries at t = 2 still differ by 0.0001.

Inside the range, the error is at most 0.0002. Outside it, the error grows: at t = 4 it is 17% of the true value.

```python
import numpy as np
from scipy.optimize import minimize

t = np.linspace(0, 2, 9)

def net(p, t):
    w, b, v, c = p[0:4], p[4:8], p[8:12], p[12]
    h = np.tanh(np.multiply.outer(t, w) + b)
    return h @ v + c, (1 - h ** 2) @ (v * w)              # y and dy/dt

def loss(p):
    y, dy_dt = net(p, t)
    return np.mean((dy_dt + y) ** 2) + (net(p, 0.0)[0] - 1) ** 2

p0 = np.random.default_rng(0).normal(0, 1, 13)
p = minimize(loss, p0, method="L-BFGS-B").x               # SciPy estimates weight gradients
print(net(p, np.array([1.0, 4.0]))[0].round(4), np.exp(-np.array([1.0, 4.0])).round(4))
```

### An inverse problem

For an inverse problem, change the equation to dy/dt = −k × y with k unknown, and give the network three measurements: y = 0.67, 0.45 and 0.20 at t = 0.5, 1 and 2. These came from k = 0.8, rounded to two decimals. Training k along with the 13 weights, with the measurements as a third loss term, gives k = 0.801.

## Common questions

**Why does the error grow outside the training range?** The loss only contains points between 0 and 2. Beyond them nothing ties the network to the equation, so it simply continues its curve, and at $t = 4$ it is off by 17%.

**Is a loss near 0 proof that the answer is right?** No. It says the equation nearly holds at the 9 collocation points. That is why the result is also compared with the exact solution at other points.

**Is the PINN better than Euler's method here?** No. A classical solver gets this accuracy with far less work. PINNs are worth it for inverse problems, like finding $k$ from three measurements, and for problems where a mesh is hard to build.

**How does the network find $k$?** $k$ is treated as one more weight. The loss has a third term for the three measurements, and only a $k$ near 0.8 lets the network fit both the measurements and the equation, so training ends at 0.801.
