## Tasks and Metrics

| Task | Output | Metric |
| --- | --- | --- |
| Classification (sentiment, topic) | one label | accuracy, macro-$F_1$ |
| Sequence labelling (POS, NER) | one label per token | entity-level $F_1$ |
| Question answering (extractive) | a span | exact match, token $F_1$ |
| Machine translation | a sequence | BLEU, chrF, COMET |
| Summarization | a sequence | ROUGE, BERTScore |
| Natural language inference | 3-way label | accuracy |

**BLEU** measures $n$-gram precision against reference translations:

$$
\text{BLEU} = \text{BP}\cdot\exp\!\left(\sum_{n=1}^{4}w_n\log p_n\right), \qquad w_n = \tfrac14,
$$

with **modified precision** $p_n$ (each reference $n$-gram can be matched only as many times as it appears, which stops a candidate of "the the the the" scoring 1.0) and a **brevity penalty**

$$
\text{BP} = \begin{cases}1 & c > r\\ e^{1-r/c} & c\le r\end{cases}
$$

for candidate length $c$ and reference length $r$. The BP exists because precision alone rewards short output: emit only the words you are sure of and precision is high.

BLEU's weaknesses: it ignores synonyms and paraphrase entirely, it correlates only moderately with human judgement at the sentence level, and it is not comparable across tokenizations (use sacrebleu, which fixes the tokenization).

**ROUGE** is the recall-oriented analogue for summarization: ROUGE-N is $n$-gram recall, ROUGE-L uses the longest common subsequence. Recall is the right orientation because a summary's failure mode is omission.

**Learned metrics**: BERTScore (cosine similarity of contextual embeddings), and COMET and BLEURT, which train a scoring model on top of such embeddings. They correlate much better with human judgement, at the cost of being model-dependent and not comparable across versions.

### Worked Example: BLEU by hand

**BLEU by hand.**

Candidate: `the cat sat on the mat`
Reference: `the cat is on the mat`

Both have 6 tokens, so $c = r = 6$ and $\text{BP} = 1$.

**Unigrams.** Candidate counts: `the`×2, `cat`, `sat`, `on`, `mat`. Reference counts: `the`×2, `cat`, `is`, `on`, `mat`. Clipped matches: `the` $\min(2,2)=2$, `cat` 1, `sat` 0, `on` 1, `mat` 1 → **5/6**.

**Bigrams.** Candidate: `the cat`, `cat sat`, `sat on`, `on the`, `the mat`. Reference: `the cat`, `cat is`, `is on`, `on the`, `the mat`. Matches: `the cat`, `on the`, `the mat` → **3/5**.

**Trigrams.** Candidate: `the cat sat`, `cat sat on`, `sat on the`, `on the mat`. Reference: `the cat is`, `cat is on`, `is on the`, `on the mat`. Matches: `on the mat` → **1/4**.

**4-grams.** Candidate: `the cat sat on`, `cat sat on the`, `sat on the mat`. Reference: `the cat is on`, `cat is on the`, `is on the mat`. Matches: **0/3**.

Since $p_4 = 0$, **BLEU-4 = 0**: a single missing 4-gram order zeroes the whole score, because the geometric mean of $\log$ precisions has a $\log 0$ term. This is why sentence-level BLEU is nearly useless and why smoothing (adding a small count to each order) is standard for short segments.

**BLEU-2** for comparison:

$$
\exp\!\left(\tfrac12\ln\tfrac56 + \tfrac12\ln\tfrac35\right) = \exp(-0.3466) = 0.7071 ,
$$

which is $\sqrt{(5/6)(3/5)} = \sqrt{0.5}$ ✓, the geometric mean, as the formula says.

**ROUGE-1 recall** (the summarization orientation): 5 of the reference's 6 unigrams are covered → $0.8333$. Notice this is higher than BLEU's picture of the same pair, because recall does not penalize the wrong word "sat", only the missing word "is".

## Evaluation

**Inception Score.**

$$
\text{IS} = \exp\Big(\mathbb{E}_x\big[D_{\text{KL}}(p(y\mid x)\Vert p(y))\big]\Big),
$$

rewarding confident per-image classification (each $p(y\mid x)$ peaked) and diverse classes overall ($p(y)$ near uniform). Deprecated: it never looks at the real data at all, so a model that generates one perfect image per ImageNet class scores near-perfectly.

**Fréchet Inception Distance** is the standard. Embed real and generated images with an Inception network, fit a Gaussian to each set, and compute the Fréchet distance:

$$
\text{FID} = \lVert\mu_r-\mu_g\rVert^2 + \operatorname{Tr}\Big(\Sigma_r+\Sigma_g-2(\Sigma_r\Sigma_g)^{1/2}\Big).
$$

Lower is better, and 0 means the two Gaussians match. It compares against real data, correlates reasonably with human judgement, and is sensitive to both quality and diversity.

**FID's problems**, which matter:
- **Biased by sample count.** FID computed on 1k samples is systematically higher than on 50k. Always report $n$: 50k is the convention.
- **Assumes Gaussian embeddings**, which they are not.
- **Depends on the Inception network**, which was trained on ImageNet, so it measures ImageNet-like features and can be gamed.
- **Insensitive to memorization.** A model that reproduces training images exactly gets FID $\approx0$.

**Precision and recall** separate the two failure modes: precision is the fraction of generated samples lying in the real data's support (quality), recall is the fraction of real data covered by the model (diversity). Mode collapse shows as high precision and low recall, invisible in FID alone if the collapsed samples are good.

**For likelihood models**, report bits per dimension: $\text{BPD} = -\log_2p(x)/d$. Not comparable to GANs, which have no likelihood.

### Worked Example: FID, precision and recall

**FID, computed on a toy example.** Two-dimensional embeddings. Real: $\mu_r = (0,0)$, $\Sigma_r = I$. Generated: $\mu_g = (1,0)$, $\Sigma_g = 0.5I$.

$$
\lVert\mu_r-\mu_g\rVert^2 = 1 .
$$
$$
(\Sigma_r\Sigma_g)^{1/2} = (0.5I)^{1/2} = 0.7071I, \qquad
\operatorname{Tr}(\Sigma_r + \Sigma_g - 2(\Sigma_r\Sigma_g)^{1/2}) = \operatorname{Tr}\big((1+0.5-1.4142)I\big) = 2(0.0858) = 0.1716 .
$$
$$
\text{FID} = 1 + 0.1716 = 1.17 .
$$

The mean shift contributes 1 and the variance mismatch 0.17. FID is dominated by the mean difference here, which is the usual case and part of why it is insensitive to some diversity failures.

**FID's sample-count bias.** The same model evaluated at different $n$ (illustrative values, since the size of the bias depends on the model):

| samples | FID |
| --- | --- |
| 1,000 | 42.3 |
| 5,000 | 18.7 |
| 10,000 | 12.1 |
| 50,000 | 7.4 |

Nothing about the model changed. With only 1000 samples the covariance estimate $\Sigma_g$ is noisy, and FID's finite-sample bias is present at any sample count, so its size depends on the generator being evaluated and even two papers that both report 10k are not strictly comparable (Chong and Forsyth, CVPR 2020). Comparing a paper's FID at 10k against another's at 50k is comparing sample sizes, not models, which is why the convention exists and why it should be stated.

**Precision and recall separate what FID conflates.** Three illustrative models on the same data:

| model | FID | precision | recall | diagnosis |
| --- | --- | --- | --- | --- |
| A | 12.0 | 0.78 | 0.62 | balanced |
| B | 11.8 | 0.95 | 0.21 | **mode collapse**: beautiful, narrow |
| C | 12.2 | 0.55 | 0.81 | broad, with artifacts |

All three have essentially the same FID, and they are completely different models. B produces gorgeous samples from a fifth of the distribution, the classic GAN failure, and FID barely notices because its high quality offsets its poor coverage in the Gaussian fit. Report both numbers.

**The memorization blind spot.** A model that emits training images verbatim achieves $\text{FID} \approx 0$, perfect precision, and high recall. Every distributional metric says it is the best model ever produced. The check is a nearest-neighbour lookup from each generated sample into the training set: if the minimum distance is near zero for a meaningful fraction, the model is retrieving rather than generating. This is not hypothetical: measurable memorization has been demonstrated in deployed diffusion models, and it carries real privacy and copyright consequences.

## Failure Modes

**Metric mismatch.** Optimizing BLEU produces literal, low-risk translations. Optimizing ROUGE produces extractive summaries that copy sentences. If the metric rewards the wrong thing, the model will deliver the wrong thing precisely.

## From Scratch

```python
import math
from collections import Counter
import numpy as np
from scipy.linalg import sqrtm


def modified_precision(candidate, reference, n):
    """Each reference n-gram can be matched only as many times as it occurs,
    which is what stops 'the the the the' scoring 1.0."""
    def grams(seq):
        return Counter(tuple(seq[i:i + n]) for i in range(len(seq) - n + 1))
    c, r = grams(candidate), grams(reference)
    match = sum(min(cnt, r[g]) for g, cnt in c.items())
    return match / max(sum(c.values()), 1)


def bleu(candidate, reference, max_n=4):
    c, r = len(candidate), len(reference)
    bp = 1.0 if c > r else math.exp(1 - r / max(c, 1))
    ps = [modified_precision(candidate, reference, n) for n in range(1, max_n + 1)]
    if min(ps) == 0:
        return 0.0                      # one missing order zeroes the whole score
    return bp * math.exp(sum(math.log(p) for p in ps) / max_n)


def rouge_n(candidate, reference, n=1):
    """Recall-oriented: a summary's failure mode is omission, not wrong words."""
    def grams(seq):
        return Counter(tuple(seq[i:i + n]) for i in range(len(seq) - n + 1))
    c, r = grams(candidate), grams(reference)
    match = sum(min(cnt, c[g]) for g, cnt in r.items())
    return match / max(sum(r.values()), 1)


def inception_score(probs, splits=10):
    """Never looks at the real data -- which is exactly why it is deprecated."""
    scores = []
    n = len(probs)
    for k in range(splits):
        part = probs[k * n // splits:(k + 1) * n // splits]
        py = part.mean(0, keepdims=True)
        kl = (part * (np.log(part + 1e-12) - np.log(py + 1e-12))).sum(1)
        scores.append(np.exp(kl.mean()))
    return float(np.mean(scores)), float(np.std(scores))


def fid(real_feats, gen_feats):
    """Fits a Gaussian to each embedding set. Biased by sample count, so always
    report n -- 50k is the convention."""
    mu_r, mu_g = real_feats.mean(0), gen_feats.mean(0)
    cov_r = np.cov(real_feats, rowvar=False)
    cov_g = np.cov(gen_feats, rowvar=False)
    covmean = sqrtm(cov_r @ cov_g)
    if np.iscomplexobj(covmean):
        covmean = covmean.real
    return float(((mu_r - mu_g) ** 2).sum() + np.trace(cov_r + cov_g - 2 * covmean))


def precision_recall(real_feats, gen_feats, k=5):
    """Separates the two failure modes FID conflates: precision = quality,
    recall = coverage. Mode collapse is high precision, low recall."""
    def knn_radii(X, k):
        d = np.sqrt(((X[:, None, :] - X[None, :, :]) ** 2).sum(-1))
        np.fill_diagonal(d, np.inf)
        return np.sort(d, axis=1)[:, k - 1]

    def in_manifold(A, B, radii_B):
        d = np.sqrt(((A[:, None, :] - B[None, :, :]) ** 2).sum(-1))
        return (d <= radii_B[None, :]).any(1).mean()

    r_real = knn_radii(real_feats, k)
    r_gen = knn_radii(gen_feats, k)
    return {"precision": float(in_manifold(gen_feats, real_feats, r_real)),
            "recall": float(in_manifold(real_feats, gen_feats, r_gen))}


def bits_per_dim(log_prob_nats, d):
    """The likelihood-model metric. Not comparable to GANs, which have none."""
    return -log_prob_nats / (d * np.log(2))


def memorization_check(gen_feats, train_feats, threshold=1e-3):
    """FID is BLIND to this: a model reproducing the training set scores ~0."""
    d = np.sqrt(((gen_feats[:, None, :] - train_feats[None, :, :]) ** 2).sum(-1))
    return float((d.min(1) < threshold).mean())
```

## Using the Library

```python
import torch
from torchmetrics.image.fid import FrechetInceptionDistance
import evaluate

# Text metrics.
bleu = evaluate.load("sacrebleu")            # fixed tokenization: comparable across papers
bleu.compute(predictions=preds, references=[[r] for r in refs])
evaluate.load("rouge").compute(predictions=preds, references=refs)

# Image metrics.
fid = FrechetInceptionDistance(feature=2048)
fid.update(real_uint8_images, real=True)
fid.update(fake_uint8_images, real=False)
fid.compute()                # report the sample count alongside; 50k is standard

# Precision/recall, which FID conflates.
#   pip install prdc
from prdc import compute_prdc
compute_prdc(real_features, fake_features, nearest_k=5)
```

Plain `bleu` is tokenizer-dependent, so always use `sacrebleu`, which is why published BLEU scores before its adoption are not comparable across papers.

Always report the number of samples used for FID and the reference statistics used, and check for memorization separately: a model can post a state-of-the-art FID by having overfitted, and no distributional metric will tell you.
