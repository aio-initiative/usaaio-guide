## Overview

[Build a Transformer: 3. Add position](2.33-TF13-transformer-add-position.md) adds a sinusoidal or learned vector to each token, so the model sees $\mathbf{x}_i + \mathbf{p}_i$ and position enters as an *absolute* index. What attention actually needs is almost always **relative**: "the adjective three tokens to my left" is a reusable pattern, while "the adjective at position 417" is not. An absolute scheme forces the model to *learn* relative structure as a derived quantity, separately at every pair of positions.

The step does show that two sinusoidal position vectors compare by offset alone: the dot product of $\mathbf{p}_i$ and $\mathbf{p}_j$ is a sum of terms $\cos(w(i - j))$, one per pair of dimensions. Attention never takes that dot product on its own, though. Queries and keys are made from the sums $\mathbf{x}_i + \mathbf{p}_i$ with $W_Q$ and $W_K$, so a score expands into four terms: content against content, position against position, and two cross terms that pair one token's content with the other token's position. A cross term changes when a token moves, even if its distance to the other token stays the same, and the $W_Q$ and $W_K$ inside the position-against-position term break the cosine identity in general. The From scratch section below measures the result: with a sinusoidal encoding added, scores at one fixed offset differ by up to 2.83.

Absolute schemes also fail past the training length. A learned table that stops at 4096 has no vector for position 5000. Sinusoidal encodings at least produce *something* for any index, since they are a formula rather than a table, but the model has never seen those values and the representations drift out of distribution.

## Relative encodings

The fix that came before RoPE was to stop encoding *where* a token is and encode *how far apart* two tokens are. Attention only ever compares pairs, so absolute indices were never what it needed.

Concretely, a term depending on $i - j$ is added to the attention logit for query $i$ and key $j$:

$$
\text{logit}_{ij} = \frac{\mathbf{q}_i^\top \mathbf{k}_j}{\sqrt{d_k}} + b_{i-j}.
$$

Three choices for $b$ span most of the literature. **Shaw et al.** learn a vector per relative offset and add it into the keys. **T5** simplifies that to a learned scalar per offset added to the logit, sharing one table across all layers. **ALiBi** drops the parameters entirely and uses a fixed linear penalty $b_{i-j} = -m_h\,(i - j)$, with a different slope $m_h$ per head, so some heads attend locally and others stay broad.

What the three share is that the matrix of relative positions is **Toeplitz**, constant along each diagonal, so it depends on the offset between positions and not on where the window sits. Slide the whole window a thousand tokens down the sequence and every logit is unchanged. An absolute encoding has no such guarantee.

One practical problem: the number of distinct offsets grows with sequence length, so a table indexed directly by $i - j$ costs $\mathcal{O}(n)$ parameters and has nothing trained for offsets never seen. The standard answer is **bucketing**. Nearby offsets get their own bucket, distant ones share one on a log scale, on the reasoning that the difference between 3 tokens away and 4 matters and the difference between 300 and 400 does not.

```python
import numpy as np

T, N_BUCKETS, MAX_D = 6, 16, 64

def rel_matrix(t, offset=0):
    idx = np.arange(offset, offset + t)
    return idx[:, None] - idx[None, :]

def bucket(rel, n_buckets=N_BUCKETS, max_distance=MAX_D):
    """Signed log-spaced buckets. Near offsets get their own, far ones share."""
    half = n_buckets // 2                 # one half per direction
    exact = half // 2                     # this many offsets are resolved exactly
    d = np.abs(rel)
    far = exact + (np.log(np.maximum(d, exact) / exact)
                   / np.log(max_distance / exact) * (half - exact)).astype(int)
    idx = np.where(d < exact, d, np.minimum(far, half - 1))
    return np.where(rel < 0, idx, idx + half)

rel = rel_matrix(T)
print(f"Toeplitz (constant on diagonals) : {all(np.unique(np.diag(rel, k)).size == 1 for k in range(-T+1, T))}")
print(f"unchanged by shifting by 1000    : {np.array_equal(rel, rel_matrix(T, 1000))}")

d = np.arange(0, 70)
bd = bucket(d)
print(f"\nbuckets used                     : {bucket(rel).min()} to {bucket(rel).max()} of {N_BUCKETS}")
print(f"monotone in distance             : {bool((np.diff(bd) >= 0).all())}")
print("distance -> bucket (ahead)       :", {int(k): int(v) for k, v in zip(d[:10], bd[:10])})
print(f"distances 40 and 63 share bucket : {bucket(np.array([40]))[0] == bucket(np.array([63]))[0]}")

rng = np.random.default_rng(0)
bias_table = rng.standard_normal(N_BUCKETS)
pos_table = rng.standard_normal((2000, 4))
rel_logits = lambda off: bias_table[bucket(rel_matrix(T, off))]
abs_logits = lambda off: pos_table[off:off + T] @ pos_table[off:off + T].T
print(f"\nrelative bias identical at offset 0 and 1000 : {np.allclose(rel_logits(0), rel_logits(1000))}")
print(f"absolute embeddings, same comparison         : {np.allclose(abs_logits(0), abs_logits(1000))}")
```

Read the last two lines together. The relative bias produces identical logits for a window at position 0 and the same window at position 1000, and the absolute embeddings do not. That is why relative schemes extrapolate past the training length at all, and it is the property RoPE below achieves by a different route.

Read the bucket table too. Offsets 0 through 3 each get their own bucket, then 4 through 7 collapse into one, and by the time the offset reaches 40 the resolution is gone entirely. That coarsening is deliberate and it is also the cost: a model using this cannot tell 40 tokens back from 63 tokens back, whatever the text needed.

An additive bias works with a KV cache. In general it depends on the query position, so it cannot be folded into a cached key, but it never needs to be. When query $t$ arrives, its bias against cached key $j$ depends on $t - j$ alone, so the step computes one number per cached key and adds it to the scores. The cached keys stay plain and nothing cached is recomputed. Decoding one token at a time this way matches full causal attention exactly:

```python
def alibi_full(Q, K, V, slope):
    """Causal attention with an ALiBi penalty, every query at once."""
    n, d = Q.shape
    i, j = np.arange(n)[:, None], np.arange(n)[None, :]
    S = Q @ K.T / np.sqrt(d) - slope * (i - j)
    S = np.where(j <= i, S, -np.inf)
    W = np.exp(S - S.max(axis=1, keepdims=True))
    return W / W.sum(axis=1, keepdims=True) @ V

def alibi_cached(Q, K, V, slope):
    """One query per step against a growing cache of plain, unmodified keys."""
    k_cache, v_cache, out = [], [], []
    for t in range(len(Q)):
        k_cache.append(K[t])
        v_cache.append(V[t])
        bias = -slope * (t - np.arange(t + 1))       # made when query t arrives
        s = np.array(k_cache) @ Q[t] / np.sqrt(Q.shape[1]) + bias
        w = np.exp(s - s.max())
        out.append(w / w.sum() @ np.array(v_cache))
    return np.array(out)

rng = np.random.default_rng(1)
Q, K, V = rng.standard_normal((3, 16, 8))
full, cached = alibi_full(Q, K, V, 0.25), alibi_cached(Q, K, V, 0.25)
print(f"cached decode matches full attention : {np.allclose(full, cached, rtol=0, atol=1e-12)}")
print(f"bias entries computed per new token  : {len(Q)} at the last step, one per cached key")
```

```output
cached decode matches full attention : True
bias entries computed per new token  : 16 at the last step, one per cached key
```

T5 and ALiBi models decode from a cache in exactly this way. The cost of a bias is where it has to go: between the scores and the softmax, inside the attention computation. A fused kernel such as FlashAttention needs a variant that knows about it, and a learned table adds a lookup to the innermost loop. Shaw et al.'s form costs more again, since its term $\mathbf{q}_i^\top \mathbf{a}_{i-j}$ is a second dot product for every query-key pair. The next section moves position out of the attention computation altogether.

## Rotary position embedding

RoPE takes a different route. Rather than *adding* position information to the vector, it **rotates** the vector by an angle proportional to its position, and applies this to $\mathbf{q}$ and $\mathbf{k}$ only: not to $\mathbf{v}$, and not to the residual stream. Queries and keys meet in a dot product, where the two rotations cancel down to the offset, as shown below. A rotated value would carry its own absolute angle straight into the output.

### The two-dimensional case

Take $d = 2$ and let $R_m$ be rotation by angle $m\theta$:

$$
R_m = \begin{pmatrix} \cos m\theta & -\sin m\theta \\
\sin m\theta & \cos m\theta \end{pmatrix}
$$

Place the query at position $m$ and the key at position $n$, and compute their attention score:

$$
\langle R_m \mathbf{q},\, R_n \mathbf{k} \rangle
= (R_m \mathbf{q})^\top (R_n \mathbf{k})
= \mathbf{q}^\top R_m^\top R_n \mathbf{k}
$$

Rotations are orthogonal, so $R_m^\top = R_m^{-1} = R_{-m}$, and composing rotations adds their angles:

$$
= \mathbf{q}^\top R_{-m} R_n \mathbf{k}
= \boxed{\mathbf{q}^\top R_{n-m} \mathbf{k}}
$$

The absolute positions have **cancelled**. The score depends on $m$ and $n$ only through the difference $n - m$. Position is applied absolutely (each vector rotated by its own index, which is cheap and needs no pairwise bookkeeping) yet the quantity attention consumes is purely relative. That is the entire idea, and everything else is bookkeeping.

### Scaling to $d$ dimensions

Split the $d$-dimensional vector into $d/2$ consecutive pairs and rotate pair $i$ by $m\theta_i$, with frequencies on the same geometric ladder as the speeds $w$ of the sinusoidal encoding in [Build a Transformer: 3. Add position](2.33-TF13-transformer-add-position.md):

$$
\theta_i = \text{base}^{-2i/d}, \qquad \text{base} = 10000
$$

The full rotation is block-diagonal with $d/2$ rotation blocks, so the cancellation above applies within each block independently, and the total score is a sum of terms each depending only on $n - m$.

The frequency ladder is what lets one mechanism cover many scales. At $d = 128$:

| $i$ | $\theta_i$ | wavelength |
| --- | --- | --- |
| 0 | $1.0$ | ~6 tokens |
| 31 | $1.15 \times 10^{-2}$ | ~544 tokens |
| 63 | $1.15 \times 10^{-4}$ | ~54,410 tokens |

Early pairs spin fast and resolve neighboring tokens sharply. The slowest pairs spin so slowly that across a 4096-token window pair 63 turns through only 0.075 of a revolution (0.473 radians), and pair 62 only 0.087. That does not make them a record of absolute position. The derivation above holds pair by pair, so a slow pair's term depends on $n - m$ alone, like every other. What is different is how little the term moves: rotating by an angle $\phi$ changes a pair's contribution by at most $|\phi|\,\|\mathbf{q}\|\|\mathbf{k}\|$, and pair 63 has turned only $0.0115$ radians at an offset of 100 tokens. A head can use the slow pairs to match keys on content at almost any distance and the fast pairs to tell neighbors apart. Barbero et al. (2024) found that Gemma 7B greatly prefers its lowest frequencies, which they suspect carry semantic information.

### Why it displaced the alternatives

* **Relative by construction**, with no extra dot product per query-key pair as in Shaw et al.
* **No parameters at all**. It is a fixed function of position.
* **Full resolution at every offset.** The bucketing above cannot distinguish 40 tokens back from 63. A rotation angle is $\theta_i$ times the offset, so every offset gets a distinct value and no resolution is traded away.
* **Invisible to the attention kernel.** Keys are rotated once when computed and cached in rotated form, and from then on attention is ordinary attention. A bias scheme caches just as well, as the check above showed, but its bias has to be added inside the kernel. RoPE runs through any attention implementation unmodified.
* **Scores decay with distance**, loosely and on average, which is a reasonable prior for language.

Caching rotated keys has one wrinkle, and it is the reason [MLA](4.10-TF28-efficient-sharing-keys-and-values.md) carries a *decoupled* RoPE key: RoPE is position-dependent while MLA's up-projection is not, and the two do not commute, so the rotated part must be stored separately from the compressed latent. A streaming cache that keeps sink tokens and evicts the middle, as the sink-tokens practice below does, builds on the eviction ideas taught in [Sparse attention, sinks and eviction](4.13-TF31-sparse-attention-sinks-and-eviction.md).

## Relative position in linear attention

[Linear attention](4.12-TF30-efficient-linear-attention.md) never forms the $n \times n$ score matrix. It keeps a running state $S_t = \sum_{j \le t} \varphi(\mathbf{k}_j)\mathbf{v}_j^\top$, which works because every term depends on the key alone. A relative weight $w(i - j)$ multiplying each similarity survives only if it splits the same way, $w(i - j) = f(i)\,g(j)$, one factor for the query and one for the key.

That requirement pins $w$ down. Setting $j = i$ gives $g(i) = w(0)/f(i)$, so $w(i - j) = w(0)\,f(i)/f(j)$. At an offset of 1 this reads $f(j + 1) = \frac{w(1)}{w(0)}\,f(j)$, so $f$ is geometric and $w(k) = w(0)\,r^k$. **The only relative weights that factorize are exponentials in the offset.** A real ratio $0 < r < 1$ is a decay. A complex ratio of modulus 1 is a rotation by a fixed angle per step. Those are the two schemes that carry over, and they are ALiBi and RoPE:

* **ALiBi becomes a decay.** Its penalty inside a softmax is $e^{s - m(i-j)} = e^{s}\,(e^{-m})^{i-j}$, a multiplicative decay with $\gamma = e^{-m}$. In linear attention that weight is one change to the recurrence, $S_t = \gamma S_{t-1} + \varphi(\mathbf{k}_t)\mathbf{v}_t^\top$ and $\mathbf{z}_t = \gamma\,\mathbf{z}_{t-1} + \varphi(\mathbf{k}_t)$, a fixed decay by age. A different $\gamma$ per head gives heads different ranges, as ALiBi's slopes do.
* **RoPE rotates the features.** Rotate $\varphi(\mathbf{q}_i)$ by $R_i$ and $\varphi(\mathbf{k}_j)$ by $R_j$, and the numerator's weight depends on $i - j$ alone, while the running state still factorizes because $R_j$ travels with the key. Su et al. rotate the numerator only. Rotated features can have negative dot products, and a plain denominator keeps the normalizer positive.

A learned table of biases, T5's or Shaw et al.'s, is an arbitrary function of the offset with no such split, so it needs exactly the matrix that linear attention exists to avoid. Both carried-over schemes check out against the $n \times n$ form they replace:

```python
def elu1(x):
    return np.where(x > 0, x + 1.0, np.exp(x))           # elu(x) + 1, strictly positive

def decayed_linear(Q, K, V, gamma):
    """Causal linear attention weighted by gamma^(i-j), as a running state."""
    S = np.zeros((K.shape[1], V.shape[1]))
    z = np.zeros(K.shape[1])
    out = []
    for t in range(len(Q)):
        S = gamma * S + np.outer(elu1(K[t]), V[t])
        z = gamma * z + elu1(K[t])
        out.append(elu1(Q[t]) @ S / (elu1(Q[t]) @ z))
    return np.array(out)

def decayed_quadratic(Q, K, V, gamma):
    """The same weights written out as an n x n matrix."""
    n = len(Q)
    i, j = np.arange(n)[:, None], np.arange(n)[None, :]
    W = (elu1(Q) @ elu1(K).T) * np.where(j <= i, gamma ** (i - j), 0.0)
    return W / W.sum(axis=1, keepdims=True) @ V

rng = np.random.default_rng(0)
Q, K, V = rng.standard_normal((3, 12, 8))
print(f"decayed recurrence equals its n x n form   : {np.allclose(decayed_linear(Q, K, V, 0.9), decayed_quadratic(Q, K, V, 0.9))}")

# ALiBi is the same decay seen from softmax: exp(s - m(i-j)) = exp(s) * (e^-m)^(i-j).
m, n = 0.25, 12
i, j = np.arange(n)[:, None], np.arange(n)[None, :]
S = Q @ K.T
alibi = np.where(j <= i, np.exp(S - m * (i - j)), 0.0)
decay = np.where(j <= i, np.exp(S) * np.exp(-m) ** (i - j), 0.0)
print(f"ALiBi slope 0.25 is a decay of gamma = {np.exp(-m):.4f} : {np.allclose(alibi, decay)}")

def rotate_pairs(x, pos, base=10000.0):
    """RoPE on the last axis: rotate coordinate pair p by angle pos * base^(-2p/d)."""
    d = x.shape[-1]
    theta = base ** (-2.0 * np.arange(d // 2) / d)
    c, s = np.cos(pos * theta), np.sin(pos * theta)
    out = np.empty_like(x)
    out[..., 0::2] = x[..., 0::2] * c - x[..., 1::2] * s
    out[..., 1::2] = x[..., 0::2] * s + x[..., 1::2] * c
    return out

def rope_linear(Q, K, V):
    """RoFormer's recipe: rotate the features in the numerator, keep the denominator plain."""
    pos = np.arange(len(Q))[:, None]
    fq, fk = elu1(Q), elu1(K)
    rq, rk = rotate_pairs(fq, pos), rotate_pairs(fk, pos)
    S = np.cumsum(rk[:, :, None] * V[:, None, :], axis=0)        # running sum of rotated k v^T
    z = np.cumsum(fk, axis=0)                                       # running sum of plain k
    return np.einsum("td,tde->te", rq, S) / np.einsum("td,td->t", fq, z)[:, None]

def rope_quadratic(Q, K, V):
    pos = np.arange(len(Q))[:, None]
    num = rotate_pairs(elu1(Q), pos) @ rotate_pairs(elu1(K), pos).T
    den = elu1(Q) @ elu1(K).T
    mask = np.tri(len(Q), dtype=bool)
    return np.where(mask, num, 0.0) @ V / np.where(mask, den, 0.0).sum(axis=1, keepdims=True)

print(f"RoPE-in-linear recurrence equals n x n form : {np.allclose(rope_linear(Q, K, V), rope_quadratic(Q, K, V))}")
q1, k1 = elu1(Q[0]), elu1(K[0])
print("rotated feature score at offset 3, three places:",
      "  ".join(f"{rotate_pairs(q1, a) @ rotate_pairs(k1, a - 3):.6f}" for a in (3, 50, 900)))
```

```output
decayed recurrence equals its n x n form   : True
ALiBi slope 0.25 is a decay of gamma = 0.7788 : True
RoPE-in-linear recurrence equals n x n form : True
rotated feature score at offset 3, three places: 5.049575  5.049575  5.049575
```

The last line is the relative property surviving the trip: the rotated features score the same at positions 3, 50 and 900 for the same offset of 3. The decay encodes position through age alone. At $\gamma = 0.9$, the value in the check, a key 10 tokens back keeps $0.9^{10} = 0.35$ of its undecayed weight and one 20 back keeps $0.12$, and that share only shrinks as the sequence grows. The rotation keeps every key reachable and gives up positivity in the numerator instead.

## Stretching the context

Because RoPE is a formula, a model *can* be evaluated at positions beyond its training length, but the angles $m\theta_i$ land outside the range ever seen, and quality collapses. The failure is abrupt rather than graceful: perplexity is normal up to the trained length and explodes just past it.

**Unseen angles.** Pair $i$ turns by $\theta_i$ radians per token, so in a context of $L$ tokens its largest angle is about $L\theta_i$, and an angle past $2\pi \approx 6.28$ wraps round to one below it. Take the $d = 128$ ladder above and a training length of 4096. Pairs 0 to 45 have wavelengths shorter than 4096 tokens, so each completes at least one turn in training, and no later position can show it an angle it has not met. Pairs 46 to 63 never complete a turn. Training shows each of them only the arc from 0 to $4096\,\theta_i$ and never the rest of the circle, which is $2\pi - 5.46 = 0.82$ radians for pair 46 and $5.81$ radians for pair 63.

**A longer context.** Now run the model on 32,768 tokens, $s = 8$ times its training length. The table gives the largest angle four of the pairs reach in each setting, in radians:

| Pair $i$ | Wavelength (tokens) | Training, 4096 tokens | 32,768 tokens, no change | Position interpolation | NTK-aware scaling |
| --- | --- | --- | --- | --- | --- |
| 0 | 6.3 | 4,096 | 32,768 | 4,096 | 32,768 |
| 46 | 4,712 | 5.46 | 43.7 | 5.46 | 9.57 |
| 54 | 14,900 | 1.73 | 13.8 | 1.73 | 2.32 |
| 63 | 54,410 | 0.473 | 3.78 | 0.473 | 0.473 |

With no change, pairs 46 to 59 pass $2\pi$ and so sweep through all of their unseen arc, and pair 63 reaches 3.78 radians against 0.473.

**Position interpolation.** Each position $m$ is replaced by $m/s$ before the rotation, so token 32,768 gets the rotation of position 4096, and the interpolation column matches the training column row for row. The cost is spacing. Consecutive tokens now sit 0.125 positions apart, so on pair 0 neighbors differ by 0.125 radians where training always had exactly 1. The model has to separate neighbors by differences 8 times finer than any it learned from, and it is fine-tuned briefly to adjust.

**NTK-aware scaling.** The positions are left alone and the base 10,000 is replaced by $10{,}000 \cdot s^{d/(d-2)} = 10{,}000 \cdot 8^{128/126} \approx 82{,}685$. Pair $i$'s frequency is then multiplied by $s^{-2i/(d-2)}$: by 1 at pair 0, by $0.219$ at pair 46 and by exactly $1/8$ at pair 63, the value the exponent $d/(d-2)$ is chosen to give. Pair 0 keeps its full radian between neighbors, and since it completed turns in training, all its angles are familiar. Pair 63 tops out at 0.473 radians, as in training. Every pair from 46 to 62 lands past its training column. Pair 54 reaches 2.32 radians against 1.73, about 0.6 radians into its unseen arc, and pair 46 reaches 9.57, more than a full turn, so it crosses the whole 0.82 radians it never saw.

**YaRN** combines both: interpolate the low-frequency dimensions, leave the high-frequency ones alone, ramp between them, and apply a temperature correction to the attention logits to compensate for the changed distribution. Ask how many full rotations pair $i$, with wavelength $\lambda_i$, completes within the *trained* window, $r_i = n_{\text{train}}/\lambda_i$. If $r_i > \beta = 32$ (many rotations, a fast, local pair), leave it alone. If $r_i < \alpha = 1$ (less than one rotation, a slow, global pair), interpolate it fully. In between, ramp linearly. Peng et al. found $\alpha = 1$ and $\beta = 32$ to work well for the LLaMA family and tune them per model. At $n_{\text{train}} = 4096$: pair 0 has $\lambda = 6.3$, so $r = 650$, untouched. Pair 48 has $\lambda = 6283$, so $r = 0.65 < 1$, fully interpolated. Pair 32 has $\lambda = 628$, $r = 6.5$, partially interpolated, at ramp $= (6.5-1)/(32-1) = 0.177$. YaRN also applies a temperature to the attention logits, $\sqrt{1/t} = 0.1\ln s + 1$, which is about $1.208$ at $s = 8$, compensating for the fact that interpolated positions produce a slightly different score distribution than the model was trained on.

Perplexity on long documents is a weak test: most tokens are predictable from the last few hundred, so a model that ignores everything beyond 4k still scores well.

**Needle in a haystack.** Insert a specific fact at a known depth in a long document and ask for it. Sweeps over depth and length produce a heat map, and a badly extended model shows a clear band of failure in the middle depths. It attends to the beginning and the end and loses the middle.

**Long-range retrieval and reasoning benchmarks** (RULER, LongBench) test use of distant information in tasks harder than single-fact recall.

The general pattern to watch for: **effective context is shorter than advertised context**. Of 17 models that all claim context sizes of 32K tokens or greater, only half maintained satisfactory performance at 32K on RULER (Hsieh et al., 2024), and the gap is precisely what these evaluations expose.

A fourth approach is simply to train with a larger base from the start, which lengthens every wavelength and makes long context native rather than retrofitted.

Evaluate a stretched context with tasks that require information at a controlled distance, and re-check short-context quality and retrieval from a known depth.

## From scratch

The claim is exact and easy to test: the score depends only on $n - m$. Here is RoPE in eight lines, checked at one fixed offset from positions spanning three orders of magnitude.

```python
import numpy as np

def rope(x, pos, base=10000.0):
    """Rotate consecutive coordinate pairs of x by an angle pos * theta_i."""
    d = x.shape[-1]
    i = np.arange(d // 2)
    theta = base ** (-2.0 * i / d)
    ang = pos * theta
    c, s = np.cos(ang), np.sin(ang)
    even, odd = x[..., 0::2], x[..., 1::2]
    out = np.empty_like(x)
    out[..., 0::2] = even * c - odd * s
    out[..., 1::2] = even * s + odd * c
    return out

rng = np.random.default_rng(0)
d = 8
q, k = rng.normal(size=d), rng.normal(size=d)

for m, n in [(5, 2), (10, 7), (100, 97), (1000, 997)]:
    print(f"  m={m:>4} n={n:>4} (offset {n-m})   score = {rope(q, m) @ rope(k, n):.6f}")
print(f"  computed directly at (3, 0):        score = {rope(q, 3) @ rope(k, 0):.6f}")
```

```output
  m=   5 n=   2 (offset -3)   score = -1.586475
  m=  10 n=   7 (offset -3)   score = -1.586475
  m= 100 n=  97 (offset -3)   score = -1.586475
  m=1000 n= 997 (offset -3)   score = -1.586475
  computed directly at (3, 0):        score = -1.586475
```

Identical to six decimals at positions 5 and 1000 alike. Nothing about the absolute index survives.

Viewed as a matrix the structure is clearer. Put the *same* $\mathbf{q}$ at every query position and the *same* $\mathbf{k}$ at every key position, so any variation in the scores can only come from position:

```python
L = 6
Q = np.stack([rope(q, m) for m in range(L)])
K = np.stack([rope(k, n) for n in range(L)])
S = Q @ K.T
for m in range(L):
    print("  " + "".join(f"{S[m, n]:<10.4f}" for n in range(L)))

spread = max(np.ptp(np.diagonal(S, offset=o)) for o in range(-(L-1), L))
print(f"\n  max spread within any diagonal: {spread:.2e}")

freq = 10000.0 ** (-2.0 * np.arange(d // 2) / d)
P = np.empty((L, d))
P[:, 0::2] = np.sin(np.arange(L)[:, None] * freq)
P[:, 1::2] = np.cos(np.arange(L)[:, None] * freq)
A = (q + P) @ (k + P).T
spread_add = max(np.ptp(np.diagonal(A, offset=o)) for o in range(-(L-1), L))
print(f"  same check with a sinusoidal encoding added: {spread_add:.2f}")
```

```output
  -1.4680   -1.3091   -1.3804   -1.6284   -1.8336   -1.8122
  -1.6954   -1.4680   -1.3091   -1.3804   -1.6284   -1.8336
  -1.7631   -1.6954   -1.4680   -1.3091   -1.3804   -1.6284
  -1.5865   -1.7631   -1.6954   -1.4680   -1.3091   -1.3804
  -1.3021   -1.5865   -1.7631   -1.6954   -1.4680   -1.3091
  -1.1427   -1.3021   -1.5865   -1.7631   -1.6954   -1.4680

  max spread within any diagonal: 6.66e-16
  same check with a sinusoidal encoding added: 2.83
```

Every diagonal is constant: the matrix is **Toeplitz**, which is exactly what "depends only on $n-m$" means, since a diagonal is the set of cells sharing an offset. The spread within a diagonal is $10^{-16}$: machine epsilon, not approximation.

For contrast, the same experiment with a sinusoidal encoding *added* to the vectors gives a maximum within-diagonal spread of **2.83**: no relative structure at all. Same position information, and the difference is entirely in whether it is applied by addition or by rotation.
