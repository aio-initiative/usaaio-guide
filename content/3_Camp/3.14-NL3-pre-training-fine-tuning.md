## Overview

Modern AI runs on a two-stage recipe. **Stage one, pretraining,** trains one large model on a huge amount of unlabeled text or images, using a *self-supervised* objective: the labels are made from the data itself, with no human annotation needed. **Stage two, adaptation,** specializes that model for a particular task using a small labeled dataset. The expensive, general work happens once, and every later task reuses the model's learned representations instead of learning from scratch.

### Self-supervised pretraining objectives

Two objectives dominate.

**Next-token prediction (autoregressive, GPT-style).** Factor the probability of a token sequence $x_1, x_2, \dots, x_T$ using the chain rule of probability, left to right:

$$
p_\theta(x_1, \dots, x_T) = \prod_{t=1}^{T} p_\theta\!\left(x_t \mid x_1, \dots, x_{t-1}\right).
$$

The model predicts each token from only the tokens *before* it. Training maximizes the likelihood of the real data, which is the same as minimizing the **negative log-likelihood (NLL)** averaged over the sequence:

$$
\mathcal{L}_{\text{AR}}(\theta) = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta\!\left(x_t \mid x_{<t}\right),
\qquad x_{<t} \equiv (x_1, \dots, x_{t-1}).
$$

This is the [cross-entropy loss](1.28-ML9-loss-functions.md) between the model's predicted distribution and the one-hot true next token. Every position supplies its own label, so a sentence of length $T$ gives $T$ training signals at once. The "causal" constraint (position $t$ may not attend to positions $>t$) is what makes the factorization valid.

**Masked language modeling (bidirectional, BERT-style).** Randomly hide a fraction (about 15%) of the tokens with a `[MASK]` symbol and train the model to reconstruct them from the *entire* surrounding context. If $\mathcal{M}$ is the set of masked positions, the objective is

$$
\mathcal{L}_{\text{MLM}}(\theta) = -\sum_{t \in \mathcal{M}} \log p_\theta\!\left(x_t \mid x_{\setminus \mathcal{M}}\right),
$$

where $x_{\setminus \mathcal{M}}$ is the sequence with the masked positions blanked out. The key difference is *directionality*: GPT sees only the past (good for generation), while BERT sees both sides (good for understanding). Both are self-supervised and reduce to cross-entropy on the same [Transformer](2.41-TF21-transformer-stack.md) backbone. Only the objective and the attention mask differ.

### How BERT masks, how T5 corrupts, and how GPT batches

The objectives above leave out three details that matter as soon as you train or use these models.

**BERT does not replace every chosen token with `[MASK]`.** Of the 15% of positions chosen for the loss, 80% become `[MASK]`, 10% become a random token, and 10% are left unchanged. The reason is that `[MASK]` never appears after pretraining. If every target showed `[MASK]`, the model could learn that only those positions need careful predictions. With some targets disguised as ordinary or random tokens, any position might be one, so the model has to keep a good prediction for every token. The loss still looks only at the chosen positions. Hugging Face marks every other position with the label $-100$, the index that cross-entropy ignores.

**T5 hides spans, not single tokens.** It replaces each hidden span with a placeholder called a sentinel token: `<extra_id_0>`, `<extra_id_1>` and so on. The decoder must output each sentinel followed by the tokens it replaced, and end with one more sentinel. Only the hidden spans are generated, so the targets are short and pretraining is cheaper than reconstructing the whole input.

**Batched generation pads on the left.** A decoder generates each next token from the last position of its row. Pad prompts of different lengths on the right and the shorter ones end on a pad, so they continue from the wrong place. Pad on the left and every row ends on its real last token. The attention mask hides the pads, and Hugging Face derives position numbers from the mask, so each prompt still starts at position 0. Set `tokenizer.padding_side = "left"` for generation. GPT-2 has no pad token at all, and the usual fix is to reuse its end-of-text token as the pad. Training is different: with right padding, causal attention means no real token ever sees the pads after it, and labels of $-100$ keep them out of the loss.

```python
import numpy as np

def mask_for_mlm(ids, vocab_size, mask_id, rng, p=0.15):
    """BERT's rule: choose 15% of positions, then 80% become [MASK], 10% a random token, 10% stay."""
    ids = ids.copy()
    labels = np.full_like(ids, -100)                 # -100 means "no loss at this position"
    chosen = rng.random(ids.shape) < p
    labels[chosen] = ids[chosen]                     # the loss only looks at chosen positions
    u = rng.random(ids.shape)
    ids[chosen & (u < 0.8)] = mask_id
    swap = chosen & (u >= 0.8) & (u < 0.9)
    ids[swap] = rng.integers(5, vocab_size, swap.sum())
    return ids, labels

rng = np.random.default_rng(0)
original = rng.integers(5, 30000, size=(64, 512))
inputs, labels = mask_for_mlm(original, 30000, mask_id=4, rng=rng)
chosen = labels != -100
print(f"chosen for the loss : {chosen.mean():.3f}")
print(f"  replaced by [MASK]: {(inputs[chosen] == 4).mean():.3f}")
print(f"  replaced at random: {((inputs[chosen] != 4) & (inputs[chosen] != original[chosen])).mean():.3f}")
print(f"  left unchanged    : {(inputs[chosen] == original[chosen]).mean():.3f}")

def span_corrupt(tokens, spans):
    """T5-style: replace each (start, length) span by a sentinel. The target lists the sentinels and what they hid."""
    inp, tgt, pos = [], [], 0
    for k, (start, length) in enumerate(spans):
        inp += tokens[pos:start] + [f"<extra_id_{k}>"]
        tgt += [f"<extra_id_{k}>"] + tokens[start:start + length]
        pos = start + length
    return inp + tokens[pos:], tgt + [f"<extra_id_{len(spans)}>"]

inp, tgt = span_corrupt("the cat sat on the warm mat by the door".split(), [(1, 2), (5, 2)])
print("\nT5 input :", " ".join(inp))
print("T5 target:", " ".join(tgt))

pad = 0
prompts = [[15, 27, 42], [15, 99]]                   # two prompts of different lengths
T = max(len(p) for p in prompts)
right = np.array([p + [pad] * (T - len(p)) for p in prompts])
left = np.array([[pad] * (T - len(p)) + p for p in prompts])
print(f"\nright padding {right.tolist()}: generation continues from {right[:, -1].tolist()}")
print(f"left padding  {left.tolist()}: generation continues from {left[:, -1].tolist()}")
```

```output
chosen for the loss : 0.152
  replaced by [MASK]: 0.791
  replaced at random: 0.102
  left unchanged    : 0.106

T5 input : the <extra_id_0> on the <extra_id_1> by the door
T5 target: <extra_id_0> cat sat <extra_id_1> warm mat <extra_id_2>

right padding [[15, 27, 42], [15, 99, 0]]: generation continues from [42, 0]
left padding  [[15, 27, 42], [0, 15, 99]]: generation continues from [42, 99]
```

The measured fractions land on the 15, 80, 10 and 10 percent the rule asks for, within sampling noise. The T5 pair shows the format: the input keeps its words but has holes, and the target fills the holes in order. The last two lines are the padding bug in miniature: with right padding, the second prompt would continue from a pad.

### Teacher forcing, and the one-token shift

During training the model never reads its own guesses. Position $t$ is conditioned on the **true** prefix $x_{<t}$ from the data, whatever the model would have predicted there. This is **teacher forcing**, and together with the causal mask it is what lets one forward pass produce all $T$ predictions at once.

In code the whole idea is a slice. Feed the sequence without its last token and score the predictions against the sequence without its first:

```python
inputs  = tokens[:, :-1]     # x_1 ... x_{T-1}
targets = tokens[:, 1:]      # x_2 ... x_T, one step ahead of each input
```

Forget the shift and every position is asked to predict the token it is already reading, which the causal mask allows, since a position may attend to itself. The loss falls toward zero and the model has learned to copy. Train the smallest possible language model, a table of next-token logits indexed by the current token, on random tokens where nothing can be learned beyond frequencies:

```python
rng = np.random.default_rng(0)
V, T, N = 16, 33, 400
data = rng.integers(0, V, size=(N, T))           # random tokens: nothing to learn but frequencies

def train_table(inputs, targets, steps=300, lr=5.0):
    """A V x V logit table, the smallest possible 'language model': row = token read."""
    W = np.zeros((V, V))
    x, y = inputs.ravel(), targets.ravel()
    for _ in range(steps):
        z = W[x]
        p = np.exp(z - z.max(axis=1, keepdims=True))
        p /= p.sum(axis=1, keepdims=True)
        loss = -np.mean(np.log(p[np.arange(len(y)), y]))
        p[np.arange(len(y)), y] -= 1.0            # softmax cross-entropy gradient
        g = np.zeros_like(W)
        np.add.at(g, x, p)
        W -= lr * g / len(y)
    return W, loss

def greedy(W, start, steps=7):
    seq = [start]
    for _ in range(steps):
        seq.append(int(np.argmax(W[seq[-1]])))
    return seq

W_ok, loss_ok = train_table(data[:, :-1], data[:, 1:])     # predict token t+1 from token t
W_bug, loss_bug = train_table(data, data)                   # shift forgotten: predict t from t
print(f"with the shift    : loss {loss_ok:.3f}  (chance is ln {V} = {np.log(V):.3f})")
print(f"shift forgotten   : loss {loss_bug:.3f}")
print(f"greedy from token 3, shift forgotten: {greedy(W_bug, 3)}")
```

```output
with the shift    : loss 2.764  (chance is ln 16 = 2.773)
shift forgotten   : loss 0.011
greedy from token 3, shift forgotten: [3, 3, 3, 3, 3, 3, 3, 3]
```

The honest model sits essentially at chance, 2.764 against ln 16 = 2.773, and the small gap is only the model picking up this sample's token-frequency fluctuations. The broken one reports a loss that looks superb and generates by repeating whatever it was given. A training loss far below [what the data could support](3.1-PS4-information-theory-core.md) is the signature of this bug. When sequences are padded, the padded target positions are excluded from the loss, which is what `ignore_index` in PyTorch's cross-entropy is for.

<ProblemCard id="ptft-loss-floor" />

Teacher forcing has one cost. At generation time the model conditions on its own earlier outputs, which it never did in training. An early mistake puts it in a situation it has never seen, and errors can build on each other. This mismatch is called **exposure bias**. Scheduled sampling and sequence-level training address it partially. In practice, large-scale pretraining reduces it more than any algorithmic fix.

### Generating text: choosing each token

Generation runs the model on the prompt and turns the last position's logits into a probability distribution over the vocabulary. It then picks a token, appends it, and repeats, with the [KV cache](4.9-TF27-efficient-kv-cache.md) making each repeat cheap. Everything interesting happens in the step that picks a token.

**Greedy decoding** takes the most probable token every time. It is deterministic and often fine, but the best first token does not always start the best sequence. **Beam search** keeps the $B$ most probable partial sequences, ranked by total log-probability, and extends all of them, so it finds sequences greedy misses. In the toy model below, greedy commits to the likeliest first token and then faces five equally likely continuations. A beam of width 2 keeps a second prefix alive and finds a sequence 3.6 times as probable.

For open-ended text, maximizing probability produces bland, repetitive output, so **sampling** is usual, reshaped by three standard controls:

* **Temperature** $\tau$ divides the logits before the softmax, $p_i \propto e^{z_i / \tau}$. Below 1 it sharpens the distribution, reaching greedy as $\tau \to 0$. Above 1 it flattens it.
* **Top-$k$** keeps the $k$ most probable tokens, zeroes the rest, and renormalizes.
* **Top-$p$** (nucleus) keeps the smallest set of most probable tokens whose total probability reaches $p$, then renormalizes. Unlike top-$k$ it adapts: many tokens survive when the model is unsure, few when it is confident.

```python
# A two-step toy model. First token: a, b or c. Second token depends on the first.
first = {"a": 0.5, "b": 0.4, "c": 0.1}
second = {"a": {w: 0.2 for w in "vwxyz"},            # after a: five equally likely words
          "b": {"x": 0.9, "y": 0.1},                 # after b: nearly certain
          "c": {"z": 1.0}}

def prob(seq):
    return first[seq[0]] * second[seq[0]][seq[1]]

g1 = max(first, key=first.get)                        # greedy: best first token...
g2 = max(second[g1], key=second[g1].get)              # ...then best second token
beams = sorted(first, key=first.get, reverse=True)[:2]
cands = [(b, w) for b in beams for w in second[b]]    # beam width 2: keep two prefixes
best_beam = max(cands, key=prob)
best_all = max(((f, w) for f in first for w in second[f]), key=prob)
print(f"greedy       : {g1}{g2}  p = {prob((g1, g2)):.3f}")
print(f"beam, width 2: {''.join(best_beam)}  p = {prob(best_beam):.3f}")
print(f"best overall : {''.join(best_all)}  p = {prob(best_all):.3f}")

def temperature(p, tau):
    z = np.log(p) / tau
    q = np.exp(z - z.max())
    return q / q.sum()

def top_k(p, k):
    q = np.where(p >= np.sort(p)[-k], p, 0.0)
    return q / q.sum()

def top_p(p, nucleus):
    order = np.argsort(-p)
    keep = np.cumsum(p[order]) - p[order] < nucleus      # include the token that crosses
    q = np.zeros_like(p)
    q[order[keep]] = p[order[keep]]
    return q / q.sum()

p = np.array([0.42, 0.25, 0.15, 0.10, 0.05, 0.03])
print(f"\nmodel        : {np.round(p, 4)}")
print(f"tau = 0.5    : {np.round(temperature(p, 0.5), 4)}")
print(f"tau = 2      : {np.round(temperature(p, 2.0), 4)}")
print(f"top-k, k = 2 : {np.round(top_k(p, 2), 4)}")
print(f"top-p, p=0.8 : {np.round(top_p(p, 0.8), 4)}")
rng = np.random.default_rng(0)
draws = rng.choice(6, size=200_000, p=top_p(p, 0.8))
print(f"200,000 top-p draws, frequencies: {np.round(np.bincount(draws, minlength=6) / 200_000, 4)}")
```

```output
greedy       : av  p = 0.100
beam, width 2: bx  p = 0.360
best overall : bx  p = 0.360

model        : [0.42 0.25 0.15 0.1  0.05 0.03]
tau = 0.5    : [0.6419 0.2274 0.0819 0.0364 0.0091 0.0033]
tau = 2      : [0.2882 0.2224 0.1723 0.1406 0.0995 0.077 ]
top-k, k = 2 : [0.6269 0.3731 0.     0.     0.     0.    ]
top-p, p=0.8 : [0.5122 0.3049 0.1829 0.     0.     0.    ]
200,000 top-p draws, frequencies: [0.5141 0.305  0.1809 0.     0.     0.    ]
```

Temperature 0.5 squares the probabilities before renormalizing, so the leader rises from 0.42 to 0.64. Top-$p$ at 0.8 keeps three tokens, because the first two cover only 0.67, and the sampled frequencies match the renormalized $(0.5122, 0.3049, 0.1829)$ to within 0.003. The three controls combine, and a common recipe is a temperature a little below 1 followed by top-$p$ around 0.9.

### Why pretraining works: representations transfer

Pretraining works because the features a model needs to predict the next word are *also* useful for almost any later language task. These include grammar, which words refer to the same thing, facts, and topic. Adaptation then only has to learn a simple mapping from those representations to your labels. In terms of the [bias-variance tradeoff](2.16-ML11-bias-variance-cross-validation.md), pretraining acts as a strong **prior**. It puts the model's weights in a region that already encodes general structure, so the new task has far fewer things left to estimate and can generalize from a small labeled set without overfitting.

### The model families, and counting their parameters

The pretrained models you will actually be handed come from three lineages, and each pairs an [architecture](2.41-TF21-transformer-stack.md) with the objective its mask permits:

| family | architecture | objective | good at | examples |
| --- | --- | --- | --- | --- |
| BERT | encoder-only | masked LM | classification, tagging, retrieval | BERT, RoBERTa, DeBERTa |
| GPT | decoder-only | next token | generation, and everything via prompting | GPT-2, LLaMA, Mistral |
| T5 | encoder-decoder | span corruption | translation, summarization, seq-to-seq | T5, BART, FLAN-T5 |

The objective column follows from the architecture. A bidirectional encoder sees the whole sequence at once, so next-token prediction would be trivial and useless, and masking is the only objective that hides anything. A causal decoder cannot see ahead, so next-token prediction is exactly the hard task available. Encoder-decoders get a third option: corrupt a span on the encoder side and reconstruct it on the decoder side.

It is also worth being able to work out the size of one of these models from its config file. That tells you whether it fits in your memory before you download it. Five big numbers decide it, plus two options (the type-vocabulary size and whether there is a pooler head):

```python
def parts(vocab, d, L, d_ff, max_pos, type_vocab=0, pooler=False):
    """Parameter count of a Transformer stack, split by where it lives."""
    emb = vocab*d + max_pos*d + type_vocab*d + 2*d      # tokens, positions, types, LN
    attn = 4*(d*d + d)                                  # Q, K, V and the output proj
    ffn = (d*d_ff + d_ff) + (d_ff*d + d)                # up then down
    layers = L*(attn + 2*d + ffn + 2*d)                 # two LayerNorms per layer
    extra = (d*d + d) if pooler else 0
    return emb, layers, extra, L*attn, L*ffn

cfgs = [
  ("BERT-base",   30522, 768,  12, 3072, 512, 2, True,  "110M"),
  ("BERT-large",  30522, 1024, 24, 4096, 512, 2, True,  "340M"),
  ("GPT-2 small", 50257, 768,  12, 3072, 1024, 0, False, "124M"),
  ("GPT-2 medium",50257, 1024, 24, 4096, 1024, 0, False, "355M"),
  ("GPT-2 XL",    50257, 1600, 48, 6400, 1024, 0, False, "1.5B"),
]
print(f"{'model':>13} {'total':>14} {'published':>10} {'embed %':>8} {'attn %':>7} {'ffn %':>6}")
for name, v, d, L, dff, mp, tv, pool, pub in cfgs:
    emb, layers, extra, attn, ffn = parts(v, d, L, dff, mp, tv, pool)
    t = emb + layers + extra
    print(f"{name:>13} {t:>14,} {pub:>10} {100*emb/t:>7.1f}% {100*attn/t:>6.1f}% {100*ffn/t:>5.1f}%")
```

```output
    BERT-base    109,482,240       110M    21.8%   25.9%  51.8%
   BERT-large    335,141,888       340M     9.5%   30.1%  60.1%
  GPT-2 small    124,439,808       124M    31.7%   22.8%  45.5%
```

Every total lands on the figure these models are published with. The whole calculation runs off five numbers from a config file, so a model's size is something you can work out rather than look up.

**The embedding column is the surprise.** For GPT-2 small, $31.7\%$ of the parameters are the input embeddings (the token table, the position table and the final layer norm). The token table alone is $31.0\%$, one vector per vocabulary entry. That share drops to $5.3\%$ at GPT-2 XL, because embeddings grow as $V \times d$ while the layers grow as $L \times d^2$. So a small model with a large vocabulary is largely a lookup table. That is why weight tying, using the same matrix for the input embedding and the output projection, saved so much at that scale and saves relatively little now. Parameter count is also an imperfect guide to compute. Looking up each input token's row in the table costs almost nothing, unlike the matrix multiplies in the layers, although GPT-2 also reuses the table as its output layer, where it does cost a full matrix multiply.

**The feed-forward column matches what one block predicted.** It runs from $45.5\%$ to $63.1\%$ as models grow, approaching roughly two thirds. That is the same ratio the [single-block count](2.41-TF21-transformer-stack.md) gives when $d_{ff} = 4d$. By weight, a Transformer is mostly feed-forward layers at every scale, and more so as it grows.

### Four ways to adapt: fine-tuning, linear probing, prompting, PEFT

Adaptation is a spectrum of how much of the pretrained model you change.

- **Full fine-tuning** updates *all* the weights on the new task. It is the most flexible option, but it needs the most data and compute, overfits small datasets, and produces a full-size copy of the model for every task. A middle course freezes some of the layers and trains the rest. PyTorch computes no gradient for a weight whose `requires_grad` is off, so a frozen layer skips part of the backward pass.
- **Linear probing** *freezes* the pretrained backbone and trains only a small new head (often a single linear layer) on top of the frozen features. It is cheap, works well with little data, and tests the representations on their own. It is what gets built below.
- **Prompting / in-context learning** changes *nothing* in the weights. You describe the task in the input text (optionally with a few examples) and let the frozen model respond directly. It costs nothing to train, but performance depends entirely on what pretraining already captured.
- **Parameter-efficient fine-tuning (PEFT)** keeps the backbone frozen but injects a tiny number of new trainable parameters. The best-known method, **LoRA** (Low-Rank Adaptation), freezes a weight matrix $W_0 \in \mathbb{R}^{d \times k}$ and learns a low-rank update $\Delta W = BA$ with $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$, and rank $r \ll \min(d,k)$. The adapted layer computes $W_0 x + BA\,x$, training only the $r(d+k)$ entries of $A$ and $B$ instead of all $dk$ entries of $W_0$. That is often under 1% of the parameters, with quality close to full fine-tuning.

<ProblemCard id="ptft-freeze-top-or-bottom" />

Two details decide whether a LoRA run works, and neither follows from the parameter count.

**Why a low-rank update suffices.** Nothing forces $\Delta W$ to be low-rank: the claim is empirical. Adapting a pretrained model to a downstream task needs far less capacity than learning the task from scratch, because the features are already present and mostly need reweighting. That update has a low **intrinsic dimension**, so constraining it to rank $r$ discards little that matters. Note this is a claim about the *update*, not about $W_0$: the pretrained weights are full-rank, and LoRA never modifies them.

**Initialization and scaling.** $A$ is initialized randomly and $B$ to **zero**, so $\Delta W = BA = 0$ at step one and training begins from exactly the pretrained model rather than a perturbed one. Both cannot be zero: the gradient of each factor is proportional to the other, so an all-zero pair never leaves the origin. The update is then applied with a constant $\alpha$:

$$
W_0 x + \frac{\alpha}{r} BA\,x
$$

Dividing by $r$ keeps the update's magnitude roughly fixed as the rank varies, so a learning rate tuned at $r = 8$ still behaves at $r = 64$. Without it, raising the rank silently scales the effective step size. Note what this is *not* about. Because $B = 0$, the initial $\Delta W$ is exactly zero at every rank, so there is no initial magnitude to hold steady. The scaling governs the learned update.

**Merging, and the arithmetic in full.** All of the above is counting, so it is worth doing rather than trusting:

```python
D, K = 4096, 4096
rng = np.random.default_rng(0)

print(f"one {D}x{K} projection, the size in a mid-range transformer")
print(f"{'rank r':>7} {'trainable':>12} {'% of full':>10}")
for r in (1, 4, 8, 32, 128):
    print(f"{r:>7} {r * (D + K):>12,} {100 * r * (D + K) / (D * K):>9.3f}%")
print(f"{'full':>7} {D * K:>12,} {100.0:>9.3f}%")

d, k, r, alpha = 64, 48, 8, 16
W0 = rng.standard_normal((d, k))
A = rng.standard_normal((r, k)) * 0.01
B = np.zeros((d, r))                 # B starts at zero, A does not
x = rng.standard_normal((5, k))

print(f"\nat init, max |B A|                : {np.abs(B @ A).max():.1e}")
print(f"at init, adapted == pretrained    : {np.allclose(x @ W0.T, x @ W0.T + (alpha / r) * (x @ A.T @ B.T))}")

B = rng.standard_normal((d, r)) * 0.1          # pretend training happened
lora_path = x @ W0.T + (alpha / r) * (x @ A.T @ B.T)
W_merged = W0 + (alpha / r) * (B @ A)
print(f"after training, merged shape      : {W_merged.shape} same as W0: {W_merged.shape == W0.shape}")
print(f"merged output matches the LoRA path: {np.allclose(lora_path, x @ W_merged.T)}")
print(f"rank of the update                : {np.linalg.matrix_rank(B @ A)} out of min(d, k) = {min(d, k)}")
```

```output
   full   16,777,216   100.000%

at init, max |B A|                : 0.0e+00
at init, adapted == pretrained    : True
after training, merged shape      : (64, 48) same as W0: True
merged output matches the LoRA path: True
rank of the update                : 8 out of min(d, k) = 48
```

Rank 8 on a $4096 \times 4096$ projection trains $65{,}536$ numbers against $16{,}777{,}216$, which is $0.39\%$. Even rank 128, far more than anyone normally uses, stays inside $6.25\%$.

The merged-output check is the property that decides whether LoRA is deployable. Once trained, $W_0 + \frac{\alpha}{r}BA$ collapses into a single matrix of the original shape, and its output is identical to running the two paths separately. So LoRA costs **nothing at inference** after merging: no extra matmul, no extra memory, no added latency. That is its practical advantage over adapter layers, which insert genuinely new modules into the forward pass and cannot be folded away.

It also means one frozen base model can serve many tasks. Keep the $A$ and $B$ pairs, each pair far smaller than the base model (rank 8 on a $4096 \times 4096$ matrix is 65,536 numbers, about 262 KB in fp32), and merge whichever the request needs, or leave them unmerged and batch several tasks at once against the shared $W_0$.

<Optional title="CLIP: pretraining across two modalities (camp/IOAI level)">

Every objective above pretrains on one kind of data. **CLIP** pretrains on two. It trains an image encoder and a text encoder together on hundreds of millions of (image, caption) pairs. The objective is contrastive: pull each image's embedding toward its own caption's embedding, and push it away from every other caption in the batch. After training, images and text live in one shared space where high cosine similarity means "these describe the same thing".

The payoff is **zero-shot classification**: embed the image, embed a prompt like "a photo of a dog" for each class name, and pick the class whose text embedding sits closest. IOAI leans on this: the syllabus lists vision-text encoders explicitly, and past tasks have handed contestants a CLIP-style model to reason about or edit.

[Contrastive Learning and CLIP](2.14-RP2-contrastive-learning.md) covers this in depth: the InfoNCE loss, what temperature does, and why the batch has to be enormous.

</Optional>
