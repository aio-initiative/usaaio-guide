## Overview

USAAIO and IOAI require deep learning solutions to be written in PyTorch, not TensorFlow. PyTorch is three things. **Tensors** are arrays like NumPy's that can also live on a GPU. **Autograd** computes the gradient of any number you compute from those tensors. `torch.nn` holds the layers and losses built on the first two. The rest of this chapter takes them in that order: [PyTorch Tensors & Autograd](1.25-PY9-pytorch-tensors-autograd.md) for the first two, [The Multilayer Perceptron](1.18-DL1-neural-networks-perceptrons-mlps-activations.md) for `nn.Module`, and [Writing a Training Loop](1.26-PY10-training-loop-in-pytorch.md) for `torch.optim`.

This module is about autograd. Training a network means computing the gradient of a loss with respect to every parameter, thousands or billions of them, at every step. Nobody writes those derivatives. Autograd does, and the way it does it is what made PyTorch the framework research moved to.

## Example: one gradient, by hand and by autograd

Take $f(a, b) = ab + \sin a$ at $a = 2$, $b = 3$. Calculus gives $\partial f / \partial a = b + \cos a = 2.584$ and $\partial f / \partial b = a = 2$. Autograd reaches the same numbers without seeing the formula, by a method that scales to a network with millions of parameters.

The computation graph of $f = ab + \sin a$. Above each box is its value, computed left to right. Below it is how much $f$ changes when that value changes, computed right to left. Each arrow is labeled with the derivative that links its two boxes.
</Figure>

**Forward pass.** Evaluate one operation at a time and keep every intermediate: $v_1 = ab = 6$, $v_2 = \sin a = 0.909$, $f = v_1 + v_2 = 6.909$. Each operation also knows its own derivative with respect to each input, its **local derivative**: $\partial v_1/\partial a = b$, $\partial v_1/\partial b = a$, $\partial v_2/\partial a = \cos a$, and $\partial f/\partial v_1 = \partial f/\partial v_2 = 1$.

**Backward pass.** Now ask, for each value in turn, how much $f$ moves when that value moves a little. That number is the value's **adjoint**, written $\bar v = \partial f / \partial v$, and for $f$ itself it is 1. For any other value, take the adjoint of the operation it feeds and multiply by that operation's local derivative. If it feeds two operations, add the two results. Visit the operations in the reverse of the order they ran:

1. $f = v_1 + v_2$ has local derivatives of 1, so $\bar v_1 = \bar v_2 = 1 \cdot 1 = 1$.
2. $v_2 = \sin a$ sends $a$ the amount $\bar v_2 \cos a = -0.416$.
3. $v_1 = ab$ sends $a$ the amount $\bar v_1 \, b = 3$ and gives $\bar b = \bar v_1 \, a = 2$.
4. $a$ feeds two operations, so it adds what both sent: $\bar a = 3 - 0.416 = 2.584$.

In PyTorch:

```python
import torch

a = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(3.0, requires_grad=True)
f = a * b + torch.sin(a)
f.backward()
print(f"{f.item():.4f} {a.grad.item():.4f} {b.grad.item():.4f}")
```

```output
6.9093 2.5839 2.0000
```

`requires_grad=True` asks PyTorch to record what happens to a tensor. The line that computes `f` is the forward pass, recorded as it runs. `f.backward()` is the backward pass, and the gradients land in `.grad`.

## Explanation

### Define-by-run

PyTorch runs every operation immediately, on real numbers, and records it as it runs. The record is the computation graph for that one forward pass: the operations, what fed them, and whatever each needs for its local derivative (`sin` keeps $a$ so it can compute $\cos a$ later). Nothing is declared ahead of time, so an ordinary Python `if` or `for` inside a model works as written, and a `print` or a breakpoint shows real values. The graph is used once by `backward()` and rebuilt on the next forward pass.

<ProblemCard id="pyt-what-requires-grad-switches-on" />

TensorFlow 1 made you declare the whole graph first and run it afterwards, which ran fast and debugged badly. Both frameworks run operations immediately now, and the rule stands because PyTorch is what research and the olympiads settled on.

<ProblemCard id="pyt-define-by-run-defined" />

### Reverse mode

The backward pass is the chain rule applied in reverse order. For a value $u$ that feeds an operation producing $v$,

$$
\bar u \mathrel{+}= \bar v \, \frac{\partial v}{\partial u} .
$$

In words, $u$'s adjoint is $v$'s adjoint times how fast $v$ changes with $u$. The $\mathrel{+}=$ is there because a value used twice collects a contribution from each use, as $a$ did above.

One backward sweep gives the gradient with respect to every input at once. That makes it the right choice for training, where the loss is one number and the parameters are millions. Forward mode, which pushes a derivative forward from one input at a time, would need one sweep per parameter. The backward sweep costs a small multiple of the forward pass, and it needs every intermediate value the forward pass produced, so training takes more memory than inference.

<ProblemCard id="pyt-why-the-sweep-runs-backward" />

### Exact, and checkable

Autograd is exact. Every local derivative is the true derivative of a simple operation such as a product or a sine, and the chain rule adds no error, so `a.grad` above matches $b + \cos a$ to the last digit a float holds. It differentiates the program you wrote, loops and branches included, which a formula manipulator such as SymPy cannot do: SymPy differentiates a formula you hand it, not the code that ran.

The other way to get a derivative is to estimate it from two nearby values of the function, a **central difference**:

$$
f'(x) \approx \frac{f(x + h) - f(x - h)}{2h} .
$$

That takes two evaluations per parameter, and $h$ is a compromise. Too large and the slope between the two points is not the slope at $x$. Too small and the two values agree in almost every digit, so their difference is mostly round-off. About $10^{-6}$ is right in float64. Its one job is checking. A hand-derived gradient that agrees with this estimate to five or six digits is right. Every derivation in [Backpropagation by Hand](2.1-MA4-backpropagation-mechanics.md), which is reverse mode on a layered network, can be checked that way.
