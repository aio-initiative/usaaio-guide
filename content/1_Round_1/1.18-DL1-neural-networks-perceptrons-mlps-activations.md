## Overview

A **multilayer perceptron** (MLP) is the simplest neural network with hidden layers. Its unit is the neuron, which takes a weighted sum of its inputs and passes the result through a fixed nonlinear function. Neurons are arranged in layers, each layer reads the outputs of the one before it, and the weights are learned from examples.

Rosenblatt's perceptron of 1958 was one layer of these neurons. Stacking layers and training them with backpropagation gave the multilayer perceptron, still a part of most larger networks. A Transformer has an MLP inside each of its blocks.

The perceptron's **learning rule** needs no gradients. Write each label as $y = \pm 1$, start from $w = 0$ and $b = 0$, and go through the training points one at a time. On a point the neuron gets wrong, that is $y(w \cdot x + b) \le 0$, add the point's own label to the parameters,

$$
w \leftarrow w + y x, \qquad b \leftarrow b + y.
$$

The step moves the weighted sum in the direction the label asks for, and its length is fixed by the point, not by how badly the point was missed. On linearly separable data the rule reaches a solution: every step pushes the weights a fixed amount further along a separating direction, while their length grows only like the square root of the number of steps, so the misses must stop. With labels that overlap it keeps chasing points it can never get, so it is capped at a fixed number of passes, and that cap is what the practice notebook below sets.

## Explanation

### A neuron

A neuron takes inputs $a_1, \dots, a_n$ (the figure labels them $x_1, x_2, x_3$) and produces one number,

$$
a = \sigma(w_1 a_1 + w_2 a_2 + \dots + w_n a_n + b).
$$

Each input has a **weight** $w_i$, one **bias** $b$ is added to the weighted sum, and the sum goes through an **activation function** $\sigma$.

<Figure src="assets/module-media/neuron.svg" alt="Three inputs x1, x2, x3 with weights w1, w2, w3 on their arrows feed a summing node that also receives a bias b. Its output z goes through a node marked sigma and comes out as a.">
One neuron: multiply each input by its weight, add the bias, apply $\sigma$.
</Figure>

With inputs 1.0, 0.5, 0.0, weights 3, −2, 1 and bias −1, the weighted sum is $3(1.0) - 2(0.5) + 1(0.0) - 1 = 1$. With the sigmoid function as $\sigma$, defined next, the output is $\sigma(1) = 0.73$.

The weights say what the neuron responds to. A positive weight means that input pushes the output up, a negative weight pushes it down, and a weight of 0 means the input is ignored. The bias sets the threshold: with a large negative bias the output stays near 0 unless the weighted inputs are large and positive. The activation function keeps the output in a fixed range.

### Activation functions

The classic activation function is the sigmoid,

$$
\sigma(z) = \frac{1}{1 + e^{-z}}.
$$

<Figure src="assets/module-media/sigmoid.svg" alt="The sigmoid curve, an S shape rising from 0 on the left through 0.5 at z = 0 to 1 on the right, with the point at z = 1 marked at 0.73.">
Large negative sums go to 0, large positive sums go to 1, and $\sigma(0) = 0.5$.
</Figure>

It maps any sum into the interval $(0, 1)$, so a sigmoid neuron's output reads as how strongly it fires. It is also the function from [logistic regression](1.27-ML8-linear-logistic-regression.md), so one sigmoid neuron is a logistic regression model. The other two activation functions you will meet are

$$
\begin{aligned}
\tanh(z) &= \frac{e^{z} - e^{-z}}{e^{z} + e^{-z}}, \\[4pt]
\mathrm{ReLU}(z) &= \max(0, z).
\end{aligned}
$$

<Figure src="assets/module-media/activation-functions.svg" alt="Three small plots. Sigmoid rises from 0 to 1. Tanh has the same S shape but runs from -1 to 1. ReLU is flat at 0 for negative z and a straight line with slope 1 for positive z.">
Tanh is a sigmoid rescaled to run from −1 to 1. ReLU is 0 for negative inputs and leaves positive inputs unchanged.
</Figure>

Every activation has a slope at every point $z$ except ReLU at $z = 0$, where it bends. The last column shows the steepest it gets, and where:

| Function | Slope at $z$ | Largest slope |
|---|---|---|
| sigmoid | $\sigma(z)\,(1 - \sigma(z))$ | 0.25, at $z = 0$ |
| tanh | $1 - \tanh^2(z)$ | 1, at $z = 0$ |
| ReLU | 1 for $z > 0$, 0 for $z < 0$ | 1 |

The digit network below uses sigmoid because it is the easiest to reason about. Most networks today use ReLU, or a variant of it, between layers: sigmoid there makes deep networks hard to train, which you will measure in the problem below. ReLU has a failure of its own. A unit whose weighted sum is negative for every training input outputs 0, and since the slope there is 0 it gets no gradient, so it stays off for good: a **dead ReLU**. Leaky ReLU, $\max(0.01z, z)$, keeps a small slope on the negative side for that reason, and GELU, $z\,\Phi(z)$ with $\Phi$ the standard normal CDF, is a smoothed ReLU that Transformers such as BERT and GPT-2 use. For everything in this module the three above are enough.

### A layer

A **layer** is a set of neurons that read the same inputs. Take two neurons reading three inputs. Neuron 1 has the weights $(3, -2, 1)$ and bias −1 from above, and neuron 2 has weights $(0, 1, -1)$ and bias 0. Put the weights in the rows of a matrix $W$ and the biases in a vector $\mathbf{b}$:

$$
\begin{gathered}
W = \begin{pmatrix} 3 & -2 & 1 \\ 0 & 1 & -1 \end{pmatrix}, \qquad
\mathbf{b} = \begin{pmatrix} -1 \\ 0 \end{pmatrix}, \\[6pt]
\mathbf{x} = \begin{pmatrix} 1.0 \\ 0.5 \\ 0.0 \end{pmatrix}.
\end{gathered}
$$

One matrix-vector product computes both weighted sums, and $\sigma$ applied to each entry gives both outputs:

$$
\begin{aligned}
W\mathbf{x} + \mathbf{b} &=
\begin{pmatrix} 3(1.0) - 2(0.5) + 1(0.0) - 1 \\ 0(1.0) + 1(0.5) - 1(0.0) + 0 \end{pmatrix} \\[6pt]
&= \begin{pmatrix} 1 \\ 0.5 \end{pmatrix}, \\[6pt]
\mathbf{a} &= \sigma(W\mathbf{x} + \mathbf{b}) = \begin{pmatrix} 0.73 \\ 0.62 \end{pmatrix}.
\end{aligned}
$$

Row $j$ of $W$ holds neuron $j$'s weights, so row $j$ of $W\mathbf{x} + \mathbf{b}$ is neuron $j$'s weighted sum. The same layout scales up. A layer of 16 neurons reading the 784 pixels has a $16 \times 784$ matrix $W$ and a vector $\mathbf{b}$ of length 16, and

$$
\mathbf{a} = \sigma(W \mathbf{x} + \mathbf{b})
$$

is all 16 outputs at once. That layer has $16 \times 784$ weights and 16 biases, 12,560 parameters.

In code, images come in batches. Put $N$ images in the rows of a matrix $X$ of shape $N \times 784$. Then $X W^\top$ is $N \times 16$, one row of outputs per image, and $\mathbf{b}$ is added to every row. This is the convention PyTorch uses, and [Forward Propagation](2.15-MA6-forward-propagation.md) works through it in detail.

### The network

An MLP is layers in sequence, each reading the output of the one before. For the digits: 784 inputs, two **hidden layers** of 16 neurons, and 10 outputs, one per digit.

<Figure src="assets/module-media/mlp-network.svg" alt="Four columns of circles joined left to right: an input column, two hidden columns, and an output column. Every circle in one column connects to every circle in the next.">
Every neuron in one layer reads every output of the layer before it. The digit network has 784, 16, 16 and 10 neurons in its four columns.
</Figure>

$$
\begin{aligned}
\mathbf{a}_1 &= \sigma(W_1 \mathbf{x} + \mathbf{b}_1), \\
\mathbf{a}_2 &= \sigma(W_2 \mathbf{a}_1 + \mathbf{b}_2), \\
\mathbf{s} &= W_3 \mathbf{a}_2 + \mathbf{b}_3 .
\end{aligned}
$$

The last layer has no activation function. Its 10 outputs $\mathbf{s}$ are **scores**, also called **logits**, and the prediction is the digit with the highest score. Training turns the scores into probabilities with a softmax and compares them with the label, as in [Loss Functions](1.28-ML9-loss-functions.md). Computing $\mathbf{s}$ from $\mathbf{x}$ is a **forward pass**.

| Layer | Weights | Biases | Parameters |
|---|---|---|---|
| $784 \to 16$ | $16 \times 784 = 12{,}544$ | 16 | 12,560 |
| $16 \to 16$ | $16 \times 16 = 256$ | 16 | 272 |
| $16 \to 10$ | $10 \times 16 = 160$ | 10 | 170 |
| All three | | | 13,002 |

These 13,002 numbers are the network's **parameters**, and training means finding good values for all of them. "Hidden" means neither input nor output. Two hidden layers of 16 is a choice, not a rule, and a small one. Wider layers do better on this problem.

The last layer depends on the task. A classifier keeps it linear and lets the loss apply the softmax, or a sigmoid for a single yes-or-no output. The loss already applies a softmax, so a softmax in the model gets applied twice, which shrinks the gradients and slows training with no error message. The mistake is `nn.Softmax()` in front of `nn.CrossEntropyLoss`, which applies its own softmax to the scores. A regression output stays linear, so it can be any number.

| Task | Last layer | Loss | In PyTorch |
|---|---|---|---|
| one of $C$ classes | $C$ scores | cross-entropy, softmax inside | `nn.CrossEntropyLoss` |
| yes or no | 1 score | binary cross-entropy, sigmoid inside | `nn.BCEWithLogitsLoss` |
| a number | 1 output | mean squared error | `nn.MSELoss` |

A ReLU on a regression output is a common bug. The network can never predict a negative number, and when the output's weighted sum is negative, no gradient flows back.

### Why the activation function is needed

Without $\sigma$ a layer only multiplies and adds, and stacking that gains nothing. Send a single number $x$ through two such layers:

$$
3(2x + 1) + 4 = 6x + 7 .
$$

The result is one multiply and one add again. The same happens with matrices:

$$
\begin{aligned}
& W_2(W_1 \mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2 \\
&\quad = (W_2 W_1)\mathbf{x} + (W_2 \mathbf{b}_1 + \mathbf{b}_2),
\end{aligned}
$$

which is a single layer with weight matrix $W_2 W_1$. However many layers you stack, the network collapses to one, and one layer cannot read digits well: trained the same way, it stops at about 92%. A function whose graph is not a straight line breaks the collapse. Such a function is called **nonlinear**, and every activation function is one. With one in place the picture turns around: a single hidden layer, made wide enough, can approximate any continuous function as closely as you like. That result is the **universal approximation theorem**. It holds for inputs in a closed, bounded range such as $[0, 1]$, and needs an activation that is continuous and not a polynomial. Sigmoid, tanh and ReLU qualify. Nonlinear alone is not enough. If the activation squares its input, each neuron's output is a quadratic in the inputs, and so is any weighted sum of them. No quadratic stays within 0.03 of $x^3$ over all of $[0, 1]$: the best one misses by $1/32$. The theorem says nothing about how wide, or whether training will find the weights, and in practice networks grow by adding layers.

### What a ReLU network computes

ReLU is a straight line on each side of 0, so a ReLU network is linear except where some unit switches on or off. With one input $x$, the unit $\mathrm{ReLU}(x - c)$ is a **hinge**: 0 up to $x = c$, then slope 1. A weighted sum of hinges is a connect-the-dots curve. Put a hinge wherever the slope should change, with output weight equal to the change in slope. The **tent** rises with slope 2 and turns at $x = \tfrac12$ to slope $-2$, a change of $-4$:

$$
\begin{aligned}
t(x) &= 2\,\mathrm{ReLU}(x) - 4\,\mathrm{ReLU}\big(x - \tfrac12\big) \\[4pt]
&= \begin{cases} 2x, & 0 \le x \le \tfrac12, \\[2pt] 2 - 2x, & \tfrac12 \le x \le 1. \end{cases}
\end{aligned}
$$

Each unit adds at most one bend, so one hidden layer of $N$ units on one input makes at most $N + 1$ straight pieces.

<Optional title="Universal approximation with one input">

With one input and ReLU, the theorem has a short proof that shows where the width comes from. Let $f$ be continuous on $[0, 1]$ and fix an error $\varepsilon > 0$. A continuous function on a closed interval is uniformly continuous: there is a $\delta > 0$ with $|f(x) - f(y)| < \varepsilon$ whenever $|x - y| < \delta$. Choose $N$ with $1/N < \delta$, put grid points $x_i = i/N$, and let $g$ be the connect-the-dots curve through the points $(x_i, f(x_i))$. Its slope on the $i$-th interval is $s_i = N\big(f(x_{i+1}) - f(x_i)\big)$.

Hinges build $g$. Start at height $f(0)$ with slope $s_0$, and at each inner grid point add a hinge that changes the slope from $s_{i-1}$ to $s_i$:

$$
\begin{aligned}
g(x) = f(0) &+ s_0\,\mathrm{ReLU}(x) \\
&+ \sum_{i=1}^{N-1} (s_i - s_{i-1})\,\mathrm{ReLU}(x - x_i).
\end{aligned}
$$

That is one hidden layer of $N$ units, with input weights 1, biases $-x_i$ (including $x_0 = 0$), output weights equal to the slope changes, and $f(0)$ as the output unit's bias. For the error, take $x$ in $[x_i, x_{i+1}]$. There $g(x) = \lambda f(x_i) + (1 - \lambda) f(x_{i+1})$ with $\lambda = N(x_{i+1} - x)$ between 0 and 1, so

$$
\begin{aligned}
|g(x) - f(x)| &\le \lambda\,|f(x_i) - f(x)| + (1 - \lambda)\,|f(x_{i+1}) - f(x)| \\
&< \varepsilon,
\end{aligned}
$$

because $x$ is within $1/N < \delta$ of both grid points. $\blacksquare$

The proof also gives a price. If $|f(x) - f(y)| \le K|x - y|$ for all $x$ and $y$, the same inequality gives $|g(x) - f(x)| \le \lambda K (x - x_i) + (1 - \lambda) K (x_{i+1} - x)$. Write $u = x - x_i$. Then $\lambda = 1 - Nu$ and the right side is $2 K u (1 - Nu)$, which is largest at $u = 1/(2N)$ and there equals $K/(2N)$, so error $\varepsilon$ costs about $K/(2\varepsilon)$ units. For $f(x) = x^2$ on $[0, 1]$, $|x^2 - y^2| = |x + y||x - y| \le 2|x - y|$, so $K = 2$, and error $0.01$ is guaranteed by about $2/(2 \times 0.01) = 100$ units. The grid idea works with $n$ inputs too, but a grid fine enough for error $\varepsilon$ on $[0, 1]^n$ has about $\varepsilon^{-n}$ cells, which is why the width the theorem promises can be enormous. The general statement, that a continuous activation gives universal approximation if and only if it is not a polynomial, is due to Leshno, Lin, Pinkus and Schocken (1993).

</Optional>

With one hidden layer on two inputs, each unit switches along the line where its weighted sum is 0. The lines cut the plane into regions. Inside a region no unit switches, so the output is linear there and its graph is a plane.

<Figure src="assets/module-media/relu-regions.svg" alt="Five heavy straight lines crossing a square, with thin contour lines of the network's output that run straight inside each region and bend wherever they cross a heavy line.">
Five ReLU units with random weights on two inputs. The output's contours are straight inside each of the 16 regions and bend only on the heavy lines, where units switch.
</Figure>

Any $N$ lines make at most $1 + N + \binom{N}{2}$ regions. The maximum is reached when every pair of lines crosses and each crossing point lies on just two of them. Five lines give $1 + 5 + 10 = 16$.

One line splits the plane into two half-planes, so a layer with no hidden units can only carve out a target whose two classes are each convex. A target that fails that, such as XOR, where class 1 holds the two diagonal corners of the square and class 0 the other two, is out of reach of any number of such units. Part 1 of the notebook below measures exactly that, by training a linear classifier on the XOR pattern and checking that its loss stays above 0.65.

<Optional title="Why N lines make at most 1 + N + C(N, 2) regions">

Let $R(N)$ be the largest number of regions $N$ lines can make. A new line meets the lines already drawn at $m$ distinct points. Those points divide it into $m + 1$ pieces. Each piece runs through one existing region and separates it into two, so the new line adds exactly $m + 1$ regions. Two distinct lines share at most one point, so $m \le N - 1$ when the new line is the $N$-th. Applying that step again to $R(N - 1)$, then to $R(N - 2)$, down to $R(0) = 1$, adds $1 + 2 + \dots + N$, and

$$
R(N) \le R(N - 1) + N, \qquad R(N) \le 1 + (1 + 2 + \dots + N) = 1 + N + \binom{N}{2} .
$$

Equality needs $m = N - 1$ at every step: the new line crosses all the old ones, at points where no other line passes through. Three lines that form a triangle give $R(3) = 7$: the triangle itself, three regions across its sides and three at its corners.

</Optional>

Setting weights by hand uses the same lines. A **threshold unit** outputs 1 when its weighted sum is at least 0, and 0 otherwise. [2026 Round 1](https://www.usaaio.org/attachments/past-problems/2026/usaaio-2026-round-1-problems.pdf), Problem 7, asked for a hand-set network of them that outputs 1 inside a triangle. A triangle is where three half-planes overlap, so use one hidden unit per side, $h_1, h_2, h_3$, each outputting 1 on the triangle's side of its line. An output unit on $h_1 + h_2 + h_3 - 2.5$ fires only when all three do. A convex polygon with $m$ sides takes $m$ hidden units and $m - \tfrac12$ in place of 2.5.

<Optional title="Why depth helps: the sawtooth">

One hidden layer of $N$ units makes at most $N + 1$ pieces on one input. On $n$ inputs its units switch along $N$ flat cuts, which make at most $\sum_{j=0}^{n} \binom{N}{j}$ regions, a number that grows like $N^n$ however the weights are set. Depth does better (Telgarsky, 2016). The tent maps $[0, 1]$ onto $[0, 1]$, so it can be fed into itself. Composing it with itself, $t(t(x))$, runs the tent twice as fast and gives two teeth. Each further composition doubles the count again, so

$$
t^{(k)} = \underbrace{t \circ t \circ \cdots \circ t}_{k \text{ times}}
$$

is a sawtooth with $2^{k-1}$ teeth and $2^k$ straight pieces. As a network it has $k$ hidden layers of width 2, which is $2k$ ReLU units in all.

<Figure src="assets/module-media/relu-sawtooth.svg" alt="Three panels: a single tent from 0 up to 1 and back, then two teeth, then four teeth, each drawn on the interval from 0 to 1.">
The same two-unit layer applied once, twice and three times. Each pass doubles the number of straight pieces, while the unit count only grows by two.
</Figure>

To see why the count doubles, follow one piece. On any piece of $t^{(k-1)}$ the output sweeps linearly from 0 to 1 or from 1 to 0. Feeding that sweep through $t$ traces a full tent, up and back down, so each piece becomes two.

A single hidden layer needs at least $2^k - 1$ units to make the same $2^k$ pieces. For $k = 20$ the deep network uses 40 units and the shallow one more than a million. The deep network wins because each layer reuses everything below it: the second tent folds the output of the first, so every existing piece is split in two for the price of two new units.

A strip of paper gives a picture of this. The tent folds a strip of length 1 in half at its midpoint and stretches the folded strip back to length 1. After $k$ layers the strip has been folded $k$ times and is $2^k$ sheets thick. Whatever the next layer draws on the folded strip, even a single straight line, is copied onto every sheet, and unfolding shows $2^k$ copies. A shallow network cannot fold, so it has to draw every copy separately.

Measuring where the slope changes confirms the counts:

```python
import numpy as np

relu = lambda z: np.maximum(0, z)
tent = lambda x: 2 * relu(x) - 4 * relu(x - 0.5)

x = np.linspace(0, 1, 2**14 + 1)
for k in range(1, 6):
    y = x
    for _ in range(k):
        y = tent(y)
    slopes = np.diff(y) / np.diff(x)
    pieces = 1 + np.sum(np.abs(np.diff(slopes)) > 1e-6)
    print(k, pieces)
```

```output
1 2
2 4
3 8
4 16
5 32
```

The sawtooth is built to reward depth, and it does not show that every useful function needs depth. It does show that the universal approximation theorem, which only counts units, can hide an exponential difference in cost. Images and text have a lot of the same reuse, with edges combining into shapes and shapes into objects, which is the informal reason depth pays off in practice.

</Optional>

## Implementation

`torch.nn` has a class for each piece above, and the code goes in the same order: a layer, the activation function, the network, a forward pass.

### One layer

`nn.Linear(784, 16)` is a layer of 16 neurons that each read 784 inputs. Its first two arguments are `in_features` and `out_features`, the names error messages use. Creating it allocates the $16 \times 784$ weight matrix and the 16 biases and fills them with small random numbers:

```python
import torch
from torch import nn

layer = nn.Linear(784, 16)
print(layer.weight.shape, layer.bias.shape)
print(type(layer.weight))
```

```output
torch.Size([16, 784]) torch.Size([16])
<class 'torch.nn.parameter.Parameter'>
```

Row $j$ of `layer.weight` is neuron $j$'s 784 weights. Both tensors are `Parameter`s, so they have `requires_grad=True` from [PyTorch Tensors & Autograd](1.25-PY9-pytorch-tensors-autograd.md). Every operation on them is recorded, and training can later get a gradient for each of the 12,560 entries.

Calling the layer like a function runs $X W^\top + \mathbf{b}$ on a batch:

```python
x = torch.rand(5, 784)                   # a batch of 5 inputs
z = layer(x)
print(z.shape)
print(torch.allclose(z, x @ layer.weight.T + layer.bias))
```

The output has one row of 16 weighted sums per input, and the two ways of computing it agree:

```output
torch.Size([5, 16])
True
```

### The activation function

`torch.sigmoid` applies $\sigma$ to every entry of a tensor and leaves the shape alone:

```python
a = torch.sigmoid(z)
print(a.shape, a.min().item() > 0, a.max().item() < 1)
```

Every entry lands strictly between 0 and 1:

```output
torch.Size([5, 16]) True True
```

`nn.Sigmoid()` is the same function wrapped as a layer object, for places that expect layers, such as `nn.Sequential` below. `torch.tanh`, `torch.relu`, `nn.Tanh()` and `nn.ReLU()` follow the same pattern.

### The network

A model with several layers is written as a class that inherits from `nn.Module`. Every model in PyTorch is written this way, from this one to a Transformer, so each line of it matters:

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(784, 16)
        self.fc2 = nn.Linear(16, 16)
        self.fc3 = nn.Linear(16, 10)

    def forward(self, x):                   # x: (N, 784)
        a1 = torch.sigmoid(self.fc1(x))     # (N, 16)
        a2 = torch.sigmoid(self.fc2(a1))    # (N, 16)
        return self.fc3(a2)                 # (N, 10) scores, no activation
```

- `class MLP(nn.Module):` makes the model a subclass of `nn.Module`, the base class of every layer and model in PyTorch (`nn.Linear` is one too). Inheriting is what gives the model `parameters()`, `print(model)`, saving and loading, and moving to a GPU, without writing any of it.
- `def __init__(self):` runs once, when `MLP()` is called, and builds the model. `self` is the model being built.
- `super().__init__()` runs `nn.Module`'s own setup, which prepares the bookkeeping the next lines rely on. It has to come first: assign a layer before it and PyTorch raises an error.
- `self.fc1 = nn.Linear(784, 16)` creates the first layer and stores it as an attribute of the model. Storing a layer on `self` registers it, so its weights and biases count as the model's parameters. The name `fc1` (fully connected) is a choice, and it is the name that appears in the parameter listing below.
- `self.fc2 = nn.Linear(16, 16)` has its first number forced: a layer's input size is the previous layer's output size, so `fc2` and `fc3` both take 16 inputs. The second number of each hidden layer is a choice.
- `def forward(self, x):` is the forward pass: it takes a batch and returns the scores. Its three lines are the three equations from the explanation, with the shapes in the comments. Only `forward` is written. The backward pass is derived from it by autograd.
- `return self.fc3(a2)` returns raw scores with no activation function, which is what the loss function used in training expects.

`MLP()` runs `__init__`, so it creates the three layers and draws their random weights. `torch.manual_seed(0)` fixes that draw so the numbers below come out the same every run. Printing a module lists the layers it registered:

```python
torch.manual_seed(0)
model = MLP()
print(model)
```

The three layers are there, each with its sizes:

```output
MLP(
  (fc1): Linear(in_features=784, out_features=16, bias=True)
  (fc2): Linear(in_features=16, out_features=16, bias=True)
  (fc3): Linear(in_features=16, out_features=10, bias=True)
)
```

Calling the model runs `forward`. `nn.Module` turns `model(x)` into `forward(x)` after some bookkeeping of its own, so `model.forward(x)` is never written:

```python
scores = model(torch.rand(5, 784))
print(scores.shape)
```

Five inputs in, five rows of ten scores out:

```output
torch.Size([5, 10])
```

Every parameter is reachable by name, which is the quickest way to check the shapes and the count:

```python
for name, p in model.named_parameters():
    print(f"{name:11s}{str(tuple(p.shape)):12s}{p.numel():6d}")
print(sum(p.numel() for p in model.parameters()))
```

Six tensors, and the counts add up to the table above:

```output
fc1.weight (16, 784)    12544
fc1.bias   (16,)           16
fc2.weight (16, 16)       256
fc2.bias   (16,)           16
fc3.weight (10, 16)       160
fc3.bias   (10,)           10
13002
```

The same network in one expression is `nn.Sequential(nn.Linear(784, 16), nn.Sigmoid(), nn.Linear(16, 16), nn.Sigmoid(), nn.Linear(16, 10))`. It is itself an `nn.Module`, with the layers numbered instead of named, and it is fine for a straight chain. The class is the form to reach for once a forward pass does anything else. A plain Python list of layers stored on `self` is not registered. For a variable number of layers use `nn.ModuleList`, a list that `nn.Module` knows about.

`__init__` can take arguments like any other. With `def __init__(self, hidden=16):` and `hidden` in place of the four 16s, `MLP(hidden=64)` builds a wider network from the same class, with 55,050 parameters (50,240 + 4,160 + 650) instead of 13,002.

### Inside `nn.Linear`

`nn.Linear` is itself a short `nn.Module`. Written out, it is a class that stores the weight matrix and the bias as `nn.Parameter`s and multiplies in `forward`:

```python
class Layer(nn.Module):
    def __init__(self, n_in, n_out):
        super().__init__()
        self.W = nn.Parameter(torch.randn(n_out, n_in) / n_in ** 0.5)
        # (n_out, n_in), scaled to the fan-in
        self.b = nn.Parameter(torch.zeros(n_out))                       # (n_out,)

    def forward(self, x):                                               # x: (N, n_in)
        return x @ self.W.T + self.b                                    # (N, n_out)

mine = Layer(784, 16)
print(sum(p.numel() for p in mine.parameters()))
print(mine(x).shape)
```

Same parameter count as `nn.Linear(784, 16)`, same output shape:

```output
12560
torch.Size([5, 16])
```

`nn.Parameter` wraps a tensor and marks it as something the model owns. Storing one on `self` registers it the way storing a layer does, so `parameters()` finds it and training updates it. A plain tensor stored on `self` would be ignored. `nn.Linear` differs from `Layer` only in how it draws its starting values. Dividing by $\sqrt{n_\text{in}}$ keeps each output about the size of the inputs whatever $n_\text{in}$ is, and [Optimizers & Training Tricks](1.21-DL4-optimization-adam-sgd.md) explains why that matters.

### A forward pass on real images

```python
from torchvision import datasets

test = datasets.MNIST("data", train=False, download=True)
X_test = test.data.reshape(-1, 784).float() / 255   # (10000, 784), pixels 0 to 1
y_test = test.targets                                # (10000,), digits 0 to 9

scores = model(X_test[:5])
print(scores.shape)
print(scores.argmax(dim=1))                         # highest score per image
print(y_test[:5])                                   # the true digits
```

`reshape(-1, 784)` unrolls each $28 \times 28$ image into a row, and dividing by 255 scales the pixels to the range 0 to 1. `nn.Flatten()` as the first layer of a model does the same unrolling inside it, so the model can take the $28 \times 28$ images directly. Five images give five rows of ten scores, and with random weights the predictions are wrong:

```output
torch.Size([5, 10])
tensor([9, 9, 9, 9, 9])
tensor([7, 2, 1, 0, 4])
```

Softmax turns each row of 10 scores into 10 probabilities that sum to 1. The largest probability sits where the largest score was, so `argmax` gives the same answer either way, and the loss used in training works from these scores:

```python
probs = torch.softmax(scores, dim=1)               # (5, 10), each row sums to 1
print(torch.allclose(probs.sum(dim=1), torch.ones(5)))
print(probs[0].detach())                           # the first image's 10 probabilities
```

With random weights every digit gets about a tenth:

```output
True
tensor([0.0887, 0.0514, 0.1093, 0.1241, 0.1145, 0.0726, 0.0980, 0.1025, 0.1130,
        0.1260])
```

Accuracy over the whole test set is one more forward pass. It goes inside `torch.no_grad()`, which switches off autograd's recording: nothing will be trained from this pass, so the record would be wasted memory.

```python
with torch.no_grad():
    predictions = model(X_test).argmax(dim=1)
print(f"{(predictions == y_test).float().mean().item():.4f}")
```

The untrained network answers 9 for every image, which is right 10.09% of the time because 1,009 of the 10,000 test images are 9s:

```output
0.1009
```

### Saving and loading

A model is its class plus its `state_dict`, a dictionary with one tensor per parameter, keyed by the names from the listing above. Saving that dictionary is the standard way to save a model. The file holds only the numbers, and loading means building a fresh model from the class and copying the numbers in:

```python
state = model.state_dict()                      # name -> tensor
print(list(state.keys()))
torch.save(state, "mlp.pt")

fresh = MLP()                                   # new random weights
fresh.load_state_dict(torch.load("mlp.pt"))     # replaced by the saved ones
print(torch.equal(fresh.fc1.weight, model.fc1.weight))
```

The file is 54 KB for this network, and the copy matches:

```output
['fc1.weight', 'fc1.bias', 'fc2.weight', 'fc2.bias', 'fc3.weight', 'fc3.bias']
True
```

A Colab runtime that restarts loses everything in memory, and one that is recycled loses its disk as well. Save after training, and download the file or copy it to Drive. Save the `state_dict`, not the model object, which breaks as soon as the class changes. To resume training, save `optimizer.state_dict()` beside it.

### Training

Training adjusts the 13,002 parameters to make the scores match the labels. The optimizer is handed `model.parameters()`, the six tensors listed above, and every step is a forward pass, a loss, `optimizer.zero_grad()`, `loss.backward()` and an update. The backward pass gives a gradient for every parameter at about the cost of two forward passes. Getting the same numbers by nudging each weight up and down and watching the loss would take two forward passes per parameter, $2 \times 13{,}002 = 26{,}004$ of them. [Writing a Training Loop in PyTorch](1.26-PY10-training-loop-in-pytorch.md) goes through the loop one line at a time, and Part 4 of the notebook runs it: cross-entropy loss on the scores, plain gradient descent, ten passes over the 60,000 training images. After that the network reads 94.76% of the test images correctly. Widening the hidden layers to 128 and 64 neurons lifts the same code to about 97.7% (109,386 parameters: 100,480 + 8,256 + 650), and a [convolutional network](1.30-CV7-convolutional-neural-networks.md) does better again, because it uses something an MLP ignores: neighboring pixels belong together.
