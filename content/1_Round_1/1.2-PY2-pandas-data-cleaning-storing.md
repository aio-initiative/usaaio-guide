## Overview

Contest data arrives as a CSV file, and it is rarely ready for a model. A number column holds a stray `"?"`, the same city is spelled two ways, a row appears twice, and some cells are empty. How do you find these problems quickly, fix them without breaking anything, and end with a clean NumPy array?

That work happens in **pandas**, a library of labeled tables built on NumPy. Problem 3 of the 2025 Round 1 paper opened this way. It loaded a CSV and asked for code that prints the table's shape, column types and missing-value counts. The later parts cleaned that table, and only then fit a model to it.

## Example: clean a messy housing table

Here is a small CSV of houses, with one row per house:

```
id,city,size_m2,rooms,price
1,Boston,80,3,500
2,boston ,95,3,560
3,Austin,120,4,410
4,Austin,?,2,250
5,Denver,70,,300
3,Austin,120,4,410
6,denver,110,4,450
```

Load it, find everything wrong with it, and fix it. Then report the average price per city, and build a feature matrix `X` (size, rooms and the city as one-hot columns) with a target vector `y` (the price). How many houses are left after cleaning, and what shape is `X`?

## Explanation

### Series and DataFrame

pandas has two data structures. A **Series** is a one-dimensional array of values with an **index**, a label for each entry. A **DataFrame** is a table of named columns that share one row index. Each column has its own **dtype** (data type), so `city` can hold text while `price` holds integers. `df["price"]` selects one column as a Series, and `df[["size_m2", "rooms"]]` selects several as a smaller DataFrame. You can also reach a column as an attribute, `df.price`, but it is fragile: prefer the bracket form. It survives spaces and punctuation in a name, and it does not collide with DataFrame methods and properties: a column called `count` or `shape` is invisible to attribute access.

### Loading and inspecting a table

`pd.read_csv("houses.csv")` reads a file into a DataFrame. It also accepts a URL. To read CSV text stored in a Python string, as the code below does, wrap the string in `io.StringIO(raw)` first. Then look at the table before you change anything:

- `df.head()` shows the first 5 rows (`df.head(10)` shows 10), and `df.shape` gives `(rows, columns)`.
- `df.dtypes` lists each column's dtype. A text column shows `str` in pandas 3 and `object` in older versions. `df.info()` adds the count of non-missing values in each column.
- `df.describe()` gives the count, mean, standard deviation, minimum, quartiles and maximum of each numeric column. A minimum or maximum that makes no sense, such as a negative size, points to a bad entry.
- `df["city"].value_counts()` counts each distinct value, and `df["city"].nunique()` counts how many distinct values there are. Ties keep their order of first appearance, because the frequency sort is stable in pandas 3.
- `df.isna().sum()` counts the missing cells in each column (`isnull` is another name for `isna`). `df.duplicated().sum()` counts rows that repeat an earlier row in every column.

On the housing table these checks show four problems. `size_m2` has dtype `str`, because one cell holds `"?"`. `value_counts` lists `Boston`, `"boston "`, `Denver` and `denver` separately. One `rooms` value is missing. And one row is a duplicate.

### Fixing types

A column stored as text cannot be averaged or fed to a model. Convert it with

```python
df["size_m2"] = pd.to_numeric(df["size_m2"], errors="coerce")
```

`errors="coerce"` turns anything that is not a number into **NaN** ("not a number"), the floating-point value pandas uses to mark a missing number. Without it, the `"?"` raises an error. `astype` converts a column to another dtype, for example `df["id"].astype(str)`. `pd.to_datetime(df["date"])` turns date strings into datetime values you can sort and subtract. Dates unlock the `.dt` accessor:

```
df["date"].dt.year, df["date"].dt.month, df["date"].dt.day
```

**Missing values and integers.** NumPy integers have no way to store "missing", so a column of integers with a single NaN becomes `float64`. The `rooms` column reads `3.0`, `4.0` and so on for this reason. After filling the gap you can convert back with `astype(int)`, which raises an error while any NaN remains. pandas also has a nullable `"Int64"` dtype, which allows missing values in an integer column. A low-cardinality string column is cheaper and faster stored as a category:

```
df["team"] = df["team"].astype("category")
```

<ProblemCard id="pdc-coerce-hides-fixable-prices" />

### Cleaning text and duplicates

Text columns have `.str`, which applies a string method to every entry at once. `.str.strip()` removes spaces at both ends. `.str.lower()` and `.str.title()` fix capitalization, and `.str.replace("-", "")` swaps text. `.str.contains("ton")` gives True for each entry that contains `"ton"`. So

```python
df["city"] = df["city"].str.strip().str.title()
```

turns `"boston "` into `"Boston"` and `"denver"` into `"Denver"`, leaving three cities instead of five.

`df.drop_duplicates()` removes rows that repeat an earlier row in every column. `subset=["id"]` judges duplicates by some columns only, and `keep="last"` keeps the last copy instead of the first. The order of the steps matters here. Before the text is cleaned, `"boston "` and `"Boston"` are different values, so two rows that differ only there are not duplicates. After cleaning they match. Decide whether such rows are the same record before you choose the order.

A duplicated row can also end up both in the rows you train a model on and in the rows you test it on. The model is then tested on a row it has already seen, so its test score comes out too high.

### Handling missing data

Three methods handle NaN, and also **NaT** ("not a time"), its version in a date column:

- `df.isna()` marks missing cells. Use it to count them or as a mask.
- `df.fillna(value)` replaces them. The value can be a constant, or a dict with one value per column such as `{"rooms": df["rooms"].median()}`. To fill one column row by row, call `fillna` on that column with a Series that has the same index. Each gap takes the value with its row label.
- `df.dropna()` deletes rows with any missing value. `subset=["price"]` checks only some columns, `how="all"` deletes only rows that are entirely missing, and `axis=1` deletes columns instead of rows.

Adding two Series pairs entries by their labels, not their positions. Suppose one Series stores scores under labels `A, B`, while another stores bonuses under `B, A`. Adding them matches A with A and B with B, even though those entries occupy different positions. If the second Series contains C instead of A, the result contains a missing value for the unmatched calculation.

Aggregations such as `mean`, `sum` and `median` skip NaN, so the mean of 1, NaN and 3 is 2.

These methods return a new table and leave `df` as it was, so write `df = df.dropna()` to keep the result. The same holds for `drop_duplicates` and `sort_values`. To edit a table while keeping the original, start from `df2 = df.copy()`. `copy()` makes a deep copy by default, so changing `df2` never changes `df`.

Filling with the **median** is a common default for numbers, because one huge value cannot drag it around the way it drags the mean. When groups differ a lot, fill from the row's own group. A missing Boston price should come from Boston prices, not from all prices. `groupby` with `transform`, below, does this. Dropping a row loses its other values. Filling assumes the missing value looks like the values you filled it from.

### Selecting rows: loc, iloc and masks

There are two ways to pick rows and columns:

- **`.loc`** selects by **label**: index values and column names. `df.loc[0, "city"]` is the city in the row labeled 0.
- **`.iloc`** selects by **position**, like NumPy. `df.iloc[0, 1]` is the first row and second column, whatever its labels.

After filtering, sorting or dropping rows, labels no longer match positions. After `drop_duplicates()` the housing table's labels are 0, 1, 2, 3, 4, 6, because the row labeled 5 was the repeat. Now `df.iloc[5]` is the Denver house labeled 6, and `df.loc[5]` raises a `KeyError`. A `.loc` slice includes its end (`df.loc[0:2]` is three rows), while `.iloc[0:2]` follows Python and gives two. `df.reset_index(drop=True)` renumbers the rows from 0.

To keep some rows, index with a boolean mask:

```python
cheap_big = df[(df["price"] < 450) & (df["size_m2"] >= 100)]
```

On the cleaned housing table this keeps one house, id 3 (Austin, 120 m², price 410). The Python words `and`, `or` and `not` need a single True or False, so they fail on a whole column of them. `&`, `|` and `~` work entry by entry. Python evaluates `&` before `<` and `>=`, so each comparison needs its own parentheses. `df.sort_values("price", ascending=False)` sorts rows, and `df.query("price < 450")` is another way to write a filter. To test membership in a list, `df["city"].isin(["Boston", "Austin"])` is a mask that is `True` where `city` is one of those values, and `~` inverts it:

```python
df[df["city"].isin(["Boston", "Austin"])]
```

<ProblemCard id="pdc-labels-after-a-filter" />

### New columns, without loops

Column arithmetic works on whole columns at once, as in NumPy:

```python
df["price_per_m2"] = df["price"] / df["size_m2"]
df["is_big"] = np.where(df["size_m2"] >= 100, 1, 0)
df["region"] = df["city"].map({"Boston": "East", "Austin": "South", "Denver": "West"})
```

`np.where(condition, a, b)` gives `a` where the condition holds and `b` elsewhere. `map` replaces each value through a dict or a function. A value the dict does not list becomes NaN, so a category you forgot shows up as a missing cell instead of a silent wrong code. When no column operation fits, `df.apply(func, axis=1)` calls `func` once per row, passing it the whole row. That runs a Python loop, and so does `for _, row in df.iterrows()`. On a 100,000-row table both are far slower than the column version, so try column arithmetic first.

<ProblemCard id="pdc-a-fee-in-tiers" />

### Groupby: split, apply, combine

`groupby` answers "per category" questions in three steps:

1. First **split** the rows into groups by one or more key columns.
2. Then **apply** a function to each group, usually an aggregation such as `mean`, `sum`, `count` or `max`.
3. Finally **combine** the results into one smaller table indexed by the keys.

`df.groupby("city")["price"].mean()` gives one average per city. A group key of NaN is dropped from the result by default (`groupby(dropna=True)`), so fill or drop missing keys before you group. For several statistics at once, use named aggregations:

```python
df.groupby("city").agg(n=("price", "size"), mean_price=("price", "mean"))
```

Each keyword becomes an output column, and its tuple says which column to use and which function to apply. `size` counts all rows in the group, while `count` counts only the non-missing values. The result is indexed by `city`. `.reset_index()` turns that index back into an ordinary column, and `groupby("city", as_index=False)` gives the same result in one step.

`transform` is the other common verb. It returns one value per **original row** rather than one per group, so `df.groupby("city")["price"].transform("mean")` gives each house its city's average. It can fill each missing price from its own city:

```python
df["price"] = df["price"].fillna(df.groupby("city")["price"].transform("median"))
```

It also builds features such as "price minus the city's average price".

### Combining tables: concat and merge

`pd.concat([a, b])` stacks tables with the same columns on top of each other, for example two months of logs. `ignore_index=True` renumbers the rows.

`merge` matches rows of two tables that share a value in a key column, and glues each matching pair into one row. The call is `people.merge(scores, on="id", how="left")`, where `on` names the key column. `how` decides what happens to keys found in only one table. Suppose `people` has ids 1, 2, 3 and `scores` has ids 1, 1, 2, 4:

- `how="inner"`, the default, keeps keys in **both** tables, giving 3 rows. Ids 3 and 4 are dropped, and id 1 appears twice because it matches two score rows.
- `how="left"` keeps **every** row of the left table and fills the unmatched columns with NaN, giving 4 rows. Id 3 survives with a missing score.
- `how="outer"` keeps keys from **either** table and fills gaps on both sides, giving 5 rows.

Compare row counts before and after a merge. More rows than expected means a key was not unique and the join multiplied rows. Fewer means an inner join dropped some. When no key on the right repeats, a `how="left"` join returns exactly `len(left)` rows, so that check cannot see a bad key match. Counting the `NaN`s it produced is how you discover that the keys matched less well than you assumed.

### Reshaping: pivot and melt

Data comes in two layouts. **Long** format has one row per measurement: `(store, month, units)`. **Wide** format has one row per store and one column per month.

- `df.pivot_table(index="store", columns="month", values="units", aggfunc="sum")` goes from long to wide. `pivot_table` sorts the new row and column labels, so the months come out alphabetically (Feb, Jan, Mar), not in calendar order. Pass `sort=False` to keep the order they appear in. Missing combinations become NaN, and `aggfunc` says how to combine repeated entries. Without `aggfunc`, `pivot_table` takes the mean of repeated entries. Plain `pivot` raises an error if a (store, month) pair repeats.
- `wide.reset_index().melt(id_vars="store", value_name="units")` goes back to long. It gives one row per (store, month) pair, with columns `store`, `month` and `units`. A wide table with $n$ rows and $k$ variable columns melts to $nk$ rows and 3 columns: the id column, the variable column and the value column (here `store`, `month` and `units`). Count $2 \times 3 = 6$ rows before `.dropna()`, which removes store A's missing March and leaves the printed `(5, 3)`.

### From a table to features and a target

Models need numbers, so a text column such as `city` becomes **one-hot** columns: one 0/1 column per category. `pd.get_dummies(df, columns=["city"], dtype=float)` replaces `city` with `city_Austin`, `city_Boston` and `city_Denver`, and a Boston house gets 0, 1 and 0.

For a house whose city is one of these three, the three columns add up to 1, so any one of them follows from the other two. A row with a missing or unseen city gets 0 in all of them. `drop_first=True` drops the first column, `city_Austin`, and an Austin house becomes (0, 0). Use it for a model that multiplies each column by a weight and adds a constant (an **intercept**), such as linear or logistic regression. With all three city columns, adding 1 to every city weight and subtracting 1 from the intercept gives the same predictions, so the best weights are not unique. [Feature Engineering & Data Preparation](1.13-ML1-data-processing-features.md) covers other encodings.

To split a table into features and target, drop the target column for `X` and select it for `y`: `X = df.drop(columns=["price"])` and `y = df["price"]`. `df.drop("price", axis=1)` means the same thing, and `drop` leaves `df` unchanged. scikit-learn accepts a DataFrame or a NumPy array. PyTorch builds tensors from NumPy arrays, and `X.to_numpy()` gives one. Before handing `X` to a model, check that every column is numeric and nothing is missing. `X.to_numpy()` returns a plain array, so the row labels and the column names disappear. Read them off first: `list(X.columns)` for the names, and `df["id"]` for the row ids.

To check a model on rows it has not seen, hold some rows back as a **test set** and train on the rest, the **training set**. A random split shuffles the row positions and cuts the list. With `idx = np.random.default_rng(0).permutation(len(df))`, the test set is `df.iloc[idx[:k]]`, the first `k` shuffled rows, and the training set is `df.iloc[idx[k:]]`. When rows have dates, split **by time** instead: sort by date and keep the latest rows for testing. A random split lets the model learn from later days and be tested on earlier ones. Its score then looks better than it will be on new days.

Compute fill values such as the median from the training rows only, and use them for both sets. Otherwise the test rows shape the training data. The focus table has no split yet, so it uses all rows.

<ProblemCard id="pdc-dummies-on-each-split" />

### Solving the focus problem

Take the fixes in order. Dropping the repeated id 3 row turns 7 rows into 6. Stripping and title-casing `city` turns `"boston "` into `"Boston"` and `"denver"` into `"Denver"`, leaving 3 cities. Converting `size_m2` turns the `"?"` into NaN. Fill each gap with its column's median. The known sizes 70, 80, 95, 110 and 120 have median 95, and the known rooms 2, 3, 3, 4 and 4 have median 3.

Now group by city and average the prices. Austin is (410 + 250) / 2 = 330, Boston is (500 + 560) / 2 = 530, and Denver is (300 + 450) / 2 = 375. For `X`, drop `id` and `price` and one-hot encode `city`. That leaves 2 numeric columns plus 3 city columns, so `X` has shape $6 \times 5$: $n = 6$ houses and $d = 5$ features. `y` holds the 6 prices.

## Implementation

The first block loads the focus CSV and runs the inspection checks:

```python
import io
import numpy as np
import pandas as pd

raw = """id,city,size_m2,rooms,price
1,Boston,80,3,500
2,boston ,95,3,560
3,Austin,120,4,410
4,Austin,?,2,250
5,Denver,70,,300
3,Austin,120,4,410
6,denver,110,4,450
"""
df = pd.read_csv(io.StringIO(raw))      # a file path or URL works the same way
print("shape:", df.shape)
print(df.head(3))
print(df.dtypes)
print(df["city"].value_counts())
print(df.isna().sum())
print("duplicate rows:", df.duplicated().sum())
```

`size_m2` has dtype `str` because of the `"?"`, and `isna` finds no missing sizes. `rooms` is `float64` because its one missing value forced the column to float.

The next block removes the duplicate, cleans the city names, converts `size_m2`, fills both gaps with the column medians and prints the average price per city. Then it builds `X` and `y`, once with all three city columns and once with `drop_first=True`:

```python
df = df.drop_duplicates()                                       # the repeated id 3 row
df["city"] = df["city"].str.strip().str.title()                 # "boston " -> "Boston"
df["size_m2"] = pd.to_numeric(df["size_m2"], errors="coerce")   # "?" -> NaN
print("shape:", df.shape, " cities:", sorted(df["city"].unique()))
print("size_m2 dtype:", df["size_m2"].dtype)

medians = {"size_m2": df["size_m2"].median(), "rooms": df["rooms"].median()}
print("medians:", {k: float(v) for k, v in medians.items()})
df = df.fillna(medians)
print(df.isna().sum().sum(), "missing values left")
print(df.groupby("city")["price"].agg(["count", "mean"]))

features = df.drop(columns=["id", "price"])
X = pd.get_dummies(features, columns=["city"], dtype=float)
y = df["price"]
print(list(X.columns))
print("X:", X.to_numpy().shape, " y:", y.to_numpy().shape)

X_drop = pd.get_dummies(features, columns=["city"], drop_first=True, dtype=float)
print(list(X_drop.columns))
```

The medians and the city averages match the hand computation, and `size_m2` is now `float64`. With `drop_first=True` the `city_Austin` column is gone, so `X_drop` has 4 columns.

The last block fills a missing value from its own group, reshapes between long and wide, and stacks another table underneath:

```python
sales = pd.DataFrame({"store": ["A", "A", "B", "B", "B"],
                      "month": ["Jan", "Feb", "Jan", "Feb", "Mar"],
                      "units": [10, 12, 7, np.nan, 9]})
print("units dtype:", sales["units"].dtype)          # NaN forces float

# fill a store's missing value with that store's own mean
sales["units"] = sales["units"].fillna(sales.groupby("store")["units"].transform("mean"))
print(sales)

wide = sales.pivot_table(index="store", columns="month", values="units", aggfunc="sum")
print(wide)
long = wide.reset_index().melt(id_vars="store", value_name="units").dropna()
print("back to long:", long.shape)

more = pd.DataFrame({"store": ["C"], "month": ["Jan"], "units": [5.0]})
print("after concat:", pd.concat([sales, more], ignore_index=True).shape)
```

```output
units dtype: float64
  store month  units
0     A   Jan   10.0
1     A   Feb   12.0
2     B   Jan    7.0
3     B   Feb    8.0
4     B   Mar    9.0
month   Feb   Jan  Mar
store                 
A      12.0  10.0  NaN
B       8.0   7.0  9.0
back to long: (5, 3)
after concat: (6, 3)
```

Store B's missing February became 8, the mean of its 7 and 9. Store A had no March sale, so the wide table shows NaN there, and `dropna` removes it again when going back to long format.

> **Warning.**
>
> `df[df["price"] < 400]["price"] = 0` first builds a filtered copy and then sets values in that copy. In pandas 3, `df` never changes, and pandas prints a `ChainedAssignmentError` warning. Select and assign in one step with `.loc`: `df.loc[df["price"] < 400, "price"] = 0`.
