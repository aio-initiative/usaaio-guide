## Printing and comments

A program runs top to bottom, one line at a time. `print(...)` writes values to the screen, and `#` starts a comment, which Python ignores.

<EmbeddedPyEditor>
# This line is a comment.
print("hello, olympiad")
print(2 + 2)
print("2" + "2")      # + joins text, so this prints 22
</EmbeddedPyEditor>

The last two lines use the same `+` but do different things, because `2` is a number and `"2"` is text. What kind of thing a value is, number or text or something else, is its **type**.

## Variables and types

A **variable** is a name for a value, set with `=`. You don't declare a type. Python works it out from the value.

```python
n = 5              # int: a whole number
pi = 3.14159       # float: a decimal number
name = "Ada"       # str: text, in single or double quotes
ready = True       # bool: True or False
nothing = None     # None: "no value"
```

`type(x)` shows the type, and `int()`, `float()`, `str()` and `bool()` convert between types. Data read from a file arrives as text, so `"42"` is not the number `42` until you call `int("42")`.

## Numbers and operators

`+ - * /` work as usual. Python has three more you will use all the time:

- `**` is a power: `2 ** 10` is `1024`.
- `//` is **floor division**, which divides and rounds down: `7 // 2` is `3`, and `-7 // 2` is `-4`.
- `%` is the **remainder**: `7 % 2` is `1`, so `n % 2 == 0` tests whether `n` is even.

`/` always gives a float, so `4 / 2` is `2.0`. In a longer expression Python does `**` first, then `*`, `/`, `//` and `%`, then `+` and `-`. So `2 + 3 * 2 ** 2` is `2 + 12`, which is `14`. When in doubt, add parentheses.

Comparisons (`==`, `!=`, `<`, `<=`, `>`, `>=`) give a bool, and bools combine with `and`, `or` and `not`.

## Strings

A string is text. To build one from values, use an **f-string**: put `f` before the quote and write expressions inside `{...}`.

<EmbeddedPyEditor>
model = "resnet"
acc = 0.9376
print(f"{model} reached {acc:.1%} accuracy")   # resnet reached 93.8% accuracy
print(f"{model:<8}|{acc:.2f}")                   # pad to 8 characters, 2 decimals
print("vit,0.94".split(","))                     # cut at the comma
print("edge".upper(), len("attention"))
</EmbeddedPyEditor>

After the colon inside `{...}` comes a **format**: `.1%` is a percentage with one decimal, `.2f` is two decimals, and `<8` pads to 8 characters.

`"vit,0.94".split(",")` cuts the string at every comma and returns the pieces as a list, `["vit", "0.94"]`. With nothing inside the parentheses, `.split()` cuts at spaces. `.split` and `.upper` are **methods**, which are functions that belong to a value and are called with a dot.

You can pick characters out by position, counting from 0. `s[0]` is the first character and `s[-1]` is the last. The **slice** `s[1:4]` gives characters 1, 2 and 3, because a slice stops just before its end index.

## Lists and tuples

A **list** holds values in order: `nums = [3, 1, 4]`. It indexes and slices like a string, and unlike a string it can change:

- `nums.append(5)` adds to the end, and `nums[0] = 7` replaces an item.
- `len(nums)` counts the items, and `4 in nums` tests whether `4` is there.
- `+` joins two lists, and `[0] * 3` is `[0, 0, 0]`.

A **tuple** is like a list but cannot change: `shape = (28, 28)`. Tuples hold small fixed groups, like the height and width of an image. You can **unpack** a tuple or list into names: `h, w = shape` sets both `h` and `w` to `28`.

## if, elif and else

<EmbeddedPyEditor>
loss = 0.42
if loss < 0.1:
    print("great")
elif loss < 0.5:
    print("okay, keep training")
else:
    print("something is wrong")
</EmbeddedPyEditor>

A line ending in a colon starts a **block**, and the indented lines under it belong to it. Python groups lines by indentation rather than braces, so the spacing is part of the code. Indent each level by four spaces.

`if` also accepts values that are not bools. `0`, `0.0`, `""`, empty lists and dicts, and `None` count as false, and almost everything else counts as true. That is why `if not values:` catches an empty list.

## Loops

<EmbeddedPyEditor>
for i in range(5):            # i = 0, 1, 2, 3, 4
    if i == 3:
        break                 # leave the loop early
    print("step", i)

n = 20
while n > 1:                  # repeat while the condition holds
    n = n // 2
print("n is now", n)

words = ["cat", "sat", "mat"]
for i, w in enumerate(words):              # index and item together
    print(i, w)
for x, y in zip([1, 2, 3], [10, 20, 30]):  # two lists in step
    print(x, "->", y)
</EmbeddedPyEditor>

- A `for` loop runs once per item, and `range(n)` gives `0` to `n - 1`.
- A `while` loop repeats while its condition is true.
- `break` leaves the loop, and `continue` jumps to the next item.
- `enumerate(xs)` gives (index, item) pairs counting from 0, or from 1 with `enumerate(xs, start=1)`.
- `zip(xs, ys)` pairs items in step and stops at the end of the shorter list, with no error.

A line indented one level too little runs once after the loop instead of on every pass, and Python raises no error. When a loop misbehaves, check the indentation first.

A **list comprehension** builds a list in one line. `[x * x for x in range(6)]` gives the squares from 0 to 25, and `[x for x in nums if x > 2]` keeps only the items above 2.

## Dictionaries and sets

A **dictionary** maps keys to values: `best = {"vit": 0.94}`.

- `best["vit"]` reads a value, and `best["cnn"] = 0.88` writes one.
- `best.get(key, default)` gives `default` when the key is missing, where `best[key]` would raise an error.
- `best.items()` gives (key, value) pairs. Looping over a dict goes through its keys, and so do `sorted(best)` and `max(best)`.

A **set** holds unique values: `{1, 2, 2, 3}` is `{1, 2, 3}`. Use it to drop duplicates or to test membership quickly with `in`.

<EmbeddedPyEditor>
nums = [3, 1, 4, 1, 5]
counts = {}
for x in nums:
    counts[x] = counts.get(x, 0) + 1    # count each number
print(counts)                           # {3: 1, 1: 2, 4: 1, 5: 1}
print(set(nums), 4 in set(nums))
</EmbeddedPyEditor>

`counts.get(x, 0)` gives `0` the first time a number appears, so the count starts at zero instead of raising an error. A dict comprehension works like a list one: `{w: len(w) for w in words}`.

## Functions

A **function** gives a piece of code a name so you can run it again with different inputs.

<EmbeddedPyEditor>
def min_max(values, scale=1.0):
    """Return the smallest and largest value, times scale."""
    return min(values) * scale, max(values) * scale

lo, hi = min_max([10, 12, 16])               # unpack the two results
print(lo, hi)                                # 10.0 16.0
print(min_max([10, 12, 16], scale=0.5))      # (5.0, 8.0)
</EmbeddedPyEditor>

- `def` names the function and its **arguments**. `scale=1.0` is a **default**, used when the caller leaves it out.
- `return` hands a value back to the caller, which can store it or use it again. `print` only shows a value on the screen. Mixing the two up is one of the most common beginner bugs. A function with no `return` gives back `None`.
- `return a, b` returns a tuple, which the caller can unpack.
- The triple-quoted line is a **docstring**, a note for people reading the code.

### Sorting with a key

`sorted(xs)` returns a new sorted list, and `reverse=True` flips the order. To sort by something else, pass a **key**: a function that Python calls on each item before comparing. `sorted(["bb", "a", "ccc"], key=len)` gives `["a", "bb", "ccc"]`.

A **lambda** is a one-line function with no name, often used as a key. This ranks (name, score) pairs by score, highest first:

```python
ranked = sorted(best.items(), key=lambda item: item[1], reverse=True)
```

`max` and `min` take a key too: `max(best, key=best.get)` is the key with the largest value.

A key can also return a tuple. Tuples compare entry by entry, the way words are ordered in a dictionary. So `sorted(words, key=lambda w: (-len(w), w))` puts longer words first and breaks ties alphabetically. The minus sign flips one entry only, while `reverse=True` would flip both. Python's sort is **stable**: items with equal keys keep their original order.

## Errors and try / except

When something goes wrong, Python **raises an exception** and stops. `float("n/a")` raises `ValueError`, a missing dict key raises `KeyError`, and `1 / 0` raises `ZeroDivisionError`. To handle an error instead of crashing, put the risky code under `try` and say what to do under `except`:

<EmbeddedPyEditor>
for text in ["0.91", "n/a", "0.88"]:
    try:
        score = float(text)
    except ValueError as err:
        print("skipping", text, "->", err)
        continue
    print("score", score)
</EmbeddedPyEditor>

`as err` stores the error so you can print its message. Catch only the error you expect. A bare `except:` catches everything, including a misspelled variable name, so a real bug fails silently.

Your own code stops with an error using `raise`, for example `raise ValueError("lr must be positive")`.

## Classes

A **class** bundles data together with the functions that work on it. Every PyTorch model is a class, so you will write one in almost every deep-learning task.

```python
class Counter:
    def __init__(self, start=0):
        self.count = start          # an attribute, stored on this object

    def add(self, k=1):
        self.count += k             # methods read and change attributes

c = Counter()
c.add()
c.add(5)
print(c.count)
```

```output
6
```

- `__init__` runs when you create an object with `Counter()`. It sets up the object's **attributes**, the values stored on it.
- `self` is the object itself. Every method takes it first, and Python passes it for you: `c.add(5)` runs `Counter.add(c, 5)`.
- Each object keeps its own attributes, so two counters count separately.

`__init__` is also the place to check the settings someone passes in. The 2025 Round 1 paper asked for exactly that in a logistic-regression class, where an unknown `solver` had to raise an error.

```python
class LogReg:
    def __init__(self, solver, lr):
        if solver not in ("GD", "Newton"):
            raise ValueError("Invalid solver")
        self.solver = solver
        self.lr = lr

model = LogReg("GD", 0.1)
print(model.solver, model.lr)
try:
    LogReg("SGD", 0.1)
except ValueError as err:
    print("error:", err)
```

```output
GD 0.1
error: Invalid solver
```

### Inheritance and nn.Module

A class can **inherit** from a parent class. It gets all the parent's methods and can add new ones or replace some. Inside the child, `super()` reaches the parent, so `super().__init__(...)` runs the parent's setup. And `__call__` is the method Python runs when you put parentheses after an object.

PyTorch builds every model out of these three ideas. Here they are in plain Python first:

```python
class Layer:
    def __init__(self, name):
        self.name = name

    def __call__(self, x):           # lets you write layer(x)
        return self.forward(x)

class Scale(Layer):                  # Scale inherits from Layer
    def __init__(self, factor):
        super().__init__("scale")    # run Layer's __init__ first
        self.factor = factor

    def forward(self, x):
        return [self.factor * v for v in x]

s = Scale(3)
print(s.name, s([1, 2, 5]))
```

```output
scale [3, 6, 15]
```

`s([1, 2, 5])` ran `Layer.__call__`, which called `Scale.forward`. PyTorch's `nn.Module` does the job of `Layer` here, so a real layer looks almost the same:

```python
import torch.nn as nn

class MyLayer(nn.Module):
    def __init__(self, d_in, d_out):
        super().__init__()                    # always first
        self.linear = nn.Linear(d_in, d_out)

    def forward(self, x):                     # layer(x) calls this
        return self.linear(x).relu()
```

You will build a full model this way in [The Multilayer Perceptron](1.18-DL1-neural-networks-perceptrons-mlps-activations.md).

## Names and copies

`b = a` does not copy anything. It gives the same object a second name, so changing a list through `b` changes `a` too. This only bites with values that can change in place, like lists, dicts, sets and most objects. Numbers, strings and tuples never change in place, so sharing them is harmless.

- A **shallow copy**, `a.copy()` or `list(a)`, makes a new outer container but shares the items inside.
- A **deep copy**, `copy.deepcopy(a)`, copies everything inside as well. Use it for nested data, or to keep a model's best weights while training continues.

```python
import copy

weights = {"layer1": [0.5, -0.2], "layer2": [1.0]}
alias = weights                  # same dict, two names
shallow = weights.copy()         # new dict, same inner lists
deep = copy.deepcopy(weights)    # new dict, new lists
weights["layer1"][0] = 99.0
print("alias  ", alias["layer1"])
print("shallow", shallow["layer1"])
print("deep   ", deep["layer1"])
```

```output
alias   [99.0, -0.2]
shallow [99.0, -0.2]
deep    [0.5, -0.2]
```

The shallow copy changed along with the original because the two share their inner lists. Only the deep copy kept `0.5`.

<ProblemCard id="py-shallow-copy-keeps-some" />

Two common bugs come from the same rule:

- `[[0] * 3] * 3` repeats one row three times, so changing `grid[0][0]` changes every row. Write `[[0] * 3 for _ in range(3)]` instead. The name `_` is the usual choice for a loop variable you never use.
- A default like `def f(x, seen=[])` is created once and shared by every call. Use `seen=None` and make the list inside the function.

## Putting it together

A training log has one line per run, as `"model,score"`, and some lines are broken:

```python
lines = ["resnet,0.91", "vit,0.94", "resnet,0.93", "mlp,n/a", "vit,0.92", "cnn,0.88", "badline"]
```

The task is to keep each model's best score, skip the broken lines without crashing, and list the top 3. It needs `split` and unpacking, `try` and `except`, a dict with `get`, sorting with a key, and a class. Try it yourself before reading on.

Two lines are broken. `"mlp,n/a"` fails at `float("n/a")`, and `"badline"` has no comma, so it cannot be unpacked into two names. Both raise `ValueError`, so a single `except` handles them. Among the good lines, resnet's best score is 0.93 and vit's is 0.94.

```python
class Leaderboard:
    def __init__(self):
        self.best = {}          # model name -> best score so far
        self.skipped = 0

    def add(self, line):
        try:
            name, text = line.split(",")
            score = float(text)
        except ValueError:      # "n/a" is not a number, "badline" has no comma
            self.skipped += 1
            return
        if score > self.best.get(name, float("-inf")):
            self.best[name] = score

    def top(self, k):
        ranked = sorted(self.best.items(), key=lambda item: item[1], reverse=True)
        return ranked[:k]

board = Leaderboard()
for line in lines:
    board.add(line)
print("skipped:", board.skipped)
for rank, (name, score) in enumerate(board.top(3), start=1):
    print(f"{rank}. {name:<7}{score:.2f}")
```

```output
skipped: 2
1. vit    0.94
2. resnet 0.93
3. cnn    0.88
```

`float("-inf")` is smaller than any real score, so a model's first score always wins. In the last loop, `start=1` numbers the models from 1, and `{name:<7}` pads each name so the scores line up.
