## Overview

An experiment log has seven lines, and some of them are broken. How do you find the three best models without your program crashing on the bad lines?

Every USAAIO coding task is answered in Python, and Round 1 tests more than loops. The 2025 paper asked for a hand-written logistic-regression class that raises an error for an invalid `solver` setting. It also used `copy.deepcopy` to copy a pandas DataFrame before changing it. The 2026 paper asked for custom PyTorch modules, which are Python classes too.

You need no programming background. Every editable code box below runs in your browser, so change the code and run it again.

## Example: a leaderboard from messy results

An experiment log has one line per run, as `"model,score"`. Some lines are broken:

```python
lines = ["resnet,0.91", "vit,0.94", "resnet,0.93", "mlp,n/a", "vit,0.92", "cnn,0.88", "badline"]
```

Write a `Leaderboard` class with two methods. `add(line)` keeps each model's best score and counts the lines it had to skip. `top(k)` returns the `k` best models, highest score first.

Before reading on, work out by hand what `top(3)` should return for these seven lines, and how many lines get skipped.

## Explanation

### Running code and printing

A Python program is a list of statements run top to bottom. `print(...)` writes values to the screen, and `#` starts a comment that Python ignores.

<EmbeddedPyEditor>
# This is a comment. The line below is a statement.
print("hello, olympiad")
print(2 + 2)          # arithmetic works as you'd expect
print("2" + "2")      # but on strings, + means "join" -> 22
</EmbeddedPyEditor>

The same symbol `+` does different things depending on the **type** of the values on each side, such as number or text.

### Variables, types and operators

A **variable** is a name bound to a value with `=`. You never declare a type, because Python works it out.

```python
n = 5              # int: a whole number
pi = 3.14159       # float: a decimal number
name = "Ada"       # str: text, in single or double quotes
ready = True       # bool: True or False
nothing = None     # NoneType: the "no value" value
```

`type(x)` tells you the type. `int()`, `float()`, `str()` and `bool()` convert between types. Data often arrives as text, and `"42"` is not `42` until you call `int("42")`.

The arithmetic operators are `+ - * /`, plus three that trip up beginners:

- `**` is exponentiation: `2 ** 10` is `1024`.
- `//` is **floor division** (divide and round towards minus infinity): `7 // 2` is `3` and `-7 // 2` is `-4`.
- `%` is the **remainder**: `7 % 2` is `1`, so `n % 2 == 0` tests whether `n` is even.

Plain `/` always gives a float: `4 / 2` is `2.0`. On strings and lists, `+` joins and `*` repeats: `"ab" * 3` is `"ababab"` and `[0] * 3` is `[0, 0, 0]`.

When an expression mixes operators, Python does `**` first, then `*`, `/`, `//` and `%` from left to right, then `+` and `-`. So `2 + 3 * 2 ** 2` is `2 + 3 * 4`, which is `14`. Add parentheses when in doubt.

Comparisons (`== != < <= > >=`) give a `bool`, and bools combine with the words `and`, `or` and `not`.

### Strings and f-strings

To build a string from values, use an **f-string**: put `f` before the quote and write expressions inside `{...}`.

<EmbeddedPyEditor>
model = "resnet"
acc = 0.9376

print(f"{model} reached {acc:.1%} accuracy")   # -> resnet reached 93.8% accuracy
print(f"{model:<8}|{acc:.2f}")                   # pad to 8 characters, 2 decimals
print("vit,0.94".split(","))                     # cut at the comma
print("edge".upper(), len("attention"))          # a method, and the length
</EmbeddedPyEditor>

After the colon inside `{...}` comes a **format spec**: `.1%` means a percentage with one decimal, `.2f` means two decimals, and `<8` pads to 8 characters.

`"vit,0.94".split(",")` cuts the string at every comma and returns the pieces as a list, `["vit", "0.94"]`. A string with no comma comes back as a one-item list. With nothing inside the parentheses, `.split()` cuts at any run of spaces, tabs or newlines. `.split` and `.upper` are **methods**: functions that belong to a value and are called with a dot.

Strings are **sequences**: ordered collections you can index by position. Counting starts at 0: `s[0]` is the first character and `s[-1]` is the last. The **slice** `s[1:4]` gives characters 1, 2 and 3, because the end index is excluded. Lists and tuples index and slice the same way.

### Control flow and loops

`if`, `elif` and `else` choose which code runs. A line ending in a colon starts a **block**: the indented lines under it belong to that `if`, loop or function. Indent each level by four spaces. Many languages group lines with curly braces, but Python uses only the indentation. A line indented one level too little runs once after a loop instead of on every pass, with no error.

<EmbeddedPyEditor>
loss = 0.42
if loss < 0.1:
    print("great")
elif loss < 0.5:
    print("okay, keep training")
else:
    print("something is wrong")

for i in range(5):            # i = 0, 1, 2, 3, 4
    if i == 3:
        break                 # leave the loop early
    print("step", i)

n = 20
while n > 1:                  # repeat while the condition holds
    n = n // 2
print("n is now", n)

words = ["cat", "sat", "mat"]
for idx, w in enumerate(words):     # index and value together
    print(idx, w)
for x, y in zip([1, 2, 3], [10, 20, 30]):   # two lists in step
    print(x, "->", y)
</EmbeddedPyEditor>

A `for` loop runs once per item. `range(n)` gives `0, 1, ..., n - 1`. A `while` loop repeats as long as its condition holds. `break` leaves a loop and `continue` skips to the next item.

`enumerate(xs)` gives (index, item) pairs counting from 0, or from 1 with `enumerate(xs, start=1)`. `zip(xs, ys)` pairs items in step and stops when the shorter list runs out. `zip([1, 2, 3], [10, 20])` gives only two pairs, with no error.

`if` also accepts values that are not bools. Empty strings, empty containers, `0`, `0.0`, `False` and `None` count as false, and everything else counts as true unless its class sets its own rule. So `if s:` skips blank strings, and `if not values:` catches an empty list.

### The four built-in containers

- A **list** is an ordered, changeable sequence: `nums = [3, 1, 4]`. Index it with `nums[0]`, add with `nums.append(5)`, measure with `len(nums)`.
- A **tuple** is an ordered sequence that cannot change: `point = (2, 5)`. Use it for fixed groups, like a shape `(28, 28)`. Tuples can be **unpacked**: `x, y = point`.
- A **dictionary** maps **keys to values**: `best = {"vit": 0.94}`. Read with `best["vit"]`, write with `best["cnn"] = 0.88`, and use `best.get(key, default)` when the key might be missing. Without a default, `best.get(key)` gives `None` for a missing key. `best.items()` gives `(key, value)` pairs. A `for` loop over a dict, or `sorted(best)` or `max(best)`, goes through its keys.
- A **set** holds unique values: `{1, 2, 2, 3}` is `{1, 2, 3}`. Use it to remove duplicates or to test membership quickly with `in`.

Lists, dicts and sets are **mutable**: you can change them in place. Numbers, strings and tuples are **immutable**: a change builds a new object instead.

<EmbeddedPyEditor>
nums = [3, 1, 4, 1, 5]
counts = {}
for x in nums:
    counts[x] = counts.get(x, 0) + 1    # count occurrences
print(counts)
print(set(nums), 4 in set(nums))
for key, value in counts.items():
    print(key, value)
</EmbeddedPyEditor>

`counts.get(x, 0)` gives 0 the first time a number appears, so the tally starts at zero instead of raising an error. The first line printed is `{3: 1, 1: 2, 4: 1, 5: 1}`: the number 1 appeared twice.

A **comprehension** builds a container in one line. `[x * x for x in range(6)]` gives the squares 0 to 25, and `[x for x in nums if x > 2]` keeps only the items above 2, giving `[3, 4, 5]`. `{w: len(w) for w in words}` builds a dict the same way.

### Functions

A **function** packages code for reuse. Define it with `def`, take **arguments**, and send back a result with `return`. Arguments can have **default values**, and returning a tuple returns several values at once.

<EmbeddedPyEditor>
def min_max(values, scale=1.0):
    """Return the smallest and largest value, times scale."""
    return min(values) * scale, max(values) * scale

lo, hi = min_max([10, 12, 16])               # unpack the returned tuple
print(lo, hi)
print(min_max([10, 12, 16], scale=0.5))      # override the default by name
</EmbeddedPyEditor>

The first call prints `10.0 16.0` and the second prints `(5.0, 8.0)`. The triple-quoted line is a **docstring**, a description for people reading the code.

`print` shows a value on the screen. `return` hands a value back to the code that called the function, so it can be stored or used again. A function with no `return` gives back `None`.

<ProblemCard id="py-return-inside-the-loop" />

### Sorting with a key, and lambda

`sorted(xs)` returns a new sorted list, and `reverse=True` flips the order. To sort by something other than the items themselves, pass a **key function**: Python calls it on each item and sorts by the results. `sorted(["bb", "a", "ccc"], key=len)` gives `["a", "bb", "ccc"]`.

A **lambda** is a one-line function with no name, handy as a key. `lambda item: item[1]` takes an item and returns its second entry. So to rank `(name, score)` pairs by score, highest first:

```python
ranked = sorted(best.items(), key=lambda item: item[1], reverse=True)
```

`max` and `min` accept `key` too: `max(best, key=best.get)` is the key with the largest value. Python's sort is **stable**: items with equal keys keep their original order.

A key can also return a tuple. Tuples compare entry by entry, like words in a dictionary: `(1, 5) < (2, 0)` and `(1, 5) < (1, 7)` are both `True`. So `sorted(words, key=lambda w: (-len(w), w))` puts longer words first and breaks ties alphabetically. The minus sign flips the order of one entry only, while `reverse=True` would flip both.

<ProblemCard id="py-sort-reverse-flips-both" />

### Errors and try / except

When something goes wrong, Python **raises an exception** and stops. `float("n/a")` raises `ValueError`, `best["mlp"]` raises `KeyError` when the key is missing, and `1 / 0` raises `ZeroDivisionError`. To handle an error instead of crashing, put the risky code under `try` and say what to do under `except`:

<EmbeddedPyEditor>
for text in ["0.91", "n/a", "badline", "0.88"]:
    try:
        score = float(text)
    except ValueError as err:
        print("skipping", text, "->", err)
        continue
    print("score", score)
</EmbeddedPyEditor>

`except ValueError as err` stores the error in `err`, so you can print its message. `continue` then skips the `print("score", ...)` line for that item.

Catch only the error you expect. A bare `except:` catches every error, including a misspelled name (`NameError`), so a real bug passes silently.

### Classes: bundling data with the functions that use it

A **class** is a blueprint for objects that carry their own data, called **attributes**, and their own methods. PyTorch models are classes, and you will write many of them in later modules.

```python
class Counter:
    def __init__(self, start=0):
        self.count = start          # an attribute, stored on this object

    def add(self, k=1):
        self.count += k             # methods read and change the object's attributes

c = Counter()
c.add()
c.add(5)
print(c.count)                      # 6
```

- `__init__` runs automatically when you create an object with `Counter()`. It sets up the attributes.
- `self` is the object itself. Every method takes it as its first argument, and `self.count` means "this object's count". Python passes it for you: `c.add(5)` calls `Counter.add(c, 5)`.
- Each object has its own attributes: two `Counter()` objects count separately.

`__init__` is also the place to check the settings a user passes in. Your own code can stop with an error using `raise`. The 2025 Round 1 paper asked for this check in a logistic-regression class: a bad `solver` had to raise an error.

```python
class LogReg:
    def __init__(self, solver, lr):
        if solver not in ("GD", "Newton"):
            raise ValueError("Invalid solver")
        self.solver = solver
        self.lr = lr

model = LogReg("GD", 0.1)
print(model.solver, model.lr)
try:
    LogReg("SGD", 0.1)
except ValueError as err:
    print("error:", err)
```

```output
GD 0.1
error: Invalid solver
```

`not in` is the opposite of `in`. The good call builds an object. The bad call stops at `raise`, so no half-built object comes back.

A class can **inherit** from another class, its **parent**. The new class is called the **child** or **subclass**. It gets all the parent's methods and can add new ones or replace some. Inside the child, `super()` reaches the parent. `super().__init__(...)` runs the parent's `__init__`, so the parent's attributes get set up. `super().update(x)` runs the parent's version of a method called `update`. A PyTorch layer uses the same pattern:

```python
import torch.nn as nn

class MyLayer(nn.Module):           # inherit from PyTorch's Module
    def __init__(self, d_in, d_out):
        super().__init__()          # must come before you set attributes
        self.linear = nn.Linear(d_in, d_out)

    def forward(self, x):           # called when you write layer(x)
        return self.linear(x).relu()
```

`__call__` is the method Python runs when you put parentheses after an object. `nn.Module` defines `__call__` to run your `forward`, so `layer(x)` ends up calling `forward(x)`. You will define a real model with `nn.Module` in [The Multilayer Perceptron](1.18-DL1-neural-networks-perceptrons-mlps-activations.md).

### Names, references and copies

`b = a` does not copy anything. It gives the same object a second name, so changing a list through `b` changes `a` too. There are two kinds of real copy:

- A **shallow copy**, `a.copy()` or `list(a)`, makes a new outer container, but the items inside are still shared. For a list of numbers that is enough.
- A **deep copy**, `copy.deepcopy(a)` after `import copy`, copies everything inside as well. Use it for nested data: a dict of lists, a list of lists, or a model whose best weights you want to keep while training continues.

<ProblemCard id="py-shallow-copy-keeps-some" />

The same "names, not copies" rule causes two common bugs. First, `[[0] * 3] * 3` repeats one row three times. All three rows are the same list, so `grid[0][0] = 5` changes every row. `[[0] * 3 for _ in range(3)]` builds a new row on each pass. The name `_` is the usual choice for a loop variable you never use.

Second, a default argument like `def f(x, seen=[])` is created once, when the function is defined. Every call that leaves `seen` out shares that one list. Use `None` as the default and make the list inside the function:

```python
def f(x, seen=None):
    if seen is None:   # `is` asks: is this the very same object as None?
        seen = []      # a new list on every call
    ...
```

### Solving the focus problem

For each line, `add` splits at the comma and unpacks the pieces into a name and a score text. It converts the text with `float`, and keeps the new score if it beats `best.get(name, float("-inf"))`. `float("-inf")` is negative infinity, smaller than any real score, so a model's first score always wins. The table follows all seven lines:

| line | after `split(",")` | what happens | skipped so far |
|---|---|---|---|
| `resnet,0.91` | `["resnet", "0.91"]` | new model: resnet 0.91 | 0 |
| `vit,0.94` | `["vit", "0.94"]` | new model: vit 0.94 | 0 |
| `resnet,0.93` | `["resnet", "0.93"]` | 0.93 beats 0.91, so resnet becomes 0.93 | 0 |
| `mlp,n/a` | `["mlp", "n/a"]` | `float("n/a")` raises `ValueError` | 1 |
| `vit,0.92` | `["vit", "0.92"]` | 0.92 does not beat 0.94, no change | 1 |
| `cnn,0.88` | `["cnn", "0.88"]` | new model: cnn 0.88 | 1 |
| `badline` | `["badline"]` | one item cannot fill two names: `ValueError` | 2 |

Both kinds of bad line raise `ValueError`, so one `except` catches them. The dict ends with three models. Sorting their `(name, score)` pairs by score, highest first, gives vit 0.94, then resnet 0.93, then cnn 0.88. That is `top(3)`, with 2 lines skipped.

## Implementation

The class below carries out that trace. `add` combines unpacking, `try` and `except`, and `dict.get` with a default. `top` sorts with a lambda key.

```python
lines = ["resnet,0.91", "vit,0.94", "resnet,0.93", "mlp,n/a", "vit,0.92", "cnn,0.88", "badline"]

class Leaderboard:
    """Keeps each model's best score."""

    def __init__(self):
        self.best = {}          # model name -> best score so far
        self.skipped = 0

    def add(self, line):
        try:
            name, text = line.split(",")
            score = float(text)
        except ValueError:      # "n/a" is not a number, "badline" has no comma
            self.skipped += 1
            return
        if score > self.best.get(name, float("-inf")):
            self.best[name] = score

    def top(self, k):
        ranked = sorted(self.best.items(), key=lambda item: item[1], reverse=True)
        return ranked[:k]

board = Leaderboard()
for line in lines:
    board.add(line)
print(board.top(3))
print("skipped:", board.skipped)
for rank, (name, score) in enumerate(board.top(3), start=1):
    print(f"{rank}. {name:<7}{score:.2f}")
```

```output
[('vit', 0.94), ('resnet', 0.93), ('cnn', 0.88)]
skipped: 2
1. vit    0.94
2. resnet 0.93
3. cnn    0.88
```

The ranking matches the trace. In the last loop, `enumerate(..., start=1)` numbers the models from 1, and `{name:<7}` pads each name so the scores line up.

The next block makes an alias, a shallow copy and a deep copy of a dict of lists, then changes one number in the original.

```python
import copy

weights = {"layer1": [0.5, -0.2], "layer2": [1.0]}
alias = weights                  # same dict, two names
shallow = weights.copy()         # new dict, same inner lists
deep = copy.deepcopy(weights)    # new dict and new lists
weights["layer1"][0] = 99.0
print("alias  ", alias["layer1"])
print("shallow", shallow["layer1"])
print("deep   ", deep["layer1"])
```

```output
alias   [99.0, -0.2]
shallow [99.0, -0.2]
deep    [0.5, -0.2]
```

The alias and the shallow copy both show `99.0`, because they share the inner list. Only the deep copy kept `0.5`.

Last, the `nn.Module` pattern in plain Python. `Layer.__call__` runs `forward`, and the child class `Scale` sets its own attribute after `super().__init__`.

```python
class Layer:
    def __init__(self, name):
        self.name = name

    def __call__(self, x):           # lets you write layer(x)
        return self.forward(x)

class Scale(Layer):
    def __init__(self, factor):
        super().__init__("scale")    # run Layer's __init__ first
        self.factor = factor

    def forward(self, x):
        return [self.factor * v for v in x]

s = Scale(3)
print(s.name, s([1, 2, 5]))
print(isinstance(s, Layer))
```

```output
scale [3, 6, 15]
True
```

`s([1, 2, 5])` ran `Layer.__call__`, which called `Scale.forward`. The name `scale` came from `Layer.__init__`, reached through `super()`. `isinstance(s, Layer)` asks whether `s` is a `Layer`. It is `True`, because an object of a child class also counts as an object of its parent.

<Warning>

`b = a` gives one list two names, so `b.append(4)` changes `a` too. Before you
change data that other code still uses, copy it: `a.copy()` for a flat list or
dict, and `copy.deepcopy(a)` for anything nested.

</Warning>
