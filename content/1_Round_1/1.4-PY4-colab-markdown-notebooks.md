## Overview

You solved the problem. Your notebook prints the right number, and below it sits a tidy derivation. The grader opens it on a fresh machine, presses run, and gets a `FileNotFoundError` in cell 2, or a different number, or a derivation full of raw dollar signs. How do you hand in a notebook that runs and reads the same for them as it did for you?

The open-ended problem on the 2026 Round 1 paper asked for a single Jupyter notebook (`.ipynb`) and said the graders "will execute all code in your submitted notebook from top to bottom." The USAAIO syllabus says some answers must be written in **Google Colab** text cells, using Markdown to enter the equations. Colab is a free Jupyter notebook in the browser, with Python and the common libraries already installed. Many parts also say "Reasoning is required", which asks for the written argument as well as the number. You only need to have typed some Python before.

## Example: a least-squares answer that survives a fresh run

A question gives a file `train.csv` with five points:

| $x$ | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| $y$ | 2.1 | 3.9 | 6.2 | 7.8 | 10.1 |

(a) Fit the line $y \approx wx + b$ by least squares and report $w$ and $b$. (b) Derive the equations you solved. *Reasoning is required.*

**Least squares** picks the $w$ and $b$ that make the sum of squared vertical gaps between the points and the line as small as possible. Here $(x_i, y_i)$ is the $i$-th point and $n = 5$ is the number of points.

The answer is $w = 1.99$ and $b = 0.05$. Full credit takes three things you will build in the Explanation. First, a cell that loads the file in a way that works on a fresh runtime. Second, a notebook that prints those numbers after a fresh run from the top. Third, a text cell that derives the **normal equations**, the two equations that $w$ and $b$ solve:

$$
\begin{bmatrix} \sum x_i^2 & \sum x_i \\ \sum x_i & n \end{bmatrix}
\begin{bmatrix} w \\ b \end{bmatrix}
=
\begin{bmatrix} \sum x_i y_i \\ \sum y_i \end{bmatrix}
$$

## Explanation

### Cells, the kernel and the runtime

A notebook is an ordered list of **cells**. A **code cell** holds Python and runs with Shift+Enter, which also moves to the next cell. A **text cell**, also called a Markdown cell, holds formatted text and math. In Colab, Ctrl+M M turns the current cell into text, Ctrl+M Y turns it into code, and Ctrl+M B inserts a new cell below.

Behind the code cells sits the **kernel**: one long-running Python process that holds every variable, import and loaded model. Running a cell changes that shared memory, and the output printed under the cell is a snapshot from the moment it ran. The number in brackets beside a cell, such as `[7]`, is its **execution count**: this was the seventh cell run since the kernel started. Sorted by count, the cells give the order of their latest runs.

<ProblemCard id="cn-a-loop-that-failed-halfway" />

Colab calls the kernel together with its machine the **runtime**. A free runtime is recycled after a stretch of idle time, and after at most about 12 hours. Recycling wipes the kernel's memory and every file you put on the machine, so anything worth keeping goes to Google Drive or gets downloaded.

**Runtime → Change runtime type** is where you would attach a GPU. Leave it on CPU for Round 1. The 2025 problem statements said "All coding tasks shall run on CPUs, not GPUs."

### Getting data in and out

The notebook's working directory starts as `/content`. A relative path such as `"train.csv"` then means `/content/train.csv`. There are four common ways to get data into the notebook:

- **Upload from your computer.** `files.upload()` opens a file picker, waits until you choose, and saves each file into the working directory. It returns a dictionary from file name to the file's bytes. If `train.csv` already exists, the new upload is saved as `train (1).csv`, so delete the old file first.
- **Mount Google Drive.** `drive.mount("/content/drive")` makes your Drive appear as a folder, with your files under `/content/drive/MyDrive/`. Files there survive a recycled runtime.
- **Download from a URL.** `pd.read_csv(url)` reads a CSV straight from the web, and `!wget -q url` saves any file into the working directory.
- **Unpack an archive.** `!unzip -q data.zip` extracts a zip file in place.

```python
from google.colab import files, drive
uploaded = files.upload()               # pick train.csv. It lands in /content
drive.mount("/content/drive")           # Drive files under /content/drive/MyDrive/
files.download("submission.csv")        # send a file from the runtime to your computer
```

Before loading, check the file is where you think: `!ls -lh` lists the working directory. A file you uploaded yesterday is gone today, because the runtime was recycled.

For the notebook you hand in, load data the way the problem gives it. The 2026 paper's starter code built a URL for each data file and read the CSV with `pd.read_csv(url)`, a line that runs the same for you and for the grader. Use `files.upload()` and Drive only while you work. An upload cell stops a fresh run until someone picks a file, and a grader who mounts Drive sees their own Drive, not yours.

To submit, save the notebook itself with **File → Download → Download .ipynb**. The file holds every cell and the output each one printed when it last ran.

### Shell commands and magics

A line that starts with `!` runs in the system shell instead of Python. Examples are `!ls` and `!unzip -q data.zip`. A line that starts with `%` is a **magic**, a command for the notebook itself:

| Command | What it does |
| --- | --- |
| `%pip install -q pkg` | installs a package into the kernel's own environment |
| `!pip install -q pkg` | the same in most notebooks, run through the shell |
| `%time stmt` | times one statement once |
| `%timeit stmt` | runs a statement many times and reports the average |
| `%%time` | as a cell's first line, times the whole cell |

Colab already has NumPy, pandas, scikit-learn, matplotlib and PyTorch. Contest problems often forbid extra imports. The 2025 statements said that beyond the starter cell's imports "you are NOT allowed to import anything else." Install a package only when the starter code does it, as the 2026 paper's `!pip install gensim` did. If you install a different version of a library that was already imported, the kernel keeps the old one in memory until you restart it with **Runtime → Restart session**.

### Reproducibility: a fresh run from the top

The kernel keeps every variable, so the outputs on screen can disagree with the code. Say a notebook has five cells. Run them all, then edit cell 2 and re-run only cell 2. Cells 3 to 5 still show outputs computed from the old cell 2. A cell can be executable yet misleading if its explanation describes an earlier experiment. Notebooks do not track which cells depend on which. Delete a cell that defined a variable, and the variable stays in memory, so later cells keep working until the next fresh start.

Three habits make a run repeatable:

- **Run everything from a fresh start before you trust a result.** **Runtime → Restart session and run all** wipes the kernel's variables and runs every cell from the top. The execution counts then read 1, 2, 3, … from top to bottom. A restart keeps the files on the runtime's disk and the packages you installed, though. Before you submit, use **Runtime → Disconnect and delete runtime**, which gives you a new machine with nothing you added, and then **Runtime → Run all**.
- **Seed every random number generator** your results depend on. The 2025 Round 1 starter code called `np.random.seed(2025)`. That fixes the older functions such as `np.random.rand` and `np.random.randint`. It does not fix a generator made with `np.random.default_rng()`, which needs its own seed: `rng = np.random.default_rng(0)`. Called with no seed, `default_rng()` takes a fresh seed from the operating system, so every run differs. Python uses `random.seed(0)` and PyTorch uses `torch.manual_seed(0)`. The same seed replays the same numbers on the same library versions and hardware. A seeded generator hands out one fixed sequence, and each draw takes the next numbers from it.
- **Print the versions** of the main libraries near the top, for example `print(np.__version__, sklearn.__version__)`. Colab upgrades its preinstalled libraries several times a year, and lists each upgrade in its release notes. A notebook from June can fail in September with code that never changed. The printed versions tell a reader what worked.

### Markdown for write-ups

Graders read the rendered text cells. **Markdown** is plain text with a few marks that become formatting:

- `#`, `##` and `###` start headings.
- A line starting with `-` is a bullet, and `1.` starts a numbered list.
- `**bold**` and `*italic*` emphasize. Every `**` needs its partner. An unmatched `**` shows up as two literal asterisks.
- Single backticks make `inline code`. Three backticks on their own lines, with a language name such as `python`, make a code block.
- A table is rows of cells between `|` marks, with a `| --- |` line under the header row.

### LaTeX: inline math, display math, matrices, aligned steps

Text cells render **LaTeX** math. Put inline math between single dollar signs: `$w = 1.99$`. Put display math, centered on its own line, between double dollar signs. The commands you need most:

| You want | Type | Renders |
| --- | --- | --- |
| subscript, superscript | `x_i^2`, `x_{10}` | $x_i^2$, $x_{10}$ |
| fraction | `\frac{a}{b}` | $\frac{a}{b}$ |
| sum | `\sum_{i=1}^{n} x_i` | $\sum_{i=1}^{n} x_i$ |
| vector, transpose, hat | `\mathbf{x}^\top`, `\hat{y}` | $\mathbf{x}^\top$, $\hat{y}$ |
| loss, partial derivative | `\mathcal{L}`, `\frac{\partial \mathcal{L}}{\partial w}` | $\mathcal{L}$, $\frac{\partial \mathcal{L}}{\partial w}$ |
| Greek | `\eta`, `\sigma`, `\lambda` | $\eta$, $\sigma$, $\lambda$ |
| words inside math | `\text{if } x > 0` | $\text{if } x > 0$ |
| tall brackets | `\left( \frac{a}{b} \right)` | $\left( \frac{a}{b} \right)$ |

Braces group: `x_10` shows $x_10$, a subscript 1 followed by a 0, while `x_{10}` shows $x_{10}$.

**Matrices.** Inside `\begin{bmatrix} … \end{bmatrix}`, an `&` separates entries in a row and `\\` ends a row. `pmatrix` gives round brackets instead of square ones:

```latex
$$
A = \begin{bmatrix} 1 & 2 \\ 3 & 4 \end{bmatrix}, \qquad
\mathbf{x} = \begin{pmatrix} x_1 \\ x_2 \end{pmatrix}
$$
```

$$

**Aligned derivations.** A derivation is a chain of equal signs, one step per line. Put it in `\begin{aligned} … \end{aligned}` inside display math. An `&` before each `=` lines the equal signs up, and `\\` ends each line. The block below fits a line through the origin, $y \approx wx$, with $\mathcal{L}(w)$ the sum of squared gaps:

```latex
$$
\begin{aligned}
\mathcal{L}(w) &= \sum_{i=1}^{n} (y_i - w x_i)^2 \\
\frac{d\mathcal{L}}{dw} &= -2 \sum_{i=1}^{n} x_i (y_i - w x_i) = 0 \\
\sum_i x_i y_i - w \sum_i x_i^2 &= 0 \\
w &= \frac{\sum_i x_i y_i}{\sum_i x_i^2}
\end{aligned}
$$
```

$$
\begin{aligned}
\mathcal{L}(w) &= \sum_{i=1}^{n} (y_i - w x_i)^2 \\
\frac{d\mathcal{L}}{dw} &= -2 \sum_{i=1}^{n} x_i (y_i - w x_i) = 0 \\
\sum_i x_i y_i - w \sum_i x_i^2 &= 0 \\
w &= \frac{\sum_i x_i y_i}{\sum_i x_i^2}
\end{aligned}
$$

Expanding the square shows $\mathcal{L}(w)$ is a parabola in $w$ whose $w^2$ coefficient, $\sum_i x_i^2$, is positive when any $x_i$ is not 0. It opens upward, so the zero of the derivative is its minimum. The official 2025 solutions put `\begin{align*} … \end{align*}` between the `$$` marks instead, which lines the steps up the same way.

A function with cases uses `cases` the same way, with an `&` separating each case from its condition and `\\` ending each case:

```latex
$$
\text{ReLU}(x) = \begin{cases} x & x > 0 \\ 0 & \text{otherwise} \end{cases}
$$
```

$$

$$

### Answering "reasoning required"

A grader reading many notebooks looks for the answer, then for each step that leads to it. Give them both in the same order every time, in a text cell directly under the code that computes the number:

```markdown
**Answer.** $w = 1.99$, $b = 0.05$.

**Reasoning.**
1. State what is being minimized, with every symbol defined.
2. One step per line in an `aligned` block, each following from the last.
3. Say which result or rule each step uses ("setting both partial derivatives to zero").

**Check.** The code cell above computes the same values with `np.polyfit`.
```

- Lead with the answer in the form the question asks for, with the requested rounding and units.
- Define every symbol before you use it.
- Write the reasoning in a text cell with LaTeX, never as Python comments. A grader reads rendered math, not `# w = (X^T X)^-1 X^T y`.
- Say how each number was measured, on which data and by which method. Give every figure a caption that says what to see in it.
- When the question says "explain" rather than "derive", answer in two or three sentences that name the cause, not a paragraph of possibilities.
- Do not narrate obvious code. "Import pandas" adds nothing. "We seed the generator because the split has to repeat on the grader's fresh run" is useful.

Clear outputs are part of correctness. A grader should not have to search through noisy logs to find the answer.

Match the label on the question. The 2026 paper used several:

- "Reasoning is required." Use the full template.
- "Reasoning is not required." Give the answer alone, in the requested form.
- "Mathematical reasoning is required. Coding is not allowed." Use the template, but check by hand, for example by substituting the answer back.

### Solving the focus problem

Least squares picks $w$ and $b$ to make $\mathcal{L}(w, b) = \sum_i (y_i - w x_i - b)^2$ as small as possible. There are now two unknowns, so we need a **partial derivative**: the ordinary derivative in one variable while you hold the other one fixed. At the minimum the loss is flat in both directions, so both partial derivatives are zero. Along any straight line in the $(w, b)$ plane, each gap $y_i - w x_i - b$ changes linearly, so its square is an upward-opening parabola or a constant. Their sum $\mathcal{L}$ never curves downward along any line, so it is bowl-shaped, and a point where it is flat sits at the bottom. Written in the template, the text cell for part (b) is:

```markdown
**Answer.** $w = 1.99$, $b = 0.05$.

**Reasoning.** For the $n = 5$ points $(x_i, y_i)$, least squares minimizes
$\mathcal{L}(w, b) = \sum_{i=1}^{n} (y_i - w x_i - b)^2$.
Set both partial derivatives to zero (chain rule on each square):

$$
\begin{aligned}
\frac{\partial \mathcal{L}}{\partial w} &= -2 \sum_{i=1}^{n} x_i (y_i - w x_i - b) = 0
  \;\Rightarrow\; w \sum_i x_i^2 + b \sum_i x_i = \sum_i x_i y_i \\
\frac{\partial \mathcal{L}}{\partial b} &= -2 \sum_{i=1}^{n} (y_i - w x_i - b) = 0
  \;\Rightarrow\; w \sum_i x_i + b\,n = \sum_i y_i
\end{aligned}
$$

With $\sum x_i = 15$, $\sum x_i^2 = 55$, $\sum y_i = 30.1$, $\sum x_i y_i = 110.2$:

$$
\begin{aligned}
55w + 15b &= 110.2 \\
15w + 5b &= 30.1
\end{aligned}
$$

Three times the second equation is $45w + 15b = 90.3$. Subtracting it from the
first gives $10w = 19.9$, so $w = 1.99$ and $b = (30.1 - 15 \cdot 1.99)/5 = 0.05$.

**Check.** The code cell above prints the same matrix, and `np.polyfit` gives
the same $w$ and $b$.
```

The two equations are the normal equations from the Example, written out row by row. Rendered, the derivation reads:

$$
\begin{aligned}
\frac{\partial \mathcal{L}}{\partial w} &= -2 \sum_{i=1}^{n} x_i (y_i - w x_i - b) = 0
  \;\Rightarrow\; w \sum_i x_i^2 + b \sum_i x_i = \sum_i x_i y_i \\
\frac{\partial \mathcal{L}}{\partial b} &= -2 \sum_{i=1}^{n} (y_i - w x_i - b) = 0
  \;\Rightarrow\; w \sum_i x_i + b\,n = \sum_i y_i
\end{aligned}
$$

The finished answer is two cells that survive a fresh run: the code cell in the Implementation below, which loads the data and solves the system, and this text cell.

## Implementation

This cell loads the five points, builds the 2×2 system from the sums, and solves it. `np.linalg.solve(A, r)` returns the pair $(w, b)$ that satisfies both equations. `np.polyfit(x, y, 1)` fits a degree-1 polynomial, a line, by least squares, so it serves as an independent check. A string stands in for the file so the cell runs anywhere. In Colab you would read the URL or file name the problem gives.

```python
import io
import numpy as np
import pandas as pd

csv_text = "x,y\n1,2.1\n2,3.9\n3,6.2\n4,7.8\n5,10.1\n"
df = pd.read_csv(io.StringIO(csv_text))      # in Colab: pd.read_csv(url)
x, y = df["x"].to_numpy(dtype=float), df["y"].to_numpy(dtype=float)

A = np.array([[np.sum(x * x), np.sum(x)],
              [np.sum(x),     len(x)]])
r = np.array([np.sum(x * y), np.sum(y)])
w, b = np.linalg.solve(A, r)
print("normal equations:", A.tolist(), "=", r.round(2).tolist())
print(f"w = {w:.2f}, b = {b:.2f}")
print("np.polyfit agrees:", np.allclose([w, b], np.polyfit(x, y, 1)))
```

```output
normal equations: [[55.0, 15.0], [15.0, 5.0]] = [110.2, 30.1]
w = 1.99, b = 0.05
np.polyfit agrees: True
```

The first line matches the matrix in the text cell entry for entry, and the last line confirms `np.polyfit` gets the same $w$ and $b$.

The next cell fakes a saved notebook with three cells and then imitates a fresh run. In this notebook, `scale` was first 10. Cells 2 and 3 ran with that value, so cell 3 printed 60. Then cell 1 was edited to `scale = 2` and run again, as execution 5. `exec(source, namespace)` runs a string of Python code and stores any variables it makes in the dictionary `namespace`. A new empty dictionary plays the role of a restarted kernel.

```python
import contextlib

# Simplified from a real .ipynb file, which stores each cell's source as a
# list of lines and its printed output inside a list under "outputs".
notebook = {"cells": [
    {"execution_count": 5, "source": "scale = 2", "output": ""},
    {"execution_count": 3, "source": "data = [scale * i for i in range(4)]", "output": ""},
    {"execution_count": 4, "source": "print(sum(data))", "output": "60"},
]}

counts = [cell["execution_count"] for cell in notebook["cells"]]
print("execution counts, top to bottom:", counts)
print("ran top to bottom:", counts == sorted(counts))

def run_all(notebook):
    """Imitate a fresh run: a new namespace, every cell in order."""
    namespace, printed = {}, []
    for cell in notebook["cells"]:
        captured = io.StringIO()
        with contextlib.redirect_stdout(captured):
            exec(cell["source"], namespace)
        printed.append(captured.getvalue().strip())
    return printed

print("saved output of the last cell:", notebook["cells"][2]["output"])
print("after restart and run all:   ", run_all(notebook)[2])
```

```output
execution counts, top to bottom: [5, 3, 4]
ran top to bottom: False
saved output of the last cell: 60
after restart and run all:    12
```

The counts `[5, 3, 4]` are not increasing, so the cells did not run top to bottom. A fresh run replaces the stale 60 with 12, the number the code as written produces.

The next cell shows what a seed does. It draws 1,000 random numbers centered at 0 and averages them, twice with seed 0 and once with seed 1. Then it seeds the older global functions with `np.random.seed(2025)` twice and checks which draws repeat.

```python
def noisy_mean(seed):
    rng = np.random.default_rng(seed)
    return rng.standard_normal(1000).mean()   # average of 1000 random draws

print("seed 0, run 1:", round(noisy_mean(0), 6))
print("seed 0, run 2:", round(noisy_mean(0), 6))
print("seed 1       :", round(noisy_mean(1), 6))

np.random.seed(2025)
old_1, new_1 = np.random.standard_normal(3), np.random.default_rng().standard_normal(3)
np.random.seed(2025)
old_2, new_2 = np.random.standard_normal(3), np.random.default_rng().standard_normal(3)
print("np.random.standard_normal repeats:", np.array_equal(old_1, old_2))
print("default_rng() with no seed repeats:", np.array_equal(new_1, new_2))
```

```output
seed 0, run 1: -0.048028
seed 0, run 2: -0.048028
seed 1       : -0.054253
np.random.standard_normal repeats: True
default_rng() with no seed repeats: False
```

Both seed-0 lines match to all six decimals, and seed 1 gives a different mean. `np.random.seed` fixed the old function but not the unseeded generator.

> **Warning.**
>
> A notebook that works for you can depend on things the grader does not have. Common ones are a file you uploaded by hand, a variable from a cell you deleted, and a package whose install cell you removed. **Restart session and run all** does not catch the file or the package, because both stay on the machine. Use **Disconnect and delete runtime** and then **Run all**. If the notebook runs from that fresh start without you clicking anything, and loads data only from URLs or files the problem provides, the grader can run it too.
