## Overview

The models so far fit weights. These two predict from the training points directly. **k-nearest neighbors** labels a new point by a vote of the $k$ training points closest to it. A **decision tree** asks a sequence of yes-or-no questions about single features and predicts the majority label of the training points that answered the same way. Neither assumes a shape for the boundary, which makes both easy to get right and easy to overfit.

Both are Round 1 material. [2026 Round 1](https://www.usaaio.org/attachments/past-problems/2026/usaaio-2026-round-1-problems.pdf), Problem 9 was an open-ended tabular task restricted to kNN and scored by macro-F1 on a hidden test set. Distance, scaling and the choice of $k$ decided the score. The fundamentals set asks for impurity and information gain by hand.

## Example: eight points, one query, one split

Eight training points. Class 0: $(4, 5)$, $(5, 1)$, $(6, 4)$, $(6, 2)$. Class 1: $(1, 3)$, $(4, 1)$, $(1, 4)$, $(3, 6)$. Classify the query $(4, 2)$ by kNN with Euclidean distance for $k = 1$ and $k = 3$, find the single split $x_1 \le t$ with the largest Gini gain, and say which of the two models changes its answer if $x_2$ is measured in millimeters instead of meters.

The query sits next to one class-1 point inside a group of class-0 points, so the two values of $k$ disagree. The split question is the first node of a tree grown on these points.

## Explanation

### A vote of the nearest neighbors

To classify a query $\mathbf{q}$, kNN finds the $k$ training points closest to it and returns their majority label. Closest needs a distance, and the default is Euclidean,

$$
d(\mathbf{q}, \mathbf{x}) = \lVert \mathbf{q} - \mathbf{x} \rVert_2 = \sqrt{\sum_j (q_j - x_j)^2},
$$

with Manhattan distance, the sum of absolute differences, and cosine distance as the usual alternatives.

Nothing is fit. The training set is stored and all the work happens when a query arrives, so kNN is called a **lazy learner**. The plain way to answer a query is to compare it with every training point, which costs $nd$ operations for $n$ points with $d$ features. A KD-tree, an index built over the points, cuts that to about $d \log n$, but only when $d$ is small.

For the example, the squared distances from $(4, 2)$ are 1 to $(4, 1)$, 2 to $(5, 1)$, 4 to $(6, 2)$, 8 to $(6, 4)$ and larger to the rest. The nearest point is class 1, so $k = 1$ says class 1. The nearest three are classes 1, 0, 0, so $k = 3$ says class 0. Square roots are never needed, because the order of the distances is the order of their squares, and an odd $k$ avoids tied votes on two classes.

Two variants are one line each. kNN **regression** predicts the mean of the $k$ neighbors' targets instead of a vote. **Distance weighting**, `weights="distance"` in scikit-learn, gives each neighbor a vote of $1/d$, so a close neighbor counts more than a far one.

### Choosing k

$k$ sets the trade between bias and variance, covered later in [Bias-Variance Tradeoff & Cross-Validation](2.16-ML11-bias-variance-cross-validation.md). At $k = 1$ every training point owns the region around it, the boundary is jagged, the training error is zero, and one mislabeled point flips its whole neighborhood: high variance. At $k = n$ every query sees the same neighbors and gets the majority class of the training set: high bias. In between, the vote averages over more points as $k$ grows and the boundary smooths out. Choose $k$ by cross-validation. The implementation does, and finds a range of good values, not a single best one.

### Distance needs comparable features

A distance adds squared differences across features, so a feature measured in large units dominates it. If $x_2$ in the example were recorded in millimeters its differences would be a thousand times larger, and the vote would be decided by $x_2$ alone. Standardize every feature before kNN, with statistics from the training rows, as in [Feature Engineering](1.13-ML1-data-processing-features.md). A tree does not care: a split $x_j \le t$ moves with the units and the partition is the same. That is also why the kNN entry in Round 1 Problem 9 needed a scaler and the tree models in the next module do not.

<ProblemCard id="dtknn-bike-nearest-after-scaling" />

### The curse of dimensionality

With many features, distances stop telling points apart. The squared distance between two random points is a sum of one term per feature. With $d$ features its average grows like $d$, and its spread only like $\sqrt{d}$. Measured against the average, the spread shrinks like $1 / \sqrt{d}$. So the nearest and the farthest neighbor of a query end up at almost the same distance, and the vote is noise. The fixes are fewer dimensions, through [PCA](2.17-ML12-principal-component-analysis.md) or feature selection, and features chosen so that distance means something.

The Cover-Hart result says that as $n \to \infty$, the error rate of kNN at $k = 1$ is at most twice the Bayes error, the best any classifier could achieve on that distribution. It explains why kNN is a fair baseline: beating it by a wide margin is evidence that a model has found real structure. The catch is that the sample size needed grows with $d$, the curse again in a different costume.

<ProblemCard id="dtknn-cube-distance-spread" />

### A tree of questions

A decision tree splits the training set on one feature and one threshold, $x_j \le t$ to the left and the rest to the right, then splits each side again, until a stopping rule fires. Each leaf predicts the majority class of the training points in it. The only decision at each node is which split to make, and the rule is to pick the one that leaves the children purest. The search is **greedy**: it chooses one split at a time and never looks ahead, because finding the best whole tree is far too expensive. The version in scikit-learn is called CART and makes only two-way splits. A prediction costs one comparison per level of the tree.

### Impurity

**Impurity** measures how mixed the classes in a node are. If the classes have proportions $p_1, \dots, p_C$, the two standard measures are

$$
\begin{aligned}
H &= -\sum_{c=1}^{C} p_c \log_2 p_c && \text{(entropy)}, \\
G &= 1 - \sum_{c=1}^{C} p_c^2 && \text{(Gini)}.
\end{aligned}
$$

Both are 0 for a pure node and largest for an even mix: with two classes $H = 1$ bit and $G = 0.5$ at $p = 0.5$. The example's eight points are four and four, so the root has $G = 1 - (0.5^2 + 0.5^2) = 0.5$.

<ProblemCard id="dtknn-gini-entropy-disagree" />

### Information gain

A split sends $n_L$ points left with impurity $I(L)$ and $n_R$ right with $I(R)$. Its **information gain** is the impurity removed,

$$
\mathrm{IG} = I(\text{parent}) - \Big(\frac{n_L}{n} I(L) + \frac{n_R}{n} I(R)\Big),
$$

with the children weighted by how many points they hold, so that one tiny pure child and one large mixed child score honestly. The parent term is fixed at a node, so the best split is the one with the smallest weighted child impurity. The search tries everything: every feature, and every midpoint between two neighboring values of it.

For the example, $x_1 \le 3.5$ sends $(1, 3)$, $(1, 4)$ and $(3, 6)$ left, all class 1, so $I(L) = 0$. The other five go right with four of class 0 and one of class 1, so $I(R) = 1 - (0.8^2 + 0.2^2) = 0.32$. The weighted child impurity is $\tfrac38 \cdot 0 + \tfrac58 \cdot 0.32 = 0.2$ and the gain is $0.5 - 0.2 = 0.3$. The split $x_1 \le 4.5$ scores the same 0.3 by moving $(4, 1)$ and $(4, 5)$ to the left, and scikit-learn takes the first one it meets. With entropy the same split gains 0.549 bits, and the two measures almost always agree on the ranking.

<ProblemCard id="dtknn-hallway-lamp-greedy" />

### Regression trees

For a numeric target the leaf predicts the mean of its points, and the impurity is the variance of the targets in the node, $\frac{1}{n}\sum_i (y_i - \bar{y})^2$. The best split is the one that removes the most squared error. The prediction is constant on each leaf, so a regression tree cannot predict a value outside the range of the targets it has seen. `DecisionTreeRegressor` is the same search with that impurity, and it is the base model gradient boosting fits to residuals in the [next module](1.16-ML4-tree-based-models-ensembles.md).

<ProblemCard id="dtknn-oat-milk-regression-tree" />

### Growing, stopping, pruning

Left alone, the recursion continues until every leaf is pure, and a leaf holding one noisy point is a memorized mistake. Training error reaches zero, and the test error stops improving well before that. So a tree needs an external stopping rule. `max_depth` is the blunt one, `min_samples_leaf` refuses leaves too small to mean anything, and `ccp_alpha` prunes a full tree back by removing splits that do not pay for their complexity. Of all the trees you can get by pruning, it keeps the one with the smallest $C_\alpha(T) = \sum_{\ell} \frac{n_\ell}{n} I(\ell) + \alpha \cdot (\text{number of leaves of } T)$, the impurity $I(\ell)$ of each leaf $\ell$ weighted by its share of the $n$ training rows, plus $\alpha$ for every leaf. Choose any of them by cross-validation and never by the training score, which only improves as the tree grows. The tree also reports which features its splits used, weighted by how much impurity each removed, as `feature_importances_`.

<ProblemCard id="dtknn-importances-by-hand" />

### Splits are axis-aligned

Every question has the form $x_j \le t$, so a tree's boundary is a staircase of cuts parallel to the axes. On a boundary that lines up with an axis a single split can be perfect. On a tilted one no finite staircase matches it, and a linear model that can write the tilt down directly wins. The implementation measures both cases. Each kind of model has shapes it finds easy. A tree is cheap on structure that lines up with the axes and expensive on everything else. A single deep tree also has high variance: a small change in the data changes its splits. [Ensemble Learning](1.16-ML4-tree-based-models-ensembles.md) turns that into a strength.

## Implementation

### The example in scikit-learn

```python
import numpy as np
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier

X = np.array([[4., 5.], [5., 1.], [6., 4.], [6., 2.], [1., 3.], [4., 1.], [1., 4.], [3., 6.]])
y = np.array([0, 0, 0, 0, 1, 1, 1, 1])
query = np.array([[4., 2.]])

for k in (1, 3, 5):
    print(f"k={k}: class {KNeighborsClassifier(n_neighbors=k).fit(X, y).predict(query)[0]}")
stump = DecisionTreeClassifier(max_depth=1).fit(X, y)
print(f"split: x{stump.tree_.feature[0] + 1} <= {stump.tree_.threshold[0]}")
print(f"gini of root and children: {np.round(stump.tree_.impurity, 2)}")
```

```output
k=1: class 1
k=3: class 0
k=5: class 0
split: x1 <= 3.5
gini of root and children: [0.5  0.   0.32]
```

The vote flips between $k = 1$ and $k = 3$, and the stump makes the split found in the explanation, with the root at 0.5, the left child pure and the right child at 0.32.

The editor above searches for one split. The same two computations, wrapped in a recursion that stops when a node is pure or a depth or size limit is reached, build a whole tree.

```python
import numpy as np

class DecisionTreeScratch:
    def __init__(self, max_depth=3, min_samples_split=2):
        self.max_depth = max_depth
        self.min_samples_split = min_samples_split
        self.tree = None

    def gini(self, y):
        classes, counts = np.unique(y, return_counts=True)
        probs = counts / len(y)
        return 1 - np.sum(probs ** 2)

    def best_split(self, X, y):
        best_feature = None
        best_threshold = None
        best_gini = float("inf")

        n_samples, n_features = X.shape

        for feature in range(n_features):
            thresholds = np.unique(X[:, feature])

            for threshold in thresholds:
                left_mask = X[:, feature] <= threshold
                right_mask = X[:, feature] > threshold

                if left_mask.sum() == 0 or right_mask.sum() == 0:
                    continue

                left_gini = self.gini(y[left_mask])
                right_gini = self.gini(y[right_mask])

                weighted_gini = (
                    left_mask.sum() / n_samples * left_gini
                    + right_mask.sum() / n_samples * right_gini
                )

                if weighted_gini < best_gini:
                    best_gini = weighted_gini
                    best_feature = feature
                    best_threshold = threshold

        return best_feature, best_threshold

    def majority_class(self, y):
        classes, counts = np.unique(y, return_counts=True)
        return classes[np.argmax(counts)]

    def build_tree(self, X, y, depth):
        if len(np.unique(y)) == 1:
            return self.majority_class(y)
        if depth >= self.max_depth:
            return self.majority_class(y)
        if len(y) < self.min_samples_split:
            return self.majority_class(y)

        feature, threshold = self.best_split(X, y)
        if feature is None:
            return self.majority_class(y)

        left_mask = X[:, feature] <= threshold
        right_mask = X[:, feature] > threshold

        left_tree = self.build_tree(X[left_mask], y[left_mask], depth + 1)
        right_tree = self.build_tree(X[right_mask], y[right_mask], depth + 1)

        return {
            "feature": feature,
            "threshold": threshold,
            "left": left_tree,
            "right": right_tree
        }

    def fit(self, X, y):
        self.tree = self.build_tree(X, y, depth=0)

    def predict_one(self, x, tree):
        if not isinstance(tree, dict):
            return tree

        feature = tree["feature"]
        threshold = tree["threshold"]

        if x[feature] <= threshold:
            return self.predict_one(x, tree["left"])
        else:
            return self.predict_one(x, tree["right"])

    def predict(self, X):
        return np.array([self.predict_one(x, self.tree) for x in X])
```


### kNN from scratch

The whole classifier is a distance matrix, a sort and a vote. The identity $\lVert\mathbf{q} - \mathbf{x}\rVert^2 = \lVert\mathbf{q}\rVert^2 - 2\,\mathbf{q}^\top\mathbf{x} + \lVert\mathbf{x}\rVert^2$ gives every query-to-training distance in one matrix product, with no loop:

```python
def knn_predict(X_train, y_train, X_query, k):
    d2 = (X_query ** 2).sum(axis=1)[:, None] - 2 * X_query @ X_train.T + (X_train ** 2).sum(axis=1)
    nearest = np.argsort(d2, axis=1)[:, :k]                 # (queries, k) indices
    return (y_train[nearest].mean(axis=1) > 0.5).astype(int)   # majority vote, two classes
```

On the breast-cancer data from the regression module, with the scaler fit on the training rows, it predicts exactly what scikit-learn predicts. The same model without the scaler loses 3.5 points of accuracy:

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

data = load_breast_cancer()
X_train, X_test, y_train, y_test = train_test_split(
    data.data, data.target, test_size=0.25, random_state=0, stratify=data.target)
scaler = StandardScaler().fit(X_train)
Xs_train, Xs_test = scaler.transform(X_train), scaler.transform(X_test)

ours = knn_predict(Xs_train, y_train, Xs_test, k=5)
sk = KNeighborsClassifier(n_neighbors=5).fit(Xs_train, y_train)
print(f"same predictions as scikit-learn: {np.array_equal(ours, sk.predict(Xs_test))}")
print(f"scaled   k=5: test accuracy {sk.score(Xs_test, y_test):.3f}")
print(f"unscaled k=5: test accuracy {KNeighborsClassifier(n_neighbors=5).fit(X_train, y_train).score(X_test, y_test):.3f}")
```

### Choosing k by cross-validation

Five stratified folds of the training rows, with the scaler inside the pipeline so it is re-fit on each fold's training part:

```python
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline

folds = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
print(f"{'k':>3} {'CV accuracy':>12}")
for k in (1, 3, 5, 7, 11, 15, 21, 31, 51):
    model = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=k))
    print(f"{k:>3} {cross_val_score(model, X_train, y_train, cv=folds).mean():>12.4f}")
```

### Axis-aligned splits, measured

A diagonal boundary with 10% of the labels flipped, so no model can beat about 0.90 in expectation (the exact ceiling depends on how many of the 240 test rows happened to be flipped), then the same noise on a boundary that one cut can express:

```python
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(0)
n, d = 600, 8
X = rng.standard_normal((n, d))
flip = rng.random(n) < 0.10          # 10% label noise, so the ceiling is 0.90

def split(rule):
    y = np.where(flip, 1 - rule, rule)
    return train_test_split(X, y, test_size=0.4, random_state=0, stratify=y)

# The true rule is a diagonal hyperplane: no single feature decides it.
Xtr, Xte, ytr, yte = split((X[:, 0] + 0.7 * X[:, 1] - 0.5 * X[:, 2] > 0).astype(int))

print("growing a tree on a diagonal boundary, 360 training rows")
print(f"{'max_depth':>10} {'leaves':>7} {'train':>7} {'test':>7} {'gap':>7}")
for depth in (1, 2, 3, 5, 8, 12, None):
    t = DecisionTreeClassifier(max_depth=depth, random_state=0).fit(Xtr, ytr)
    tr, te = t.score(Xtr, ytr), t.score(Xte, yte)
    print(f"{str(depth):>10} {t.get_n_leaves():>7} {tr:>7.3f} {te:>7.3f} {tr - te:>7.3f}")

lr = LogisticRegression(max_iter=2000).fit(Xtr, ytr).score(Xte, yte)
print(f"\n  logistic regression on the same data: {lr:.3f}   (noise ceiling 0.900)")

# Same features, same noise, but a rule one axis-aligned cut can express.
Xtr2, Xte2, ytr2, yte2 = split((X[:, 0] > 0).astype(int))
stump = DecisionTreeClassifier(max_depth=1, random_state=0).fit(Xtr2, ytr2).score(Xte2, yte2)
lr2 = LogisticRegression(max_iter=2000).fit(Xtr2, ytr2).score(Xte2, yte2)
print(f"  rule changed to a single cut on x0: depth-1 tree {stump:.3f}, logistic {lr2:.3f}")
```

```output
growing a tree on a diagonal boundary, 360 training rows
 max_depth  leaves   train    test     gap
         1       2   0.747   0.704   0.043
         2       4   0.792   0.692   0.100
         3       8   0.836   0.742   0.094
         5      29   0.928   0.758   0.169
         8      52   0.989   0.742   0.247
        12      56   1.000   0.746   0.254
      None      56   1.000   0.746   0.254
```

On the tilted boundary the best tree at any depth reaches 0.758 and logistic regression, which can write the plane down, reaches 0.867. The gap column widens from 0.043 to 0.254 as the tree absorbs the flipped labels one leaf at a time. Change the rule to a single cut on $x_0$ and a one-split tree beats the same logistic regression, 0.912 to 0.883. Same data, same noise, and the winner flips on whether the boundary lines up with an axis.
