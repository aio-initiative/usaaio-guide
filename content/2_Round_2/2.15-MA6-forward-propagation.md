## Overview

Forward propagation is computing a network's output from its input, one layer at a time, keeping every intermediate value. It is what `model(x)` runs in PyTorch, and the contest asks for it by hand. A Round 1 problem gives you a small network's weights and an input and expects every weighted sum, every activation and the output probabilities, as [2025 Round 1](https://forum.beaver-edge.ai/c/ai-olympiads/usa-north-america-ai-olympiad/8), Problem 2 did. The intermediate values matter too, because [backpropagation](2.1-MA4-backpropagation-mechanics.md) uses every one of them.

## Example: a forward pass by hand

A network has two inputs, one hidden layer of three ReLU units, and a softmax output over two classes, with

$$
\begin{aligned}
W^{(1)} &= \begin{pmatrix} 1 & -1 \\ 0 & 1 \\ 1 & 1 \end{pmatrix}, &
\mathbf{b}^{(1)} &= \begin{pmatrix} 0 \\ 0 \\ -2 \end{pmatrix}, \\[6pt]
W^{(2)} &= \begin{pmatrix} 1 & 0 & 1 \\ 0 & 1 & 1 \end{pmatrix}, &
\mathbf{b}^{(2)} &= \begin{pmatrix} 0 \\ 0 \end{pmatrix}.
\end{aligned}
$$

The input is $\mathbf{x} = (1, 2)^\top$ and the true class is 0.

**(a)** Compute the hidden layer's weighted sums $\mathbf{z}^{(1)}$, called its pre-activation, and its activation $\mathbf{a}^{(1)}$.

**(b)** Compute the logits $\mathbf{z}^{(2)}$ and the output probabilities $\hat{\mathbf{y}}$.

**(c)** Compute the cross-entropy loss.

The worked solution is the section below.

## Explanation

### One layer after another

Number the layers $1, \dots, L$ and call the input $\mathbf{a}^{(0)}$. Each layer does two things. It takes a weighted sum of the previous layer's outputs and adds a bias, which gives its **pre-activation** $\mathbf{z}^{(l)}$. Then it applies its activation function $\varphi$, which gives its **activation** $\mathbf{a}^{(l)}$:

$$
\begin{aligned}
\mathbf{z}^{(l)} &= W^{(l)} \mathbf{a}^{(l-1)} + \mathbf{b}^{(l)}, \\
\mathbf{a}^{(l)} &= \varphi\!\left(\mathbf{z}^{(l)}\right).
\end{aligned}
$$

In the example $\varphi$ is ReLU for the hidden layer and softmax for the output. The network's output is $\hat{\mathbf{y}} = \mathbf{a}^{(L)}$, and the pre-activations of the last layer are the **logits**. For the example, layer 1 is

$$
\begin{aligned}
\mathbf{z}^{(1)} &= W^{(1)}\mathbf{x} + \mathbf{b}^{(1)} \\[4pt]
&= \begin{pmatrix} 1 - 2 \\ 0 + 2 \\ 1 + 2 \end{pmatrix} + \begin{pmatrix} 0 \\ 0 \\ -2 \end{pmatrix} =
\begin{pmatrix} -1 \\ 2 \\ 1 \end{pmatrix}, \\[6pt]
\mathbf{a}^{(1)} &= \mathrm{ReLU}(\mathbf{z}^{(1)}) = \begin{pmatrix} 0 \\ 2 \\ 1 \end{pmatrix}.
\end{aligned}
$$

That is part (a). The first unit is off. ReLU zeroes it, and no later layer sees anything from it. Layer 2 reads $\mathbf{a}^{(1)}$:

$$
\begin{aligned}
\mathbf{z}^{(2)} &= W^{(2)}\mathbf{a}^{(1)} + \mathbf{b}^{(2)} \\[4pt]
&= \begin{pmatrix} 0 + 0 + 1 \\ 0 + 2 + 1 \end{pmatrix} = \begin{pmatrix} 1 \\ 3 \end{pmatrix}.
\end{aligned}
$$

### Softmax and the loss

The output layer of a classifier turns its logits into probabilities with the softmax,

$$
\operatorname{softmax}(\mathbf{z})_i = \frac{e^{z_i}}{\sum_j e^{z_j}},
$$

so here $\hat{\mathbf{y}} = (e^1, e^3) / (e^1 + e^3) = (0.1192, 0.8808)$. That completes part (b). For two classes the softmax of the second class is a sigmoid of the logit gap, $\hat y_1 = 1 / (1 + e^{-(z_1 - z_0)}) = \sigma(3 - 1) = \sigma(2) \approx 0.8808$, which matches the softmax above.

With a one-hot label $\mathbf{y}$ the **cross-entropy loss** is $L = -\sum_k y_k \log \hat y_k$, which picks out the probability of the true class. The true class is 0, so $L = -\log 0.1192 = 2.127$. That is part (c). The network puts 88% on the wrong class and the loss says so: $\log 2 = 0.693$ would be a coin flip and 0 would be certainty on the right answer.

Typed in as written, softmax overflows. A logit of 1000 makes $e^{1000}$ infinite and the ratio `nan`. Subtracting the largest logit $m$ from every entry first changes nothing, because the factor $e^{-m}$ cancels top and bottom, and leaves every exponent at or below 0. Every softmax should be written that way.

### Batches: rows are examples

Code runs many examples at once. The convention NumPy and PyTorch share is that rows are examples: $N$ inputs stacked into a matrix $A^{(0)}$ of shape $N \times n_0$. To keep that layout the weight matrix is stored transposed relative to the derivation, and the weighted-sum step is

$$
Z^{(l)} = A^{(l-1)} W^{(l)} + \mathbf{b}^{(l)} .
$$

Here $W^{(l)}$ has shape $n_{l-1} \times n_l$, $Z^{(l)}$ has shape $N \times n_l$, and the bias, one row of length $n_l$, is added to every row. Same arithmetic, one example per row. Every $W$ in the derivation above is the transpose of the `W` in the code below, and a forward pass that runs but returns nonsense is almost always a transpose or shape error. Write the shape of each intermediate next to the line that produces it.

### The cache

Training runs the chain rule backward through the same layers. The backward pass needs $\mathbf{z}^{(l)}$ at each layer to differentiate $\varphi$ and $\mathbf{a}^{(l-1)}$ to differentiate the matrix multiply. Recomputing them would double the work, so the forward pass keeps every $Z^{(l)}$ and $A^{(l)}$ as it goes. PyTorch does the same thing inside autograd. The next module uses this cache for the backward pass of the same example.

## Implementation

The recurrence as a loop, for any depth and any per-layer activation, in the rows-are-examples layout:

```python
import numpy as np

np.set_printoptions(precision=4, suppress=True)

def relu(Z):
    return np.maximum(0.0, Z)

def softmax(Z):
    Z = Z - Z.max(axis=1, keepdims=True)        # the shift that keeps exp from overflowing
    E = np.exp(Z)
    return E / E.sum(axis=1, keepdims=True)

def forward(X, params, acts):
    """X: (N, n_0), one example per row. params[i] = (W, b) for layer i + 1, i = 0 .. L-1,
    with W of shape (n_i, n_{i+1}) and b of shape (n_{i+1},). Returns the output and the cache."""
    cache = {"A0": X}
    A = X
    for l, ((W, b), phi) in enumerate(zip(params, acts), start=1):
        Z = A @ W + b                           # (N, n_l): the bias broadcasts down the rows
        A = phi(Z)
        cache[f"Z{l}"] = Z
        cache[f"A{l}"] = A
    return A, cache
```

The example's weights go in transposed, and the input becomes a one-row matrix:

```python
W1 = np.array([[1., 0., 1.], [-1., 1., 1.]])    # (2, 3): the derivation's W1, transposed
b1 = np.array([0., 0., -2.])
W2 = np.array([[1., 0.], [0., 1.], [1., 1.]])   # (3, 2)
b2 = np.array([0., 0.])
params = [(W1, b1), (W2, b2)]

X = np.array([[1., 2.]])                        # one example, as a row
out, cache = forward(X, params, [relu, softmax])
for name in ("Z1", "A1", "Z2", "A2"):
    print(name, cache[name])
print(f"loss {-np.log(out[0, 0]):.4f}")
```

Every number from the hand computation, in order:

```output
Z1 [[-1.  2.  1.]]
A1 [[0. 2. 1.]]
Z2 [[1. 3.]]
A2 [[0.1192 0.8808]]
loss 2.1269
```

A second example costs one more row. The parameters do not change shape, only the activations do:

```python
X2 = np.array([[1., 2.], [0., 1.]])             # two examples
out2, cache2 = forward(X2, params, [relu, softmax])
for name in ("A0", "Z1", "A1", "Z2", "A2"):
    print(name, cache2[name].shape)
print(out2)
```

```output
A0 (2, 2)
Z1 (2, 3)
A1 (2, 3)
Z2 (2, 2)
A2 (2, 2)
[[0.1192 0.8808]
 [0.2689 0.7311]]
```

And the overflow that the shift in `softmax` prevents:

```python
z = np.array([[1000., 0.]])
with np.errstate(over="ignore", invalid="ignore"):
    print(np.exp(z) / np.exp(z).sum())          # the formula as written
print(softmax(z))                               # with the shift
```

```output
[[nan  0.]]
[[1. 0.]]
```
