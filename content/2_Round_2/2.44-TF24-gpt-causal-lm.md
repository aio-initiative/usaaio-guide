## Overview

Your phone's keyboard suggests the next word as you type. Tap a suggestion, and it suggests another. Keep tapping and it writes a whole (usually silly) sentence. Could a model that plays this one game well enough answer questions or translate a sentence?

**GPT** (Generative Pre-trained Transformer) models show that it can. A GPT is trained only to predict the next token, and it writes by doing that over and over. GPT-3 answered questions and translated text this way, given a few examples in its prompt.

The USAAIO contest lists pre-training under natural language processing, and the IOAI contest lists language modeling by name. Round 2 papers have had attention problems (multi-head attention in 2025, linear attention in 2026), and a GPT's attention layer is that attention code with one mask added. Training it also needs the targets shifted by one, and both steps are easy to get wrong.

## Example: the probability of a sentence

A model gives these probabilities: $P(\text{the}) = 0.2$, $P(\text{cat} \mid \text{the}) = 0.1$ and $P(\text{sat} \mid \text{the cat}) = 0.5$. Here $P(\text{the})$ is its probability that a text starts with "the".

1. What probability does it give the sentence "the cat sat"?
2. What is its average loss per token, and its perplexity?
3. When training on these 3 tokens, which tokens may position 2 ("cat") attend to?

## Explanation

### One sentence, many predictions

How do you give a probability to a whole sentence? Build it one token at a time. In this example each word is one token, a simplification that [tokenization and word embeddings](3.4-NL1-natural-language-processing-tokenization-embeddings.md) exist to remove. First pick the first word, then the second given the first, and so on:

$$
P(\text{the cat sat}) = P(\text{the}) \cdot P(\text{cat} \mid \text{the}) \cdot P(\text{sat} \mid \text{the cat}) = 0.2 \cdot 0.1 \cdot 0.5 = 0.01 .
$$

Each step uses the rule $P(A, B) = P(A)\,P(B \mid A)$: the chance of $A$ and $B$ together is the chance of $A$ times the chance of $B$ once $A$ has happened. Applying it twice splits the sentence into one factor per word. This is the **chain rule of probability**, and it works for any sentence. So a model that predicts the next token from everything before it can give a probability to any text. This is **causal language modeling**: each token is predicted only from the tokens before it.

<ProblemCard id="gpt-one-text-two-tokenizations" />

### Where the probabilities come from

A Transformer turns each input token into a vector. At every position, a final linear layer turns that vector into one score for each token in the vocabulary. These scores are the **logits**, and a softmax turns them into probabilities. So each position is a classifier whose classes are the tokens of the vocabulary.

It is trained like any softmax classifier, with the [cross-entropy loss](1.28-ML9-loss-functions.md): $-\ln$ of the probability it gave the true next token. Averaged over the three tokens of the focus sentence:

$$
\mathcal{L} = -\tfrac13\left(\ln 0.2 + \ln 0.1 + \ln 0.5\right) = \tfrac13(1.609 + 2.303 + 0.693) \approx 1.535 .
$$

The more probability the model gives the real text, the lower the loss.

A loss of 1.535 is hard to picture, so people often report the **perplexity** $e^{\mathcal{L}}$ instead. Here it is $e^{1.535} \approx 4.64$. Why is that a useful number? Suppose a model spreads its probability evenly over $k$ tokens. Each true token gets $1/k$, so the loss is $-\ln(1/k) = \ln k$ and the perplexity is $e^{\ln k} = k$. So a perplexity of 4.64 means the model is, on average, as unsure as if it were picking evenly among about 4.6 tokens. Perplexity only compares within one tokenization: across tokenizers, divide the total loss by words or bytes instead.

### Training on every position at once

The focus sentence holds three predictions: "the" at the start, "cat" after "the", and "sat" after "the cat". Running the model once per prefix would be slow. Can one pass give all of them?

A Transformer already gives one output per position in a single pass. The catch is attention. If position 2 could attend to position 3, it could read the token it is supposed to predict. So we block every position from attending to later ones.

Look at the matrix of attention scores. Row $t$ is the query at position $t$, and column $s$ is the key at position $s$. The entries above the diagonal have $s > t$, so they point to the future. We set them to $-\infty$ before the softmax. Since $e^{-\infty} = 0$, their weights become exactly 0. This is the **causal mask**, the same one the decoder uses in [Build a Transformer: 6. Mask and softmax](2.36-TF16-transformer-mask-and-softmax.md).

Every attention layer uses this mask, and the other layers act on each position alone. So the output at position $t$ depends only on tokens $1, \dots, t$, and changing token $t+1$ cannot change it. The output at position $t$ is the same as if we ran the model on the first $t$ tokens alone. So one masked pass does the work of one separate run per prefix.

In code, the targets are the inputs shifted by one. The model reads tokens $1, \dots, T-1$ and is scored on predicting tokens $2, \dots, T$. So $T$ tokens give $T - 1$ predictions, because nothing comes before token 1. To get a probability for the first word too, as in the focus problem, many models (Llama among them) put a special start token `<s>` in front of every text. The first word is then predicted from `<s>` like any other token. Training on the true earlier tokens, rather than the model's own guesses, is called **teacher forcing**. [Pre-training & Fine-tuning](3.14-NL3-pre-training-fine-tuning.md#teacher-forcing-and-the-one-token-shift) covers it and the shift in more detail.

<ProblemCard id="gpt-window-cuts-what-gets-trained" />

Put together, a GPT is a stack of Transformer decoder blocks with the causal mask. There is no encoder, so the blocks also drop the cross-attention sublayer. Each block is masked self-attention followed by a feed-forward layer. BERT is the mirror image: an encoder with no causal mask, trained by [filling in blanks](2.10-TF2-transformer-architectures-bert-mlm.md).

### Generating text

To write, start from a prompt and repeat:

1. Run the model on the text so far and take the probabilities at the last position. They are its guess for the next token.
2. Choose a token.
3. Append it to the text and go back to step 1.

Generation stops after a set number of tokens, or when the model picks a special end-of-text token.

How to choose? Always taking the most likely token is called **greedy decoding**. It gives safe text that often repeats itself in a loop. Sampling from the probabilities gives variety, but it sometimes picks an unlikely token and drifts into nonsense. **Temperature** $\tau$ controls the trade-off. We divide every logit by $\tau$ before the softmax:

$$
p_i = \frac{e^{z_i/\tau}}{\sum_j e^{z_j/\tau}} ,
$$

where $z_i$ is the logit of token $i$, $p_i$ is its probability, and the sum runs over every token in the vocabulary. At $\tau = 1$ this is the ordinary softmax. A $\tau$ below 1 stretches the gaps between logits, so the most likely token takes more of the probability. A $\tau$ above 1 shrinks every logit toward 0, so the probabilities even out.

<ProblemCard id="gpt-temperature-without-logits" />

Top-$k$ sampling, top-$p$ (nucleus) sampling and beam search are other ways to choose the token. [Pre-training & Fine-tuning](3.14-NL3-pre-training-fine-tuning.md#generating-text-choosing-each-token) works through each one on an example. A fluent sample also does not certify factuality: next-token likelihood rewards compatibility with text patterns, including patterns that do not ground a claim in external evidence.

### Solving the focus problem

1. Multiply the conditional probabilities: $0.2 \cdot 0.1 \cdot 0.5 = 0.01$.
2. Average $-\ln$ of each one: $\tfrac13(1.609 + 2.303 + 0.693) \approx 1.535$. The perplexity is $e^{1.535} \approx 4.64$.
3. Row 2 of the causal mask keeps columns 1 and 2. So "cat" attends to "the" and to itself, and never to "sat".

For any text of tokens $x_1, \dots, x_T$, the same steps read

$$
P(x_1, \dots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_1, \dots, x_{t-1}),
\qquad
\mathcal{L} = -\frac{1}{T} \sum_{t=1}^{T} \ln P(x_t \mid x_1, \dots, x_{t-1}),
$$

and the perplexity is $e^{\mathcal{L}}$. Here $x_t$ is the token at position $t$, $T$ is the number of tokens, and $\prod$ means multiply the terms together. For $t = 1$ nothing comes before the token, so its factor is the probability of starting with it (in practice, predicted from `<s>`).

## Implementation

Here is one causal self-attention layer in PyTorch, on 4 positions with random vectors. `torch.tril` marks the allowed keys (the diagonal and below), and `masked_fill` writes $-\infty$ everywhere else. Then we change the vector at position 4 and measure how far each output moves. Code counts from 0, so `x[3]` is position 4.

```python
import torch

torch.manual_seed(0)
T, d = 4, 8
x = torch.randn(T, d)                                # one vector per position
W_q, W_k, W_v = (torch.randn(d, d) / d ** 0.5 for _ in range(3))

def causal_self_attention(x):
    Q, K, V = x @ W_q, x @ W_k, x @ W_v
    scores = Q @ K.T / d ** 0.5                      # row t = query t, column s = key s
    allowed = torch.tril(torch.ones(len(x), len(x), dtype=torch.bool))
    scores = scores.masked_fill(~allowed, float("-inf"))
    weights = torch.softmax(scores, dim=-1)
    return weights @ V, weights

out, weights = causal_self_attention(x)
print(weights.round(decimals=3))

x_changed = x.clone()
x_changed[3] += 1.0                                  # change only the last position
out_changed, _ = causal_self_attention(x_changed)
print("largest change at positions 1-3:", (out_changed[:3] - out[:3]).abs().max().item())
print("largest change at position 4:   ", round((out_changed[3] - out[3]).abs().max().item(), 2))
```

```output
tensor([[1.0000, 0.0000, 0.0000, 0.0000],
        [0.4020, 0.5980, 0.0000, 0.0000],
        [0.3770, 0.5880, 0.0350, 0.0000],
        [0.0880, 0.1310, 0.6840, 0.0980]])
largest change at positions 1-3: 0.0
largest change at position 4:    0.39
```

Every weight above the diagonal is 0, and each row still sums to 1. Position 1 can see only itself, so all its weight is on itself. Changing position 4 moves its own output by 0.39 and the outputs at positions 1 to 3 by exactly 0.

The loss needs the shift. `F.cross_entropy` expects one row of logits per prediction and one target id per row, so we flatten the batch and position axes together. As a stand-in for `model(inputs)` we use all-zero logits over a 10-token vocabulary, which is a model that knows nothing.

```python
import torch.nn.functional as F

vocab_size = 10
tokens = torch.tensor([[5, 9, 2, 7, 3]])             # a batch of one sequence, shape (1, 5)
inputs, targets = tokens[:, :-1], tokens[:, 1:]      # each shape (1, 4)
logits = torch.zeros(1, 4, vocab_size)               # stand-in for model(inputs): all logits equal
loss = F.cross_entropy(logits.reshape(-1, vocab_size), targets.reshape(-1))
print("inputs: ", inputs.tolist(), " targets:", targets.tolist())
print(f"loss = {loss.item():.3f}, perplexity = {loss.exp().item():.2f}")
```

```output
inputs:  [[5, 9, 2, 7]]  targets: [[9, 2, 7, 3]]
loss = 2.303, perplexity = 10.00
```

Equal logits give each of the 10 tokens probability 0.1. So the loss is $\ln 10 \approx 2.303$ and the perplexity is 10, the size of the vocabulary. A trained model should score well below that.

<NotebookCard id="gpt-packed-rows-numpy" />

One of the smallest language models predicts the next word from the current word only. This is called a **bigram model**. We count how often each word follows each other word in a tiny corpus. We also add 1 to every count, so no next word has probability 0 (this is **add-one smoothing**). Dividing each row by its total gives $P(\text{next} \mid \text{current})$. The logs of these probabilities play the role of logits, so temperature works the same way as in a GPT. The model is not a Transformer, but it generates text with the same loop.

```python
import numpy as np

corpus = "the cat sat on the mat . the dog sat on the log . the cat saw the dog .".split()
vocab = sorted(set(corpus))
idx = {w: i for i, w in enumerate(vocab)}
counts = np.ones((len(vocab), len(vocab)))          # add-one smoothing
for a, b in zip(corpus[:-1], corpus[1:]):           # inputs corpus[:-1], targets corpus[1:]
    counts[idx[a], idx[b]] += 1
probs = counts / counts.sum(axis=1, keepdims=True)  # P(next word | current word)

def generate(start, steps, temperature, rng):
    words = [start]
    for _ in range(steps):
        logits = np.log(probs[idx[words[-1]]]) / temperature
        q = np.exp(logits - logits.max()); q /= q.sum()
        words.append(vocab[rng.choice(len(vocab), p=q)])
    return " ".join(words)

rng = np.random.default_rng(0)
greedy = ["the"]
for _ in range(6):
    greedy.append(vocab[probs[idx[greedy[-1]]].argmax()])
print("greedy:           ", " ".join(greedy))
print("temperature 1.0:  ", generate("the", 6, 1.0, rng))
print("temperature 0.3:  ", generate("the", 6, 0.3, rng))
```

```output
greedy:            the cat sat on the cat sat
temperature 1.0:   the mat cat . . the saw
temperature 0.3:   the dog sat on the log .
```

Greedy decoding falls into a loop. "Cat" and "dog" follow "the" equally often, and `argmax` picks the first one in the vocabulary, "cat", every time. Temperature 1.0 samples too freely. Smoothing gave every pair of words some probability, and this sample uses four pairs that never appear in the corpus, such as "mat cat". Temperature 0.3 keeps to likely pairs and still produces a different sentence from the greedy one.

<Warning>

The targets are the inputs moved one position left: `inputs = tokens[:-1]`,
`targets = tokens[1:]`. Suppose you score position $t$ against token $t$
instead of token $t + 1$. Each position can attend to itself, so the model only
has to copy its input. The loss drops to almost 0, and the model learns
nothing useful. A training loss that is suspiciously close to 0 from the start
is the usual sign.

Hugging Face models such as `GPT2LMHeadModel` do the shift inside the model,
so you pass `labels=input_ids`. If you shift the labels yourself as well, the
model learns to predict two tokens ahead.

</Warning>

<Optional title="Why bigger GPTs behave so differently">

GPT-1 (2018) had 117 million parameters, GPT-2 (2019) had 1.5 billion and GPT-3 (2020) had 175 billion. All three were trained on the same next-token objective. The larger models showed **in-context learning**: shown a few examples of a task in the prompt, they continue the pattern without any change to their weights. The loss never mentions tasks or examples. One common explanation is that predicting web text well rewards working out what task a document is doing. Why in-context learning appears is still being studied.

Generating one token at a time is slow if every step recomputes attention over the whole prefix. Real systems store each layer's keys and values for the tokens already processed. This store is the **KV cache**, covered in [Efficient Transformers: 2. KV cache](4.9-TF27-efficient-kv-cache.md).

</Optional>
