## The problem

One convolution layer finds simple patterns such as edges. Recognizing a face or a car needs patterns built from patterns: edges make corners and curves, those make eyes and wheels, and those make faces and cars. Each stage needs at least one more layer, so a network that recognizes real objects has to be deep.

<Figure src="assets/module-media/vision-problem-depth.svg" alt="Four boxes joined by arrows: edges, found by the first layer, then corners and curves after a few layers, then eyes and wheels after more layers, then faces and cars after many layers. A note says: each stage is built from the one before.">
Why depth is needed. Each kind of pattern is built from the simpler ones below it.
</Figure>

But simply stacking more layers stopped working. He et al. trained a 20-layer and a 56-layer network of the same design on CIFAR-10, and the 56-layer one had the higher error, even on its own training images. A deeper network can do everything a shallower one can, so the extra layers should not hurt. The deep network was not too powerful. It could not be trained well.

## Earlier approaches

### AlexNet

AlexNet (2012) had 8 layers with learned weights, 5 convolutional and 3 fully connected, and about 60 million weights. It used large filters, 11 × 11 in its first layer, and showed that depth trained on GPUs pays off.

### VGG

VGG (2014) used only 3 × 3 filters and went to 16 and 19 layers. Two stacked 3 × 3 layers cover the same 5 × 5 area as one 5 × 5 filter with fewer weights, 2 × 9 = 18 instead of 25, and they put a ReLU after each layer, two where the single filter has one. But the VGG authors found that error stopped improving at 19 layers.

## Shortcut connections

**Why depth is hard.** The gradient reaches early layers by passing back through every layer above them, and each layer can shrink it. If every layer scales it by 0.8, after $n$ layers $0.8^n$ of it is left:

| Layers | Gradient left |
|---|---|
| 10 | $0.8^{10} = 0.107$ |
| 20 | $0.8^{20} = 0.012$ |
| 50 | $0.8^{50} = 0.000014$ |

**The shortcut.** **ResNet** (2015) adds a **shortcut** around each block of layers: the block's input is added to its output, so a block computes

$$
\text{output} = x + F(x)
$$

instead of $F(x)$. For example, if a block's layers output $F(x) = (0, 0)$ for the input $x = (6, 0)$, the block returns (6, 0), its input unchanged.

<Figure src="assets/module-media/vision-shortcut.svg" alt="A row of boxes: x, then a block of layers F(x), then a plus sign, then x + F(x). A dashed line labeled shortcut: the input, unchanged carries x around the block and into the plus sign. Under the boxes are the running example's numbers: x is 6, 0, 6, 0. The block, with all its weights at 0, outputs 0, 0, 0, 0. x + F(x) is 6, 0, 6, 0.">
A block with a shortcut. With its weights at 0 the block adds nothing, and the input passes through.
</Figure>

**Why it helps.** A small change in $x$ reaches the output twice, once through the shortcut and once through $F$, so the gradient through the block is multiplied by $1 +$ (the factor of $F$) instead of by the factor of $F$ alone. For a block whose weights are all 0, a change of 0.001 in the input changes the output by 0 without the shortcut and by 0.001 with it: factors of 0 and 1. The gradient keeps a path back to the early layers at full size. It is not a guarantee against vanishing or exploding gradients: the learned block can still cancel or amplify a direction, so a deep residual network can still train badly. And a block that has nothing useful to add only needs $F(x) = 0$, which is easy to learn.

**The result.** With shortcuts, networks of 152 layers trained well, and an ensemble of six ResNets won the 2015 ImageNet challenge with 3.57% top-5 error.

## ResNet-50

**Stem and stages.** ResNet-50 starts with a **stem**, a 7 × 7 convolution with stride 2 and then a 3 × 3 max pooling with stride 2, which turn a 224 × 224 image into 64 maps of 56 × 56. Four **stages** of blocks follow, with 3, 4, 6 and 3 blocks. Stage 1 keeps the maps at 56 × 56 and gives 256 channels, and stage 4 ends with 2,048 maps of 7 × 7.

**Bottleneck blocks.** Each block is a **bottleneck**: a 1 × 1 convolution shrinks the channels, a 3 × 3 convolution works on the smaller number, and a second 1 × 1 convolution expands them 4 times. The first block of stage 1 takes 64 channels in and gives 256 out, so its shortcut carries a 1 × 1 convolution from 64 to 256 channels to match the shapes.

<Figure src="assets/module-media/vision-bottleneck.svg" alt="A row of boxes: x, with 64 maps of 56 by 56, then a 1 by 1 convolution from 64 to 64 channels with 4,096 weights, a 3 by 3 convolution from 64 to 64 with 36,864, outlined most heavily, and a 1 by 1 convolution from 64 to 256 with 16,384. Under them, batch normalization adds 128, 128 and 512. A plus sign gives 256 maps of 56 by 56. A dashed shortcut from x to the plus sign carries a 1 by 1 convolution from 64 to 256 with 16,384 weights and 512 for batch normalization. A note says: 75,008 in all.">
The first bottleneck block of ResNet-50 with the number of weights in each layer.
</Figure>

**The last layer.** After stage 4, **global average pooling** turns each of the 2,048 maps of 7 × 7 into one number, its average, and a fully connected layer turns those 2,048 numbers into scores for the 1,000 ImageNet classes.

## Counting parameters

**The rules.** A network's **parameters** are the numbers training adjusts. Each kind of layer has a fixed count:

| Layer | Parameters |
|---|---|
| $k \times k$ convolution from $c_\text{in}$ to $c_\text{out}$ channels | $k \times k \times c_\text{in} \times c_\text{out}$, plus $c_\text{out}$ offsets (biases) if used |
| Batch normalization over $c$ channels | $2 \times c$, a scale and a shift for each channel |
| Fully connected, $n_\text{in}$ to $n_\text{out}$ | $n_\text{in} \times n_\text{out}$, plus $n_\text{out}$ offsets if used |

ResNet's convolutions have no offsets, because the [batch normalization](1.19-DL2-neural-network-regularization-dropout-batchnorm.md) after each one adds its own shift.

**The running example.** The two 3 × 3 filters have 3 × 3 × 1 × 2 = 18 weights and the classification layer 8 × 2 = 16, so the network of Steps 2 to 4 has 34. Suppose the extra block of this step is two 3 × 3 convolutions from the 2 pooled maps to 2 maps, padded so the maps stay 2 × 2, each followed by batch normalization. It adds 2 × (3 × 3 × 2 × 2 + 2 × 2) = 2 × (36 + 4) = 80, and the shortcut adds none.

**One block of ResNet-50.** The first block of stage 1, `layer1[0]` in torchvision's `resnet50`, from the figure:

| Layer | Weights | Batch normalization |
|---|---|---|
| 1 × 1, 64 to 64 | 1 × 1 × 64 × 64 = 4,096 | 2 × 64 = 128 |
| 3 × 3, 64 to 64 | 3 × 3 × 64 × 64 = 36,864 | 128 |
| 1 × 1, 64 to 256 | 1 × 1 × 64 × 256 = 16,384 | 2 × 256 = 512 |
| Shortcut, 1 × 1, 64 to 256 | 16,384 | 512 |

The total is 73,728 weights and 1,280 for batch normalization, 75,008. The other two blocks of stage 1 take 256 channels in and have no convolution on their shortcut, so each has 70,400, and the stage has 75,008 + 2 × 70,400 = 215,808.

**Where the parameters are.** Counted the same way, stage 4 has 14,964,736 parameters, 58.6% of the network's 25.6 million, because a convolution's count grows with the product of its channel numbers. The work is spread far more evenly. A 3 × 3 convolution in stage 4 has 64 times the weights of one in stage 1 but runs at 1/64 as many positions, so each does 3 × 3 × 64 × 64 × 56 × 56 = 3 × 3 × 512 × 512 × 7 × 7 = 115,605,504 multiply-adds for one image.

## Running example

Add one more block after the pooling of Step 3, and suppose its weights are all 0, as if it has learned nothing yet. The vertical pooled map going into it is 6, 0, 6, 0:

| Block | Output for the vertical map | p(vertical) |
|---|---|---|
| Plain, F(x) | 0, 0, 0, 0 | 0.5 |
| With a shortcut, x + F(x) | 6, 0, 6, 0 | 0.953 |

The plain block wipes out everything the earlier layers found, and the network is back to guessing. The block with a shortcut passes its input through, so the network still gives 95.3%. Training can then improve F from there.

```python
import numpy as np

x = np.array([6.0, 0.0, 6.0, 0.0])     # vertical pooled map
f = np.zeros(4)                         # block with all-zero weights

for name, out in [("plain", f), ("shortcut", x + f)]:
    scores = np.array([0.25 * out.sum(), 0.0])
    print(name, (np.exp(scores) / np.exp(scores).sum()).round(3))
```

## Common questions

**Is the 56-layer network overfitting?** No. Overfitting would mean a lower error on the training images and a higher one on new images. Here the deeper network was worse on its own training images, so the problem is that it was not trained well, not that it memorized.

**Were the gradients vanishing in the 56-layer network?** Not by much. He et al. used batch normalization and checked that the gradients reaching the early layers were of normal size, yet the 56-layer plain network still trained worse than the 20-layer one. A shortcut helps in both ways: the gradient keeps a path with a factor of 1, and a block that should do nothing only has to learn $F(x) = 0$.

**Does a shortcut add weights?** Not when the input and the output of the block have the same shape: it is an addition, with no weights. Where they differ, ResNet puts a 1 × 1 convolution on the shortcut to match them, and that convolution has weights, as the first block of each stage shows.

**Is this the same as the residual connection in a Transformer?** Yes. Step 9 of Build a Transformer adds the input of each layer back to its output in the same way, and for the same reason.
