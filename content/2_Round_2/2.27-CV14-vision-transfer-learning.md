> **Goal:** Freezing, linear probes and fine-tuning a trained network.
> **Stage:** Round 2, Core contest depth.

## The problem

A large network learns well from ImageNet's 1.2 million labeled photos. Most real tasks have far fewer. For example, a hospital might have a few hundred labeled X-rays.

<Figure src="assets/module-media/vision-problem-transfer.svg" alt="A horizontal bar chart on a logarithmic scale. The weights of ResNet-50: 25,600,000. The labeled photos in ImageNet: 1,200,000. The labeled images of a small task: a few hundred.">
A small task has thousands of times fewer images than ImageNet, and far fewer images than the network has weights.
</Figure>

ResNet-50 has about 25.6 million weights. With a few hundred images there are tens of thousands of weights for every image, so the network can simply memorize the training images: it scores well on them and fails on new ones. Collecting and labeling a million X-rays is not an option. The model needs a way to learn a new task from a small number of examples.

## Earlier approaches

### Training from scratch

Starting from random weights on a small dataset is the obvious approach, and it overfits: the network scores well on the training images and badly on new ones.

Augmentation is the usual answer: random, label-preserving transforms on the training images, and the same deterministic resize and normalization on the validation ones.

```python
from torchvision import transforms

train_tf = transforms.Compose([
    transforms.RandomResizedCrop(224, scale=(0.6, 1.0)),
    transforms.RandomHorizontalFlip(),          # Requires label-preserving flips.
    transforms.ColorJitter(0.2, 0.2, 0.2),
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
])
val_tf = transforms.Compose([                   # deterministic: no randomness at eval
    transforms.Resize(256), transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
])
```

### Hand-made features

The older answer was to describe each image with hand-made features, as in Step 1, and train a small classifier on them. It needs little data but is limited by how good the hand-made features are.

## Reusing a trained network

**What carries over.** The early layers of a network trained on ImageNet have learned edges, textures and shapes, which are useful for almost any kind of image. The same holds outside vision: in text, early layers learn syntax and morphology, while late layers learn task-specific facts that do not transfer. **Transfer learning** keeps those layers, the **backbone**, and replaces only the last layer, the **head**, with a new one for the new classes.

<Figure src="assets/module-media/vision-transfer.svg" alt="A row of boxes: filters, then ReLU and pooling, then totals of the two maps, all under a line labeled kept from the old network, frozen. A fourth box, outlined, reads new layer, 6 weights, under a line labeled trained. Its output is vertical, horizontal or cross.">
Transfer learning in the running example. Only the new layer is trained.
</Figure>

**Feature extraction.** Freeze the old layers and train only the new layer. When the new layer is a single linear layer, as here, this is also called a **linear probe**.

**Freezing in code.** In PyTorch, freezing sets `requires_grad = False` on every old parameter, so no gradient is computed for it and training cannot change it. In the running example the 18 weights of the two filters stay fixed and only the 2 × 3 = 6 weights of the new layer are trained, 6 of 24.

**Fine-tuning.** Then also train some of the old layers, with a small learning rate so they change only a little. A common middle ground trains only the last stage, such as stage 4 of ResNet-50, and keeps the rest frozen.

**Counting the weights.** A layer from $m$ features to $c$ classes has $m \times c$ weights and usually $c$ offsets. The running example below omits them, so each score is a pure weighted sum. ResNet-50 has about 25.6 million parameters. It averages each of its last 2,048 maps to one number, the job the totals do in the running example, and its last layer maps those 2,048 features to 1,000 ImageNet classes. Without that layer about 23.5 million remain. For a new task with 2 classes, the new layer has 2,048 × 2 + 2 = 4,098 weights. With feature extraction those are the only ones trained, 0.017% of the new network.

**A shorter backbone.** The frozen network can also be cut before its last stage. Cut after stage 1, ResNet-50 keeps 225,344 parameters and ends with 256 maps of 56 × 56. Averaging each map gives 256 features, and a new 2-class layer on them has 256 × 2 + 2 = 514 weights. The earlier stages hold more general patterns such as edges and textures, so a shorter backbone can suit images that look little like ImageNet's.

## Running example

### The new task

The new task has three classes: vertical, horizontal and a cross of both. The old layer cannot handle the cross: its two pooled maps total 10 each, so the old scores are 2.5 and 2.5, a tie.

### The frozen features

Keep the two filters, ReLU and pooling, and use the totals of the two pooled maps as features:

| Image | Vertical total | Horizontal total |
|---|---|---|
| vertical line | 12 | 0 |
| horizontal line | 0 | 12 |
| cross | 10 | 10 |

### The new layer

A new layer of 2 × 3 = 6 weights is trained on these three images for 100 steps. Rounded, it learns:

| Class | Weight on vertical total | Weight on horizontal total |
|---|---|---|
| vertical | 0.32 | −0.42 |
| horizontal | −0.42 | 0.32 |
| cross | 0.10 | 0.10 |

The cross class has a small positive weight on both totals, and each line class has a negative weight on the other line's total. Now each image gets its own label, using the unrounded weights: 0.934 for the vertical line, 0.934 for the horizontal line and 0.911 for the cross. The filters were never retrained.

```python
import numpy as np

features = np.array([[12.0, 0.0], [0.0, 12.0], [10.0, 10.0]])   # one row per image
W = np.zeros((2, 3))                                             # the new layer

for _ in range(100):
    s = features @ W
    p = np.exp(s) / np.exp(s).sum(axis=1, keepdims=True)
    p[np.arange(3), np.arange(3)] -= 1          # softmax gradient, image i is class i
    W -= 0.01 * features.T @ p / 3

s = features @ W
print((np.exp(s) / np.exp(s).sum(axis=1, keepdims=True)).round(3))
```

## Common questions

**When should the old layers be fine-tuned?** Images close to the ones the network was trained on need only the new layer. Images of a different kind, such as X-rays, usually benefit from fine-tuning the old layers as well. How much target data justifies unfreezing them is measured in [ResNets and Transfer Learning](2.8-CV4-modern-vision-architectures-resnet-efficientnet-transfer.md), which sweeps the crossover and sets the per-block rates.

**Do new images need the same preprocessing?** Yes. The frozen filters were set for pixel values from 0 to 1. The vertical line stored with values up to 255 gives totals of 3,060 and 0 instead of 12 and 0, far from anything the new layer was trained on. Torchvision's ImageNet networks expect values from 0 to 1, then each color channel standardized with ImageNet's means 0.485, 0.456 and 0.406 and standard deviations 0.229, 0.224 and 0.225.

**Why could the old layer not handle the cross?** It had one score per line direction. A cross lights up both pooled maps equally, 10 and 10, so the two scores tie at 2.5. The new layer has a third class that responds when both totals are high.
