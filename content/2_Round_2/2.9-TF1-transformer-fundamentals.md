### From Scratch

```python
import numpy as np


def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)     # shift-invariant, prevents overflow
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)


def attention(Q, K, V, mask=None):
    """Q: (..., n, d_k)  K: (..., m, d_k)  V: (..., m, d_v) -> (..., n, d_v).
    The 1/sqrt(d_k) keeps logit variance at 1 regardless of head width; without
    it the softmax saturates and its Jacobian diag(p) - pp^T goes to zero."""
    d_k = Q.shape[-1]
    scores = Q @ np.swapaxes(K, -1, -2) / np.sqrt(d_k)
    if mask is not None:
        # -inf BEFORE the softmax, so the surviving weights renormalize to 1.
        # Zeroing AFTER would leave rows summing to less than 1.
        scores = np.where(mask, scores, -np.inf)
    A = softmax(scores, axis=-1)
    return A @ V, A


def causal_mask(n):
    """True where attention is allowed: position i may see j <= i."""
    return np.tril(np.ones((n, n), dtype=bool))


def padding_mask(lengths, n):
    """(B, 1, 1, n) -- broadcast over heads and query positions."""
    idx = np.arange(n)[None, :]
    return (idx < np.asarray(lengths)[:, None])[:, None, None, :]


class MultiHeadAttention:
    """Total parameters are 4 d^2 regardless of h, because each head is d/h wide."""

    def __init__(self, d_model, n_heads, seed=0):
        assert d_model % n_heads == 0
        rng = np.random.default_rng(seed)
        self.h, self.d, self.dk = n_heads, d_model, d_model // n_heads
        scale = 1.0 / np.sqrt(d_model)
        # Only the products Wq @ Wk.T and Wv @ Wo actually matter to the function
        # computed, which is why the factorization into low-rank pieces is a
        # parameter-efficiency choice as much as a conceptual one.
        self.Wq, self.Wk, self.Wv, self.Wo = (
            rng.normal(0, scale, (d_model, d_model)) for _ in range(4))

    def _split(self, X):
        B, n, _ = X.shape
        return X.reshape(B, n, self.h, self.dk).transpose(0, 2, 1, 3)   # (B, h, n, dk)

    def _merge(self, X):
        B, h, n, dk = X.shape
        return X.transpose(0, 2, 1, 3).reshape(B, n, h * dk)

    def __call__(self, X, mask=None, kv=None):
        src = X if kv is None else kv           # kv != None gives cross-attention
        Q = self._split(X @ self.Wq)
        K = self._split(src @ self.Wk)
        V = self._split(src @ self.Wv)
        out, A = attention(Q, K, V, mask)
        return self._merge(out) @ self.Wo, A


def softmax_jacobian_scale(logits):
    """diag(p) - pp^T collapses to zero as the softmax saturates. Returns the
    largest entry, which is what the gradient through attention is proportional to."""
    z = np.asarray(logits, float)
    t = np.exp(z - z.max())              # the winner lands on 1.0
    p = t / t.sum()
    # 1 - p is the sum of the *other* probabilities. For the winner that sum has
    # to be built from those terms, because by the time it matters the winner's
    # own p has rounded to 1.0 and 1 - p has underflowed to 0.
    winner = int(np.argmax(t))
    one_minus_p = 1.0 - p
    one_minus_p[winner] = np.sum(np.delete(t, winner)) / t.sum()
    return float(np.max(p * one_minus_p))
```

`softmax_jacobian_scale` is the experiment behind the worked example's Step 5: feed it the row-3 logits scaled by 1, 20, and 100 and watch the value fall from $0.25$ to $10^{-31}$.

### Using the Library

PyTorch uses two different mask arguments in the same API. Both accept a boolean or a float tensor: for a float mask both are additive, so blocked entries receive `-inf`, and for a boolean mask `True` means blocked in either argument. What differs is the shape and the job: `key_padding_mask` is `(batch, src_len)` and masks padding keys, while `attn_mask` is `(tgt_len, src_len)` or `(batch*num_heads, tgt_len, src_len)` and can block any query-key pair. Check which one you have before blaming the attention scores. Also leave `need_weights=False` unless you intend to inspect the matrix, since requesting the weights disables the FlashAttention fast path.

### Worked Example

Single-head self-attention on a 3-token sequence with $d_k = d_v = 2$.

**Setup.**

$$
Q = \begin{bmatrix}1&0\\0&1\\1&1\end{bmatrix}, \quad
K = \begin{bmatrix}1&0\\0&1\\1&1\end{bmatrix}, \quad
V = \begin{bmatrix}1&2\\3&4\\5&6\end{bmatrix}.
$$

**Step 1: scores.**

$$
QK^\top = \begin{bmatrix}1&0&1\\ 0&1&1\\ 1&1&2\end{bmatrix},
\qquad
\frac{QK^\top}{\sqrt2} = \begin{bmatrix}0.7071&0&0.7071\\ 0&0.7071&0.7071\\ 0.7071&0.7071&1.4142\end{bmatrix}.
$$

**Step 2: softmax, row 1.** Exponentials: $e^{0.7071} = 2.0281$, $e^0 = 1$, $e^{0.7071} = 2.0281$. Sum $= 5.0562$.

$$
A_1 = (0.4011,\ 0.1978,\ 0.4011).
$$

**Row 2** is the same by symmetry: $A_2 = (0.1978,\ 0.4011,\ 0.4011)$.

**Row 3.** Exponentials: $2.0281, 2.0281, e^{1.4142} = 4.1132$. Sum $= 8.1694$.

$$
A_3 = (0.2483,\ 0.2483,\ 0.5035).
$$

Every row sums to 1 ✓.

**Step 3: output.** $O = AV$:

$$
O_1 = 0.4011(1,2) + 0.1978(3,4) + 0.4011(5,6) = (3.0000,\ 4.0000).
$$
$$
O_2 = 0.1978(1,2)+0.4011(3,4)+0.4011(5,6) = (3.4067,\ 4.4067).
$$
$$
O_3 = 0.2483(1,2)+0.2483(3,4)+0.5035(5,6) = (3.5105,\ 4.5105).
$$

Sanity check: every output lies inside the convex hull of the rows of $V$, i.e. between $(1,2)$ and $(5,6)$ ✓, since attention cannot escape it.

Token 3 has the largest query norm, so it attends most sharply (weight 0.5035 on itself) and its output is pulled furthest toward $V_3 = (5,6)$.

**Step 4: with a causal mask.**

Row 1 may see only position 1, so $A_1 = (1,0,0)$ and $O_1 = (1,2)$ exactly.

Row 2 sees positions 1 and 2: logits $(0,\ 0.7071)$, exponentials $(1,\ 2.0281)$, sum $3.0281$, so

$$
A_2 = (0.3302,\ 0.6698,\ 0),\qquad O_2 = 0.3302(1,2)+0.6698(3,4) = (2.3395,\ 3.3395).
$$

Row 3 sees everything, so $A_3$ is unchanged at $(0.2483, 0.2483, 0.5035)$ and $O_3 = (3.5105, 4.5105)$.

Note row 2's weights **renormalized**: $0.1978$ and $0.4011$ became $0.3302$ and $0.6698$, preserving their ratio $0.4931$ while summing to 1. Zeroing after the softmax would have left them at $0.1978$ and $0.4011$, summing to $0.5989$, so $O_2$ would have been $(1.4011, 2.0000)$, a vector shrunk by 40% purely because of the position index. That is the concrete reason the mask goes in before the softmax.

**Step 5: the scaling factor, demonstrated.** Multiply $Q$ and $K$ by 10, so the logits scale by 100 (before the $\sqrt2$).

Row 3 logits become $(100,\ 100,\ 200)$ before the $\sqrt2$ scaling, i.e. $(70.71,\ 70.71,\ 141.42)$. Softmax gives

$$
A_3 = (2.0\times10^{-31},\ 2.0\times10^{-31},\ 1.0000),
$$

essentially one-hot. The softmax Jacobian entry for the winner is $p(1-p) \approx 3.9\times10^{-31}$, so the gradient with respect to the logits is **zero to machine precision**. The model can no longer learn to attend anywhere else. Even if attending to position 1 would reduce the loss, nothing in the gradient says so. The forward pass looks fine. Only training is dead. This is what the $\sqrt{d_k}$ prevents, and it is why the division is by $\sqrt{d_k}$ and not by $d_k$ or anything else.

**Step 6: two heads on the same input.** Split $d_{\text{model}} = 2$ into two heads of width 1, so head 1 uses only the first coordinate and head 2 only the second. Head 1's scores are $q_1k_1/\sqrt1$, giving row 3 logits $(1, 0, 1)$ and weights $(0.4223, 0.1554, 0.4223)$, a completely different pattern from head 2, whose logits are $(0, 1, 1)$. Concatenating their outputs and projecting gives the layer access to both relations at once, at exactly the same parameter count as the single head above.

### Cost

For sequence length $n$ and model dimension $d$, per layer:

| Component | FLOPs | Memory |
| --- | --- | --- |
| $Q,K,V$ projections | $6nd^2$ | $O(nd)$ |
| $QK^\top$ | $2n^2d$ | $O(n^2)$ per head |
| $AV$ | $2n^2d$ | $O(nd)$ |
| Output projection | $2nd^2$ | $O(nd)$ |
| FFN | $16nd^2$ | $O(nd)$ |

Total $\approx 24nd^2 + 4n^2d$. The crossover, where attention overtakes the projections, is at

$$
4n^2d = 24nd^2 \;\Longrightarrow\; n = 6d .
$$

At $d = 768$ that is $n = 4608$, so for typical sequence lengths the **feed-forward and projection cost dominates**, and the quadratic term only takes over at long context. That surprises people who assume attention is always the bottleneck.

**Memory is the sharper constraint.** The $n\times n$ attention matrix must be materialized per head per layer for the backward pass: at $n=8192$, $h=32$, $L=32$ in fp16 that is

$$
8192^2\times32\times32\times2\text{ bytes} = 137\text{ GB}.
$$

FlashAttention avoids ever materializing it by tiling the computation and recomputing in the backward pass, reducing memory to $O(n)$ with no change to the result ([Efficient Attention](/module/?id=efficient-attention-long-context)). Approximate methods that *do* change the result are covered in [Efficient Attention](/module/?id=efficient-attention-long-context).

**KV cache.** At autoregressive inference, keys and values for earlier tokens are reused, so cache them: generation cost per token drops from $O(n^2)$ to $O(n)$, at a memory cost of $2Lnhd_k$ elements. This cache, not the weights, is usually what limits serving batch size, the subject of [GQA and MLA](/module/?id=efficient-sharing-keys-and-values).

### From Scratch

```python
import numpy as np
from attention_mechanisms import MultiHeadAttention, softmax     # defined above


def sinusoidal_pe(n, d, base=10000.0):
    """Wavelengths in geometric progression from 2*pi up to 2*pi*base**((d-2)/d), so each
    dimension resolves position at a different scale."""
    pos = np.arange(n)[:, None]
    i = np.arange(0, d, 2)[None, :]
    ang = pos / (base ** (i / d))
    pe = np.zeros((n, d))
    pe[:, 0::2] = np.sin(ang)
    pe[:, 1::2] = np.cos(ang)
    return pe


def rope(x, base=10000.0):
    """Rotary: rotate each 2-D subspace by an angle proportional to position.
    Since R_a^T R_b = R_{b-a}, the q.k dot product depends only on (n - m) --
    relative position emerges from the algebra rather than being added on."""
    n, d = x.shape[-2], x.shape[-1]
    half = d // 2
    freqs = 1.0 / (base ** (np.arange(half) / half))
    ang = np.arange(n)[:, None] * freqs[None, :]
    cos, sin = np.cos(ang), np.sin(ang)
    x1, x2 = x[..., :half], x[..., half:]
    return np.concatenate([x1 * cos - x2 * sin, x1 * sin + x2 * cos], axis=-1)


def alibi_bias(n, n_heads):
    """Linear distance penalty added to the logits; no embeddings at all."""
    slopes = 2.0 ** (-8.0 * (np.arange(n_heads) + 1) / n_heads)
    dist = np.arange(n)[None, :] - np.arange(n)[:, None]
    return slopes[:, None, None] * np.minimum(dist, 0)[None, :, :]


def layer_norm(x, gamma, beta, eps=1e-5):
    """Across FEATURES within each token: batch-independent, so it works at
    batch size 1 and on variable-length sequences, unlike BatchNorm."""
    mu = x.mean(-1, keepdims=True)
    var = x.var(-1, keepdims=True)
    return gamma * (x - mu) / np.sqrt(var + eps) + beta


def rms_norm(x, gamma, eps=1e-6):
    return gamma * x / np.sqrt((x ** 2).mean(-1, keepdims=True) + eps)


def gelu(x):
    return 0.5 * x * (1 + np.tanh(np.sqrt(2 / np.pi) * (x + 0.044715 * x ** 3)))


class TransformerBlock:
    """PRE-norm: the residual stream x + f1(x) + f2(...) is never normalized,
    so the gradient path to every layer is clean. Post-norm puts LayerNorm ON
    that path, which compounds over depth and needs careful warmup."""

    def __init__(self, d_model, n_heads, d_ff=None, seed=0):
        rng = np.random.default_rng(seed)
        d_ff = d_ff or 4 * d_model
        self.mha = MultiHeadAttention(d_model, n_heads, seed)
        s = 1.0 / np.sqrt(d_model)
        self.W1 = rng.normal(0, s, (d_model, d_ff)); self.b1 = np.zeros(d_ff)
        self.W2 = rng.normal(0, s, (d_ff, d_model)); self.b2 = np.zeros(d_model)
        self.g1 = np.ones(d_model); self.be1 = np.zeros(d_model)
        self.g2 = np.ones(d_model); self.be2 = np.zeros(d_model)

    def __call__(self, x, mask=None):
        a, A = self.mha(layer_norm(x, self.g1, self.be1), mask)
        x = x + a                                        # mixes across POSITIONS
        h = layer_norm(x, self.g2, self.be2)
        x = x + (gelu(h @ self.W1 + self.b1) @ self.W2 + self.b2)   # across FEATURES
        return x, A


def block_params(d, d_ff=None):
    d_ff = d_ff or 4 * d
    return {"attention": 4 * d * d, "ffn": 2 * d * d_ff,
            "ffn_fraction": 2 * d * d_ff / (4 * d * d + 2 * d * d_ff)}


def attention_flops(n, d):
    proj = 8 * n * d * d                       # Q, K, V, O
    attn = 4 * n * n * d                       # QK^T and AV
    ffn = 16 * n * d * d
    return {"proj": proj, "attn": attn, "ffn": ffn, "total": proj + attn + ffn,
            "crossover_n": 6 * d}


def attention_memory_bytes(n, h, L, bytes_per=2):
    """The n x n matrix per head per layer -- what OOMs at long context."""
    return n * n * h * L * bytes_per


def kv_cache_bytes(n, L, h, dk, bytes_per=2):
    """Two tensors (K and V) per layer per head. Often the real serving limit."""
    return 2 * L * n * h * dk * bytes_per
```

### Using the Library

```python
import torch, torch.nn as nn

layer = nn.TransformerEncoderLayer(
    d_model=512, nhead=8, dim_feedforward=2048,
    norm_first=True,          # PRE-norm: default is False, and you almost always want True
    activation="gelu", batch_first=True,
)
encoder = nn.TransformerEncoder(layer, num_layers=6)

decoder_layer = nn.TransformerDecoderLayer(d_model=512, nhead=8, norm_first=True,
                                           batch_first=True)   # adds cross-attention

# A batch of token ids to make the snippet below runnable end to end.
vocab_size, max_len = 50_000, 2048
batch, seq_len = 4, 1024
ids = torch.randint(vocab_size, (batch, seq_len))

mask = nn.Transformer.generate_square_subsequent_mask(seq_len)   # causal, -inf above diagonal

# Learned absolute positions, the BERT/GPT-2 approach.
tok_emb = nn.Embedding(vocab_size, 512)
pos_emb = nn.Embedding(max_len, 512)
x = tok_emb(ids) + pos_emb(torch.arange(ids.size(1), device=ids.device))

# Memory, not FLOPs, is usually the wall: activation checkpointing trades
# recompute for storage on the backward pass.
from torch.utils.checkpoint import checkpoint_sequential
out = checkpoint_sequential(encoder.layers, segments=3, input=x)
```

`norm_first` defaults to `False` (post-norm), which needs warmup and is harder to train. Set it to `True`. And note that PyTorch's `TransformerEncoderLayer` applies dropout in three places. If you are comparing against a paper's parameter or FLOP count, check whether their block has the same layout before concluding that anything is wrong.

### Worked Example

**Part A: FLOPs for a real configuration.** $n = 2048$, $d = 768$, 12 layers, 12 heads.

**Projections** ($Q,K,V,O$): $8nd^2 = 8(2048)(768^2) = 9.664\times10^9$.
**Attention** ($QK^\top$ and $AV$): $4n^2d = 4(2048^2)(768) = 1.288\times10^{10}$.
**FFN** ($d_{\text{ff}} = 4d$): $16nd^2 = 16(2048)(768^2) = 1.933\times10^{10}$.

Total per layer $\approx 4.19\times10^{10}$, of which attention is **31%**. The crossover is at $n > 6d = 4608$, so at 2048 tokens we are still below it, consistent with the 31%.

**Part B: memory for the same configuration.** The $n\times n$ matrix per head per layer in fp16:

$$
2048^2\times12\times12\times2\text{ bytes} = 1.21\text{ GB per sequence.}
$$

At batch 8 that is 9.7 GB **just for attention maps**, before weights, activations, or optimizer state. This is why FlashAttention is a requirement rather than an optimization at this scale, and why the memory column of the cost table matters more than the FLOP column.
