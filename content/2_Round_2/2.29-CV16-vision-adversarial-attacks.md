## The problem

A network that classifies images well can still be fooled by changes too small for a person to notice. Szegedy et al. found this in 2013.

In a well-known example from Goodfellow et al., a network labels a photo of a panda correctly, with 57.7% confidence. Every pixel is then changed by 0.007, less than 1% of its range. To a person the picture looks the same. The network now calls it a gibbon, with 99.3% confidence.

The change is not random noise. It is chosen, pixel by pixel, to push the network toward the wrong answer. For systems such as self-driving cars, this is a security problem. The questions are how such changes are found, and how to defend against them.

## Earlier approaches

### Optimizing each image

Szegedy et al. found their examples with a slow optimization run separately for every image. It showed the problem existed but was too slow to use widely, for example to make many attacked images for training.

### Nonlinearity as the cause

Szegedy et al. suggested these images were rare pockets caused by how nonlinear deep networks are. Goodfellow et al. argued the opposite: networks behave almost linearly, so many tiny pushes in the same direction add up. That explanation led directly to a fast attack.

## Gradient attacks

**The idea.** Training uses the gradient of the loss with respect to the weights to make the right answer more likely. An attack uses the gradient with respect to the **pixels** to make the right answer less likely.

**FGSM.** The **fast gradient sign method** moves every pixel by the same small amount $\varepsilon$ in whichever direction raises the loss:

$$
x_{\text{attacked}} = x + \varepsilon \cdot \text{sign}(\text{gradient of the loss with respect to } x)
$$

For example, with $\varepsilon = 0.1$, a pixel of 0.5 whose gradient is positive becomes 0.6, and one whose gradient is negative becomes 0.4, however large or small the gradient is.

**Why the sign.** To first order, a change $\delta$ of the pixels raises the loss by $g_1\delta_1 + g_2\delta_2 + \dots$, where $g$ is the gradient. With every $|\delta_i|$ at most $\varepsilon$, each term is largest when $\delta_i = \varepsilon \cdot \text{sign}(g_i)$, and the rise is then $\varepsilon \cdot (|g_1| + |g_2| + \dots)$. At the running example's image (the 6 by 6 image with one bright vertical line, in the Running example section below) the 36 values of $|g|$ add up to 0.759, so with $\varepsilon = 0.1$ FGSM is expected to raise the loss by 0.076. A step along the gradient itself, scaled so that its largest pixel change is also 0.1, is expected to raise it by only 0.047. The real changes are smaller, because pixels are clipped and the ReLUs bend the loss, but the order holds: at $\varepsilon = 0.4$ FGSM brings p(vertical) down to 0.690 and the scaled gradient step only to 0.821. The 12 pixels whose gradient is 0 are left as they are. A budget on the total length of the change, instead of on each pixel, would make the gradient's own direction the best one.

**Why small changes add up.** Each pixel changes by at most $\varepsilon$, but every change pushes the score the same way. If each of 150,528 pixels shifts a score by only 0.0001, together they shift it by 15.05.

**PGD.** **Projected gradient descent** repeats many small FGSM steps and finds stronger attacks. Each step moves every pixel by a small $\alpha$ in the direction of the sign of the gradient, then clips it back to within $\varepsilon$ of the original and to between 0 and 1:

$$
x \leftarrow \text{clip}\big(x + \alpha \cdot \text{sign}(\text{gradient of the loss with respect to } x)\big)
$$

The running example takes 40 steps with $\alpha = 0.02$. PGD is often started from a random point within $\varepsilon$ of the image, so that one starting gradient does not decide the result. Madry et al. argued that no attack using only gradients does much better, which makes PGD the usual test of a defense.

**A valid image.** Every attack also keeps pixels between 0 and 1. At $\varepsilon = 0.4$, FGSM would push 2 pixels of the line above 1 and 4 background pixels below 0, and the clip holds them at 1 and 0.

**Defense.** The main defense is **adversarial training**: attack the training images with PGD as the network trains, and train on the attacked versions. In symbols, training looks for the weights with the smallest average of the worst loss any allowed change can cause:

$$
\min_{\text{weights}} \; \text{average over images of} \max_{\text{every } |\delta_i| \le \varepsilon} \text{loss}(x + \delta)
$$

PGD finds the inner maximum approximately. For the running example at $\varepsilon = 0.4$ it is the attacked image with p(vertical) = 0.354, and training on it labeled vertical would push that probability back up. Adversarial training makes the network much harder to fool, at the cost of slower training and somewhat lower accuracy on normal images.

**Gradient masking.** A defense can seem to work only because it hides the gradient. Multiply the running example's scores by 100. Every decision stays the same, but p(vertical) for the original image rounds to exactly 1 and the gradient is 0 at every pixel, so FGSM changes nothing and PGD has no direction to follow. The attacked image found on the original network still makes the scaled one say horizontal, with p(vertical) below $10^{-26}$. This is **gradient masking**. Athalye et al. (2018) found it in 7 of the 9 defenses they examined from one conference, and by estimating the hidden gradients their attacks completely got around 6 of them.

## Running example

### FGSM and PGD

The attack aims to lower p(vertical), which is 0.953 on the original image. For each ε, every pixel may move by at most ε:

| ε | FGSM, one step | PGD, 40 small steps |
|---|---|---|
| 0.1 | 0.921 | 0.891 |
| 0.2 | 0.870 | 0.769 |
| 0.3 | 0.794 | 0.574 |
| 0.4 | 0.690 | 0.354 |

### The attacked image

At ε = 0.4, PGD makes the network say horizontal. Its main change is two faint horizontal lines across rows 2 and 5, with the vertical line dimmed:

| Row | Col 1 | Col 2 | Col 3 | Col 4 | Col 5 | Col 6 |
|---|---|---|---|---|---|---|
| 1 | 0 | 0 | 0.6 | 0 | 0 | 0 |
| 2 | 0.4 | 0.4 | 1 | 0.4 | 0.4 | 0.4 |
| 3 | 0 | 0 | 0.6 | 0 | 0 | 0 |
| 4 | 0 | 0 | 0.6 | 0 | 0 | 0 |
| 5 | 0.4 | 0.4 | 1 | 0.4 | 0.4 | 0.4 |
| 6 | 0 | 0 | 0.6 | 0 | 0 | 0 |

The vertical line is still the brightest thing in the image, but the network gives "horizontal" 0.646. The faint lines sit where the horizontal filter picks them up in all four pooling blocks, 2.4 in each, a total of 9.6. The dimmed line gives the vertical filter only 3.6 + 3.6 = 7.2. This image has only 36 pixels, so the attack needs large changes. On a real photo the same idea works with changes too small to see.

```python
import numpy as np

def p_vertical(img):
    v = np.array([[-1, 2, -1]] * 3, dtype=float)
    scores = []
    for k in (v, v.T):
        m = np.array([[(img[i:i + 3, j:j + 3] * k).sum() for j in range(4)]
                      for i in range(4)])
        pooled = np.maximum(m, 0).reshape(2, 2, 2, 2).max(axis=(1, 3))
        scores.append(0.25 * pooled.sum())
    return np.exp(scores[0]) / np.exp(scores).sum()

image = np.zeros((6, 6)); image[:, 2] = 1.0
attacked = image.copy()
attacked[[0, 2, 3, 5], 2] -= 0.4                            # dim the line
attacked[[1, 4], :] = np.clip(attacked[[1, 4], :] + 0.4, 0, 1)  # faint lines
print(round(p_vertical(image), 3), round(p_vertical(attacked), 3))  # 0.953 0.354

def gradient(img, h=1e-5):                                  # of the loss, by differences
    loss = lambda im: -np.log(p_vertical(im))
    g = np.zeros_like(img)
    for i in range(6):
        for j in range(6):
            d = np.zeros_like(img); d[i, j] = h
            g[i, j] = (loss(img + d) - loss(img)) / h
    return g

fgsm = np.clip(image + 0.4 * np.sign(gradient(image)), 0, 1)   # FGSM, epsilon 0.4
print(round(p_vertical(fgsm), 3))                                # 0.69
```

## Common questions

**How large is ε on a real photo?** Small. A common choice is 8 ÷ 255 = 0.031 on pixel values between 0 and 1, which the eye cannot see. The toy image needs 0.4 only because it has 36 pixels to add up, not 150,528.

**Can the attack aim for a chosen label?** Yes. A **targeted** attack lowers the loss of the chosen class instead of raising the loss of the true one: $x - \varepsilon \cdot \text{sign}(\text{gradient of the loss for the target})$. With two classes the two attacks are the same, since raising the loss of vertical lowers that of horizontal.

**Does the attacker need the network's weights?** These attacks do, because they need the gradient. But attacked images made for one network often fool another network trained on the same task, so an attacker can use a stand-in.

**Why is PGD stronger than FGSM?** FGSM takes one step along the gradient at the original image. PGD takes many small steps and recomputes the gradient after each, so it follows the loss as it bends. At ε = 0.4 it brings p(vertical) to 0.354 where FGSM reaches 0.690. This only helps because the gradient changes within the budget: its sign at the final PGD image differs from its sign at the original on 17 of the 36 pixels. For a two-class model whose score is linear in the pixels, such as logistic regression, the sign never changes and PGD ends where FGSM does.
