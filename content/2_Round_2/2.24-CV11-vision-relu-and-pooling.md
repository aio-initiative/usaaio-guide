## The problem

Step 2 produced a feature map for each filter. For the vertical filter, every row of the map is −3, 6, −3, 0.

<Figure src="assets/module-media/vision-problem-relu-pool.svg" alt="A bar chart of one row of the vertical feature map. Column 2 has a tall bar of 6, labeled found it. Columns 1 and 3 have bars of -3, labeled not this pattern. Column 4 is 0, labeled nothing.">
One row of the vertical feature map from Step 2.
</Figure>

Two things about it get in the way of the layers that follow:

- **Negative values.** The 6 says "a vertical line is centered here". The −3 on each side only says "not centered here". Added up, the row comes to −3 + 6 − 3 + 0 = 0, the same total as the horizontal map, where nothing was found at all.
- **Size.** The map is 4 × 4, almost as large as the 6 × 6 image, and a real network has dozens of maps in every layer. The exact column of the line also matters little: a line one pixel to the left is still a vertical line.

The model needs to keep the responses that mean "found it" and shrink the map, so that later layers work on less and care less about exact positions.

## Earlier approaches

### Sigmoid and tanh

Earlier networks squashed every value into a fixed range with sigmoid or tanh. In deep networks these slow training down, because their slope is nearly flat for large values. AlexNet switched to ReLU and trained several times faster.

### Average pooling

LeNet shrank its maps by averaging neighboring values. That blurs a strong response with weak ones: averaging 6 and 0 gives 3.

## ReLU and max pooling

**ReLU.** **ReLU** replaces every negative number with 0 and keeps the rest:

$$
\text{ReLU}(x) = \max(0, x).
$$

So −3 becomes 0 and 6 stays 6. What is left are the places where the pattern was found.

**Max pooling.** **Max pooling** splits the map into 2 × 2 blocks and keeps only the largest number in each. For example, the block holding 0, 6, 0 and 6 becomes 6. This halves the width and the height, so a 4 × 4 map becomes 2 × 2 and 16 numbers become 4.

<Figure src="assets/module-media/vision-relu-pool.svg" alt="Three grids joined by arrows. The 4 by 4 feature map has rows of -3, 6, -3, 0. After ReLU every -3 has become 0, so the rows are 0, 6, 0, 0. The top-left 2 by 2 block is outlined. After max pooling the map is 2 by 2 with rows 6, 0. The top-left cell, 6, is outlined as the largest value of that block.">
The vertical feature map of the running example through ReLU and max pooling.
</Figure>

**What pooling gives up.** The pooled map still says "found a vertical line here", but no longer exactly where inside each block. That is useful: a small shift of the image often leaves the pooled map unchanged. It is also a loss, which Step 9 has to work around.

## Running example

### ReLU

After ReLU, the vertical feature map from Step 2 keeps only the 6s:

| | Map col 1 | Map col 2 | Map col 3 | Map col 4 |
|---|---|---|---|---|
| Every row | 0 | 6 | 0 | 0 |

### Max pooling

Max pooling takes each 2 × 2 block. The top-left block holds 0, 6, 0 and 6, so it keeps 6. The top-right block is all 0:

| | Pooled col 1 | Pooled col 2 |
|---|---|---|
| Pooled row 1 | 6 | 0 |
| Pooled row 2 | 6 | 0 |

The horizontal map was all 0, so it stays all 0.

### A small shift

Moving the line one column left, into column 2, moves each 6 from map column 2 to map column 1. Both columns fall in the same 2 × 2 blocks, so the pooled map is still 6, 0 in each row.

```python
import numpy as np

feature_map = np.tile([-3.0, 6.0, -3.0, 0.0], (4, 1))
relu = np.maximum(feature_map, 0)
pooled = relu.reshape(2, 2, 2, 2).max(axis=(1, 3))   # max of each 2 x 2 block
print(pooled)            # [[6, 0], [6, 0]]
```

## Common questions

**Does the order of ReLU and max pooling matter?** Not for the result. The largest value of a block is the same before or after the negatives are set to 0, unless the whole block is negative, and then both orders give 0.

**Does pooling have weights?** No. Max pooling has nothing to learn. It only keeps the largest number of each block.

**Why keep the maximum and not the average?** The maximum answers "was the pattern found anywhere in this block". The block 0, 6, 0, 6 keeps its 6. Averaging would give 3 and blur a strong response with the places where nothing was found.

**Do all networks use max pooling?** No. Many newer networks shrink their maps with a convolution of stride 2 instead, and Vision Transformers (Step 7) have no pooling layers between their blocks: they shrink the image once, when they cut it into patches.
