## The problem

A model can only take numbers as input, so an image has to become numbers first.

The numbers are easy to get, because every pixel has a brightness. A 6 × 6 black-and-white image is 36 numbers, and a 224 × 224 color photo is 224 × 224 × 3 = 150,528. The question is how to arrange them.

The simplest arrangement is one long list, row after row. That loses which pixels are next to which. For example, in the image below the pixels at row 1, column 3 and at row 2, column 3 touch. In the list they are 6 places apart, and nothing marks them as neighbors.

Neighboring pixels are what make up edges, lines and shapes, so the model needs a form that keeps them together.

## Earlier approaches

### Hand-made features

Before deep learning, engineers wrote rules to describe images, for example counting how many edges point in each direction in each part of the image, and fed those counts to a classifier. Methods such as SIFT (2004) and HOG (2005) worked well on narrow tasks like finding pedestrians, but every new kind of image needed new rules.

### A plain network on all the pixels

Treating the 150,528 numbers as one long list and using a fully connected network throws away which pixels are neighbors. It is also huge: one hidden layer of 1,000 units already needs about 150 million weights, and a pattern learned in one corner has to be learned again for every other position.

## Images as grids

**The grid.** An image is kept as a grid of numbers with three sizes: height × width × **channels**. Keeping the grid keeps the neighbors: the pixel at row 2, column 3 sits next to the pixel at row 2, column 4.

**Channels.** A black-and-white image has one channel, its brightness. A color image has three, red, green and blue, so each pixel is three numbers: a pure red pixel is (1, 0, 0) and a white one is (1, 1, 1).

**Values.** Values usually run from 0 to 255 and are scaled to between 0 and 1 by dividing by 255. A mid-gray of 128 becomes 128 ÷ 255 = 0.502.

**Counting.** The number of values is the product of the three sizes:

| Image | Height × width × channels | Numbers |
|---|---|---|
| Running example | 6 × 6 × 1 | 36 |
| MNIST digit | 28 × 28 × 1 | 784 |
| ImageNet photo, as usually resized | 224 × 224 × 3 | 150,528 |

## Running example

The image used through this chapter is 6 × 6, black and white, with a bright vertical line in its third column. 1 is bright and 0 is dark:

| Row | Col 1 | Col 2 | Col 3 | Col 4 | Col 5 | Col 6 |
|---|---|---|---|---|---|---|
| 1 | 0 | 0 | 1 | 0 | 0 | 0 |
| 2 | 0 | 0 | 1 | 0 | 0 | 0 |
| 3 | 0 | 0 | 1 | 0 | 0 | 0 |
| 4 | 0 | 0 | 1 | 0 | 0 | 0 |
| 5 | 0 | 0 | 1 | 0 | 0 | 0 |
| 6 | 0 | 0 | 1 | 0 | 0 | 0 |

The task is to decide whether the line is vertical or horizontal.

```python
import numpy as np

image = np.zeros((6, 6))
image[:, 2] = 1.0        # column 3 is bright
print(image)
```

## Common questions

**Why scale the values to between 0 and 1?** Training is more stable when the inputs are small and on a similar scale. Values up to 255 would make the first layer's outputs about 255 times larger than with scaled inputs, which throws off the balance of activations and gradients through the network.

**In what order are the three sizes stored?** It depends on the library. This page writes height × width × channels. PyTorch stores the channels first, so a color photo is 3 × 224 × 224. The numbers are the same either way.

**What does a list of pixels lose?** The neighbors. In the grid, the pixel at row 2, column 3 is next to row 3, column 3. In a list of 36 numbers they are 6 places apart, and nothing marks them as related.
