## Overview

Supervised pretraining needs a fixed set of labels, and that limits what the model learns. A model trained on ImageNet's 1000 classes learns features shaped by those 1000 classes. Labeling enough images to cover much more is too expensive.

**Contrastive learning** avoids labels entirely. Instead of asking *what is this?*, it asks *which of these goes with which?* The answers to that question cost nothing to collect, because hundreds of millions of images already appear on the web next to their captions.

This matters directly for the contest. [2025 Round 2](https://forum.beaver-edge.ai/c/ai-olympiads/2025-usa-na-aio-round-2/9) Problem 3 was a 100-point CLIP task: combine a text encoder with an image encoder and get image-text matching working from start to finish.

## The objective

Take a **query** $q$, one **positive** $k^+$ that truly matches it, and a set of **negatives** $k^-_1, \dots, k^-_{N-1}$ that do not. The goal is to pull the positive closer and push the negatives away. Closeness is measured by cosine similarity between embeddings scaled to length 1 ($\ell_2$-normalized). The **InfoNCE** loss is

$$
\mathcal{L} = -\log \frac{\exp\!\big(\operatorname{sim}(q, k^+)/\tau\big)}
{\sum_{i=1}^{N} \exp\!\big(\operatorname{sim}(q, k_i)/\tau\big)}
$$

<NotebookCard id="contrastive-learning-and-clip" />

Look at its shape: the $\log$ of a softmax, with one correct index singled out. **That is exactly cross-entropy**, and the "classes" are the items in the batch. Contrastive learning is classification where the set of labels is built on the spot from whatever else is in the batch. That is why it needs no human labels: the pairings come from augmentations or from data already on the web, not from an annotator.

Since it is cross-entropy over $N$ options, a model that has learned nothing, and so spreads its probability evenly, scores $\log N$. That number matters. Oord et al. showed that InfoNCE gives a **lower bound on the mutual information** between the query and the positive:

$$
I(q; k^+) \;\ge\; \log N - \mathcal{L}
$$

So minimizing the loss pushes up a guaranteed minimum on the [mutual information](3.1-PS4-information-theory-core.md) between the two views. The inequality also shows the bound can never exceed $\log N$. **More negatives allow a higher bound**, which is the theoretical reason contrastive methods want large batches.

### Where positives come from

The loss is the same everywhere. Methods differ in what counts as a positive.

* **SimCLR**: two random augmentations (cropping, color changes, blur) of the *same* image. The model must recognize them as the same thing despite the changes, so it learns the features that survive augmentation. The choice of augmentations *is* the supervision. If they are too weak, the model can solve the task by matching color histograms. If they are too strong, the two views no longer share any content.
* **CLIP**: an image and its own caption. The pairing comes free with web data.

Another kind of positive comes from a pretext task. In rotation prediction, the model sees each image turned by 0, 90, 180 or 270 degrees and must name the angle. That task has its own shortcut. A border stamp from the camera, or any capture artifact that sits at the edge, lets a classifier read the angle off the border alone without looking at the content.

### Temperature

$\tau$ scales the similarities before the softmax, and it is not a minor setting. A small $\tau$ sharpens the softmax, which focuses the loss on the **hardest** negatives, the ones already close to the query. A large $\tau$ flattens it, spreading the penalty roughly evenly over all negatives.

<ProblemCard id="cl-push-on-the-negatives" />

CLIP **learns** $\tau$ instead of fixing it. It optimizes $\log(1/\tau)$, which is more stable, and caps it so the logits cannot grow without limit.

## CLIP

CLIP trains two encoders at once, usually a [ViT](3.3-CV6-vision-transformers-vit-attention.md#lesson-vision-transformer) for images and a Transformer for text. A linear projection on each side maps both into one shared space.

For a batch of $N$ pairs, embed everything and form the $N \times N$ similarity matrix $S_{ij} = \operatorname{sim}(I_i, T_j)/\tau$. The **correct pairings are exactly the diagonal**. Then apply cross-entropy twice and average:

* along each row, so each image picks its caption,
* along each column, so each caption picks its image.

<ProblemCard id="cl-collapsed-caption-encoder" />

The two directions are not redundant. A row's softmax compares captions with each other, so anything all the captions share cancels out inside it. Suppose every caption has a large component in common. Then the images that happen to point toward that component score well against *every* caption. Image-to-text retrieval does not notice, but text-to-image retrieval returns those few images for almost every query. In a batch of 8 built this way, with $\tau = 0.07$, the row loss can stay low while the column loss goes well above the chance level of $\ln 8 = 2.079$, and the column term is what penalizes this.

A text encoder that maps everything to one point (a collapsed encoder) does not fool the row loss either. If every caption lands on the same point, each row is constant, its softmax is uniform, and the loss is exactly $\ln N$, the chance level.

That is the loss catching the failure. Take the negatives away and it does not: $f(x) = c$ for all $x$ makes every positive pair perfectly similar, so any objective that only rewards positive agreement has collapse as a global optimum, and gradient descent finds it quickly, usually within a few hundred steps. **Collapse is silent.** The training curve of a collapsed run looks better than the training curve of a healthy one. The loss stays low at the minimum, so only the embeddings reveal it. Two numbers read collapse off the embeddings. Effective rank is the exponential of the entropy of the normalized singular values, so it counts how many directions the embeddings actually use. Mean per-dimension standard deviation after scaling each row to length 1 is the companion check. A healthy run spreads over many directions while a collapsed run sits near one.

$$
\mathcal{L}_{\text{CLIP}} = \tfrac{1}{2}\Big(
\text{CE}(S, \text{diag}) + \text{CE}(S^\top, \text{diag})\Big)
$$

Each row's $N-1$ negatives come free from the other pairs in the batch. CLIP was trained accordingly, with a very large batch size of 32,768. The batch *is* the source of negatives, so batch size changes the objective itself, not just how fast training runs.

### Zero-shot classification

Because images and text share one space, classifying an image needs no trained classifier. Embed the image. For each candidate class, write a prompt such as `"a photo of a {class}"` and embed it. Pick the class whose text embedding is most similar. Any set of labels you can put into words works, with no retraining. With labeled data the counterpart is a nearest-neighbor vote over the embeddings, which is k-nearest neighbors applied in the learned space as taught in [Decision Trees & k-Nearest Neighbors](1.29-ML10-decision-trees-knn.md).

The wording of the prompt matters more than you might expect. Bare class names work noticeably worse than `"a photo of a {class}"`. The captions the text encoder was trained on are sentences, so a single noun is unlike what it saw in training.

## Building CLIP from pretrained encoders

Training CLIP from scratch takes hundreds of millions of pairs. The practical version, and the one [2025 Round 2](https://forum.beaver-edge.ai/c/ai-olympiads/2025-usa-na-aio-round-2/9) Problem 3 asked for, starts from two encoders that were each pretrained on one kind of data: a ViT for images and BERT for text. That pretrained-encoder setup is [pre-training and fine-tuning](3.14-NL3-pre-training-fine-tuning.md), reused here with the two sides frozen at first. You then train the shared space on tens of thousands of captioned images. Each step is a decision with a reason:

* **Reduce each side to one vector (pooling).** For images, use the ViT's class token. For text, average the token states using the attention mask, or take BERT's `[CLS]` state. Captions differ in length and the tokenizer pads each batch to its longest caption, so an average that includes the padding mixes in tokens that are not really there.
* **Project into one space and normalize.** A linear layer on each side maps the encoder's width to a shared dimension, and L2 normalization turns every dot product into a cosine similarity.
* **Learn the temperature.** Keep $\log(1/\tau)$ as a parameter, start it at $\log(1/0.07)$ as CLIP did, and cap the scale at 100 so it cannot grow without limit.
* **Give the parts different learning rates.** The pretrained encoders should change slowly, at around $10^{-5}$. The new projections and the temperature start from nothing and need around $10^{-3}$. A common way to begin is to freeze both encoders for the first epoch, so only the projections and the temperature learn.

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F
from transformers import AutoModel, AutoTokenizer, ViTModel

class CLIP(nn.Module):
    def __init__(self, text_encoder, image_encoder, dim=256):
        super().__init__()
        self.text, self.image = text_encoder, image_encoder
        self.text_proj = nn.Linear(text_encoder.config.hidden_size, dim, bias=False)
        self.image_proj = nn.Linear(image_encoder.config.hidden_size, dim, bias=False)
        self.log_scale = nn.Parameter(torch.tensor(math.log(1 / 0.07)))   # learned log(1/tau), exp() gives 1/tau

    def encode_text(self, input_ids, attention_mask):
        h = self.text(input_ids=input_ids, attention_mask=attention_mask).last_hidden_state
        m = attention_mask.unsqueeze(-1).to(h.dtype)
        pooled = (h * m).sum(dim=1) / m.sum(dim=1)                  # mean over real tokens, pads excluded
        return F.normalize(self.text_proj(pooled), dim=-1)

    def encode_image(self, pixel_values):
        h = self.image(pixel_values=pixel_values).last_hidden_state
        return F.normalize(self.image_proj(h[:, 0]), dim=-1)        # the class token

    def forward(self, pixel_values, input_ids, attention_mask):
        img = self.encode_image(pixel_values)
        txt = self.encode_text(input_ids, attention_mask)
        logits = self.log_scale.exp().clamp(max=100.0) * img @ txt.T
        labels = torch.arange(len(img), device=img.device)
        return (F.cross_entropy(logits, labels) + F.cross_entropy(logits.T, labels)) / 2

tok = AutoTokenizer.from_pretrained("bert-base-uncased")
model = CLIP(AutoModel.from_pretrained("bert-base-uncased"),
             ViTModel.from_pretrained("google/vit-base-patch16-224-in21k"))
opt = torch.optim.AdamW([
    {"params": [*model.text.parameters(), *model.image.parameters()], "lr": 1e-5},
    {"params": [*model.text_proj.parameters(), *model.image_proj.parameters(), model.log_scale],
     "lr": 1e-3},
], weight_decay=0.01)

# One step: captions are tokenized per batch, padded to the batch's longest.

```

### Several captions per image

Caption datasets usually give each image several captions, five in Flickr30k. If you sample a batch by caption, the same image can land in it twice, and then the diagonal target is wrong. For that row, the other copy's caption is a correct match, but the cross-entropy counts it as a negative. This happens more often than you might expect. Draw 256 captions from 30,000 images with five captions each, and a batch has on average 0.87 pairs of rows that share an image. More than half of all batches contain at least one such pair.

Take perfect encoders, where every copy of an image and every caption of it embed at the same point, and a batch whose images are A, A, B, C, C, C:

```python
import numpy as np

def softmax_rows(S):
    S = S - S.max(axis=1, keepdims=True)
    E = np.exp(S)
    return E / E.sum(axis=1, keepdims=True)

image_of = np.array([0, 0, 1, 2, 2, 2])          # the pairs' images: A, A, B, C, C, C
emb = np.eye(3)[image_of]                        # perfect encoders: copies and captions coincide
for tau in (0.07, 0.01, 0.001):
    P = softmax_rows(emb @ emb.T / tau)
    print(f"tau {tau:<6} image-to-text loss {-np.mean(np.log(np.diag(P))):.4f}")
print(f"(2 ln 2 + 3 ln 3) / 6 = {(2 * np.log(2) + 3 * np.log(3)) / 6:.4f}")

P = softmax_rows(emb @ emb.T / 0.07)
print("gradient on row 0, labels on the diagonal :", np.round(P - np.eye(6), 3)[0] + 0.0)
Y = (image_of[:, None] == image_of[None, :]).astype(float)
Y /= Y.sum(axis=1, keepdims=True)                # split each row's target over its image's captions
print("gradient on row 0, labels split evenly    :", np.round(P - Y, 3)[0] + 0.0)
```

```output
tau 0.07   image-to-text loss 0.7804
tau 0.01   image-to-text loss 0.7804
tau 0.001  image-to-text loss 0.7804
(2 ln 2 + 3 ln 3) / 6 = 0.7804
gradient on row 0, labels on the diagonal : [-0.5  0.5  0.   0.   0.   0. ]
gradient on row 0, labels split evenly    : [0. 0. 0. 0. 0. 0.]
```

No temperature takes the loss below 0.7804. Row 0's best possible prediction splits evenly between its two identical captions and pays $\ln 2$, and each C row pays $\ln 3$. The gradient on row 0 also pushes caption 1, a true match, away just as hard as it pulls caption 0 in. Here row 1 holds the same image and pulls caption 1 back as hard, so the pushes cancel and only the floor remains. They stop cancelling when the two copies differ, as two random crops of one photo do. Then the diagonal target trains the model to tell crops of the same photo apart, which works against the alignment it is meant to build. There are two fixes. Build batches with at most one caption per image, or give each row a target split evenly over every caption of its image, which leaves nothing to push against at the optimum.

## From scratch

The claim that InfoNCE is cross-entropy is exact, and checkable in a few lines.

```python
import numpy as np

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def l2norm(x):
    return x / np.linalg.norm(x, axis=-1, keepdims=True)

rng = np.random.default_rng(0)
N, d, tau = 8, 16, 0.07
img = l2norm(rng.normal(size=(N, d)))
txt = l2norm(img + 0.3 * rng.normal(size=(N, d)))   # caption i matches image i

S = img @ txt.T / tau                                # similarity / temperature

# InfoNCE written out: for each image, -log the softmax weight on its own caption
manual = -np.mean([np.log(softmax(S[i])[i]) for i in range(N)])
# the identical thing as cross-entropy with the diagonal as the label
ce = -np.mean(np.log(softmax(S, axis=1)[np.arange(N), np.arange(N)]))

print(f"InfoNCE written out:        {manual:.6f}")
print(f"cross-entropy, labels=diag: {ce:.6f}")
print(f"difference:                 {abs(manual - ce):.2e}")

row = -np.mean(np.log(softmax(S, axis=1)[np.arange(N), np.arange(N)]))
col = -np.mean(np.log(softmax(S, axis=0)[np.arange(N), np.arange(N)]))
print(f"image->text: {row:.6f}")
print(f"text->image: {col:.6f}")
print(f"CLIP symmetric loss: {(row + col) / 2:.6f}")
```

```output
InfoNCE written out:        0.048065
cross-entropy, labels=diag: 0.048065
difference:                 0.00e+00
image->text: 0.048065
text->image: 0.065131
CLIP symmetric loss: 0.056598
```

The two are identical, so everything you know about cross-entropy applies. Note that the two directions give *different* numbers on the same matrix. Here image→text happens to be easier than text→image. CLIP averages both rather than picking one, so both directions are trained.

<ProblemCard id="cl-clip-loss-numpy" />

The easiest way to understand temperature is to run the same embeddings at several values, alongside a useless encoder for comparison:

```python
aligned = txt                                        # the good embeddings above
useless = l2norm(rng.normal(size=(N, d)))            # unrelated to img

print(f"chance level = log(N) = {np.log(N):.4f}")
print(f"{'tau':<8}{'aligned':>12}{'useless':>12}")
for t in [1.0, 0.5, 0.2, 0.07, 0.01]:
    out = []
    for e in (aligned, useless):
        St = img @ e.T / t
        out.append(-np.mean(np.log(softmax(St, axis=1)[np.arange(N), np.arange(N)])))
    print(f"{t:<8}{out[0]:>12.4f}{out[1]:>12.4f}")
```

```output
chance level = log(N) = 2.0794
tau          aligned     useless
1.0           1.5706      2.1663
0.5           1.1705      2.3118
0.2           0.4809      3.0273
0.07          0.0481      6.3886
0.01          0.0000     42.5195
```

At $\tau = 1$ the two encoders are hard to tell apart: the aligned encoder sits only half a nat below the chance level of 2.08 and the useless one just above it. At $\tau = 0.01$ they score 0.0000 against 42.5. Temperature works like a **contrast setting**. It magnifies the difference between good and bad embeddings, which is what gives a useful gradient, but it also punishes mistakes very harshly. Set it too low and training becomes unstable at the first bad batch. That is why CLIP learns $\tau$, with a cap, rather than fixing it.

Finally, batch size really is part of the objective:

```python
print(f"{'N':<8}{'chance = log N':>16}{'loss':>10}")
for n in [8, 32, 128, 512]:
    a = l2norm(rng.normal(size=(n, d)))
    b = l2norm(a + 0.35 * rng.normal(size=(n, d)))
    Sn = a @ b.T / tau
    loss = -np.mean(np.log(softmax(Sn, axis=1)[np.arange(n), np.arange(n)]))
    print(f"{n:<8}{np.log(n):>16.3f}{loss:>10.4f}")
```

```output
N         chance = log N      loss
8                  2.079    0.1272
32                 3.466    0.8494
128                4.852    2.0140
512                6.238    3.1880
```

The embedding quality, the noise and the temperature are all the same. Only the number of wrong options changes, and the task gets steadily harder. That is intended, not a problem. A larger $N$ raises $\log N$, and the mutual-information bound $I \ge \log N - \mathcal{L}$ can never be higher than $\log N$.
