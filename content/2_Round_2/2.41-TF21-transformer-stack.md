# 2.41 · TF21 · 11. Stack

> **Goal:** Stacking blocks and counting GPT-2's weights.
> **Stage:** Round 2, Core contest depth.

## The problem

One block gives each token one round of gathering information, in attention, and one round of working on it, in the feed-forward network. Some predictions need more than one round, because the second step depends on the result of the first.

For example, after "Harry Potter went home. Later, Harry", the next word is probably "Potter". To get there, the model has to:

1. find where "Harry" appeared earlier in the text,
2. look at the token that came right after it, and copy that.

<Figure src="assets/module-media/transformer-problem-stack.svg" alt="A row of tokens: Harry, Potter, went, home, a full stop, Later, a comma, Harry, and a blank. A heavy arrow labelled round 1: find the earlier Harry runs from the second Harry back to the first. A second arrow labelled round 2: take the token after it runs from the first Harry to Potter. Under the blank is the answer, Potter.">
Predicting "Potter" takes two rounds.
</Figure>

The second step cannot start until the first has finished: the model does not know where to look for "the token after" until it has found the earlier "Harry". Within one block, every head works from the same input at the same time, so no head can use another head's result. Olsson et al. (2022) showed that this task needs two attention layers in sequence.

## Earlier approaches

### A wider block

More heads let a block compute more relationships from the same input, but not relationships built on the results of other ones: one head can find the earlier "Harry", but no head in the same block can use that to copy "Potter".

### Deep recurrent networks

Recurrent networks were stacked too, but were hard to train deep. Google's 2016 translation system used eight layers in its encoder and eight in its decoder.

## Stacking blocks

**Same shape in, same shape out.** A block takes one vector per token and returns one vector per token of the same width, so the output of one block can be the input of the next. Writing $H^{(0)}$ for the input from Step 3:

$$
H^{(1)} = \text{block}_1(H^{(0)}), \quad H^{(2)} = \text{block}_2(H^{(1)}), \quad \dots
$$

Each block has its own weights. For "the cat sat" with a width of 4, every $H$ is a table of 3 rows and 4 columns, however many blocks there are.

<Figure src="assets/module-media/transformer-steps.svg" alt="The whole model drawn from bottom to top: the text, then 1 Tokenize, 2 Embed, 3 Add position, then a dashed frame labelled one block, times N, containing masked multi-head attention, add and norm, feed-forward, and add and norm, then 12 Predict and the next token on. Dashed arrows show the residual connections inside the block and the generation loop back to the input.">
The dashed frame is one block. Stacking repeats it $N$ times, each time with new weights.
</Figure>

**What depth adds.** A later block works on the results of the earlier ones. In the "Harry Potter" example, a head in block 1 can mark each token with the token before it, and a head in block 2 can then use that mark to find the token that followed the earlier "Harry". Thanks to the residual connections, each block only refines the vectors a little. In BERT, lower layers tend to capture simpler things, such as parts of speech, and higher layers more abstract ones (Tenney et al., 2019).

**Counting the weights.** GPT-2 small has 12 blocks. Its weights add up like this:

| Part | Where it comes from | Weights |
|---|---|---|
| Token embeddings (Step 2) | One row of 768 for each of 50,257 tokens | 38,597,376 |
| Position embeddings (Step 3) | One row of 768 for each of 1,024 positions | 786,432 |
| Attention layer (Steps 4 to 8) | Query, key, value and output tables, 768 × 768 each, each with 768 offsets | 2,362,368 |
| Feed-forward layer (Step 10) | Two tables, 768 × 3,072 and 3,072 × 768, with 3,072 and 768 offsets | 4,722,432 |
| Two LayerNorms (Step 9) | A scale and a shift of 768 in each | 3,072 |
| One block | The three rows above | 7,087,872 |
| Twelve blocks | 12 × 7,087,872 | 85,054,464 |
| Final LayerNorm | Two lists of 768 | 1,536 |
| **Total** | | **124,439,808** |

The output layer adds nothing, because GPT-2 reuses the token embeddings for it, as Step 12 explains.

## Common questions

**Where do the 176 weights come from?** The embedding table has 8 × 4 = 32. The query, key, value and output tables have 4 × 4 = 16 each, 64 in all. The two feed-forward tables have 4 × 8 = 32 each, 64 in all. The two LayerNorms have a scale and a shift for each of 4 dimensions, 16 in all. That is 32 + 64 + 64 + 16 = 176.

**How many blocks do real models have?** GPT-2 small has 12, medium 24, large 36 and XL 48. The original Transformer had 6 in its encoder and 6 in its decoder.

**Do the blocks share weights?** No. Every block has its own tables, which is why 12 blocks cost 12 × 7,087,872 weights.

**Does a deep stack forget the original token?** Not by itself. Every block adds to the vector through the residual connections of Step 9 and never replaces it, so the pattern of the Step 2 embedding is still present at the top, rescaled once per block in the running example's post-norm.
