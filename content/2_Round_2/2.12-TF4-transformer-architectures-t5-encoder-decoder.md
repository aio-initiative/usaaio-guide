## Overview

Translate "the black cat sat on the mat" into French: "le chat noir était assis sur le tapis". The French has 8 words for the English 7, and "black cat" becomes "chat noir", with the adjective after the noun. BERT gives one output per input token, so it cannot do this directly. A GPT can, but it reads the English left to right, so each English word sees only the words before it. Can we build a model where every input word sees the whole input, and a separate part writes the output?

A model that maps one sequence to another, possibly of a different length, is a **sequence-to-sequence** (seq2seq) model. A well-known one is **T5**, the Text-to-Text Transfer Transformer from Google (2019). It treats every task, classification included, as reading one text and writing another. The USAAIO contest lists Transformers, pretraining and fine-tuning for NLP. The IOAI contest names encoder-decoder models for machine translation.

## Example: turn a sentence into a T5 training pair

T5 is pretrained by hiding runs of consecutive words and asking the model to write them out. Take the sentence

"Thank you for inviting me to your party last week ."

and hide "for inviting" and "last". Count each word, and the period, as one token.

## Explanation

### Two halves: one reads, one writes

Split the job in two:

- The **encoder** reads the whole input at once, with attention in both directions, as in [BERT and Masked Language Modeling](2.10-TF2-transformer-architectures-bert-mlm.md). Its output is one vector per input token.
- The **decoder** writes the output one token at a time, with a causal mask, as in [GPT and Causal Language Modeling](2.44-TF24-gpt-causal-lm.md).

A model built this way is an **encoder-decoder**. Write $T_\text{in}$ for the input length and $T_\text{out}$ for the output length. The encoder's self-attention scores form a $T_\text{in} \times T_\text{in}$ grid. The decoder's form a $T_\text{out} \times T_\text{out}$ grid, and the causal mask hides every entry above the diagonal.

But a decoder that only sees its own previous tokens has no idea what it is translating. Each decoder block needs a way to look at the encoder's output.

### Cross-attention: the decoder asks the input questions

So far there are two kinds of attention: the encoder's self-attention in both directions and the decoder's causal self-attention. Each decoder block adds a third, between its self-attention and its feed-forward layer. In **cross-attention**:

- the queries come from the decoder (what am I trying to write next?)
- the keys and values come from the encoder output (what does the input say?)

Ideally, when the decoder is about to write "chat", its query matches the key for "cat" best, so it pulls in mostly that token's value. This story is simplified. Real heads spread their weight over several tokens, and they work on pieces of words.

Attention weights can help debug which positions influenced a computation, but are not automatically faithful explanations of a model's decision.

The scores form a grid with one row per decoder position and one column per input token, so the grid is $T_\text{out} \times T_\text{in}$. A softmax along each row turns the scores into weights that sum to 1. No causal mask is needed, because the whole input is known before the decoder starts.

Now the compact form. Stack the encoder output as a matrix $H_\text{enc}$, one row per input token, so it is $T_\text{in} \times d_\text{model}$, where $d_\text{model}$ is the model width. Stack the decoder states as $H_\text{dec}$, which is $T_\text{out} \times d_\text{model}$. With learned $d_\text{model} \times d_k$ matrices $W_Q$, $W_K$ and $W_V$, where $d_k$ is the head width:

$$
Q = H_\text{dec} W_Q, \quad K = H_\text{enc} W_K, \quad V = H_\text{enc} W_V,
\qquad \text{output} = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V .
$$

This is the formula from [Build a Transformer: Scores](2.34-TF14-transformer-qkv.md#lesson-scores), with the queries and the keys taken from different places. $QK^\top$ is the $T_\text{out} \times T_\text{in}$ grid of scores. The softmax runs along each row. The output has one $d_k$-wide vector per decoder position.

### Three families of Transformer

Now we can compare the three shapes a Transformer can take:

| Family | Example | Attention | Typical use |
| --- | --- | --- | --- |
| Encoder-only | BERT | both directions | classification, tagging, embeddings |
| Decoder-only | GPT | causal | open-ended generation, chat |
| Encoder-decoder | T5, BART | both, then causal plus cross-attention | translation, summarization |

An encoder-decoder lets every input token see the whole input. A decoder-only model puts the input at the start of its one stream, where each input token sees only the tokens before it.

### Training and generating

During training the target is known. The decoder reads the whole target at once, shifted right by one position: a start token in front, the last token dropped. At each position it predicts the next target token, and the loss is the cross-entropy, as in GPT. Feeding the decoder the true previous tokens, not its own guesses, is called **teacher forcing**.

<ProblemCard id="t5-typo-in-the-target" />

At test time there is no target. The encoder runs once on the input. The decoder starts from the start token, picks the most likely next token, appends it and repeats until it writes an end token. Every step cross-attends to the same encoder output. Always picking the most likely token is called **greedy decoding**, and the T5 paper uses it at test time.

### Text in, text out

T5 uses the encoder-decoder for every task. Each task becomes "read some text, write some text", with a short prefix naming the task:

| Input | Target |
| --- | --- |
| `translate English to German: That is good.` | `Das ist gut.` |
| `summarize: <a long article>` | `<a short summary>` |
| `sst2 sentence: this movie was wonderful` | `positive` |

For classification, T5 writes the label as a word. So it needs no task-specific output layer, and every task uses the same loss: cross-entropy on each target token. T5 is first pretrained on plain text, then **fine-tuned** on prefixed pairs like these (see [Pre-training & Fine-tuning](3.14-NL3-pre-training-fine-tuning.md)).

<ProblemCard id="t5-greedy-label" />

### Pretraining by filling in spans

The pretraining game is a fill-in-the-blank game like BERT's. A **span** is a run of consecutive words. T5 hides whole spans instead of single tokens, and the decoder writes out the hidden words. This game is called **span corruption**:

1. Pick spans to hide. T5 hides 15% of the tokens, in spans 3 tokens long on average.
2. In the input, replace each span with one **sentinel**: a special token, `<X0>`, `<X1>`, ..., that marks a gap.
3. The target lists each sentinel followed by the words it hid. One more sentinel at the end marks where the last span stops.

The released T5 vocabulary writes the sentinels as `<extra_id_0>`, `<extra_id_1>`, .... The target holds only the hidden words and the sentinels, so it is much shorter than the sentence. A shorter target means fewer decoder positions, so pretraining runs faster than it would if the decoder rewrote the whole sentence.

<ProblemCard id="t5-passage-for-a-fixed-input" />

### Solving the focus problem

With one token per word and one for the period, the sentence has 11 tokens. Real T5 cuts text into pieces of words and adds an end token to the input and the target, so its counts would differ.

**Part 1.** Hide "for inviting" (words 3 and 4) and "last" (word 9). The input keeps every other word and puts `<X0>` and `<X1>` in the two gaps. The target lists each sentinel with the words it hid, then a closing `<X2>`:

- input: "Thank you `<X0>` me to your party `<X1>` week .", 10 tokens
- target: "`<X0>` for inviting `<X1>` last `<X2>`", 6 tokens

**Part 2.** With teacher forcing, the decoder reads the target shifted right: "`<start>` `<X0>` for inviting `<X1>` last", which is 6 tokens. Each of those 6 positions attends over the 10 input tokens, so the cross-attention weights are $6 \times 10$.

## Implementation

The function below walks through the hidden spans in order. For each span it copies the words before the span into the input and adds a sentinel. Then it writes that sentinel and the hidden words into the target.

```python
def span_corrupt(words, spans):
    """spans: sorted (start, end) pairs to hide, end exclusive."""
    inputs, targets, pos = [], [], 0
    for k, (a, b) in enumerate(spans):
        inputs += words[pos:a] + [f"<X{k}>"]       # one sentinel replaces the whole span
        targets += [f"<X{k}>"] + words[a:b]        # the target spells the span out
        pos = b
    inputs += words[pos:]
    targets += [f"<X{len(spans)}>"]                # a final sentinel marks the end
    return inputs, targets

words = "Thank you for inviting me to your party last week .".split()
inp, tgt = span_corrupt(words, [(2, 4), (8, 9)])
print("input: ", " ".join(inp))
print("target:", " ".join(tgt))
print(f"{len(words)} words -> input {len(inp)} tokens, target {len(tgt)} tokens")
```

```output
input:  Thank you <X0> me to your party <X1> week .
target: <X0> for inviting <X1> last <X2>
11 words -> input 10 tokens, target 6 tokens
```

The output matches part 1 of the focus problem. Python counts from 0, so "for inviting" is the span `(2, 4)`.

Next, one head of cross-attention for the focus pair in NumPy. Random numbers stand in for the encoder output and the decoder states.

```python
import numpy as np

rng = np.random.default_rng(0)
d_model, d_k, T_in, T_out = 8, 4, 10, 6
H_enc = rng.standard_normal((T_in, d_model))    # encoder output, one row per input token
H_dec = rng.standard_normal((T_out, d_model))   # decoder states, one row per decoder position
W_Q, W_K, W_V = (rng.standard_normal((d_model, d_k)) / np.sqrt(d_model) for _ in range(3))
Q = H_dec @ W_Q                                 # queries from the decoder
K, V = H_enc @ W_K, H_enc @ W_V                 # keys and values from the encoder
scores = Q @ K.T / np.sqrt(d_k)                 # one row per decoder position
weights = np.exp(scores - scores.max(axis=1, keepdims=True))
weights /= weights.sum(axis=1, keepdims=True)   # softmax along each row
out = weights @ V
print("weights", weights.shape, "rows sum to", np.round(weights.sum(axis=1), 6))
print("output ", out.shape)
```

```output
weights (6, 10) rows sum to [1. 1. 1. 1. 1. 1.]
output  (6, 4)
```

The weights are $6 \times 10$, one row per decoder position, and every row sums to 1. The output has one 4-wide vector per decoder position. Its width $d_k$ comes from the values, not from the input length.

In PyTorch, `nn.MultiheadAttention` does the projections and the softmax for you. Pass the decoder states as the query and the encoder output as the key and the value.

```python
import torch
import torch.nn as nn

torch.manual_seed(0)
d_model, T_in, T_out = 8, 10, 6
H_enc = torch.randn(T_in, d_model)
H_dec = torch.randn(T_out, d_model)
cross_attn = nn.MultiheadAttention(embed_dim=d_model, num_heads=2)
out, weights = cross_attn(query=H_dec, key=H_enc, value=H_enc)
print("weights", tuple(weights.shape))
print("output ", tuple(out.shape))
```

```output
weights (6, 10)
output  (6, 8)
```

By default the returned weights are averaged over the 2 heads, so they are still $6 \times 10$. Each head is $d_\text{model}/2 = 4$ wide, as in the NumPy block. PyTorch places the two heads' outputs side by side, which gives width 8, then applies one more linear layer. PyTorch's `nn.TransformerDecoderLayer` holds this kind of layer between its self-attention and its feed-forward layer.

<Warning>

For the focus target, the decoder reads "`<start>` `<X0>` for inviting `<X1>`
last" and must predict "`<X0>` for inviting `<X1>` last `<X2>`". If you feed
it the unshifted target, each position can see the token it must predict, so
the model learns to copy its input and is useless at test time. Hugging
Face's `T5ForConditionalGeneration` builds the shifted input for you when you
pass `labels=`. T5 uses its padding token as the start token.

</Warning>

<Optional title="What the T5 paper compared, and related models">

Most of the T5 paper compares design choices inside the text-to-text setup. Among the architectures it tried, an encoder-decoder did best. Among pretraining objectives, hiding text and recovering it clearly beat plain language modeling. The different ways of hiding text, BERT-style masking and span corruption included, scored about the same. The paper chose span corruption because it did marginally better and its short targets make training faster. T5 came in five sizes: Small (about 60 million parameters), Base (220 million), Large (770 million), 3B (about 2.8 billion) and 11B (about 11 billion).

**BART** (Lewis et al., 2019) is a close relative. It corrupts text in several ways, including masking, deleting and shuffling, and trains the decoder to rebuild the original.

Many well-known large language models, such as GPT-3, are decoder-only, with the input placed in the prompt. Encoder-decoders are still used for tasks that map one sequence onto another. OpenAI's Whisper, which turns speech into text, is an encoder-decoder.

</Optional>
