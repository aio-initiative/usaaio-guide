## Segmentation

### The problem

Some tasks need a label for every pixel: which pixels are tumor in a scan, or which are road in a dashcam frame. The output is a map the same size as the image.

For the running example, the wanted output is a 6 × 6 map with a 1 for every pixel of the line and a 0 for every background pixel.

<Figure src="assets/module-media/vision-problem-segmentation.svg" alt="Three grids joined by arrows. The 6 by 6 image, with its bright column 3. The 2 by 2 map left after pooling, with rows 6, 0. Then, after an arrow with a question mark, the wanted output: a 6 by 6 map with a label for every pixel, 1 for the line in column 3 and 0 for the background.">
The network shrinks the image to a 2 × 2 map, but the output has to be 6 × 6 again.
</Figure>

The network of parts 2 and 3 works against this. It shrinks the image as it goes, from 6 × 6 to a 4 × 4 feature map to a 2 × 2 pooled map. The shrinking is useful, because it lets the network take in large areas cheaply. But the pooled map, 6, 0 in each row, only says that the line is somewhere in the left part of the image. The exact column has been thrown away, and a label for every pixel needs it back.

### Earlier approaches

#### One patch per pixel

Classify a small patch around each pixel, one pixel at a time. This works but is slow, because neighboring patches overlap and the same work is repeated for every pixel.

#### Growing the small map back

Fully convolutional networks (Long et al., 2015) run the image through a normal CNN and then enlarge the small final map back to full size. This is fast, but the enlarged map alone is blurry, because the small map no longer knows exactly where things were. The FCN paper fixes this by fusing the coarse map with finer maps from earlier layers, and U-Net's skip connections do the same job.

### U-Net

**Two halves.** **U-Net** (2015) has two halves. The **encoder** shrinks the image with convolution and pooling, as before, learning what is in it. The **decoder** grows the map back to full size, step by step.

**Skip connections.** **Skip connections** copy each encoder map across to the decoder at the same size, so the decoder gets back the exact positions that pooling threw away. Drawn out, the two halves and the connections between them form a U. The skip connections also give the gradient a short path back to the early layers, as the shortcuts in [Deeper networks](2.25-CV12-vision-classify.md#lesson-deeper-networks) do.

<Figure src="assets/module-media/unet-architecture.svg" alt="A U-shaped diagram. On the left, the encoder shrinks a 64 by 64 input to 32 by 32, then 16 by 16, then an 8 by 8 bottleneck at the bottom, labeled downsample (what). On the right, the decoder grows it back to 16 by 16, 32 by 32 and a 64 by 64 output map, labeled upsample (where). Dashed arrows labeled skip connections carry each encoder map straight across to the decoder map of the same size.">
A U-Net on a 64 × 64 image. The dashed arrows are the skip connections.
</Figure>

**Growing a map.** The simplest way to enlarge a map is to repeat each number in a 2 × 2 block, so a 2 × 2 map becomes 4 × 4. For example, the row 6, 0 becomes 6, 6, 0, 0, twice. The enlarged map is the right size but blurry: it cannot say which of the two columns the 6 came from.

**Bilinear enlarging.** Instead of repeating, **bilinear** enlarging blends the two nearest values in each direction. The second of the four new values sits a quarter of the way from the 6 to the 0, and the third three quarters of the way, so it is 6 × 0.75 + 0 × 0.25 = 4.5, and the row 6, 0 becomes 6, 4.5, 1.5, 0. The result is smoother, but the 6 is spread over three columns. Label maps are usually enlarged by repeating, because blending two class labels gives a value that is neither.

**Transposed convolution.** A **transposed convolution** learns how to enlarge. Each input value multiplies a small kernel, and the result is added into the output starting at the value's position times the stride. With stride 2 and the kernel (1, 1), the row 6, 0 becomes 6, 6, 0, 0, the same as repeating. With the kernel (0, 1) it becomes 0, 6, 0, 0, which matches the map from before pooling. But the kernel is the same for every block, so it cannot know where in its block the line was. For the line moved one column left, as in [ReLU and pooling](2.23-CV10-vision-convolution.md#lesson-relu-and-pooling), the pooled row is still 6, 0 and the output is still 0, 6, 0, 0, while the map before pooling is now 6, 0, 0, 0. The skip connection carries that position. An input of $n$ values gives $(n - 1) \times \text{stride} - 2 \times \text{padding} + \text{kernel size}$ values, (2 − 1) × 2 − 0 + 2 = 4 here. Padding $p$ drops the first $p$ and the last $p$ of the sums, hence its term. A layer from 2 channels to 2 with a 2 × 2 kernel has 2 × 2 × 2 × 2 = 16 weights, counted like a convolution.

**Checkerboard pattern.** When the kernel size is not a multiple of the stride, the copies of the kernel overlap unevenly. Down the first column of the pooled map, 6, 6, the line runs the whole height, so the enlarged column should be even. With the kernel (1, 1, 1) and stride 2, the two copies overlap at the third of five values, which gets 12 where the rest get 6: a stripe across the map. In two directions the stripes form a checkerboard. The kernel (1, 1) gives 6, 6, 6, 6. A kernel size that is a multiple of the stride makes the overlaps even but does not make the output even, since a learned kernel such as (1, 0.3) still gives 6, 1.8, 6, 1.8. Repeating or bilinear enlarging followed by an ordinary convolution cannot turn an even column into stripes, which is why many networks enlarge that way.

<Figure src="assets/module-media/vision-transposed.svg" alt="Two panels. On the left, kernel 1, 1, 1 with stride 2: the first 6 of the pooled column places 6, 6, 6 at positions 1 to 3, the second 6 places 6, 6, 6 at positions 3 to 5, and their sum is 6, 6, 12, 6, 6, with the 12 outlined most heavily. A note says the copies overlap at position 3, a stripe. On the right, kernel 1, 1 with stride 2: the copies 6, 6 and 6, 6 sit side by side and sum to 6, 6, 6, 6. A note says no overlap, even.">
Transposed convolution of the pooled column 6, 6. A kernel of 3 at stride 2 adds two copies into one place.
</Figure>

**Shapes.** Through the running example, written as channels × height × width:

| Stage | Shape |
|---|---|
| Image | 1 × 6 × 6 |
| After the two filters | 2 × 4 × 4 |
| After pooling | 2 × 2 × 2 |
| Enlarged | 2 × 4 × 4 |
| With the skip connection | 4 × 4 × 4 |
| Transposed 3 × 3 convolution, stride 1, one map per class | 2 × 6 × 6 |

The skip connection adds its 2 maps as channels, so the convolution after it reads 4 maps where the enlarging made 2. The two 3 × 3 filters took the image from 6 × 6 to 4 × 4, and a transposed 3 × 3 convolution with stride 1 undoes that size change: (4 − 1) × 1 + 3 = 6. With one output map per class it gives a score for line and for background at every pixel, and each pixel takes the class with the higher score.

**Output and loss.** The output has one score per class for every pixel, and training uses cross-entropy at every pixel. For a 6 × 6 image and 2 classes that is 6 × 6 × 2 = 72 scores. The original U-Net was trained on just 30 labeled images for the electron microscopy segmentation challenge, helped by heavy augmentation.

**Dice coefficient** measures overlap directly: $\text{Dice} = \frac{2|A\cap B|}{|A|+|B|}$. Take a $4\times4$ image. The ground-truth object occupies a $2\times2$ block in the top-left (4 pixels). The prediction is a $2\times2$ block shifted one pixel right and one pixel down. The overlap is the single pixel at $(1,1)$, so $|A\cap B| = 1$, with $|A| = |B| = 4$, and $\text{Dice} = \frac{2}{8} = 0.25$. The **IoU** of the same two masks is $\frac{|A\cap B|}{|A\cup B|} = \frac{1}{7} \approx 0.143$. The two always rank models identically, but Dice is always at least as large, which is worth remembering when comparing papers. **mIoU**, mean IoU over classes, is the standard reporting metric. Averaging over classes rather than pixels prevents a large background class from dominating. Classes absent from an image should be skipped rather than scored zero, or a rare class drags the average down for images it never appears in. For large objects, **boundary IoU** scores only a thin band around each contour, because a sloppy blob can keep almost the same area and so almost the same IoU. The practice notebooks measure both conventions.

#### Instance segmentation

**Semantic and instance.** U-Net does **semantic segmentation**: every pixel gets a class, and touching objects of one class merge. Put a second line next to the running example's, in column 4. Semantic segmentation marks one region of 12 line pixels and cannot say where one line ends. **Instance segmentation** gives one mask per object, two masks of 6 pixels here, so the lines can be counted. **Panoptic segmentation** asks for both: a mask for each countable object and a class for every other pixel, such as road or sky.

**Mask R-CNN.** Mask R-CNN (2017) gets instance segmentation from a detector. It adds a third head to Faster R-CNN (see [Object detection](3.3-CV6-vision-transformers-vit-attention.md#lesson-object-detection)), next to the class and the box, that predicts a small mask, 28 × 28, inside each box, from features read with RoIAlign. Each class has its own mask with its own sigmoid, so deciding what the object is and deciding which pixels it covers do not compete. For box A from [Object detection](3.3-CV6-vision-transformers-vit-attention.md#lesson-object-detection), the mask marks the 5 pixels of column 3 in rows 2 to 6.

### Running example

The pooled vertical map from part 2 is 2 × 2. The decoder enlarges it back to 4 × 4 by repeating each number in a 2 × 2 block. The skip connection brings across the 4 × 4 map from before pooling:

| | Map col 1 | Map col 2 | Map col 3 | Map col 4 |
|---|---|---|---|---|
| Enlarged pooled map | 6 | 6 | 0 | 0 |
| Skip connection (before pooling) | 0 | 6 | 0 | 0 |

Every row looks the same. The enlarged map only knows the line is somewhere in map columns 1 and 2. The skip connection pins it to map column 2, which is the 3 × 3 patch centered on image column 3, exactly where the line is. With both, the decoder can label column 3 as "line" and every other pixel as background.

```python
import numpy as np

pooled = np.array([[6.0, 0.0], [6.0, 0.0]])
skip = np.tile([0.0, 6.0, 0.0, 0.0], (4, 1))     # ReLU map from part 2

enlarged = np.kron(pooled, np.ones((2, 2)))      # repeat each value in a 2 x 2 block
print(enlarged[0], skip[0])                      # [6. 6. 0. 0.] [0. 6. 0. 0.]
```

### Common questions

**How is this different from detection?** Detection draws a box around each object. Segmentation labels every pixel, so it gives the exact outline. For the running example, detection returns one box and segmentation returns a 6 × 6 map with column 3 marked.

**Why shrink the image at all?** A small map covers a wide area with each number, which is what lets the network recognize large things, and it is cheaper to compute. The skip connections bring back the positions that shrinking lost.

**Must the network shrink at all?** **Dilated** (or **atrous**) convolution is the alternative: grow the receptive field without downsampling at all, at higher compute cost. DeepLab's ASPP module runs several dilation rates in parallel to capture multiple scales.

**What does a skip connection do with the two maps?** It places them side by side as channels, and the next convolution reads both. Here the decoder sees the enlarged map, 6, 6, 0, 0, and the skipped map, 0, 6, 0, 0, for the same row.

## Adversarial attacks

### The problem

A network that classifies images well can still be fooled by changes too small for a person to notice. Szegedy et al. found this in 2013.

In a well-known example from Goodfellow et al., a network labels a photo of a panda correctly, with 57.7% confidence. Every pixel is then changed by 0.007, less than 1% of its range. To a person the picture looks the same. The network now calls it a gibbon, with 99.3% confidence.

<Figure src="assets/module-media/vision-problem-attack.svg" alt="Three boxes in a sum. A photo of a panda, labeled panda with 57.7% confidence, plus a change of 0.007 to each pixel, equals an image that looks the same but is labeled gibbon with 99.3% confidence. A note says: too small for a person to notice.">
The panda example of Goodfellow et al.
</Figure>

The change is not random noise. It is chosen, pixel by pixel, to push the network toward the wrong answer. For systems such as self-driving cars, this is a security problem. The questions are how such changes are found, and how to defend against them.

### Earlier approaches

#### Optimizing each image

Szegedy et al. found their examples with a slow optimization run separately for every image. It showed the problem existed but was too slow to use widely, for example to make many attacked images for training.

#### Nonlinearity as the cause

Szegedy et al. suggested these images were rare pockets caused by how nonlinear deep networks are. Goodfellow et al. argued the opposite: networks behave almost linearly, so many tiny pushes in the same direction add up. That explanation led directly to a fast attack.

### Gradient attacks

**The idea.** Training uses the gradient of the loss with respect to the weights to make the right answer more likely. An attack uses the gradient with respect to the **pixels** to make the right answer less likely.

**FGSM.** The **fast gradient sign method** moves every pixel by the same small amount $\varepsilon$ in whichever direction raises the loss:

$$
x_{\text{attacked}} = x + \varepsilon \cdot \text{sign}(\text{gradient of the loss with respect to } x)
$$

For example, with $\varepsilon = 0.1$, a pixel of 0.5 whose gradient is positive becomes 0.6, and one whose gradient is negative becomes 0.4, however large or small the gradient is.

**Why the sign.** To first order, a change $\delta$ of the pixels raises the loss by $g_1\delta_1 + g_2\delta_2 + \dots$, where $g$ is the gradient. With every $|\delta_i|$ at most $\varepsilon$, each term is largest when $\delta_i = \varepsilon \cdot \text{sign}(g_i)$, and the rise is then $\varepsilon \cdot (|g_1| + |g_2| + \dots)$. At the running example's image (the 6 by 6 image with one bright vertical line, in the Running example section below) the 36 values of $|g|$ add up to 0.759, so with $\varepsilon = 0.1$ FGSM is expected to raise the loss by 0.076. A step along the gradient itself, scaled so that its largest pixel change is also 0.1, is expected to raise it by only 0.047. The real changes are smaller, because pixels are clipped and the ReLUs bend the loss, but the order holds: at $\varepsilon = 0.4$ FGSM brings p(vertical) down to 0.690 and the scaled gradient step only to 0.821. The 12 pixels whose gradient is 0 are left as they are. A budget on the total length of the change, instead of on each pixel, would make the gradient's own direction the best one.

**Why small changes add up.** Each pixel changes by at most $\varepsilon$, but every change pushes the score the same way. If each of 150,528 pixels shifts a score by only 0.0001, together they shift it by 15.05.

**PGD.** **Projected gradient descent** repeats many small FGSM steps and finds stronger attacks. Each step moves every pixel by a small $\alpha$ in the direction of the sign of the gradient, then clips it back to within $\varepsilon$ of the original and to between 0 and 1:

$$
x \leftarrow \text{clip}\big(x + \alpha \cdot \text{sign}(\text{gradient of the loss with respect to } x)\big)
$$

The running example takes 40 steps with $\alpha = 0.02$. PGD is often started from a random point within $\varepsilon$ of the image, so that one starting gradient does not decide the result. Madry et al. argued that no attack using only gradients does much better, which makes PGD the usual test of a defense.

**A valid image.** Every attack also keeps pixels between 0 and 1. At $\varepsilon = 0.4$, FGSM would push 2 pixels of the line above 1 and 4 background pixels below 0, and the clip holds them at 1 and 0.

After a PGD attack with epsilon 0.4, the line is dimmed to 0.6 except in rows 2 and 5, which have become faint horizontal lines of 0.4. The network now gives p(vertical) = 0.354.">
The running example before and after a PGD attack. No pixel has changed by more than 0.4.
</Figure>

**Defense.** The main defense is **adversarial training**: attack the training images with PGD as the network trains, and train on the attacked versions. In symbols, training looks for the weights with the smallest average of the worst loss any allowed change can cause:

$$
\min_{\text{weights}} \; \text{average over images of} \max_{\text{every } |\delta_i| \le \varepsilon} \text{loss}(x + \delta)
$$

PGD finds the inner maximum approximately. For the running example at $\varepsilon = 0.4$ it is the attacked image with p(vertical) = 0.354, and training on it labeled vertical would push that probability back up. Adversarial training makes the network much harder to fool, at the cost of slower training and somewhat lower accuracy on normal images.

**Gradient masking.** A defense can seem to work only because it hides the gradient. Multiply the running example's scores by 100. Every decision stays the same, but p(vertical) for the original image rounds to exactly 1 and the gradient is 0 at every pixel, so FGSM changes nothing and PGD has no direction to follow. The attacked image found on the original network still makes the scaled one say horizontal, with p(vertical) below $10^{-26}$. This is **gradient masking**. Athalye et al. (2018) found it in 7 of the 9 defenses they examined from one conference, and by estimating the hidden gradients their attacks completely got around 6 of them.

### Running example

#### FGSM and PGD

The attack aims to lower p(vertical), which is 0.953 on the original image. For each ε, every pixel may move by at most ε:

| ε | FGSM, one step | PGD, 40 small steps |
|---|---|---|
| 0.1 | 0.921 | 0.891 |
| 0.2 | 0.870 | 0.769 |
| 0.3 | 0.794 | 0.574 |
| 0.4 | 0.690 | 0.354 |

#### The attacked image

At ε = 0.4, PGD makes the network say horizontal. Its main change is two faint horizontal lines across rows 2 and 5, with the vertical line dimmed:

| Row | Col 1 | Col 2 | Col 3 | Col 4 | Col 5 | Col 6 |
|---|---|---|---|---|---|---|
| 1 | 0 | 0 | 0.6 | 0 | 0 | 0 |
| 2 | 0.4 | 0.4 | 1 | 0.4 | 0.4 | 0.4 |
| 3 | 0 | 0 | 0.6 | 0 | 0 | 0 |
| 4 | 0 | 0 | 0.6 | 0 | 0 | 0 |
| 5 | 0.4 | 0.4 | 1 | 0.4 | 0.4 | 0.4 |
| 6 | 0 | 0 | 0.6 | 0 | 0 | 0 |

The vertical line is still the brightest thing in the image, but the network gives "horizontal" 0.646. The faint lines sit where the horizontal filter picks them up in all four pooling blocks, 2.4 in each, a total of 9.6. The dimmed line gives the vertical filter only 3.6 + 3.6 = 7.2. This image has only 36 pixels, so the attack needs large changes. On a real photo the same idea works with changes too small to see.

```python
import numpy as np

def p_vertical(img):
    v = np.array([[-1, 2, -1]] * 3, dtype=float)
    scores = []
    for k in (v, v.T):
        m = np.array([[(img[i:i + 3, j:j + 3] * k).sum() for j in range(4)]
                      for i in range(4)])
        pooled = np.maximum(m, 0).reshape(2, 2, 2, 2).max(axis=(1, 3))
        scores.append(0.25 * pooled.sum())
    return np.exp(scores[0]) / np.exp(scores).sum()

image = np.zeros((6, 6)); image[:, 2] = 1.0
attacked = image.copy()
attacked[[0, 2, 3, 5], 2] -= 0.4                            # dim the line
attacked[[1, 4], :] = np.clip(attacked[[1, 4], :] + 0.4, 0, 1)  # faint lines
print(round(p_vertical(image), 3), round(p_vertical(attacked), 3))  # 0.953 0.354

def gradient(img, h=1e-5):                                  # of the loss, by differences
    loss = lambda im: -np.log(p_vertical(im))
    g = np.zeros_like(img)
    for i in range(6):
        for j in range(6):
            d = np.zeros_like(img); d[i, j] = h
            g[i, j] = (loss(img + d) - loss(img)) / h
    return g

fgsm = np.clip(image + 0.4 * np.sign(gradient(image)), 0, 1)   # FGSM, epsilon 0.4
print(round(p_vertical(fgsm), 3))                                # 0.69
```

### Common questions

**How large is ε on a real photo?** Small. A common choice is 8 ÷ 255 = 0.031 on pixel values between 0 and 1, which the eye cannot see. The toy image needs 0.4 only because it has 36 pixels to add up, not 150,528.

**Can the attack aim for a chosen label?** Yes. A **targeted** attack lowers the loss of the chosen class instead of raising the loss of the true one: $x - \varepsilon \cdot \text{sign}(\text{gradient of the loss for the target})$. With two classes the two attacks are the same, since raising the loss of vertical lowers that of horizontal.

**Does the attacker need the network's weights?** These attacks do, because they need the gradient. But attacked images made for one network often fool another network trained on the same task, so an attacker can use a stand-in.

**Why is PGD stronger than FGSM?** FGSM takes one step along the gradient at the original image. PGD takes many small steps and recomputes the gradient after each, so it follows the loss as it bends. At ε = 0.4 it brings p(vertical) to 0.354 where FGSM reaches 0.690. This only helps because the gradient changes within the budget: its sign at the final PGD image differs from its sign at the original on 17 of the 36 pixels. For a two-class model whose score is linear in the pixels, such as logistic regression, the sign never changes and PGD ends where FGSM does.
