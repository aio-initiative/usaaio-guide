## The problem

Some tasks need a label for every pixel: which pixels are tumor in a scan, or which are road in a dashcam frame. The output is a map the same size as the image.

For the running example, the wanted output is a 6 × 6 map with a 1 for every pixel of the line and a 0 for every background pixel.

<Figure src="assets/module-media/vision-problem-segmentation.svg" alt="Three grids joined by arrows. The 6 by 6 image, with its bright column 3. The 2 by 2 map left after pooling, with rows 6, 0. Then, after an arrow with a question mark, the wanted output: a 6 by 6 map with a label for every pixel, 1 for the line in column 3 and 0 for the background.">
The network shrinks the image to a 2 × 2 map, but the output has to be 6 × 6 again.
</Figure>

The network of Steps 2 to 4 works against this. It shrinks the image as it goes, from 6 × 6 to a 4 × 4 feature map to a 2 × 2 pooled map. The shrinking is useful, because it lets the network take in large areas cheaply. But the pooled map, 6, 0 in each row, only says that the line is somewhere in the left part of the image. The exact column has been thrown away, and a label for every pixel needs it back.

## Earlier approaches

### One patch per pixel

Classify a small patch around each pixel, one pixel at a time. This works but is slow, because neighboring patches overlap and the same work is repeated for every pixel.

### Growing the small map back

Fully convolutional networks (Long et al., 2015) run the image through a normal CNN and then enlarge the small final map back to full size. This is fast, but the enlarged map alone is blurry, because the small map no longer knows exactly where things were. The FCN paper fixes this by fusing the coarse map with finer maps from earlier layers, and U-Net's skip connections do the same job.

## U-Net

**Two halves.** **U-Net** (2015) has two halves. The **encoder** shrinks the image with convolution and pooling, as before, learning what is in it. The **decoder** grows the map back to full size, step by step.

**Skip connections.** **Skip connections** copy each encoder map across to the decoder at the same size, so the decoder gets back the exact positions that pooling threw away. Drawn out, the two halves and the connections between them form a U. The skip connections also give the gradient a short path back to the early layers, as the shortcuts of Step 5 do.

**Growing a map.** The simplest way to enlarge a map is to repeat each number in a 2 × 2 block, so a 2 × 2 map becomes 4 × 4. For example, the row 6, 0 becomes 6, 6, 0, 0, twice. The enlarged map is the right size but blurry: it cannot say which of the two columns the 6 came from.

**Bilinear enlarging.** Instead of repeating, **bilinear** enlarging blends the two nearest values in each direction. The second of the four new values sits a quarter of the way from the 6 to the 0, and the third three quarters of the way, so it is 6 × 0.75 + 0 × 0.25 = 4.5, and the row 6, 0 becomes 6, 4.5, 1.5, 0. The result is smoother, but the 6 is spread over three columns. Label maps are usually enlarged by repeating, because blending two class labels gives a value that is neither.

**Transposed convolution.** A **transposed convolution** learns how to enlarge. Each input value multiplies a small kernel, and the result is added into the output starting at the value's position times the stride. With stride 2 and the kernel (1, 1), the row 6, 0 becomes 6, 6, 0, 0, the same as repeating. With the kernel (0, 1) it becomes 0, 6, 0, 0, which matches the map from before pooling. But the kernel is the same for every block, so it cannot know where in its block the line was. For the line moved one column left, as in Step 3, the pooled row is still 6, 0 and the output is still 0, 6, 0, 0, while the map before pooling is now 6, 0, 0, 0. The skip connection carries that position. An input of $n$ values gives $(n - 1) \times \text{stride} - 2 \times \text{padding} + \text{kernel size}$ values, (2 − 1) × 2 − 0 + 2 = 4 here. Padding $p$ drops the first $p$ and the last $p$ of the sums, hence its term. A layer from 2 channels to 2 with a 2 × 2 kernel has 2 × 2 × 2 × 2 = 16 weights, counted like a convolution.

**Checkerboard pattern.** When the kernel size is not a multiple of the stride, the copies of the kernel overlap unevenly. Down the first column of the pooled map, 6, 6, the line runs the whole height, so the enlarged column should be even. With the kernel (1, 1, 1) and stride 2, the two copies overlap at the third of five values, which gets 12 where the rest get 6: a stripe across the map. In two directions the stripes form a checkerboard. The kernel (1, 1) gives 6, 6, 6, 6. A kernel size that is a multiple of the stride makes the overlaps even but does not make the output even, since a learned kernel such as (1, 0.3) still gives 6, 1.8, 6, 1.8. Repeating or bilinear enlarging followed by an ordinary convolution cannot turn an even column into stripes, which is why many networks enlarge that way.

A note says the copies overlap at position 3, a stripe. On the right, kernel 1, 1 with stride 2: the copies 6, 6 and 6, 6 sit side by side and sum to 6, 6, 6, 6. A note says no overlap, even.">

**Shapes.** Through the running example, written as channels × height × width:

| Stage | Shape |
|---|---|
| Image | 1 × 6 × 6 |
| After the two filters | 2 × 4 × 4 |
| After pooling | 2 × 2 × 2 |
| Enlarged | 2 × 4 × 4 |
| With the skip connection | 4 × 4 × 4 |
| Transposed 3 × 3 convolution, stride 1, one map per class | 2 × 6 × 6 |

The skip connection adds its 2 maps as channels, so the convolution after it reads 4 maps where the enlarging made 2. The two 3 × 3 filters took the image from 6 × 6 to 4 × 4, and a transposed 3 × 3 convolution with stride 1 undoes that size change: (4 − 1) × 1 + 3 = 6. With one output map per class it gives a score for line and for background at every pixel, and each pixel takes the class with the higher score.

**Output and loss.** The output has one score per class for every pixel, and training uses cross-entropy at every pixel. For a 6 × 6 image and 2 classes that is 6 × 6 × 2 = 72 scores. The original U-Net was trained on just 30 labeled images for the electron microscopy segmentation challenge, helped by heavy augmentation.

**Dice coefficient** measures overlap directly: $\text{Dice} = \frac{2|A\cap B|}{|A|+|B|}$. Take a $4\times4$ image. The ground-truth object occupies a $2\times2$ block in the top-left (4 pixels). The prediction is a $2\times2$ block shifted one pixel right and one pixel down. The overlap is the single pixel at $(1,1)$, so $|A\cap B| = 1$, with $|A| = |B| = 4$, and $\text{Dice} = \frac{2}{8} = 0.25$. The **IoU** of the same two masks is $\frac{|A\cap B|}{|A\cup B|} = \frac{1}{7} \approx 0.143$. The two always rank models identically, but Dice is always at least as large, which is worth remembering when comparing papers. **mIoU**, mean IoU over classes, is the standard reporting metric. Averaging over classes rather than pixels prevents a large background class from dominating. Classes absent from an image should be skipped rather than scored zero, or a rare class drags the average down for images it never appears in. For large objects, **boundary IoU** scores only a thin band around each contour, because a sloppy blob can keep almost the same area and so almost the same IoU. The practice notebooks measure both conventions.

### Instance segmentation

**Semantic and instance.** U-Net does **semantic segmentation**: every pixel gets a class, and touching objects of one class merge. Put a second line next to the running example's, in column 4. Semantic segmentation marks one region of 12 line pixels and cannot say where one line ends. **Instance segmentation** gives one mask per object, two masks of 6 pixels here, so the lines can be counted. **Panoptic segmentation** asks for both: a mask for each countable object and a class for every other pixel, such as road or sky.

**Mask R-CNN.** Mask R-CNN (2017) gets instance segmentation from a detector. It adds a third head to Faster R-CNN (Step 8), next to the class and the box, that predicts a small mask, 28 × 28, inside each box, from features read with RoIAlign. Each class has its own mask with its own sigmoid, so deciding what the object is and deciding which pixels it covers do not compete. For box A of Step 8, the mask marks the 5 pixels of column 3 in rows 2 to 6.

## Running example

The pooled vertical map from Step 3 is 2 × 2. The decoder enlarges it back to 4 × 4 by repeating each number in a 2 × 2 block. The skip connection brings across the 4 × 4 map from before pooling:

| | Map col 1 | Map col 2 | Map col 3 | Map col 4 |
|---|---|---|---|---|
| Enlarged pooled map | 6 | 6 | 0 | 0 |
| Skip connection (before pooling) | 0 | 6 | 0 | 0 |

Every row looks the same. The enlarged map only knows the line is somewhere in map columns 1 and 2. The skip connection pins it to map column 2, which is the 3 × 3 patch centered on image column 3, exactly where the line is. With both, the decoder can label column 3 as "line" and every other pixel as background.

```python
import numpy as np

pooled = np.array([[6.0, 0.0], [6.0, 0.0]])
skip = np.tile([0.0, 6.0, 0.0, 0.0], (4, 1))     # ReLU map from Step 3

enlarged = np.kron(pooled, np.ones((2, 2)))      # repeat each value in a 2 x 2 block
print(enlarged[0], skip[0])                      # [6. 6. 0. 0.] [0. 6. 0. 0.]
```

## Common questions

**How is this different from detection?** Detection draws a box around each object. Segmentation labels every pixel, so it gives the exact outline. For the running example, detection returns one box and segmentation returns a 6 × 6 map with column 3 marked.

**Why shrink the image at all?** A small map covers a wide area with each number, which is what lets the network recognize large things, and it is cheaper to compute. The skip connections bring back the positions that shrinking lost.

**Must the network shrink at all?** **Dilated** (or **atrous**) convolution is the alternative: grow the receptive field without downsampling at all, at higher compute cost. DeepLab's ASPP module runs several dilation rates in parallel to capture multiple scales.

**What does a skip connection do with the two maps?** It places them side by side as channels, and the next convolution reads both. Here the decoder sees the enlarged map, 6, 6, 0, 0, and the skipped map, 0, 6, 0, 0, for the same row.
