# 2.25 · CV12 · 3. Classifying, going deeper and transfer learning

> **Goal:** A classifier head, deeper networks with residual connections, and reusing a trained network.
> **Stage:** Round 2, Core contest depth.

## Classify

### The problem

After part 2, the image has become two small pooled maps, one per filter. For the running example the vertical map is 6, 0, 6, 0 and the horizontal one is 0, 0, 0, 0.

The maps say which patterns were found, and roughly where. They are not yet an answer. The task is to decide whether the line is vertical or horizontal.

<Figure src="assets/module-media/vision-problem-classify.svg" alt="On the left, the vertical pooled map with rows 6, 0 and the horizontal pooled map with all zeros. An arrow with a question mark leads to two boxes: p(vertical) = ? and p(horizontal) = ?. A note says: two probabilities that add up to 1.">
What this section has to produce from the two pooled maps.
</Figure>

The model has to turn the 8 numbers into a decision with a probability for each class, two numbers that add up to 1. From these maps it should answer "vertical" with a probability close to 1. The way of deciding also has to be learned from examples, because for real images nobody can write the rule by hand.

### Earlier approaches

#### Hand-written rules

A rule such as "vertical if the vertical map has the larger total" works for lines, but nobody can write such rules for "cat" or "dog".

#### A separate classifier

Older systems fed their features into a classifier trained on its own, such as HOG features into a support vector machine for finding pedestrians. The features could not improve to help the classifier.

### The classification layer

**Flatten.** The pooled maps are laid out as one list, called **flattening**. Two 2 × 2 maps become a list of 8 numbers.

**Scores.** The list is multiplied by learned weights to give one score per class. Each class has one weight per number in the list:

$$
\text{score of a class} = w_1 x_1 + w_2 x_2 + \dots + w_8 x_8.
$$

For example, with weights of 0.25 on the first four numbers and 0 on the rest, the list 6, 0, 6, 0, 0, 0, 0, 0 gives 0.25 × 6 + 0.25 × 6 = 3.

**Probabilities.** A softmax turns the scores into probabilities, as in [Mask and softmax](2.34-TF14-transformer-qkv.md#lesson-mask-and-softmax) in Build a Transformer. Scores of 3 and 0 give $e^3 = 20.09$ and $e^0 = 1$, so the probabilities are 20.09 ÷ 21.09 = 0.953 and 0.047.

<Figure src="assets/module-media/vision-classify.svg" alt="The vertical pooled map, with rows 6, 0, and the horizontal pooled map, all 0, are flattened into a list of 8 numbers: 6, 0, 6, 0, 0, 0, 0, 0. Weights turn the list into two scores, 3 for vertical and 0 for horizontal. A softmax turns the scores into probabilities, 0.953 and 0.047.">
The classification layer of the running example.
</Figure>

**Training.** The whole network, filters included, is trained together to make the right class more likely.

**Deeper networks.** Real networks repeat convolution, ReLU and pooling several times before this layer, and each repeat covers a wider area of the image. In this chapter's network, each pooled number already covers a 4 × 4 patch of the image.

### Running example

Flattening the two pooled maps gives 8 numbers: 6, 0, 6, 0 from the vertical map and 0, 0, 0, 0 from the horizontal one. In the running example the weights are 0.25 on the four numbers of a class's own map and 0 on the other map's, so each score is a quarter of the total of its own map:

| Class | Total of its pooled map | Score | Probability |
|---|---|---|---|
| vertical | 6 + 0 + 6 + 0 = 12 | 3 | 0.953 |
| horizontal | 0 | 0 | 0.047 |

The softmax gives $e^3 = 20.09$ and $e^0 = 1$, and 20.09 ÷ 21.09 = 0.953. The network is 95.3% sure the line is vertical.

```python
import numpy as np

pooled_vertical = np.array([[6.0, 0.0], [6.0, 0.0]])
pooled_horizontal = np.zeros((2, 2))

scores = np.array([0.25 * pooled_vertical.sum(), 0.25 * pooled_horizontal.sum()])
probs = np.exp(scores) / np.exp(scores).sum()
print(probs.round(3))    # [0.953 0.047]
```

### Common questions

**How many weights does this layer have?** One per input number for every class. With 8 numbers and 2 classes that is 16 weights, plus 2 offsets if they are used. The running example sets them to 0.25 or 0 by hand.

**Why a softmax, and not just the larger score?** Picking the larger score gives a decision, but training needs to know how wrong the network was. Probabilities of 0.953 and 0.047 can be compared with the right answer through the cross-entropy loss, and they change smoothly as the weights change.

**What would a horizontal line give?** The two maps swap roles. The horizontal pooled map totals 12 and the vertical one 0, so the scores are 0 and 3, and the network is 95.3% sure the line is horizontal.

## Deeper networks

### The problem

One convolution layer finds simple patterns such as edges. Recognizing a face or a car needs patterns built from patterns: edges make corners and curves, those make eyes and wheels, and those make faces and cars. Each stage needs at least one more layer, so a network that recognizes real objects has to be deep.

<Figure src="assets/module-media/vision-problem-depth.svg" alt="Four boxes joined by arrows: edges, found by the first layer, then corners and curves after a few layers, then eyes and wheels after more layers, then faces and cars after many layers. A note says: each stage is built from the one before.">
Why depth is needed. Each kind of pattern is built from the simpler ones below it.
</Figure>

But simply stacking more layers stopped working. He et al. trained a 20-layer and a 56-layer network of the same design on CIFAR-10, and the 56-layer one had the higher error, even on its own training images. A deeper network can do everything a shallower one can, so the extra layers should not hurt. The deep network was not too powerful. It could not be trained well.

### Earlier approaches

#### AlexNet

AlexNet (2012) had 8 layers with learned weights, 5 convolutional and 3 fully connected, and about 60 million weights. It used large filters, 11 × 11 in its first layer, and showed that depth trained on GPUs pays off.

#### VGG

VGG (2014) used only 3 × 3 filters and went to 16 and 19 layers. Two stacked 3 × 3 layers cover the same 5 × 5 area as one 5 × 5 filter with fewer weights, 2 × 9 = 18 instead of 25, and they put a ReLU after each layer, two where the single filter has one. But the VGG authors found that error stopped improving at 19 layers.

### Shortcut connections

**Why depth is hard.** The gradient reaches early layers by passing back through every layer above them, and each layer can shrink it. If every layer scales it by 0.8, after $n$ layers $0.8^n$ of it is left:

| Layers | Gradient left |
|---|---|
| 10 | $0.8^{10} = 0.107$ |
| 20 | $0.8^{20} = 0.012$ |
| 50 | $0.8^{50} = 0.000014$ |

**The shortcut.** **ResNet** (2015) adds a **shortcut** around each block of layers: the block's input is added to its output, so a block computes

$$
\text{output} = x + F(x)
$$

instead of $F(x)$. For example, if a block's layers output $F(x) = (0, 0)$ for the input $x = (6, 0)$, the block returns (6, 0), its input unchanged.

<Figure src="assets/module-media/vision-shortcut.svg" alt="A row of boxes: x, then a block of layers F(x), then a plus sign, then x + F(x). A dashed line labeled shortcut: the input, unchanged carries x around the block and into the plus sign. Under the boxes are the running example's numbers: x is 6, 0, 6, 0. The block, with all its weights at 0, outputs 0, 0, 0, 0. x + F(x) is 6, 0, 6, 0.">
A block with a shortcut. With its weights at 0 the block adds nothing, and the input passes through.
</Figure>

**Why it helps.** A small change in $x$ reaches the output twice, once through the shortcut and once through $F$, so the gradient through the block is multiplied by $1 +$ (the factor of $F$) instead of by the factor of $F$ alone. For a block whose weights are all 0, a change of 0.001 in the input changes the output by 0 without the shortcut and by 0.001 with it: factors of 0 and 1. The gradient keeps a path back to the early layers at full size. It is not a guarantee against vanishing or exploding gradients: the learned block can still cancel or amplify a direction, so a deep residual network can still train badly. And a block that has nothing useful to add only needs $F(x) = 0$, which is easy to learn.

**The result.** With shortcuts, networks of 152 layers trained well, and an ensemble of six ResNets won the 2015 ImageNet challenge with 3.57% top-5 error.

### ResNet-50

**Stem and stages.** ResNet-50 starts with a **stem**, a 7 × 7 convolution with stride 2 and then a 3 × 3 max pooling with stride 2, which turn a 224 × 224 image into 64 maps of 56 × 56. Four **stages** of blocks follow, with 3, 4, 6 and 3 blocks. Stage 1 keeps the maps at 56 × 56 and gives 256 channels, and stage 4 ends with 2,048 maps of 7 × 7.

**Bottleneck blocks.** Each block is a **bottleneck**: a 1 × 1 convolution shrinks the channels, a 3 × 3 convolution works on the smaller number, and a second 1 × 1 convolution expands them 4 times. The first block of stage 1 takes 64 channels in and gives 256 out, so its shortcut carries a 1 × 1 convolution from 64 to 256 channels to match the shapes.

<Figure src="assets/module-media/vision-bottleneck.svg" alt="A row of boxes: x, with 64 maps of 56 by 56, then a 1 by 1 convolution from 64 to 64 channels with 4,096 weights, a 3 by 3 convolution from 64 to 64 with 36,864, outlined most heavily, and a 1 by 1 convolution from 64 to 256 with 16,384. Under them, batch normalization adds 128, 128 and 512. A plus sign gives 256 maps of 56 by 56. A dashed shortcut from x to the plus sign carries a 1 by 1 convolution from 64 to 256 with 16,384 weights and 512 for batch normalization. A note says: 75,008 in all.">
The first bottleneck block of ResNet-50 with the number of weights in each layer.
</Figure>

**The last layer.** After stage 4, **global average pooling** turns each of the 2,048 maps of 7 × 7 into one number, its average, and a fully connected layer turns those 2,048 numbers into scores for the 1,000 ImageNet classes.

### Counting parameters

**The rules.** A network's **parameters** are the numbers training adjusts. Each kind of layer has a fixed count:

| Layer | Parameters |
|---|---|
| $k \times k$ convolution from $c_\text{in}$ to $c_\text{out}$ channels | $k \times k \times c_\text{in} \times c_\text{out}$, plus $c_\text{out}$ offsets (biases) if used |
| Batch normalization over $c$ channels | $2 \times c$, a scale and a shift for each channel |
| Fully connected, $n_\text{in}$ to $n_\text{out}$ | $n_\text{in} \times n_\text{out}$, plus $n_\text{out}$ offsets if used |

ResNet's convolutions have no offsets, because the [batch normalization](1.19-DL2-neural-network-regularization-dropout-batchnorm.md) after each one adds its own shift.

**The running example.** The two 3 × 3 filters have 3 × 3 × 1 × 2 = 18 weights and the classification layer 8 × 2 = 16, so the network built so far has 34. Suppose the extra block of this section is two 3 × 3 convolutions from the 2 pooled maps to 2 maps, padded so the maps stay 2 × 2, each followed by batch normalization. It adds 2 × (3 × 3 × 2 × 2 + 2 × 2) = 2 × (36 + 4) = 80, and the shortcut adds none.

**One block of ResNet-50.** The first block of stage 1, `layer1[0]` in torchvision's `resnet50`, from the figure:

| Layer | Weights | Batch normalization |
|---|---|---|
| 1 × 1, 64 to 64 | 1 × 1 × 64 × 64 = 4,096 | 2 × 64 = 128 |
| 3 × 3, 64 to 64 | 3 × 3 × 64 × 64 = 36,864 | 128 |
| 1 × 1, 64 to 256 | 1 × 1 × 64 × 256 = 16,384 | 2 × 256 = 512 |
| Shortcut, 1 × 1, 64 to 256 | 16,384 | 512 |

The total is 73,728 weights and 1,280 for batch normalization, 75,008. The other two blocks of stage 1 take 256 channels in and have no convolution on their shortcut, so each has 70,400, and the stage has 75,008 + 2 × 70,400 = 215,808.

<ProblemCard id="cv-first-block-of-stage-2" />

**Where the parameters are.** Counted the same way, stage 4 has 14,964,736 parameters, 58.6% of the network's 25.6 million, because a convolution's count grows with the product of its channel numbers. The work is spread far more evenly. A 3 × 3 convolution in stage 4 has 64 times the weights of one in stage 1 but runs at 1/64 as many positions, so each does 3 × 3 × 64 × 64 × 56 × 56 = 3 × 3 × 512 × 512 × 7 × 7 = 115,605,504 multiply-adds for one image.

### Running example

Add one more block after the pooling from part 2, and suppose its weights are all 0, as if it has learned nothing yet. The vertical pooled map going into it is 6, 0, 6, 0:

| Block | Output for the vertical map | p(vertical) |
|---|---|---|
| Plain, F(x) | 0, 0, 0, 0 | 0.5 |
| With a shortcut, x + F(x) | 6, 0, 6, 0 | 0.953 |

The plain block wipes out everything the earlier layers found, and the network is back to guessing. The block with a shortcut passes its input through, so the network still gives 95.3%. Training can then improve F from there.

```python
import numpy as np

x = np.array([6.0, 0.0, 6.0, 0.0])     # vertical pooled map
f = np.zeros(4)                         # block with all-zero weights

for name, out in [("plain", f), ("shortcut", x + f)]:
    scores = np.array([0.25 * out.sum(), 0.0])
    print(name, (np.exp(scores) / np.exp(scores).sum()).round(3))
```

### Common questions

**Is the 56-layer network overfitting?** No. Overfitting would mean a lower error on the training images and a higher one on new images. Here the deeper network was worse on its own training images, so the problem is that it was not trained well, not that it memorized.

**Were the gradients vanishing in the 56-layer network?** Not by much. He et al. used batch normalization and checked that the gradients reaching the early layers were of normal size, yet the 56-layer plain network still trained worse than the 20-layer one. A shortcut helps in both ways: the gradient keeps a path with a factor of 1, and a block that should do nothing only has to learn $F(x) = 0$.

**Does a shortcut add weights?** Not when the input and the output of the block have the same shape: it is an addition, with no weights. Where they differ, ResNet puts a 1 × 1 convolution on the shortcut to match them, and that convolution has weights, as the first block of each stage shows.

**Is this the same as the residual connection in a Transformer?** Yes. [Residual and LayerNorm](2.39-TF19-transformer-residual-and-layernorm.md#lesson-residual-and-layernorm) in Build a Transformer adds the input of each layer back to its output in the same way, and for the same reason.

## Transfer learning

### The problem

A large network learns well from ImageNet's 1.2 million labeled photos. Most real tasks have far fewer. For example, a hospital might have a few hundred labeled X-rays.

<Figure src="assets/module-media/vision-problem-transfer.svg" alt="A horizontal bar chart on a logarithmic scale. The weights of ResNet-50: 25,600,000. The labeled photos in ImageNet: 1,200,000. The labeled images of a small task: a few hundred.">
A small task has thousands of times fewer images than ImageNet, and far fewer images than the network has weights.
</Figure>

ResNet-50 has about 25.6 million weights. With a few hundred images there are tens of thousands of weights for every image, so the network can simply memorize the training images: it scores well on them and fails on new ones. Collecting and labeling a million X-rays is not an option. The model needs a way to learn a new task from a small number of examples.

### Earlier approaches

#### Training from scratch

Starting from random weights on a small dataset is the obvious approach, and it overfits: the network scores well on the training images and badly on new ones.

Augmentation is the usual answer: random, label-preserving transforms on the training images, and the same deterministic resize and normalization on the validation ones.

```python
from torchvision import transforms

train_tf = transforms.Compose([
    transforms.RandomResizedCrop(224, scale=(0.6, 1.0)),
    transforms.RandomHorizontalFlip(),          # Requires label-preserving flips.
    transforms.ColorJitter(0.2, 0.2, 0.2),
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
])
val_tf = transforms.Compose([                   # deterministic: no randomness at eval
    transforms.Resize(256), transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
])
```

#### Hand-made features

The older answer was to describe each image with hand-made features, as in [part 1](2.21-CV8-vision-setup.md#lesson-pixels), and train a small classifier on them. It needs little data but is limited by how good the hand-made features are.

### Reusing a trained network

**What carries over.** The early layers of a network trained on ImageNet have learned edges, textures and shapes, which are useful for almost any kind of image. The same holds outside vision: in text, early layers learn syntax and morphology, while late layers learn task-specific facts that do not transfer. **Transfer learning** keeps those layers, the **backbone**, and replaces only the last layer, the **head**, with a new one for the new classes.

<Figure src="assets/module-media/vision-transfer.svg" alt="A row of boxes: filters, then ReLU and pooling, then totals of the two maps, all under a line labeled kept from the old network, frozen. A fourth box, outlined, reads new layer, 6 weights, under a line labeled trained. Its output is vertical, horizontal or cross.">
Transfer learning in the running example. Only the new layer is trained.
</Figure>

**Feature extraction.** Freeze the old layers and train only the new layer. When the new layer is a single linear layer, as here, this is also called a **linear probe**.

**Freezing in code.** In PyTorch, freezing sets `requires_grad = False` on every old parameter, so no gradient is computed for it and training cannot change it. In the running example the 18 weights of the two filters stay fixed and only the 2 × 3 = 6 weights of the new layer are trained, 6 of 24.

**Fine-tuning.** Then also train some of the old layers, with a small learning rate so they change only a little. A common middle ground trains only the last stage, such as stage 4 of ResNet-50, and keeps the rest frozen.

**Counting the weights.** A layer from $m$ features to $c$ classes has $m \times c$ weights and usually $c$ offsets. The running example below omits them, so each score is a pure weighted sum. ResNet-50 has about 25.6 million parameters. It averages each of its last 2,048 maps to one number, the job the totals do in the running example, and its last layer maps those 2,048 features to 1,000 ImageNet classes. Without that layer about 23.5 million remain. For a new task with 2 classes, the new layer has 2,048 × 2 + 2 = 4,098 weights. With feature extraction those are the only ones trained, 0.017% of the new network.

**A shorter backbone.** The frozen network can also be cut before its last stage. Cut after stage 1, ResNet-50 keeps 225,344 parameters and ends with 256 maps of 56 × 56. Averaging each map gives 256 features, and a new 2-class layer on them has 256 × 2 + 2 = 514 weights. The earlier stages hold more general patterns such as edges and textures, so a shorter backbone can suit images that look little like ImageNet's.

### Running example

#### The new task

The new task has three classes: vertical, horizontal and a cross of both. The old layer cannot handle the cross: its two pooled maps total 10 each, so the old scores are 2.5 and 2.5, a tie.

#### The frozen features

Keep the two filters, ReLU and pooling, and use the totals of the two pooled maps as features:

| Image | Vertical total | Horizontal total |
|---|---|---|
| vertical line | 12 | 0 |
| horizontal line | 0 | 12 |
| cross | 10 | 10 |

#### The new layer

A new layer of 2 × 3 = 6 weights is trained on these three images for 100 steps. Rounded, it learns:

| Class | Weight on vertical total | Weight on horizontal total |
|---|---|---|
| vertical | 0.32 | −0.42 |
| horizontal | −0.42 | 0.32 |
| cross | 0.10 | 0.10 |

The cross class has a small positive weight on both totals, and each line class has a negative weight on the other line's total. Now each image gets its own label, using the unrounded weights: 0.934 for the vertical line, 0.934 for the horizontal line and 0.911 for the cross. The filters were never retrained.

```python
import numpy as np

features = np.array([[12.0, 0.0], [0.0, 12.0], [10.0, 10.0]])   # one row per image
W = np.zeros((2, 3))                                             # the new layer

for _ in range(100):
    s = features @ W
    p = np.exp(s) / np.exp(s).sum(axis=1, keepdims=True)
    p[np.arange(3), np.arange(3)] -= 1          # softmax gradient, image i is class i
    W -= 0.01 * features.T @ p / 3

s = features @ W
print((np.exp(s) / np.exp(s).sum(axis=1, keepdims=True)).round(3))
```

### Common questions

**When should the old layers be fine-tuned?** Images close to the ones the network was trained on need only the new layer. Images of a different kind, such as X-rays, usually benefit from fine-tuning the old layers as well. How much target data justifies unfreezing them is measured in [ResNets and Transfer Learning](2.8-CV4-modern-vision-architectures-resnet-efficientnet-transfer.md), which sweeps the crossover and sets the per-block rates.

**Do new images need the same preprocessing?** Yes. The frozen filters were set for pixel values from 0 to 1. The vertical line stored with values up to 255 gives totals of 3,060 and 0 instead of 12 and 0, far from anything the new layer was trained on. Torchvision's ImageNet networks expect values from 0 to 1, then each color channel standardized with ImageNet's means 0.485, 0.456 and 0.406 and standard deviations 0.229, 0.224 and 0.225.

**Why could the old layer not handle the cross?** It had one score per line direction. A cross lights up both pooled maps equally, 10 and 10, so the two scores tie at 2.5. The new layer has a third class that responds when both totals are high.
