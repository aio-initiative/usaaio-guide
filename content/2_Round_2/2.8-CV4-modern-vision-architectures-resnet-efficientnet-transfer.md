## Transfer Learning

### Why transfer works

[6. Transfer learning](2.27-CV14-vision-transfer-learning.md) covers the basics: an ImageNet network's early layers have learned edges, textures and shapes that are useful for almost any image, so freezing them and training only a new head already works, and the linear probe and fine-tuning are defined there. What it leaves open is how much of the network you can afford to retrain.

This has been measured directly. Freeze the first $k$ layers of a pretrained network, retrain the rest on a different task, and accuracy is essentially unaffected for small $k$ and degrades as $k$ approaches the output. The crossover marks where the representation stops being general. In vision that is typically around two-thirds of the way up.

### Learning rates and forgetting

**Discriminative learning rates.** Use a smaller rate for early layers than late ones, typically a geometric decay of $2$–$3\times$ per block going down. Early features are already good and a large update destroys them, while the head is random and needs a large one.

**Warmup and head-first training.** A randomly initialized head produces large, meaningless gradients in its first steps, and those propagate into the pretrained backbone. Training the head alone for an epoch before unfreezing anything (or simply using a warmup) avoids damaging the backbone before the head is sane.

**Catastrophic forgetting.** Fine-tuning on a small target set can erase the pretrained knowledge, especially at high learning rates. Mitigations: low learning rate, few epochs, layer-wise decay, freezing early layers, or an $\ell_2$ penalty toward the pretrained weights (sometimes weighted by parameter importance, as in elastic weight consolidation).

### When transfer fails

A large domain gap (natural images to medical scans to satellite imagery) reduces the benefit and can make training from scratch competitive, especially when the target dataset is itself large. Pretrained features are also only as good as the pretraining distribution: a model pretrained on object-centric photographs has learned to ignore texture statistics that a materials-classification task depends on.

Two further failure modes worth naming. **Negative transfer**: the pretrained initialization is actively worse than random, which happens when the source task encourages an invariance the target task needs to be sensitive to. And **input mismatch**: a model pretrained on 224×224 three-channel images does not transfer cleanly to single-channel 12-bit medical scans without deciding what to do about the channel count, the resolution, and the normalization statistics. Those decisions frequently cost more accuracy than the choice of strategy.

### Parameter-efficient fine-tuning

**LoRA** freezes $W$ and learns a low-rank update $\Delta W = BA$ with $A\in\mathbb{R}^{r\times d}$, $B\in\mathbb{R}^{d\times r}$, $r\ll d$. Parameters drop from $d^2$ to $2rd$. At $d = 4096$, $r=8$, that is $16.8$M to $65.5$K, a $256\times$ reduction, and the update can be merged into $W$ at inference so there is no added latency. The premise, supported empirically, is that the *change* required for adaptation is intrinsically low-rank even though $W$ is not.

$B$ is initialized to zero so that $\Delta W = 0$ at the start and training begins exactly at the pretrained model. The scaling $\alpha/r$ applied to the update lets $r$ be changed without re-tuning the learning rate.

**Adapters** insert small bottleneck MLPs between blocks and train only those, while **prefix tuning** and **prompt tuning** prepend trainable vectors to the input or to each layer's keys and values. **QLoRA** combines LoRA with a 4-bit quantized frozen base, which is what makes fine-tuning a 65B model on a single 48GB GPU possible.

All of them share the deployment advantage: one frozen backbone in memory, many small task-specific deltas swapped in as needed.

### From Scratch

```python
import numpy as np


def discriminative_lrs(n_blocks, base_lr=1e-3, decay=2.5):
    """Head gets base_lr, and each block deeper gets divided by `decay`. Early
    features are already good -- a large update destroys them."""
    return [base_lr / (decay ** (n_blocks - 1 - i)) for i in range(n_blocks)]


def lora_params(d, r):
    return {"full": d * d, "lora": 2 * r * d, "reduction": d * d / (2 * r * d)}


class LoRALinear:
    """W is frozen, and only A and B train. B starts at zero so the model begins
    exactly at the pretrained function, and alpha/r decouples r from the LR."""

    def __init__(self, W, r=8, alpha=16, seed=0):
        rng = np.random.default_rng(seed)
        d_out, d_in = W.shape
        self.W = W                                   # frozen
        self.A = rng.normal(0, 1.0 / r, (r, d_in))
        self.B = np.zeros((d_out, r))
        self.scale = alpha / r

    def __call__(self, x):
        return x @ self.W.T + self.scale * (x @ self.A.T) @ self.B.T

    def merged(self):
        """Fold the update into W: zero added latency at inference."""
        return self.W + self.scale * self.B @ self.A


def l2_sp_penalty(params, pretrained, lam=1e-3):
    """L2-SP: penalize distance from the PRETRAINED weights rather than from
    zero. Directly targets catastrophic forgetting."""
    return lam * sum(((p - q) ** 2).sum() for p, q in zip(params, pretrained))


def linear_probe(Z_train, y_train, Z_test, y_test, lam=1e-3):
    """Ridge-regularized least squares on ONE-HOT targets. A linear model cannot
    create structure, so success means the structure was already in Z."""
    Zc = np.hstack([Z_train, np.ones((len(Z_train), 1))])
    Y = np.eye(int(max(y_train.max(), y_test.max())) + 1)[y_train]
    W = np.linalg.solve(Zc.T @ Zc + lam * np.eye(Zc.shape[1]), Zc.T @ Y)
    Zt = np.hstack([Z_test, np.ones((len(Z_test), 1))])
    return float(((Zt @ W).argmax(1) == y_test).mean())


def forgetting_score(acc_source_before, acc_source_after):
    """How much of the source task was destroyed by fine-tuning on the target."""
    return acc_source_before - acc_source_after
```

### Using the Library

```python
import torch, torch.nn as nn
from torchvision.models import resnet50, ResNet50_Weights
from peft import LoraConfig, get_peft_model

# ---- linear probe
m = resnet50(weights=ResNet50_Weights.DEFAULT)
for p in m.parameters():
    p.requires_grad = False
m.fc = nn.Linear(2048, n_classes)           # new head is trainable by default

# ---- discriminative learning rates
groups = [{"params": m.layer1.parameters(), "lr": 1e-5},
          {"params": m.layer2.parameters(), "lr": 3e-5},
          {"params": m.layer3.parameters(), "lr": 1e-4},
          {"params": m.layer4.parameters(), "lr": 3e-4},
          {"params": m.fc.parameters(),     "lr": 1e-3}]
opt = torch.optim.AdamW(groups, weight_decay=1e-2)

# ---- LoRA
cfg = LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"], lora_dropout=0.05)
model = get_peft_model(base_model, cfg)
model.print_trainable_parameters()          # typically well under 1%
model = model.merge_and_unload()            # fold into W for deployment

# ---- freezing batch norm properly
for mod in m.modules():
    if isinstance(mod, nn.BatchNorm2d):
        mod.eval()                          # stop the running stats updating
        for p in mod.parameters():
            p.requires_grad = False
```

The trap worth naming: when fine-tuning with batch norm, `model.train()` updates the running statistics even for layers whose parameters are frozen. If the target batch size is small, those pretrained statistics get overwritten with noisy estimates and the model degrades for a reason that looks nothing like its cause. Call `.eval()` on the batch-norm modules explicitly when you freeze them.

### Worked Example

**Part A: LoRA parameter counting.** A transformer with $d = 4096$ has $W^Q$ of size $4096^2 = 16{,}777{,}216$.

$$
\text{LoRA at } r = 8: \quad 2rd = 2(8)(4096) = 65{,}536 .
$$
$$
\text{Reduction} = \frac{16{,}777{,}216}{65{,}536} = 256\times .
$$

Across a 32-layer model touching $W^Q$ and $W^V$ in each layer:

$$
\text{Full: } 32\times2\times16{,}777{,}216 = 1.074\times10^9 \text{ parameters.}
$$
$$
\text{LoRA: } 32\times2\times65{,}536 = 4{,}194{,}304 \text{ parameters.}
$$

**4.19M instead of 1.07B**, which is 0.39%. And since $\Delta W = BA$ can be added into $W$ after training, inference costs exactly what the base model costs.

**Part B: what that buys in memory.** Full fine-tuning of a 7B model in mixed precision needs roughly: 14 GB for the fp16 weights, 28 GB for fp32 master weights, and 56 GB for Adam's two moment buffers in fp32, about 98 GB before a single activation, which does not fit on one 80 GB accelerator.

With LoRA on more of the model than the two attention projections above, say 0.4% of the 7B parameters trainable, the optimizer state is 0.4% of 56 GB $\approx$ 0.2 GB, and the frozen base can be held in fp16 or, with QLoRA, in 4-bit at about 3.5 GB. The whole run fits comfortably on one GPU. That memory arithmetic, not the accuracy, is why parameter-efficient methods took over.

**Part C: discriminative rates, laid out.** Five stages with base rate $10^{-3}$ and decay 2.5:

| stage | rate |
| --- | --- |
| head | $1.0\times10^{-3}$ |
| block 4 | $4.0\times10^{-4}$ |
| block 3 | $1.6\times10^{-4}$ |
| block 2 | $6.4\times10^{-5}$ |
| block 1 | $2.6\times10^{-5}$ |

The first block moves at about one fortieth (1/39) of the head's rate. Over 10 epochs the head is effectively retrained and block 1 has barely shifted, which is the intended behavior, since block 1's edge detectors were already correct.

**Part D: the forgetting arithmetic.** A model at 76% on ImageNet is fine-tuned on 200 medical images. At $\eta = 10^{-3}$ for 20 epochs, target accuracy reaches 88% and ImageNet accuracy falls to 31%. The pretrained knowledge has been largely overwritten by 200 examples, and the target number is itself suspect, since 200 examples cannot support 25M trainable parameters.

At $\eta = 10^{-5}$ for 5 epochs with the first three blocks frozen, target accuracy is 86% and ImageNet accuracy is 71%. Slightly worse on the target, far better preserved, and the second model is much more likely to hold up on new medical images, because it is still relying on general features rather than on 200 memorized ones.

**Part E: the crossover, empirically.** Train a linear probe, then unfreeze one block at a time and record target accuracy as a function of the target-set size:

| target size | best strategy |
| --- | --- |
| 100 | linear probe |
| 1,000 | last block + head |
| 10,000 | last two blocks |
| 100,000 | full fine-tune |

The pattern is the bias–variance trade-off in a different costume: each unfrozen block adds capacity, and capacity pays only once there is enough data to constrain it. Running this sweep on your own task takes an afternoon and settles the question better than any rule of thumb.

### Practice

1. Sweep the LoRA rank $r\in\{1,2,4,8,16,64\}$ on a fine-tuning task and plot accuracy against trainable parameters.
2. Reproduce the crossover table above on a dataset of your own by subsampling the training set.
3. Measure catastrophic forgetting directly: fine-tune on a target task and evaluate on the source task before and after, at three learning rates.
4. Freeze batch norm incorrectly (parameters frozen, module in train mode) and measure the damage at batch size 4.
5. Compare LoRA on attention projections only against LoRA on the feed-forward layers only, at matched parameter budgets.

## Intuition

Fine-tuning can move useful features as well as overfit, so give early layers a smaller learning rate and validate where the crossover falls rather than assuming early layers are always task-independent. Layerwise rates and low-rank updates are both priors about where change is needed, and the crossover sweep is what tells you which to trust.
