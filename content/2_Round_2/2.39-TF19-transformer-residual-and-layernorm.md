# 2.39 · TF19 · 9. Residual and LayerNorm

> **Goal:** Residual connections, LayerNorm and pre-norm.
> **Stage:** Round 2, Core contest depth.





## The problem

Steps 4 to 8 are one attention layer, and a model stacks many layers. Three things go wrong when layers are simply chained, each one feeding the next.

**The training signal fades.** Training adjusts each layer using a signal passed back from the output through every layer in between. If each layer passes back only half of it, layer 1 of a 12-layer model receives $0.5^{12} = 0.00024$ of the signal and barely learns. Deeper plain networks do train worse: He et al. (2016) found that a plain 56-layer network did worse than a 20-layer one, and attributed the degradation to an optimization difficulty, arguing that vanishing gradients are not the cause.

**The numbers drift.** Nothing keeps the size of the numbers steady from one layer to the next. If each layer's output were twice as large as its input, the numbers would be $2^{12} = 4{,}096$ times as large after 12 layers.

On the left, the training signal reaching layer 1 if each layer passes back half: it falls in a straight line to 0.00024 at 12 layers. On the right, the size of the numbers if each layer doubles them: it rises in a straight line to 4,096 at 12 layers.">
Small effects in each layer multiply. After 12 layers the training signal has almost vanished, or the numbers have grown thousands of times.
</Figure>

**A token loses itself.** Head 1's half of the attention output for "sat" in Step 8, (0.872, 1.135), is mostly the value of "cat". If the whole output simply replaced the vector of "sat", the model would lose track of the verb itself.

## Earlier approaches

### Plain stacking

Feeding each layer straight into the next has all of these problems. If each of 12 layers passes back only 1% of the training signal, the first layer receives $0.01^{12} = 10^{-24}$ of it, effectively nothing.

### Batch normalization

Batch normalization rescales numbers using statistics across a whole batch of texts, which fits text poorly: the same sentence gets different numbers depending on which other sentences share its batch, and generating one token at a time gives it no batch to average over, so it reuses statistics fixed during training instead of computing fresh ones.

## Residual connections and LayerNorm

**The residual connection.** A **residual connection** adds a layer's input back to its output. For the attention layer, with input $H$ and output $M$:

$$
\text{sum} = H + M.
$$

The layer then only has to learn a correction, and the token's own information is never lost. For example, a layer with nothing to add can output zeros, and the token passes through unchanged: (1, 2) + (0, 0) = (1, 2). The addition also gives the training signal a direct path back to earlier layers, one that does not shrink on the way.

A dashed line labelled residual connection carries H around the attention box and into the plus sign. Under the boxes are the numbers for sat: H is 0.909, -0.416, 1.020, 2.000. The attention output M is 0.872, 1.135, 0.893, 1.771. Their sum is 1.781, 0.719, 1.913, 3.771. Y, after LayerNorm, is -0.241, -1.208, -0.121, 1.571.">
Add and normalize for "sat" in the running example. The input goes round attention unchanged and is added to its output.
</Figure>

**The direct path.** Training passes its signal back through a layer by multiplying it by how much the layer's output changes with its input. A residual layer outputs $x + f(x)$, so it passes back 1 for the path around $f$, plus whatever $f$ passes back. Through two layers whose $f$ pass back $a$ and $b$:

$$
(1 + a)(1 + b) = 1 + a + b + ab,
$$

one term for each route the signal can take. With $a = b = 0.5$:

| Route | Signal it carries |
|---|---|
| Around both layers | 1 |
| Through the first layer only | 0.5 |
| Through the second layer only | 0.5 |
| Through both layers | 0.25 |

Plain stacking keeps only the last route. With 12 layers that route carries $0.5^{12} = 0.00024$, but the route around every layer still carries 1, so layer 1 keeps receiving the signal. For vectors the 1 becomes the identity table, which leaves a vector unchanged, and the same expansion holds.

**LayerNorm.** **Layer normalization** rescales each token's vector on its own: subtract the average of its numbers, then divide by their spread, the **standard deviation**:

$$
\text{LayerNorm}(z) = \frac{z - \text{average}}{\sqrt{\text{average of the squared deviations} + \varepsilon}}.
$$

For example, take (2, 4, 6, 8). The average is 5, so subtracting it gives (−3, −1, 1, 3). The squares of those average to (9 + 1 + 1 + 9) ÷ 4 = 5, so the standard deviation is $\sqrt{5} = 2.236$. Dividing gives (−1.34, −0.45, 0.45, 1.34). Whatever the input, the result has an average of 0 and a standard deviation of 1, so the size of the numbers cannot drift from layer to layer. Real models then multiply each dimension by a learned scale and add a learned shift. The running example leaves these at 1 and 0.

**Where the norm goes.** The original Transformer normalizes after each addition, **post-norm**, as in the running example. GPT-2 and most later models normalize only the copy that each part reads, **pre-norm**:

$$
\text{post-norm: } \text{LayerNorm}(H + \text{attention}(H)), \qquad \text{pre-norm: } H + \text{attention}(\text{LayerNorm}(H)).
$$

For "sat", pre-norm attention would read the normalized vector (0.036, −1.506, 0.165, 1.305), and its output would be added to $H$ itself, (0.909, −0.416, 1.020, 2.000). The copy of $H$ that skips around attention reaches the addition untouched, so the 1 of the direct path survives every block. In post-norm, every sum goes into a LayerNorm, so the skipped copy is rescaled once per block, and so is the signal sent back along it. Deep post-norm models train less stably and need a **warmup**, a learning rate raised slowly over the first steps of training, while pre-norm models train well without one (Xiong et al., 2020).

**The final norm.** With pre-norm, each part adds to the vectors and nothing normalizes them, so they tend to grow with depth. GPT-2 therefore adds one more LayerNorm after the last block, the final LayerNorm counted in [Step 11](2.41-TF21-transformer-stack.md), and scales the starting weights at the end of each part by $1/\sqrt{N}$, where $N$ counts the residual additions: 2 per block, 24 in GPT-2 small, a factor of 0.204. Post-norm needs neither of these, because every block already ends with a norm. The rows of $H$ in the running example have lengths 1.732, 2.258 and 2.458, and every row of $Y$ below has length 2: after LayerNorm the squares of its 4 numbers average 1, so they add up to 4.

## Running example

### The residual connection

First, the residual connection adds $H$ from Step 3 to $M$ from Step 8. For "sat":

| | Dim 1 | Dim 2 | Dim 3 | Dim 4 |
|---|---|---|---|---|
| $H$ | 0.909 | −0.416 | 1.020 | 2.000 |
| $M$ | 0.872 | 1.135 | 0.893 | 1.771 |
| Sum | 1.781 | 0.719 | 1.913 | 3.771 |

For all three tokens:

| Token | Dim 1 | Dim 2 | Dim 3 | Dim 4 |
|---|---|---|---|---|
| the | 2.000 | 2.000 | 0.000 | 2.000 |
| cat | 1.722 | 2.945 | 1.659 | 2.000 |
| sat | 1.781 | 0.719 | 1.913 | 3.771 |

### LayerNorm

Then LayerNorm, worked through for "sat":

| Step | Values |
|---|---|
| Numbers | 1.781, 0.719, 1.913, 3.771 |
| Average | (1.781 + 0.719 + 1.913 + 3.771) / 4 = 2.046 |
| Subtract the average | −0.265, −1.327, −0.133, 1.725 |
| Average of the squares of those | (0.070 + 1.761 + 0.018 + 2.976) / 4 = 1.206 |
| Standard deviation, the square root | 1.098 |
| Divide by it | −0.241, −1.208, −0.121, 1.571 |

Doing every row gives the output of this step, $Y$:

| Token | Dim 1 | Dim 2 | Dim 3 | Dim 4 |
|---|---|---|---|---|
| the | 0.577 | 0.577 | −1.732 | 0.577 |
| cat | −0.698 | 1.677 | −0.821 | −0.158 |
| sat | −0.241 | −1.208 | −0.121 | 1.571 |

Every row now has an average of 0 and a standard deviation of 1.

```python
import numpy as np

H = np.array([[1.000, 1.000, 0.000, 1.000],
              [0.841, 1.540, 1.010, 1.000],
              [0.909, -0.416, 1.020, 2.000]])
M = np.array([[1.000, 1.000, 0.000, 1.000],
              [0.881, 1.405, 0.649, 1.000],
              [0.872, 1.135, 0.893, 1.771]])

def layer_norm(z, eps=1e-5):
    mean = z.mean(axis=-1, keepdims=True)
    var = z.var(axis=-1, keepdims=True)
    return (z - mean) / np.sqrt(var + eps)

Y = layer_norm(H + M)
print(Y.round(3))    # last digits differ slightly: the inputs are rounded
```

## Common questions

**Does LayerNorm lose information?** It removes the overall size and offset of a vector. (2, 2, 0, 2) and (4, 4, 0, 4) both become (0.577, 0.577, −1.732, 0.577), which is the row of "the" above. What is kept is the pattern, which numbers are larger than which. The learned scale and shift let the model put a size back if it needs one.

**Why add $H$ back and not just use $M$?** For "sat", the first half of $M$ is mostly the value of "cat". Without the addition, that half of "sat" would be replaced by what it looked at. With it, the vector holds both what the token was and what it found.

**How is LayerNorm different from batch normalization?** LayerNorm uses only the numbers of one token's vector, 4 here, so the result does not depend on the other tokens or the other texts in the batch. Batch normalization averages over the batch.

**What does the small number in the code do?** The code adds $10^{-5}$ under the square root so that a vector whose numbers are all equal, with a standard deviation of 0, does not cause a division by zero.
