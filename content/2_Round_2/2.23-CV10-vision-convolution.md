## The problem

An image is recognized by its local patterns: edges, strokes, corners. The model needs to find a pattern, such as a bright vertical stroke, wherever it appears.

For example, the three images below contain the same vertical line, in column 1, column 3 and column 5. To a person they show the same thing. As numbers, the bright pixels are in different places each time.

<Figure src="assets/module-media/vision-problem-convolution.svg" alt="Three 6 by 6 grids of numbers. Each has one column of ones and zeros everywhere else. The bright column is column 1 in the first image, column 3 in the second and column 5 in the third. A note says: one pattern, three sets of pixels.">
The same pattern in three places.
</Figure>

A model with a separate set of weights for every position has to learn the stroke again for each place it could be. A 3 × 3 pattern fits in 16 places in a 6 × 6 image, and in about 50,000 places in a 224 × 224 photo. The model needs one set of weights that finds the pattern at every position.

## Earlier approaches

### Hand-designed filters

Image processing used fixed filters chosen by people. The Sobel filter, for example, finds vertical edges with the numbers −1, 0, 1 in each row, weighted 1, 2, 1 down the rows. It works for edges, but nobody can design by hand the filters needed to recognize a cat.

### Fully connected layers

A fully connected layer gives every pixel its own weight for every unit, so it cannot reuse what it learned about a stroke in one place for a stroke somewhere else.

## Convolution

**One position.** A **convolution** slides a small grid of weights, a **filter**, across the image. At each position it multiplies the filter with the patch underneath, number by number, and adds up the results:

$$
\text{output} = \sum_{\text{rows } i} \; \sum_{\text{columns } j} \text{filter}_{i,j} \times \text{patch}_{i,j}.
$$

For example, the filter row (−1, 2, −1) over the patch row (0, 1, 0) gives −1 × 0 + 2 × 1 + −1 × 0 = 2. A 3 × 3 filter adds up three such rows.

<Figure src="assets/module-media/vision-convolution.svg" alt="The 6 by 6 image with a 3 by 3 window outlined over rows 1 to 3 and columns 2 to 4, where the bright column runs through the middle of the window. It is multiplied by the vertical filter, whose three rows are each -1, 2, -1, and the products are added up. The result, 6, is outlined in the second cell of the top row of a 4 by 4 feature map whose rows are each -3, 6, -3, 0.">
One position of the vertical filter in the running example. The 9 products add up to 6, one number of the feature map.
</Figure>

**Every position.** Sliding the filter over every position gives a grid of outputs called a **feature map**. Each number says how strongly the filter's pattern appears at that place: large where the patch looks like the filter, and 0 or negative where it does not.

**Shared weights.** The same weights are used at every position, so a 3 × 3 filter has just 9 weights for an image of any size, and a pattern learned in one place is found everywhere. Convolution also does not automatically reuse a filter across rotations or changes of scale. We can encourage those behaviors with appropriate training examples or additional architectural choices. The filter's numbers are learned during training, not designed. Because those weights are shared, one weight's gradient has to add up a term for every position it was used at. Using the site's notation from [Convolutional Neural Networks](1.30-CV7-convolutional-neural-networks.md), $Y_{i,j}=\sum_u\sum_v X_{i+u,\,j+v}\,K_{u,v}$, and writing $g_{i,j}=\partial L/\partial Y_{i,j}$ for the error at one position of the feature map, the chain rule gives

$$\frac{\partial L}{\partial K_{u,v}}=\sum_{i,j} g_{i,j}\,X_{i+u,\,j+v}.$$

[Backpropagation by Hand](2.1-MA4-backpropagation-mechanics.md) derives its rule: a weight's gradient is the error at the unit it feeds times the activation it reads, for a weight that appears in one place only. A filter's weight appears at every position, so the sum runs over all of them. In the example above, the filter's middle weight $2$ reads the bright pixel at four positions, and its gradient picks up all four terms. An input pixel is shared the same way: it belongs to several patches, up to nine for a $3\times3$ filter, so its gradient adds up the errors at every position whose patch contains it, each times the weight that read it:

$$\frac{\partial L}{\partial X_{a,b}}=\sum_{i,j} g_{i,j}\,K_{a-i,\,b-j},$$

with the terms left out where $a-i$ or $b-j$ falls outside the filter's range.

**Output size.** An image of $n \times n$ pixels and a filter of $k \times k$ give a feature map of $(n - k + 1) \times (n - k + 1)$, because that is how many positions the filter fits in. For our image, 6 − 3 + 1 = 4, so 4 × 4. For a 224 × 224 photo and a 3 × 3 filter, 222 × 222.

## Running example

### The filters

The model has two filters, one for vertical lines and one for horizontal ones:

| Filter | Row 1 | Row 2 | Row 3 |
|---|---|---|---|
| Vertical | −1, 2, −1 | −1, 2, −1 | −1, 2, −1 |
| Horizontal | −1, −1, −1 | 2, 2, 2 | −1, −1, −1 |

### One position, then every position

Placed over columns 2 to 4 of the image, the vertical filter has the bright column under its middle, so each of its three rows gives 2 × 1 = 2, and the total is 6. Placed over columns 1 to 3, the bright column is under its right edge, so each row gives −1 × 1 = −1, and the total is −3. Sliding it over every position gives the vertical feature map:

| | Map col 1 | Map col 2 | Map col 3 | Map col 4 |
|---|---|---|---|---|
| Every row | −3 | 6 | −3 | 0 |

### The horizontal filter

The horizontal filter gives 0 everywhere. Where the line is under it, the line crosses all three of its rows, which contribute −1, 2 and −1, for a total of 0. In the rightmost position the line has slid out of the window, so the patch is all zeros. So the vertical filter fires on this image and the horizontal one does not.

```python
import numpy as np

image = np.zeros((6, 6)); image[:, 2] = 1.0
vertical = np.array([[-1, 2, -1], [-1, 2, -1], [-1, 2, -1]], dtype=float)

feature_map = np.array([[(image[i:i + 3, j:j + 3] * vertical).sum()
                         for j in range(4)] for i in range(4)])
print(feature_map)       # every row is -3, 6, -3, 0
```

## Common questions

**Why does the filter have negative numbers?** So that it responds to a line and not just to brightness. Over a patch that is bright everywhere, each row of the vertical filter gives −1 + 2 − 1 = 0. It gives a large output only when the middle column is brighter than its neighbors.

**Why does the feature map get smaller?** A 3 × 3 filter cannot be centered on an edge pixel, so a 6 × 6 image has only 4 × 4 positions. Networks often add a border of zeros around the image, called **padding**, so that the map keeps the size of the image.

**What if there are several filters?** Each filter gives its own feature map, and the maps are stacked as channels. The two filters here turn a 6 × 6 × 1 image into a 4 × 4 × 2 output. The first layer of a real network has dozens of filters.

**What is the stride?** How far the filter moves between positions. This page moves it 1 pixel at a time. A stride of 2 skips every other position and roughly halves each side of the map.
