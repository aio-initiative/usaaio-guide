# 2.37 · TF17 · 7. Weighted sum

> **Goal:** Averaging the values by attention weight, and its gradients.
> **Stage:** Round 2, Core contest depth.

## The problem

After Step 6, each token has a weight for every token it can see. For "sat" in head 1 the weights are 0.115 for "the", 0.709 for "cat" and 0.175 for itself. Each of those tokens also has a value from Step 4.

What "sat" has in head 1 after Step 6: three weights and three values, and no result yet.
</Figure>

The weights say how much each token matters, but a weight is not information. "sat" still has to receive something. The three values have to be combined into one new vector for "sat" that carries what it found. The way of combining has to meet three needs:

- **Fixed size.** The result is the same size whether the token looked at 3 others or 3,000.
- **Follows the weights.** A token with a weight of 0.709 should count for far more than one with 0.115.
- **Smooth.** A small change in a weight gives a small change in the result, so that training can adjust it.

## Earlier approaches

### Copying one token

Copying only the highest-weighted token ignores the rest and cannot be trained: "sat" would take the value of "cat" and drop everything else.

### The context vector

Bahdanau et al. (2014) combined a translation model's states by a weighted sum, called a context vector: when translating "the black cat" into French, the word "chat" draws mostly on "cat". The Transformer keeps this idea.

## The weighted sum

**One token.** Each token's new vector is the **weighted average** of the values of the tokens it can see. Multiply each value by its weight and add:

$$
\text{output} = a_1 v_1 + a_2 v_2 + \dots
$$

where $a_j$ is the weight on token $j$ and $v_j$ is its value. For example, weights of 0.5 and 0.5 on the values (2, 0) and (0, 2) give 0.5 × (2, 0) + 0.5 × (0, 2) = (1, 1).

**What the weights do.** If one weight is close to 1, the output is close to that token's value: weights of 0.9 and 0.1 on (2, 0) and (0, 2) give (1.8, 0.2). If the weights are equal, the output is the plain average. Because the weights are positive and add up to 1, the output always lies between the values.

The statement that the output lies between the values applies to the averaging operation, rather than to the full transformer block. Later projections, residual additions, and feed-forward layers transform this result further, so the block as a whole is not confined to the hull of the values.

A heavier arrow shows the output for sat, (0.872, 1.135), which lies between the three values and is built mostly from the value of cat.">
Head 1 of the running example. The output for "sat" lies between the three values, and the value of "cat", which has the largest weight, contributes the most to it.

**Every token at once.** With the weights as the rows of $A$ and the values as the rows of $V$, the outputs for all tokens are one matrix multiplication, $A V$. Steps 4 to 7 together are called **scaled dot-product attention**. In one line, with the mask of Step 6 applied before the softmax:

$$
\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V,
$$

where $d_k$ is the head size, 2 in the running example. For head 1, the softmax gives the 3 × 3 table of weights from Step 6, and $V$ is the 3 × 2 table of values from Step 4, so the output is a 3 × 2 table with one row per token.

### Gradients

**One score.** Training changes attention through its scores. When the score $s_j$ of token $j$ rises by a small amount, its weight rises and the others fall (Step 6), and the output moves toward that token's value:

$$
\frac{\partial \, \text{output}}{\partial s_j} = a_j \, (v_j - \text{output}).
$$

The move is large when the token already has a large weight and its value lies far from the output. For "sat" in head 1, whose output is (0.872, 1.135):

| Score of | Weight | Value − output | Weight × (value − output) |
|---|---|---|---|
| the | 0.115 | (0.128, −0.135) | (0.015, −0.016) |
| cat | 0.709 | (−0.031, 0.405) | (−0.022, 0.287) |
| sat | 0.175 | (0.037, −1.551) | (0.006, −0.271) |

Raising the score of "cat" pulls the output up, toward the value of "cat". Raising the score of "sat" pulls it down, toward the value of "sat". The three moves add up to (0, 0), because raising every score by the same amount changes no weight. Added up, the rows of the table give (−0.001, 0.000) rather than (0, 0), because each is rounded. At full precision they cancel exactly.

Two arrows start at the output and are drawn to scale: one labeled score of cat rises points up along the line to cat, and one labeled score of sat rises points down along the line to sat. How fast the output for "sat" in head 1 moves as each score rises. Each arrow points toward its token's value.
</Figure>

**The whole table.** Training starts from $dO$, how much the loss of [Step 12](2.42-TF22-transformer-predict.md) changes with each number of the output, one row per token. Working back through $O = AV$, the softmax and $S = QK^\top / \sqrt{d_k}$:

$$
dV = A^\top dO, \qquad dS = A \odot \left(dO \, V^\top - r\right), \qquad dQ = \frac{dS \, K}{\sqrt{d_k}}, \qquad dK = \frac{dS^\top Q}{\sqrt{d_k}}.
$$

Here $\odot$ multiplies matching entries, and $r$ is a column with one number per row: the weighted average of that row of $dO \, V^\top$, using the row's weights, subtracted from every entry of the row. The $dS$ formula is the rule for one score applied to every row at once. For example, let the loss be the first number of the output of "sat", so $dO$ is 0 except for (1, 0) in the row of "sat". Then $dV$ gives the three values 0.115, 0.709 and 0.175 times (1, 0): each value is blamed in proportion to its weight. In the row of "sat", $dO \, V^\top$ holds the first number of each value, 1.000, 0.841 and 0.909, and their weighted average is the first number of the output, 0.872 (the rounded weights and values shown give 0.870). Subtracting 0.872 and multiplying by the weights gives 0.115 × 0.128 = 0.015, 0.709 × (−0.031) = −0.022 and 0.175 × 0.037 = 0.006, the first numbers of the table above.

<ProblemCard id="tf-which-value-takes-the-blame" />

**Only the outputs.** The weighted average subtracted in each row equals the dot product of that token's row of $dO$ with its row of the output, because the output is itself the weighted average of the values. In the example it is (1, 0) · (0.872, 1.135) = 0.872. So it can be found from $O$ and $dO$ alone, before any weight is known. [Efficient Transformers: 4. FlashAttention](4.11-TF29-efficient-flashattention.md) relies on this: it stores no table of weights, and in the backward pass it recomputes them a block at a time.

## Running example

### One token

For "sat" in head 1, the weights from Step 6 are 0.115, 0.709 and 0.175, and the values of head 1 come from Step 4:

| Token | Weight | Value | Weight × value |
|---|---|---|---|
| the | 0.115 | (1.000, 1.000) | (0.115, 0.115) |
| cat | 0.709 | (0.841, 1.540) | (0.596, 1.092) |
| sat | 0.175 | (0.909, −0.416) | (0.159, −0.073) |
| | | **Sum** | **(0.870, 1.134)** |

At full precision it is (0.872, 1.135), mostly the value of "cat".

### Every token in head 1

| Token | Head 1 output |
|---|---|
| the | (1.000, 1.000) |
| cat | (0.881, 1.405) |
| sat | (0.872, 1.135) |

### Head 2

| Token | Weight | Value | Weight × value |
|---|---|---|---|
| the | 0.124 | (0.000, 1.000) | (0.000, 0.124) |
| cat | 0.105 | (1.010, 1.000) | (0.106, 0.105) |
| sat | 0.771 | (1.020, 2.000) | (0.786, 1.542) |
| | | **Sum** | **(0.892, 1.771)** |

At full precision it is (0.893, 1.771), close to the value of "sat" itself.

| Token | Head 2 output |
|---|---|
| the | (0.000, 1.000) |
| cat | (0.649, 1.000) |

```python
import numpy as np

A1 = np.array([[1.000, 0, 0], [0.250, 0.750, 0], [0.115, 0.709, 0.175]])
V1 = np.array([[1.000, 1.000], [0.841, 1.540], [0.909, -0.416]])

O1 = A1 @ V1
print(O1.round(3))   # last digits differ slightly: the inputs are rounded
```

The gradient formulas can be checked against small nudges to each input, a check worth running on any backward pass written by hand:

```python
import numpy as np

Q1 = np.array([[0.000, 1.000], [1.010, 1.000], [1.020, 2.000]])
K1 = np.array([[1.000, 0.000], [1.540, 1.010], [-0.416, 1.020]])
V1 = np.array([[1.000, 1.000], [0.841, 1.540], [0.909, -0.416]])
hidden = np.triu(np.ones((3, 3), dtype=bool), k=1)

def attention(Q, K, V):
    S = np.where(hidden, -np.inf, Q @ K.T / np.sqrt(2))
    A = np.exp(S - S.max(axis=1, keepdims=True))
    A /= A.sum(axis=1, keepdims=True)
    return A @ V, A

O, A = attention(Q1, K1, V1)
dO = np.zeros((3, 2))
dO[2, 0] = 1                     # loss: first number of the output of "sat"
dV = A.T @ dO
dS = A * (dO @ V1.T - (dO * O).sum(axis=1, keepdims=True))
dQ, dK = dS @ K1 / np.sqrt(2), dS.T @ Q1 / np.sqrt(2)

def nudged(X, h=1e-6):
    """The same gradient from small nudges: raise and lower each number of X."""
    G = np.zeros_like(X)
    for i in np.ndindex(X.shape):
        X[i] += h
        up = attention(Q1, K1, V1)[0][2, 0]
        X[i] -= 2 * h
        down = attention(Q1, K1, V1)[0][2, 0]
        X[i] += h
        G[i] = (up - down) / (2 * h)
    return G

print([np.allclose(G, nudged(X)) for X, G in ((Q1, dQ), (K1, dK), (V1, dV))])
# [True, True, True]
```

## Common questions

**Does the output replace the token's vector?** No. It is what the token gathered from the others. Step 9 adds it to the token's own vector, so nothing the token already had is lost.

**Why is the output of "the" just its own value?** "the" has a weight of 1 on itself and 0 on everything else, so its weighted sum is its own value: (1.000, 1.000) in head 1.

**Can the output be larger than every value?** No. The weights are positive and add up to 1, so each number of the output lies between the smallest and the largest of the values. In head 1 the first numbers of the values are 1.000, 0.841 and 0.909, and the output has 0.872.

**Why do the hand sums differ in the last digit?** The weights and values shown are rounded to three decimals. Adding the rounded products gives (0.870, 1.134), and full precision gives (0.872, 1.135).
